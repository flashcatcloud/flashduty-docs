## Rate limits

Every operation is rate limited. Limits are counted per account (all APP Keys and console sessions of the account share one budget), in a per-second and a per-minute window; each operation also has a platform-wide limit shared by all accounts. The exact numbers for an operation are on its page under **Restrictions**.

Default limits per account:

| Operation type | Per second | Per minute |
| --- | :---: | :---: |
| Read (list, get, query) | 50 | 1,000 |
| Write (create, update, delete, enable, …) | 20 | 300 |

Some operations have tighter limits, for example exports and heavy analytics queries; their **Restrictions** table shows the actual values.

### When you hit a limit

The request fails with HTTP `429` and error code `RequestTooFrequently`. The response carries the header `Flashcat-Request-Rate-Limit-Delay`, the number of seconds until the current window resets. Wait at least that long before retrying; if the header is absent, back off exponentially (1 s, 2 s, 4 s, …).

<Warning>
Retrying immediately in a loop keeps the window saturated. Spread bulk jobs over time, and prefer list operations that accept multiple IDs over one call per object.
</Warning>

## Permission checks

- An APP Key with **All permissions** has no additional API-scope restriction, but remains limited by the creator's current role permissions.
- An APP Key with **Custom permissions** can call only the APIs in its selected scope.
- A call outside either the key's scope or the creator's role permissions fails with HTTP `403` and `AccessDenied`. The required permission of each operation is listed under **Restrictions** on its page.
- Some operations additionally check object-level access (for example, only members of a channel's team can change it); those rules are described in each operation's **Usage** section.
- Create separate APP Keys for different purposes, each with the smallest scope it needs.

## Error codes

Every failure returns the envelope `{ "request_id": "…", "error": { "code": "…", "message": "…" } }`. Branch on `error.code`; it is stable. `message` is localized and may change.

| Error code | HTTP status | Meaning | What to do |
| --- | :---: | --- | --- |
| `InvalidParameter` | 400 | A parameter is missing, has the wrong type, or failed validation. `message` usually names the field. | Fix the request; do not retry unchanged. |
| `BadRequest` | 400 | The request breaks a business rule or conflicts with the current state of an object; `message` says which. | Read `message`, then fix the request or the object state. |
| `InvalidContentType` | 400 | The body is not sent as `application/json`. | Set `Content-Type: application/json`. |
| `ResourceNotFound` | 400 | The referenced object does not exist in this account or was deleted. Returned as 400, not 404. | Check the ID. |
| `ReferenceExist` | 400 | The object is still referenced by other objects, so it cannot be deleted. | Remove the references first. |
| `NoLicense` | 400 | The account's plan does not include the feature, a plan quota is used up, the plan has expired, or credits are insufficient. | Upgrade the plan, buy licenses, or add credits in the billing center. |
| `Unauthorized` | 401 | The APP Key is missing, invalid, or deleted. | Check the `app_key` parameter or `Fd-App-Key` header. |
| `AccessDenied` | 403 | The key's scope or the creator's role does not allow this operation or object. | Grant the permission or use another key. |
| `RouteNotFound` | 404 | No operation matches the method and path. | Check the path and HTTP method on the operation page. |
| `MethodNotAllowed` | 405 | The path exists but not for this HTTP method. | Use the method shown on the operation page. |
| `EntityTooLarge` | 413 | The request body exceeds the size limit. | Send less data per request. |
| `RequestTooFrequently` | 429 | A rate limit was hit. | Wait for `Flashcat-Request-Rate-Limit-Delay` seconds, then retry. |
| `InternalError` | 500 | Unexpected server error. | Retry with backoff; if it persists, contact support with the `request_id`. |
| `ServiceUnavailable` | 503 | A backend dependency is overloaded or unavailable. | Retry with backoff. |

Other values of the `ErrorCode` enum in the API reference (`RequestVerifyRequired`, `DangerousOperation`, `RequestLocked`, `BalanceNotEnough`, `UndonedOrderExist`) belong to console-only flows such as MFA and billing and are not returned by Open API operations.

## Retry advice

- **Retry** only `429`, `500`, `503`, and network errors, with exponential backoff (start at 1 second, at most 3 retries). For `429`, honor `Flashcat-Request-Rate-Limit-Delay`.
- **Do not retry** other `4xx` errors unchanged; they will fail the same way.
- **Treat creates as not idempotent.** Before retrying a create that timed out, list or query to check whether the first attempt succeeded.
- **Log the `request_id`** of every failed call; support needs it to locate the request.
