## Organization information

The **Organization Information** page centralizes your organization's identity and org-level default settings, and is accessible to all members. Entry: **Platform Management → Organization → Organization Information**, or click the **Organization Information** button on your profile card in Personal Center.

The page contains the following sections:

| Section | Description |
| --- | --- |
| **Organization Profile** | Organization logo, name, ID, and domain |
| **Join Restrictions** | Email-domain allowlist controlling who can join the organization through an invitation |
| **Notification Settings** | Content and language of system notifications within the organization, applied to all members |
| **Free Notification Quota Reminders** | Switches that email the organization's administrators before the free notification quota runs out or when it does |
| **Readiness requirement** | How many high-urgency notification methods each on-call member must have; members who fall short are reminded |
| **Incident Handling** | Org-level defaults for incident-handling operations, applied to the console and IM alert cards |

<Note>
This page is **open to all members**: regular members can view every configuration item in read-only mode; only the **subject account** or accounts with the **Admin** role can modify settings.
</Note>

## Organization profile

| Item | Description |
| --- | --- |
| **Logo** | Organization logo image, set through a **Logo URL** that must be a reachable http/https address; click **Reset to Default Logo** to clear the custom logo and restore the default |
| **Name** | Organization name, displayed in invitation emails and SMS messages |
| **ID** | Unique identifier of the organization; provide it when integrating APIs or contacting support |
| **Domain** | Dedicated subdomain for login and email integration push |
| **Time Zone** | The organization time zone. Members without their own personal time zone see all times in it |

### Organization time zone

The organization time zone determines what "organization-following" members see across the console. Changing it requires confirming the blast radius:

- Every member **without** a personal time zone switches to the new zone **immediately**.
- **Organization-level on-call schedules keep their original wall-clock time** when the organization time zone changes. A rotation set to "09:00 every day" in the schedule's time zone stays at 09:00 there.
- Members can override the display zone for themselves through the **Display Preferences** section of [Personal Settings](/en/on-call/configuration/personal-settings).

### Domain

The domain is an important identifier for the subject account, used to locate the correct SSO configuration during single sign-on. Each organization's login domain is globally unique. After configuration, members can initiate single sign-on directly through `{domain}.sso.flashcat.cloud`.

Note the following rules when changing the domain:

- The domain must be **5–40 characters** and can only contain letters, numbers, or `-`, and cannot start or end with `-`
- The new domain cannot be the same as the current one
- The change requires confirming the impact scope and may require multi-factor authentication (MFA)

After changing the domain, it applies to the following scenarios:

- **SSO single sign-on configuration**: All configured SSO login domains change accordingly; members must use the new domain to initiate single sign-on
- **Email integration push addresses**: The email integration receiving address format is `prefix@{domain}.{email-suffix}`; the address changes when the domain changes, so update related configurations promptly

See [SSO Configuration](/en/platform/configure-sso) for more information.

## Join restrictions

The Join Restrictions section controls **who can join the organization through an invitation**. It currently offers an email-domain allowlist: only people whose email domain is on the list can join.

| Item | Description |
| --- | --- |
| **Email domain allowlist** | Email domains allowed to join the organization. Type a domain and press Enter to add it; you can add several. **Leave it empty for no restriction** |
| **Allow subdomains** | Appears only when the allowlist contains at least one valid domain; off by default. When enabled, an allowlisted `corp.com` also covers subdomain addresses such as `mail.corp.com` |

<Note>
- Enter full domains (for example, `corp.com`); matching is case-insensitive
- The list must include **your own email domain**, or you can't save it
</Note>

### Where it applies

The allowlist only applies when someone **joins the organization**; it does not affect regular sign-in:

| Scenario | Restricted by the allowlist? |
| --- | --- |
| Email invitation | Yes. Addresses outside the allowlist cannot be invited |
| Joining through an invite link / QR code | Yes, based on the email the invitee signs in with, which must be verified |
| Phone invitation | No |
| Existing members and the owner account | No, even if their domain is not on the list |

<Note>
Organizations that enable [SSO-only login](/en/platform/configure-sso#sso-only-login) cannot be joined through an invite link / QR code; an administrator grants access through SSO instead.
</Note>

## Notification settings

The Notification Settings section maintains the content and language of system notifications within the organization, applied to all members.

### Default notification language

The org-level default language for system notification copy — **Chinese** or **English** — applied to incident dispatch, schedule shift, subscription expiration reminders, and other system notifications.

<Note>
- This setting does **not** affect the console UI language
- Verification and invitation emails follow the recipient's browser language and are unaffected by this setting
</Note>

### Send full incident alert SMS

An org-level toggle that controls whether incident alert SMS messages are truncated:

| State | Behavior |
| --- | --- |
| **Enabled** | Incident alert SMS messages are no longer truncated; long content may be split by carriers into multiple messages, billed per message |
| **Disabled** | Incident alert SMS messages are truncated to a single message length |

<Note>
Verification, invitation, and on-call SMS messages are **unaffected** by this toggle and always follow their original behavior.
</Note>

### Free notification quota reminders

When your free notification quota (SMS / voice call / email) runs low, Flashduty emails the organization's administrators so notifications do not stop once the quota is used up. This block is **available on SaaS only** and is not shown on private deployments. Both switches are **on by default** and can be turned off independently.

| Switch | Trigger |
| --- | --- |
| **Remind at 20% remaining** | Free quota drops to 20% or below while still above 0 |
| **Remind when exhausted** | Free quota reaches 0 for the first time |

<Note>
- Turning a switch back on does **not** backfill thresholds crossed while it was off
- Flashduty counts only **paid accounts** (Standard / Pro, not in trial, not expired), and only notifications **sent successfully and counted toward the quota**. Free accounts don't get this reminder
- SMS, voice calls, and emails are counted and reminded **separately**: at most one reminder per quota period per channel
- Reminder emails don't count toward the notification quota
- Reminders are **email-only** — no SMS or phone call. They go to the account's own email address plus the verified email addresses of currently enabled **Admin** members (up to 20)
</Note>

For quota amounts, overage billing, and what happens when a free quota runs out, see [Plans and Billing](/en/platform/pricing#notification-quota).

## Readiness requirement

**Readiness requirement** sets how many high-urgency notification methods every on-call member must have. When an incident needs an immediate response, only phone calls and IM reach people fast enough; this setting is that bar. Which on-call members currently meet it is shown in the legend on the schedule detail page — see [On-call schedules](/en/on-call/configuration/schedule#view-schedule-details).

| Setting | Description |
| --- | --- |
| **No extra requirement** | Default. Notification methods aren't checked, and no reminders are sent |
| **At least 1 (phone or IM)** | Each member has at least one high-urgency method: a phone number on record, or a bound IM |
| **At least 2 (phone and IM)** | Both are required |

How each method is judged:

- **Phone**: having a phone number in the member's profile counts. Calls and SMS both go to that number.
- **IM**: having any one IM app bound counts.
- Installing the app alone does not count — app push is not a high-urgency method.
- On a self-hosted deployment with the phone turned off, only **No extra requirement** and **Require IM** are available.

Once the bar is set, a member who falls short gets at most one reminder every 24 hours naming the missing method. The reminder goes to the member's IM when one is bound, otherwise to app push, otherwise to email; a member reachable on none of them gets no reminder. A change applies to every member; regular members can only see the current bar.

## Incident handling

The Incident Handling section maintains org-level defaults for incident-handling operations, applied to **the console and IM alert cards**.

### Snooze time presets

When snoozing incidents in the console or IM cards (Feishu/Lark, DingTalk, WeCom, Slack, Teams), the system offers 3 preset durations:

- Exactly **3 fixed slots**; each slot uses **hours** or **minutes** as its unit
- Each value must be greater than 0, and at most **24 hours** (max 24 in hours, max 1440 in minutes)
- Presets **cannot be duplicated**
- Defaults are **2 hours / 4 hours / 12 hours**; click **Restore Defaults** to reset quickly

Saved changes take effect immediately in the console and IM cards. See [Snooze](/en/on-call/incident/handle-update-incident) for more snooze operations.

### Quick-silence label exclusion rules

When you create a [quick silence](/en/on-call/channel/noise-reduction#quick-silence), Flashduty builds the matching conditions from the incident's severity and labels. It leaves out labels that hit an exclusion rule. Labels whose values change every time (trigger value, current value, links, and so on) would otherwise let similar alerts escape silencing.

**Where to configure**: Organization Information → Incident Handling → **Quick-silence excluded labels**. Changes apply only to quick silences created afterwards.

Configuration contents:

- **Per-integration exclusion lists**: maintain an excluded label list for each integration separately. When creating a quick silence, a label hitting any exclusion list is excluded
- **System format rule toggles**: `json` (JSON values), `datetime` (datetime format), and `numeric` (numeric values), all on by default. Flashduty also always excludes label values longer than 235 characters
- **Global blacklist**: a built-in set of labels whose values change often (such as `trigger_value`, `current_value`, `detail_url`, `query`) is always excluded and cannot be configured
