## Overview

A new session starts from the memory files already in the current scope. Without memory, you'd re-explain your habits every time: where to look first for a kind of failure, or why you dropped an earlier approach. Every investigation would start with the same background. Memory keeps those points as Markdown files and later sessions reuse them.

Memory and [knowledge](/en/ai-sre/knowledge) are two different kinds of material. People maintain knowledge, and it describes how the environment runs. The system organizes memory: preferences, procedures, facts, and lessons kept from conversations. Both belong to the console's [Context](/en/ai-sre/context) group, but each has its own page: **AI SRE → Customize → Context → Memory**.

## Memory types

Each memory file starts with a name, a one-line description, and a type. There are four types:

| Type | What it is for |
| --- | --- |
| preference | How answers should be written, such as leading with the conclusion or which timezone to use |
| procedure | The steps to take first in a kind of situation |
| fact | An environment fact that will come up again, such as who owns a system |
| lesson | Why an approach does not work, so it is not tried again |

Memory is written to the scope of the session that produced it. A session bound to a team writes that team's memory; a bot DM, web, or console session with no team writes your personal memory; a shared group chat (including a war room) with no team neither reads nor writes memory. A memory stays until you change or delete it.

## How memory is created

Memory has three sources:

- **You ask for it.** In the conversation, tell the assistant to remember, change, or forget something, and it writes or updates the matching memory file in the same turn. When you state a standing preference or correct how the assistant works, it also saves a preference right away — you don't need to say "remember".
- **A background pass after the turn.** About 6 hours after a session's last turn ends, a background pass distills procedures, facts, and lessons. It never writes a preference: a habit you mention in passing does not become memory that way.
- **`/init` import.** When `/init` imports material from your local AI coding tools, it writes personal preferences and reusable habits as memory; see [Setup (/init)](/en/ai-sre/init).

The first two write into the scope of the current session; `/init` writes into the scope it was started under.

## How the Agent uses memory

When a session starts, the memory files in the current scope are ready. The assistant sees each file's name and description first, and opens the body when it needs the detail. A session bound to a team uses that team's memory; a bot DM, web, or console session with no team uses the creator's personal memory; a shared group chat (including a war room) with no team loads no memory and writes none — to use memory in a group, first bind the session to a team with `/scope`.

The four types are used differently: procedure, fact, and lesson are past records that must be checked against the current situation before use. Preference is a request you made explicitly, followed within its stated scope, and it wins when it conflicts with a Skill's or tool's default behavior.

## Scope & isolation

Memory has only two scopes, **Personal** and **Team**. There is no account-level memory.

- **Personal memory**: readable only by the person it belongs to.
- **Team memory**: readable when the current session is bound to that team, or when the reader is a member of that team. Account owners and admins get no exemption, and there is no cross-team read.

In the console, viewing, editing, and deleting team memory all require real team membership: a read-only Viewer cannot open it even when they belong to the team, and account owners and admins get no exemption — without membership they cannot open it either. Personal memory is readable and writable only by its owner.

For the overall permission rules, see [Scope and permissions](/en/ai-sre/context#scope-and-permissions).

## View and edit it in the console

Go to **AI SRE → Customize → Context → Memory**.

- **Pick a scope**: switch between **Personal** and **Team** at the top; for Team, pick one of your teams from the dropdown. There is no Shared (account-level) memory.
- **Find a memory**: the list on the left is grouped by Preference / Procedure / Fact / Lesson, newest update first within each group. The search box filters by name, description, and file name.
- **Edit**: click **Edit** on the right, change the name, the one-line description (when it applies), and the content, then save. This page has no create entry — memory is produced or imported only in a session (see [How Memory Is Created](#how-memory-is-created)). The **type** cannot be changed here either, because it is fixed when the memory is written. The page only groups by type and writes the type back unchanged.
- **Delete**: after deletion, later conversations no longer use it. Telling the assistant to forget something in the conversation has the same effect.

If someone else or the AI changed the memory while you were editing, saving warns you; saving again overwrites it with your version, and canceling shows the latest content.

### Ask AI to change it

With edit permission, an input box sits below the body (placeholder: "What should change? for example, make the release window weekdays 10:00 to 16:00"). After you send it, the console opens a new chat whose input already holds a reference to this scope's memory and your request. Personal memory opens a personal session, and team memory opens a session bound to that team, because memory is written only to the session's own scope. Once sent, the AI first explains in text which memories it will add, merge, or delete, and saves only after you agree.
