## Overview

A new session starts from the memory files already in the current scope. If you had to re-explain your habits, where to look first for a kind of failure, or why a previous approach was abandoned, troubleshooting would begin with the same background every time. Memory keeps those points as Markdown files and later sessions reuse them.

Memory is not [knowledge](/en/ai-sre/knowledge). People maintain knowledge, and it describes how the environment runs. The system organizes memory: preferences, procedures, facts, and lessons kept from conversations. Both belong to the console's [Context](/en/ai-sre/context) group, but each has its own page: **AI SRE → Customize → Context → Memory**.

## Memory Types

Each memory file starts with a name, a one-line description, and a type. There are four types:

| Type | What it is for |
| --- | --- |
| preference | How answers should be written, such as leading with the conclusion or which timezone to use |
| procedure | The steps to take first in a kind of situation |
| fact | An environment fact that will come up again, such as who owns a system |
| lesson | Why an approach does not work, so it is not tried again |

Where the file is saved follows the session. A session bound to a team writes that team's memory. A session with no team writes your personal memory. A memory stays until you change or delete it.

## How Memory Is Created

Memory arrives in two ways:

- **You ask for it.** In the conversation, tell the assistant to remember, change, or forget something. It writes or updates the matching memory file.
- **After the session.** When a session ends, the system keeps what will still be useful later.

Both ways write into the scope of the current session.

## How the Agent Uses Memory

When a session starts, the memory files in the current scope are ready. The assistant sees each file's name and description first, and opens the body when it needs the detail. A session bound to a team uses that team's memory. A session with no team uses your personal memory.

The four types carry different weight: procedure, fact, and lesson are past records that must be checked against the current situation before use; preference is a request you made explicitly, followed within its stated scope, and it wins when it conflicts with a Skill's or tool's default behavior.

## Scope & Isolation

Memory has only two scopes, personal and team. There is no account-level memory, and cross-account reads are rejected outright.

| Dimension | personal | team |
| --- | --- | --- |
| Ownership | The person the memory belongs to | The team the memory belongs to |
| Read condition | The person the memory belongs to | The current session is bound to that team, or the caller is a genuine member of that team |
| Exemption | Not applicable | Owners and admins get no exemption |
| Cross-team reads | Not applicable | No such path exists |

This isolation follows the same permission model as other AI SRE resources: team scope does not open up just because you're the account owner or an admin. You must be an actual member of that team.

## View and edit it in the console

Go to **AI SRE → Customize → Context → Memory**.

- **Pick a scope**: switch between **Personal** and **Team** at the top; for Team, pick one of your teams from the dropdown. There is no Shared (account-level) memory. The scope and team are kept in the page URL, so a refresh or a shared link opens the same set of memories.
- **Find a memory**: the list on the left is grouped by Preference / Procedure / Fact / Lesson, newest update first within each group; the search box filters by name, description, and file name.
- **Create or edit**: click **New memory**, or click **Edit** on the right, fill in the name, type, a one-line description (when it applies), and the content, then save.
- **Delete**: after deletion, later conversations no longer use it. Telling the assistant to forget something in the conversation has the same effect.

If someone else or the AI changed the memory while you were editing, saving warns you; saving again overwrites it with your version, and canceling shows the latest content.

### Ask AI to change it

With edit permission, an input box sits below the body (placeholder: "What should change? e.g. make the release window weekdays 10:00 to 16:00"). After you send it, the console opens a new chat whose input already holds a reference to this scope's memory and your request. Personal memory opens a personal session, and team memory opens a session bound to that team, because memory is written only to the session's own scope. Once sent, the AI first explains in text which memories it will add, merge, or delete, and saves only after you agree.
