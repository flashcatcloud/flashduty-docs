## Overview

---

A Skill is a **reusable capability package**. Each skill consists of two parts:

- A **SKILL.md** description document that tells the agent when to use the skill, how to use it, and what steps to follow.
- The **set of tools the skill is allowed to use**, plus optional reference resource files (scripts, templates, sub-documents, etc.).

A skill is packaged into a `.zip` archive and uploaded to AI SRE. The root of the archive must contain a `SKILL.md` file; other resource files may be placed anywhere inside the archive and the agent can read them on demand during execution.

Once enabled, a skill appears in the session's `<available_skills>` list. The agent can **autonomously decide** when to invoke a skill, or you can **explicitly trigger** it in the chat box using `/<skill-name>` (e.g., `/flashduty`).

<Tip>
Skills vs. MCP: MCP provides **the ability to connect external tools**, while a skill provides **the methodology for orchestrating those tools to accomplish a class of tasks**. The two work together — a skill declares in its SKILL.md which tools it needs, including built-in tools and MCP tools in the form `mcp:server/tool`.
</Tip>

### SKILL.md Format

`SKILL.md` consists of two parts: a YAML frontmatter (metadata) section and a body (agent-readable instructions), separated by `---`:

```markdown
---
name: skill-name
description: USE FIRST for ... — a concise description of the problem this skill solves and when to use it
version: "1.0.0"
tags:
  - tag1
  - tag2
author: author-name
license: MIT
allowed-tools: bash, read, task
---

## Instructions

The skill body goes here: execution steps, constraints, notes…
```

Frontmatter fields:

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `name` | string | Yes | Skill name in kebab-case (lowercase letters, digits, and hyphens only — e.g. `my-skill-name`), 1–64 characters. Used as the `/<skill-name>` trigger word. |
| `description` | string | No | Skill description. This is the primary signal the agent uses when selecting a skill. Write it as an imperative phrase such as "USE FIRST / prefer-over-X" — the more precise, the more reliably it will be invoked. |
| `version` | string | No | Version string, e.g. `1.0.0`. |
| `tags` | string[] | No | List of tags. |
| `author` | string | No | Author name. |
| `license` | string | No | License identifier. |
| `allowed-tools` | string[] | No | List of tools this skill is allowed to use. Leave empty to impose no additional restrictions. |

There are two ways to specify tools:

- **Built-in tools**: write the tool name directly. Available built-in tools include `read`, `write`, `edit`, `bash`, `grep`, `glob`, `skill`, `mcp`, `todo`, `time`, `webfetch`, `web_search`, and others.
- **MCP tools**: write in the form `mcp:server/tool` (e.g. `mcp:my-server/query`). At upload time the system only checks whether the referenced MCP server exists; the specific tool name is validated when MCP is loaded at session runtime.

<Note>
The built-in `flashduty` skill (pre-installed for every account) is a good reference example: it covers the entire Flashduty API via the `fduty` CLI, allowing the agent to triage incidents, read AI analysis details, query alerts, associate changes, and more. Use it as a reference when writing your own skills.
</Note>

## Install from the Marketplace

---

Go to **Customize → Skills**, then click **Browse Marketplace** to open the skill **catalog** — a card grid of all available skill templates provided by Flashduty and Anthropic, which you can browse and install with one click.

<Steps>
  <Step title="Open the catalog">
    Click **Browse Marketplace** on the Skills list page. A catalog dialog opens, displaying all available skill templates as a card grid.
  </Step>
  <Step title="Search and filter">
    Use the search box at the top to find skills by name or description. The **Filter** in the top-right corner lets you show only "Installed" or "Not installed" items; **Sort** supports "Installed first" or "Name A–Z".
  </Step>
  <Step title="One-click install">
    Click the **+** button on any uninstalled card to install it. Installation copies the template content into your account as a regular skill entry and marks its source template (cards show a `v<version>` badge indicating "from Marketplace").
  </Step>
  <Step title="Manage installed items">
    The top-right corner of an installed card changes to a gear icon. Click it to open that skill's detail panel for management.
  </Step>
</Steps>

### Automatic and Manual Updates

When a template in the Marketplace publishes a newer version, the corresponding skill entry shows an **Update available** badge. Whether the update is applied automatically depends on whether the skill has been modified locally (`is_modified`):

<CardGroup cols={2}>
  <Card title="Clean skill (unmodified)" icon="rotate">
    Skills that have not been modified locally after installation are **automatically** updated to the latest Marketplace version when the list loads — no manual action required. A notification appears after a successful update.
  </Card>
  <Card title="Modified skill" icon="pen">
    Skills that have been locally edited or re-uploaded are **skipped** by automatic updates to avoid overwriting your changes. The "Update available" badge remains, and you must **manually** click to update and confirm the overwrite.
  </Card>
</CardGroup>

<Warning>
Updating a modified skill **overwrites your local changes with the latest Marketplace version, and this cannot be undone**. A confirmation dialog will appear before the overwrite proceeds — review carefully. Once you reinstall the Marketplace version, the local-modification flag is cleared and the skill reverts to a clean state, resuming participation in automatic updates.
</Warning>

## Custom Skills

---

In addition to installing from the Marketplace, you can upload your own skill packages. Click **Upload Skill** on the Skills list page and fill in the form:

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| Owner | Team / Account | Yes | Choose the skill's scope: **Account** (visible to everyone in the account) or a specific **Team** (visible only to members of that team). See "Scope" below for details. |
| Zip file | File | Yes | A `.zip` archive containing `SKILL.md` (required) and any optional resource files. Only `.zip` files are accepted. |

At upload time the system automatically validates: the archive is a valid zip, `SKILL.md` exists at the root, the frontmatter is parseable, the `name` follows kebab-case naming, and declared tools are valid (built-in tools exist, referenced MCP servers exist). **Skill names must be unique within an account** — duplicate names are rejected with a prompt to choose a different name.

<Note>
All metadata other than the skill name (description, version, tags, author, tools, etc.) is parsed from the `SKILL.md` frontmatter automatically. You do not need to re-enter these fields in the upload form.
</Note>

Skills can also be **generated or modified directly by the agent in a conversation**: after the agent edits files under the `skills/<name>/` directory in the workspace, it can save them as a skill with one click. If a skill with the same name already exists, you will be prompted to confirm replacement first. Click **Edit in chat** in the detail panel to let the agent use the built-in `skill-creator` to help you rewrite a skill.

<Warning>
Skill archives have size limits: archives packaged and saved by the agent during a conversation are capped at **10 MB**; archives uploaded via the web form or file upload in a session are capped at **100 MB**.
</Warning>

## Management and Detail Panel

---

The Skills list displays each skill's **name** (with source template badge and "Update available" indicator), **scope** (account or team), **version**, **enabled** toggle, and an **Actions** column.

<AccordionGroup>
  <Accordion title="Enable / Disable" icon="toggle-on">
    Toggle using the switch in the list or in the detail panel. Only **enabled** skills appear in the session's `<available_skills>` list. Disabled skills are invisible to the agent and cannot be invoked.
  </Accordion>
  <Accordion title="Edit" icon="pen-to-square">
    Click the edit button to update the **description** and **scope**. To modify the skill content itself, download the zip, edit it, and **re-upload** (this creates a new version and marks the skill as modified).
  </Accordion>
  <Accordion title="Replace / Re-upload" icon="upload">
    In the detail panel, choose "Replace" to overwrite the current skill content with a new zip. The SkillID remains unchanged, so any references to this skill (such as `/<skill-name>` triggers) continue to work.
  </Accordion>
  <Accordion title="Download" icon="download">
    Download the complete zip package (including `SKILL.md` and all resource files) for offline editing or backup.
  </Accordion>
  <Accordion title="Uninstall / Delete" icon="trash">
    Remove the skill from the current scope. Active sessions that are using it will continue to fail until the skill is reinstalled. This action requires confirmation.
  </Accordion>
</AccordionGroup>

### Detail Panel

Click any row in the list to open the skill **detail panel**:

- **Left side**: the file tree of the skill package (`SKILL.md`, `README.md`, etc. are prioritized as the default preview file).
- **Right side**: a content preview of the selected file, with the skill description shown at the top.
- **Header area**: skill name (short reference such as `skill-xxxxxx`), scope label (account or team name), source template version badge (hover to see "From Marketplace — template name vX.Y.Z"), **Update available** indicator, author, `version`, and the full SkillID.
- **Actions**: Try in chat (injects `/<skill-name>` into a new session), Update to latest version, Edit in chat, Replace, Download, Uninstall.

<Tip>
If a skill package is **too large to preview**, the detail panel will show the file size and suggest using "Download" to view it instead.
</Tip>

## Scope

---

Skills share the same **two-level scope** model with other custom resources (Knowledge Packs, MCP, A2A Agents, Environments). The scope is determined by the `team_id` field on each resource row:

| `team_id` | Scope | Visibility |
| --- | --- | --- |
| `0` | Account level | Visible to all members of the account |
| `>0` | Team level | Visible only to members of that team |

**Edit permissions**: the account owner or an account admin can edit any skill; team members can edit team-level skills belonging to **their own team**. There is no "creator retains rights" exception. When you have no edit permission, the corresponding row in the list is shown as **read-only**.

**Runtime visibility**: when a session starts, only **account-level** skills and skills belonging to **the team bound to the current session** are included in the prompt. Skills and MCP from another team are only mounted into the current session on demand after the agent reads that team's knowledge (`.flashduty/knowledge/team_<id>/DUTY.md`). **The account is the only security boundary at runtime; team is an ownership and editing tag only.**

<Note>
For the complete scope model — including permission rules and runtime loading details — see [Custom Resources and Scope](/en/ai-sre/customize).
</Note>
