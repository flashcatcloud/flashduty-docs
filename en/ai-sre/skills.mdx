## Overview

---

A Skill is a **reusable capability bundle**. Each skill consists of two parts:

- A **SKILL.md** description document that tells the agent "when to use this, how to use it, and what steps to follow";
- The **allowed tools** declared by the skill, along with optional reference resource files (scripts, templates, sub-documents, etc.).

A skill is packaged as a `.zip` archive and uploaded to AI SRE. The archive's root directory must contain a `SKILL.md` file; other resource files can be placed anywhere inside the archive and the agent can read them on demand during execution.

Once enabled, a skill appears in the session's `<available_skills>` list. The agent can **autonomously decide** when to invoke a skill, or you can **explicitly trigger** it in the chat input with `/<skill-name>` (e.g. `/flashduty`).

<Tip>
The difference between a Skill and a Connector (Connector/MCP): a Connector provides **access to external tools**, while a Skill provides **the methodology for orchestrating those tools to accomplish a class of tasks**. They work together — a skill declares which tools it needs in SKILL.md, including built-in tools and MCP tools in the form `mcp:server-name/tool-name`.
</Tip>

### SKILL.md Format

A `SKILL.md` file consists of a YAML frontmatter block (metadata) and a body (agent-readable instructions), separated by `---`:

```markdown
---
name: skill-name
description: USE FIRST for ... — concise description of the problem this skill solves and when to use it
version: "1.0.0"
tags:
  - tag1
  - tag2
author: author-name
license: MIT
allowed-tools: bash, read, task
---

## Instructions

Write the skill body here: execution steps, constraints, important notes…
```

The frontmatter fields are:

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `name` | string | Yes | Skill name in kebab-case (lowercase letters, digits, and hyphens only, e.g. `my-skill-name`), 1–64 characters. Used as the trigger word for `/<skill-name>` |
| `description` | string | No | Skill description. This is the primary signal the agent uses to select a skill. Write it as an imperative sentence in the style of "USE FIRST / prefer-over-X" — the more precise it is, the more reliably the skill will be invoked correctly |
| `version` | string | No | Version number, e.g. `1.0.0` |
| `tags` | string[] | No | Tag list |
| `author` | string | No | Author |
| `license` | string | No | License |
| `allowed-tools` | string[] | No | The list of tools this skill is allowed to use. Leave empty to impose no additional restrictions |

There are two ways to specify tools:

- **Built-in tools**: write the tool name directly. Available built-in tools include `read`, `write`, `edit`, `bash`, `grep`, `glob`, `skill`, `mcp`, `todo`, `time`, `webfetch`, `web_search`, and the subagent dispatch tools `agent_dispatch`, `agent_message`, and `agent_stop`.
- **MCP tools**: write `mcp:server-name/tool-name` (e.g. `mcp:my-server/query`). At upload time only the existence of the MCP server is validated; the specific tool name is verified when the MCP server is loaded at session runtime.

<Note>
The built-in `flashduty` skill (pre-installed with every account) is a reference example: it covers the entire Flashduty API via the `fduty` command-line tool, letting the agent troubleshoot incidents, read AI-generated details, query alerts, associate changes, and more. You can use it as a template when writing your own skills.
</Note>

## Install from the Marketplace

---

Go to **Customize → Skills**, then click **Browse Marketplace** to open the skill **catalog**, where you can browse and install skill templates provided by Flashduty and Anthropic with one click.

<Steps>
  <Step title="Open the catalog">
    On the skill list page, click **Browse Marketplace**. A catalog dialog opens, displaying all available skill templates in a card grid.
  </Step>
  <Step title="Search and filter">
    Use the search box at the top to search by name or description. The **Filter** control in the upper right lets you show only "Installed" or "Not installed" items; **Sort** supports "Installed first" or "Name A–Z".
  </Step>
  <Step title="Install with one click">
    Click the **+** button on an uninstalled card to install it. Installation copies the template content to your account, creating a regular skill entry and recording its source template (cards display a `v<version>` badge indicating "from Marketplace").
  </Step>
  <Step title="Manage installed items">
    The upper-right corner of an installed card changes to a gear icon. Click it to open that skill's detail panel for management.
  </Step>
</Steps>

### Automatic and Manual Updates

When a template in the Marketplace publishes a newer version, the corresponding skill entry displays an **Update available** badge. Whether the update is applied automatically depends on whether the skill has been modified locally (`is_modified`):

<CardGroup cols={2}>
  <Card title="Clean skill (unmodified)" icon="rotate">
    Skills that have not been modified locally after installation are **automatically** updated to the latest Marketplace version when the list loads — no manual action needed. A notification appears after a successful update.
  </Card>
  <Card title="Modified skill" icon="pen">
    Skills that have been locally edited or re-uploaded are **skipped** by automatic updates to avoid overwriting your changes. They retain the "Update available" badge and require you to **manually** click the update button and confirm the overwrite.
  </Card>
</CardGroup>

<Warning>
Updating a modified skill overwrites your local changes with the latest Marketplace version and **cannot be undone**. A confirmation dialog ("Overwrite and update") will appear — proceed with caution. After reinstalling the Marketplace version, the local-modification flag is cleared and the skill returns to a clean state, once again eligible for automatic updates.
</Warning>

## Custom Skills

---

In addition to installing from the Marketplace, you can upload your own skill packages. On the skill list page, click **Upload Skill** and fill in the form:

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| Owner | Team / Account | Yes | Select the skill's scope: **Account** (visible to all members under the account) or a specific **Team** (visible only to that team's members). See "Scope" below for details |
| Zip file | File | Yes | A `.zip` archive containing `SKILL.md` (required) and optional resource files; only `.zip` files are accepted |

At upload time the system automatically validates: the archive is a valid zip, the root directory contains `SKILL.md`, the frontmatter is parseable, the `name` follows kebab-case naming, and declared tools are valid (built-in tools exist, MCP servers exist). **Skill names must be unique within the same account** — duplicates are rejected with a prompt to rename.

<Note>
All metadata other than the skill name (description, version, tags, author, tools, etc.) is parsed from the `SKILL.md` frontmatter automatically; you do not need to enter it again in the form.
</Note>

Skills can also be **generated or modified directly by the agent during a conversation**: after the agent edits files under the `skills/<name>/` directory in the workspace, the result can be saved as a skill with one click. If the name conflicts with an existing skill, a "Replace" confirmation prompt appears first. In the detail panel, click "Edit in chat" to have the agent use the built-in `skill-creator` to help you revise a skill.

<Warning>
Skill archives have size limits: archives packaged and saved by the agent during a conversation are capped at **10 MB**; archives uploaded via the web form or presented as file uploads within a session are capped at **100 MB**.
</Warning>

## Management and Detail Panel

---

The skill list displays each skill's **name** (including source-template badge and "Update available" marker), **scope** (account or team), **version**, **enabled** toggle, and **actions** column.

<AccordionGroup>
  <Accordion title="Enable / Disable" icon="toggle-on">
    Toggle using the switch in the list or the detail panel. Only **enabled** skills appear in the session's `<available_skills>` list; a disabled skill is invisible to the agent and cannot be invoked.
  </Accordion>
  <Accordion title="Edit" icon="pen-to-square">
    Click the edit button to update the **description** and **owner (scope)**. To modify the skill's content, download the zip, make your edits, and **re-upload** (this creates a new version and marks the skill as modified).
  </Accordion>
  <Accordion title="Replace / Re-upload" icon="upload">
    In the detail panel, select "Replace" to overwrite the current skill's content with a new zip. The SkillID remains unchanged, so any references to it (e.g. `/<skill-name>` triggers) continue to work.
  </Accordion>
  <Accordion title="Download" icon="download">
    Download the complete zip package (including `SKILL.md` and all resource files) for offline editing or backup.
  </Accordion>
  <Accordion title="Uninstall / Delete" icon="trash">
    Remove the skill from the current scope. Active sessions that are using it will continue to fail until it is reinstalled. A confirmation prompt appears before this action.
  </Accordion>
</AccordionGroup>

### Detail Panel

Click any row in the list to open the skill **detail panel**:

- **Left side**: the file tree of the skill package (`SKILL.md`, `README.md`, etc. are shown as the default preview file).
- **Right side**: content preview for the selected file, with the skill description shown at the top.
- **Header area**: skill name (short reference in the form `skill-xxxxxx`), scope label (account / team name), source-template version badge (hover to see "From Marketplace — template name vX.Y.Z"), **Update available** badge, author, `version`, and the full SkillID.
- **Actions**: try in chat (injects `/<skill-name>` into a new session), update to the latest version, edit in chat, replace, download, uninstall.

<Tip>
If the skill package is **too large to preview**, the detail panel will display the file size and suggest using "Download" to view it instead.
</Tip>

## Scope

---

Skills share the same **two-level scope** model with other custom resources (Knowledge Packs, Connectors/MCP, Subagents, A2A Agents, and BYOC Runners). The scope is determined by the `team_id` field on each resource row:

| `team_id` | Scope | Visibility |
| --- | --- | --- |
| `0` | Account-level | Visible to all members under the account |
| `>0` | Team-level | Visible only to members of that team |

**Edit permissions**: the account owner or account admin can edit any skill; team members can edit team-level skills **belonging to their own team**; there is no "creator retains rights" exception. When a user does not have edit permission, the corresponding row in the list is shown as **read-only**.

**Runtime visibility**: at session start, only **account-level** skills and skills belonging to **the team bound to the current session** are included in the prompt. A team's skills and connectors are mounted into the current session on demand only after the agent reads that team's knowledge (`.flashduty/knowledge/team_<id>/DUTY.md`). **The account is the only security boundary at runtime; team is purely an ownership and editing tag.**

<Note>
The complete description of the scope model (including permission rules and runtime loading details) can be found at [Custom Resources and Scope](/en/ai-sre/customize).
</Note>
