## Overview

---

AI SRE works out of the box, but **how well it understands your systems — and how accurately it diagnoses — depends on how much you equip it with**, especially the [Knowledge](/en/ai-sre/knowledge) base. In the console you capture team knowledge, package reusable troubleshooting flows, connect external tools, and specify where the agent runs — and it draws on these on demand when diagnosing incidents. **The more complete and accurate you keep them, the more accurate and useful AI SRE becomes.**

All extensible resources live behind three console entry points (matching the AI SRE left sidebar menu):

- **Plugins** — three tabs: **Skill**, **Agents** (remote A2A agents), and **MCP** (external tools), extending the capabilities the agent can execute and the parties it can delegate to.
- **Knowledges** — captures operational knowledge such as DUTY.md and runbooks as Knowledge Packs for the agent to consult during a session. **This is the resource that most affects diagnostic quality.**
- **Environments** — manages your self-hosted environments (BYOC Runners); the agent's tool calls, MCP connections, and Skill execution all run inside the selected environment.

<Tip>
Not sure where to start? Type [`/init`](/en/ai-sre/init) in any session and the agent walks you through building the knowledge base from scratch as an interview; then use [`/insight`](/en/ai-sre/insight) to review and keep finding what to add next.
</Tip>

<Note>
Whether a menu entry is visible depends on whether you have the corresponding access permission for that account. Entries you do not have access to will not appear in the navigation.
</Note>

## Scope: Account and Team

---

Every type of extensible resource (Skills, Knowledge, MCP, Agents, Environments) belongs to a **scope**:

- **Account level** — visible and usable across the entire account.
- **Team level** — visible only to members of that team.

You set this in the "Account or Team…" selector when creating a resource; the "Scope" column in the list shows whether a row belongs to the account or a specific team.

| Resource type | Console entry | Account level | Team level |
|---|---|---|---|
| Skill | Plugins → Skill | Visible and loadable in all sessions across the account | Visible only to that team's members; loaded only in that team's sessions |
| MCP | Plugins → MCP | Callable by all sessions across the account | Visible and editable only to that team's members |
| Agent | Plugins → Agents | Visible account-wide; can be delegated to by AI SRE | Visible and editable only to that team's members |
| Knowledge Pack | Knowledges | Visible to all sessions in the account | Loaded only in that team's sessions |
| Environment | Environments | Selectable by all sessions across the account | Visible and editable only to that team's members |

When a resource does not belong to your team, the list marks it as "Read-only (other team)" — you can view it, but you cannot edit it.

**Edit permissions**: the account owner or an account administrator can edit any resource in the account; team members can edit team-level resources in their own team (no "creator retains rights" exception). Each resource page documents its own specifics.

<Note>
A session bound to a team automatically loads that team's knowledge, Skills, and MCP, while account-level resources are always available to every session. For cross-team joint investigations, the agent can also read and load another team's knowledge when needed — the account is the only security boundary, and resources from other accounts are never visible under any circumstances.
</Note>

---

<CardGroup cols={2}>
  <Card title="Skill" icon="bug" href="/en/ai-sre/skills">
    Skill packages the agent can invoke to extend AI's ability to handle complex scenarios; can be set to account or team scope, and are loaded into the session when enabled.
  </Card>
  <Card title="Knowledge" icon="book" href="/en/ai-sre/knowledge">
    Capture DUTY.md and runbooks as Knowledge Packs — each target can have at most one Pack — for the agent to search and load on demand.
  </Card>
  <Card title="MCP (External Tools)" icon="plug" href="/en/ai-sre/mcp">
    MCP servers your agent can call; connections are established per environment at agent runtime.
  </Card>
  <Card title="Agent" icon="satellite-dish" href="/en/ai-sre/agents">
    Manage remote A2A (Agent-to-Agent) agents that AI SRE can delegate tasks to via the A2A protocol.
  </Card>
  <Card title="Environment (BYOC)" icon="server" href="/en/ai-sre/environments">
    A persistent process running on your own infrastructure that executes the agent's tool calls, connects to MCP servers, and runs Skills; falls back to a cloud sandbox when no environment is available.
  </Card>
