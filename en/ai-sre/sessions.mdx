## Overview

---

A session is one complete conversation between you and AI SRE. It holds every message you send, the agent's streaming replies, any tool calls made along the way, and all artifacts the agent produces (for example, code, reports, charts, or Skill packages).

Each session is fully independent, with its own context, bound team, and environment. You switch between sessions in the left sidebar and exchange messages — along with replies and artifacts — in the center conversation panel.

<Note>
Sessions are isolated from one another: context, bound team, and environment do not bleed across sessions. Switching away from a session does not interrupt a running turn — the backend continues writing events to that session, so you can return at any time and still see the streaming output.
</Note>

## Creating and Managing Sessions

---

The left sidebar is the central entry point for all sessions. Click **New Chat** to start a fresh session. The list is sorted by most recent activity, showing the latest few by default; expand older history with **Show more**.

### Search and Filter

<Steps>
  <Step title="Search chats">
    The search box at the top filters sessions by name. If nothing matches, the sidebar displays **No matching chats found**.
  </Step>
  <Step title="Filter by scope / status / activity">
    Click the **Filter** icon in the upper-right corner of the list to open the filter panel. Combine any of the dimensions below; a small dot appears on the filter button whenever a non-default filter is active.
  </Step>
</Steps>

Dimensions available in the filter panel:

| Dimension | Options | Notes |
|---|---|---|
| Scope | All / Personal / Team | Selecting **Team** reveals an inline search where you can pick one or more teams |
| Status | Active / Archived / All | Defaults to **Active** only; switch to **Archived** to find archived sessions |
| Recent activity | All / 24 hours / 7 days / 30 days | Narrows results by the session's last activity time |

The panel footer provides **Reset** (restore defaults) and **Done** (close the panel).

### Per-Session Actions

Hover over a session row to reveal the pin and archive actions. A pinned session displays a persistent pin icon to the left of its name.

| Action | Entry point | Notes |
|---|---|---|
| Pin / Unpin | Inline pin button (hover) | Pinned sessions appear at the top of the list |
| Archive / Unarchive | Inline archive button (hover) | Archived sessions are hidden from the active list by default; find them by switching the Status filter to **Archived** |
| Rename | Click the session title to edit inline | Press Enter or click away to save; press Esc to cancel. Maximum 60 characters |

<Tip>
Hover over a session row for a moment to see a tooltip showing the full session name, the bound team, and the exact timestamp — handy when the name is truncated and you need to confirm you have the right session.
</Tip>

### List Status Indicators

Each row shows one mutually exclusive indicator on the right:

| Indicator | Meaning |
|---|---|
| Spinning circle | The agent in this session is currently running (a turn is in progress) |
| Blue dot (unread) | The agent has produced new content you have not yet viewed |
| Relative time | When neither of the above applies, the time since the last activity is shown (e.g., `5m`, `3h`, `3d`) |

Opening a session clears its unread dot.

## Sending Messages and Streaming Responses

---

Type a message in the bottom input box and press Enter to send. The input box supports Markdown and slash commands — type `/` to bring up the command menu and trigger built-in skills or commands.

### Attachments and Context References

<AccordionGroup>
  <Accordion title="Upload attachments" icon="paperclip">
    Click the paperclip button, or drag and drop / paste files directly. Supported formats include images, PDFs, and Office documents (Word / Excel / PowerPoint), up to **20 MB** per file. Screenshots can be pasted directly into the conversation.
  </Accordion>
  <Accordion title="Context references" icon="link">
    When you navigate to AI SRE from an incident detail page or similar surface, the relevant context is automatically inserted as a reference in the input box, letting the agent start analyzing that incident immediately. You can remove the reference before sending.
  </Accordion>
  <Accordion title="Knowledge and skills" icon="book">
    When a session starts, the Knowledge Packs and Skills associated with the bound team are loaded automatically. See <a href="/en/ai-sre/knowledge">Knowledge Packs</a> and <a href="/en/ai-sre/skills">Skills</a> for details.
  </Accordion>
</AccordionGroup>

### Real-Time Streaming Output

After you send a message, the agent's reply streams back in real time over SSE — text appears token by token, and tool calls and reasoning steps are shown as they happen.

The moment you send, the frontend optimistically marks the turn as "running"; the backend's `is_running` status takes over after roughly 300 ms, so the running state is preserved even if you navigate away and return.

<Note>
While a turn is running, **the Send button becomes a Stop button**. Clicking Stop immediately interrupts the current turn: the UI reflects this at once, and the backend delivers the interruption signal asynchronously. An interrupted turn is marked as "interrupted" and remains visible after a page refresh.
</Note>

### Queuing Messages While a Turn Is Running

The input box stays active while a turn is in progress: you can keep typing and send additional messages, which are queued and executed in order once the current turn finishes. Queued messages can be edited or removed before they run.

## Tool Calls and Artifacts

---

Tools the agent invokes during a turn — reading or writing files, querying metrics, running commands, calling MCP tools, and so on — appear inline in the conversation as collapsible blocks. Click to expand and inspect the inputs and outputs; they are collapsed by default to keep the conversation tidy.

### Artifacts Preview

Files produced by the agent are surfaced as artifacts with built-in previews. Click an artifact to open the preview panel on the right, which renders by type:

| Type | Preview |
|---|---|
| Code (multi-language) | Syntax highlighting + line numbers |
| Markdown | Rendered view by default; toggle to **Source** |
| HTML | Rendered view by default (sandboxed iframe); toggle to **Source** |
| Image | Displayed directly; a retryable error prompt appears if loading fails |
| PDF | Rendered by the browser's built-in PDF viewer |
| Skill package (`.skill`) | File tree on the left + content on the right; download the entire package, or click **Save Skill** to add it directly to your account |

The preview panel provides **Copy**, **Download**, and **Close** actions.

<Tip>
Report-style artifacts (such as operational insight reports) can include Mermaid diagrams and charts rendered as HTML, viewable directly in the rendered panel. See <a href="/en/ai-sre/insight">Operational Insight Reports</a> for related capabilities.
</Tip>

### Message Actions

Hover over a message to reveal action buttons:

| Action | Applies to | Notes |
|---|---|---|
| Copy | User message / artifact | Copies the message text or file content to the clipboard |
| Retry | User message | Re-sends that message to start a new turn |
| Edit | User message | Loads the message back into the input box for editing before resending |

## Context Compaction

---

As a conversation grows, the session context approaches the model's context window limit. AI SRE automatically compacts earlier conversation history — summarizing it into a digest while retaining the most recent content — freeing up context space without losing key information.

Compaction is triggered in three ways:

| Trigger | When |
|---|---|
| Automatic (PreTurn) | Before a turn begins, when context usage exceeds the threshold |
| Automatic (MidTurn) | Mid-turn, if context continues to grow past the threshold |
| Manual | You explicitly trigger compaction with the `/compact` command |

### What You Will See

- **Compaction in progress**: A status line reading "Compacting conversation context…" appears in the conversation, showing elapsed time and progress. It disappears automatically once compaction is done.
- **Compaction complete**: The conversation continues seamlessly with no action required from you. The clearest signal is that the **Context** usage percentage in the chat header drops — it reflects the current utilization of the context window, and hovering over it shows the exact token counts.
- **No compaction needed**: When compaction is unnecessary (e.g., the conversation history is too short or is already in a compacted state), a manual trigger returns a corresponding notice such as "Context compaction is not needed" or "Conversation history is too short to compact."

<Note>
Compaction is transparent to you: you experience a continuous conversation. The agent retains a summary of the compacted content in the background, so subsequent turns can still build on earlier key conclusions.
</Note>

## Binding a Team

---

When creating a session you can **bind a team** to it. Once bound, the session automatically loads that team's Knowledge Packs, Skills, and MCP servers at startup, giving the agent the domain context and capabilities of that team from the very first turn. Without a bound team, the session runs at account scope.

<Steps>
  <Step title="Select a team">
    In the new-session input area, use the team selector to choose the team you want to bind. Your last selection is remembered so you do not have to repeat it each time.
  </Step>
  <Step title="Auto-load team context">
    At session startup, Knowledge Pack / Skill / MCP metadata for "account scope + bound team" is loaded, making them immediately available to the agent.
  </Step>
  <Step title="On-demand cross-team knowledge mounting">
    When the agent needs knowledge from another team, it reads that team's knowledge directory on demand and mounts that team's knowledge and capabilities as persistent context in the current session — once mounted, it remains available for the rest of the session.
  </Step>
</Steps>

The bound team persists with the session: reopening the same session restores the original team binding. The session's team is also shown in the sidebar tooltip for that session.

<Warning>
Automatic linking between incidents / war rooms and teams is still evolving. You can currently bind a team to a session explicitly; automatic binding in incident scenarios will be refined in future updates.
</Warning>

For the team scope rules that govern custom resources — account scope vs. team scope, visibility, and edit permissions — see <a href="/en/ai-sre/customize">Custom Resources and Scope</a>.
