## Overview

---

A session is a complete conversation between you and AI SRE. It holds every message you send, the agent's streaming replies, tool calls made during the conversation, and any artifacts the agent produces (such as code, reports, charts, or skill packages).

Each session is fully independent, with its own context, bound team, and runtime environment. You switch between sessions in the left sidebar, and send and receive messages — as well as view replies and artifacts — in the central conversation area.

<Note>
Sessions are completely isolated from one another: context, bound team, and runtime environment do not affect each other. Switching sessions does not interrupt an active turn — the backend continues writing events into the session, so you can return and still see the streaming output.
</Note>

## Creating and Managing Sessions

---

The left sidebar is the central entry point for all sessions. Click **New Chat** to start a brand-new session. The list is sorted by most recent activity in descending order. An initial set of recent sessions is shown, and you can expand further history by clicking **Show more**.

### Search and Filter

<Steps>
  <Step title="Search chats">
    Use the search box at the top to filter sessions by name. If nothing matches, **No chats found** is displayed.
  </Step>
  <Step title="Filter by scope / status / activity">
    Click the **Filter** icon in the upper-right corner of the list to open the filter panel. You can combine multiple dimensions to narrow results. When any non-default filter is active, a small dot appears on the filter button as a visual indicator.
  </Step>
</Steps>

Supported filter dimensions:

| Dimension | Options | Description |
|---|---|---|
| Scope | All / Personal / Team | When **Team** is selected, you can search and multi-select specific teams from an inline list |
| Status | Active / Archived / All | Only **Active** sessions are shown by default; switch to **Archived** to see archived sessions |
| Recent activity | All / 24 hours / 7 days / 30 days | Narrow results by the time of the session's most recent activity |

The bottom of the panel provides **Reset** (restore default filters) and **Done** (close the panel).

### Per-session Actions

Hover over a session row to reveal the pin and archive actions. Pinned sessions display a persistent pin icon to the left of the session name.

| Action | Entry point | Description |
|---|---|---|
| Pin / Unpin chat | Inline pin button on hover | Pinned sessions appear at the top of the list |
| Archive / Unarchive chat | Inline archive button on hover | Archived sessions are hidden from the active list by default; find them by switching to **Archived** in the filter |
| Rename | Click the chat title to edit in place | Press Enter or click away to save; press Esc to cancel. Name length limit: 60 characters |

<Tip>
Hover over a session row for a moment and a tooltip will appear showing the full session name, the team it belongs to, and the precise timestamp — useful for confirming the right session when the name is truncated.
</Tip>

### List Status Indicators

Each row displays one mutually exclusive status indicator on the right:

| Indicator | Meaning |
|---|---|
| Spinning circle | The agent in this session is running (a turn is in progress) |
| Blue dot (unread) | The agent has produced new content you have not yet viewed |
| Relative time | When neither of the above applies, the relative time of the most recent activity is shown (e.g. `5m`, `3h`, `3d`) |

Opening a session clears its unread dot.

## Sending Messages and Streaming Responses

---

Type your message in the input box at the bottom and press Enter to send. The input box supports Markdown and slash commands (type `/` to open the command menu) to trigger built-in skills and commands.

### Attachments and Context References

<AccordionGroup>
  <Accordion title="Upload attachments" icon="paperclip">
    Click the paperclip button, or drag and drop / paste files directly. Supported formats include images, PDFs, and Office documents (Word / Excel / PowerPoint). The maximum file size is **20 MB**. Screenshots can be pasted directly into the conversation.
  </Accordion>
  <Accordion title="Context references" icon="link">
    When you enter AI SRE from a page such as an incident detail view, the relevant context is automatically inserted as a reference in the input box, allowing the agent to start analysis directly from that incident. The reference can be removed before sending.
  </Accordion>
  <Accordion title="Knowledge and skills" icon="book">
    When a session starts, the knowledge and skills associated with the bound team are loaded automatically. See <a href="/en/ai-sre/knowledge">Knowledge</a> and <a href="/en/ai-sre/skills">Skills</a> below for details.
  </Accordion>
</AccordionGroup>

### Real-time Streaming Output

After you send a message, the agent's reply is streamed back in real time via SSE — text appears token by token, and tool calls and reasoning steps are shown as they occur.

At the moment you send, the frontend optimistically marks the turn as "running"; after approximately 300 ms the backend's `is_running` status takes over, so the running state is not lost even if you navigate away and return.

<Note>
While a turn is running, **the Send button becomes a Stop button**. Clicking Stop immediately interrupts the current turn: the UI reflects this at once, and the backend asynchronously sends the interrupt signal. Interrupted turns are marked with an "interrupted" label that remains visible after a page refresh.
</Note>

### Queuing Messages While Running

The input box remains usable while a turn is in progress. You can continue typing and send messages; they enter a queue and are executed in order after the current turn completes. Queued messages can be edited or removed before they are sent.

## Tool Calls and Artifacts

---

Tools invoked by the agent during a turn (reading and writing files, querying monitoring systems, running commands, dispatching sub-agents, etc.) appear inline in the conversation as collapsible items. Click to expand and view the input and output. They are collapsed by default to keep the conversation tidy.

### Artifact Preview

Files produced by the agent are offered as artifacts with preview support. Click an artifact to open the preview panel on the right; content is rendered according to type:

| Type | Preview |
|---|---|
| Code (multiple languages) | Syntax highlighting + line numbers |
| Markdown | Rendered view by default; toggle to **Source** |
| HTML | Rendered view by default (iframe sandbox); toggle to **Source** |
| Image | Displayed directly; a retryable error prompt is shown if loading fails |
| PDF | Rendered using the browser's built-in PDF viewer |
| Skill package (`.skill`) | File tree on the left + content on the right; the entire package can be downloaded, and you can **Save Skill** to your account with one click |

The preview panel provides **Copy**, **Download**, and **Close** actions.

<Tip>
Report-type artifacts (such as operational insight reports) can generate HTML that includes Mermaid diagrams and charts, viewable directly in the rendered view. For operational insight capabilities, see <a href="/en/ai-sre/insight">Operational Insight Report</a>.
</Tip>

### Message Actions

Hovering over a message reveals action buttons:

| Action | Applies to | Description |
|---|---|---|
| Copy | User messages / artifacts | Copies the message or file content to the clipboard |
| Retry | User messages | Re-triggers a new turn using that message |
| Edit | User messages | Pre-fills the input box with the message content for editing before re-sending |

## Context Compaction

---

As a conversation grows longer, the session context approaches the model's context window limit. AI SRE automatically compacts earlier conversation history — summarizing it into a digest and retaining the most recent content — to free up context space without losing critical information.

Compaction is triggered in three ways:

| Mode | When it triggers |
|---|---|
| Automatic (PreTurn) | Before a turn starts, when context usage exceeds the threshold |
| Automatic (MidTurn) | When context continues to grow during a turn and crosses the threshold again |
| Manual | When you explicitly trigger compaction with the `/compact` command |

### What You Will See

- **Compaction in progress**: A status line reading "Compacting conversation context…" appears in the conversation, showing elapsed time and progress. It disappears automatically when compaction is complete.
- **Compaction complete**: The conversation remains coherent with no action required on your part. The most direct indicator is that the **Context** usage percentage in the chat header drops — it reflects the current utilization of the context window. Hover over it to see the exact token count.
- **No compaction needed**: When compaction is unnecessary (e.g., the conversation history is too short or is already compacted), manually triggering it will display an appropriate message such as "No compaction needed" or "Conversation history too short to compact."

<Note>
Compaction is transparent to you: from your perspective the conversation is continuous. The agent retains a summary of compacted content in the background, so subsequent turns can still build on the key conclusions from earlier in the conversation.
</Note>

## Binding a Team

---

When creating a session you can **bind a team** to it. Once bound, the session automatically loads that team's knowledge, skills, and connectors (MCP) at startup, so the agent starts with the domain context and capabilities of that team. When no team is bound, the session runs at account scope.

<Steps>
  <Step title="Select a team">
    Use the team selector in the new-session input area to choose the team you want to bind. Your last selection is remembered so you do not have to repeat it each time.
  </Step>
  <Step title="Team context loaded automatically">
    As soon as the session starts, the knowledge / skills / MCP metadata for the "account scope + bound team" combination is loaded and the agent is ready to use.
  </Step>
  <Step title="Cross-team knowledge mounted on demand">
    When the agent needs knowledge from another team, it reads that team's knowledge directory on demand and mounts that team's knowledge and capabilities as persistent context in the current session — one mount remains active for the lifetime of the session.
  </Step>
</Steps>

The bound team is persisted with the session: reopening the same session restores the original team binding. The team the session belongs to is also displayed in the session tooltip in the sidebar.

<Warning>
Automatic linking between incidents / war rooms and teams is still evolving. For now you can explicitly **bind a team** to a session; automatic binding in incident scenarios will be improved over time.
</Warning>

For the rules governing team scope for resources (account scope vs. team scope, visibility, and edit permissions), see <a href="/en/ai-sre/customize">Custom Resources and Scope</a>.
