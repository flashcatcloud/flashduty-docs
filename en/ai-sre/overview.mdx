## What is AI SRE

---

AI SRE is Flashduty's autonomous SRE agent platform. You issue instructions to the AI through conversation, and it independently investigates incidents, traces root causes, calls tools to run diagnostics, and captures the operational knowledge gained from each investigation for future reuse.

This is not a simple Q&A chatbot — it is a **hands-on troubleshooting worker**: it plans its own steps, reads and writes files, queries monitoring and logs, executes commands, calls external tools (MCP), and delegates subtasks when needed, ultimately delivering conclusions backed by a full investigation trail.

AI SRE integrates deeply with Flashduty's incident response system. When Flashduty generates an incident or opens a war room for collaboration, you can directly trigger an AI SRE session so the agent enters the investigation scene with full incident context — you can interact in the console, or **@ it directly in your IM group (Slack / Lark / DingTalk / WeCom)**.

## Typical Use Cases

---

AI SRE is more than a chat window in the console — it covers multiple collaboration entry points across the full incident lifecycle from trigger to retrospective.

<CardGroup cols={2}>
<Card title="Conversational troubleshooting" icon="comments">
  Ask questions proactively in the console's conversation workspace: why a service is behaving abnormally, the root cause of an alert, or the blast radius of a change. The agent streams its planning, tool calls, and intermediate findings, then delivers a conclusion.
</Card>
<Card title="On-demand from IM" icon="comment-dots">
  No context switching needed — **@ AI SRE** in a Slack, Lark, DingTalk, or WeCom group or direct message to start or continue an investigation. It replies **in-thread** so all team members stay in the loop. See [IM Integration](/en/ai-sre/im).
</Card>
<Card title="War room auto-diagnosis" icon="people-group">
  When you open an IM war room for an incident, AI SRE **automatically runs an initial diagnostic round** and posts the findings back to the war room — your team has a first-pass analysis before anyone starts investigating manually.
</Card>
<Card title="Operational insight reports" icon="gauge-high">
  Use [`/insight`](/en/ai-sre/insight) to review the last 30 days of sessions, quantify where you spent your time, identify missing runbooks, and surface repeatedly copy-pasted context — with actionable improvement suggestions.
</Card>
</CardGroup>

## Core Capabilities

---

AI SRE is built around three pillars — conversational troubleshooting, knowledge capture, and autonomous execution — with everything configurable and manageable from the console.

<CardGroup cols={2}>
<Card title="Conversational troubleshooting" icon="comments" href="/en/ai-sre/sessions">
  Collaborate with the agent one session at a time. Each session is driven serially by a single actor, with streaming output, cancel-at-any-time, context compaction, and one-click launch from an incident.
</Card>
<Card title="IM integration" icon="comment-dots" href="/en/ai-sre/im">
  @ the agent in Slack / Lark / DingTalk / WeCom to start or continue an investigation, and get automatic initial diagnostics posted to incident war rooms.
</Card>
<Card title="Skills" icon="wrench" href="/en/ai-sre/skills">
  Skill packages the agent can invoke, encapsulating reusable troubleshooting workflows. Scope can be set to account or team; once enabled they are loaded on demand during sessions.
</Card>
<Card title="Knowledge Packs" icon="book" href="/en/ai-sre/knowledge">
  Knowledge packages indexed with DUTY.md as the entry point and @-reference navigation, carrying long-lived context such as service catalogs, runbooks, and on-call paths — loaded in layers by account and team.
</Card>
<Card title="MCP (External Tools)" icon="plug" href="/en/ai-sre/mcp">
  Connect external tools and data sources via the Model Context Protocol. MCP servers are not pre-connected; the agent connects, executes, and disconnects on demand when a tool call is needed.
</Card>
<Card title="A2A Agents" icon="satellite-dish" href="/en/ai-sre/agents">
  Delegate tasks to external remote agents via the standard A2A protocol. AI SRE also exposes its own Agent Card so external clients can invoke it in the opposite direction.
</Card>
<Card title="Environments (BYOC)" icon="server" href="/en/ai-sre/environments">
  The execution layer for agents. By default, Flashduty-managed cloud sandboxes are used. You can also deploy a persistent Runner on your own infrastructure to bring troubleshooting inside your private network.
</Card>
<Card title="Operational insight reports" icon="gauge-high" href="/en/ai-sre/insight">
  Use /insight to review the last 30 days of AI SRE sessions and get a quantified overview, a narrative of work done, and actionable operational improvement suggestions (read-only, not applied automatically).
</Card>
</CardGroup>

## Console Navigation

---

Once inside AI SRE, the top navigation is organized into four areas (menu names match the console):

| Area | Menu Name | Purpose |
|------|-----------|---------|
| Conversation | Chat | The primary workspace for collaborating with the agent on troubleshooting. The left panel shows the session list (with search, filtering, pinning, and archiving); the right panel shows the conversation and investigation trail. |
| Plugins | Plugins | Manage extension resources the agent can invoke, organized into three sub-tabs: **Skill** (skill packages), **Agents** (A2A remote agents), and **MCP** (external tools). |
| Knowledges | Knowledges | Manage Knowledge Packs. Each target supports at most one: account-level (visible to all agents) plus per-team (loaded only in sessions for that team). |
| Environments | Environments | Manage self-hosted Runners. The persistent process handles the agent's tool, Skill, and MCP calls; if no Runner is available, sessions fall back to the cloud sandbox. |

<Note>
Visibility of each area is controlled by account permission keys: `AiSreChatVisit` (Chat), `AiSrePluginSkillsVisit` / `AiSrePluginAgentsVisit` / `AiSrePluginMcpVisit` (the three Plugins sub-tabs), `AiSreKnowledgesVisit` (Knowledges), and `AiSreEnvironmentsVisit` (Environments). Areas for which you lack the corresponding permission will not be displayed.
</Note>

## Quick Start

---

<Steps>
  <Step title="Activate access">
    Confirm your account has a VPro or higher subscription and has been added to the AI SRE beta whitelist (contact the sales team to request access).
  </Step>
  <Step title="Open AI SRE">
    Open **AI SRE** from the Flashduty console side menu. You land in the Chat workspace by default.
  </Step>
  <Step title="Create a new session">
    Click "New Chat" to create a session. Sessions use the `app_name=ai-sre` agent by default and automatically select an available environment (falling back to the cloud sandbox if none is available).
  </Step>
  <Step title="Ask in natural language">
    Describe the problem you want to investigate in the chat input — for example, an abnormal service, the root cause of an alert, or the impact scope of a change.
  </Step>
  <Step title="Review the investigation and conclusion">
    The agent streams its planning, tool calls, and intermediate findings, then delivers a conclusion. You can follow up at any time, cancel, or re-launch the session from an incident or war room with full context.
  </Step>
</Steps>

<Tip>
On first use, run [`/init`](/en/ai-sre/init) in a session to let the agent help you build your [Knowledge](/en/ai-sre/knowledge) base — the more complete it is, the more accurate AI SRE. New knowledge from day-to-day troubleshooting can also be saved as a Knowledge Pack or a Skill.
</Tip>
