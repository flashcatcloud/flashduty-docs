## What is AI SRE

---

AI SRE is Flashduty's autonomous SRE agent platform built on [Google ADK](https://github.com/google/adk). You give the AI instructions through natural conversation, and it independently investigates incidents, diagnoses root causes, invokes tools to perform diagnostics, and captures the operational knowledge gained from each investigation for future reuse.

AI SRE is deeply integrated with Flashduty's incident response system: when Flashduty generates an incident or opens a war-room collaboration session, you can directly trigger an AI SRE session, bringing the agent into the investigation with full incident context.

<CardGroup cols={2}>
<Card title="Conversation as troubleshooting" icon="comments">
  Describe the problem in natural language. The agent plans autonomously, invokes tools, and delivers an investigation process and conclusions — no need to script each step yourself.
</Card>
<Card title="Integrated with incident response" icon="bug">
  Launch a session with one click from an incident or war room. The agent enters the investigation carrying the incident context, and the knowledge it accumulates feeds back into the next response.
</Card>
</CardGroup>

## Core Capabilities

---

AI SRE is built around three pillars — conversational troubleshooting, knowledge accumulation, and autonomous execution — each of which can be configured and managed from the console.

<CardGroup cols={2}>
<Card title="Conversational troubleshooting" icon="comments" href="/en/ai-sre/sessions">
  Collaborate with the agent on a per-session basis. Each session is driven serially by a single actor, with support for streaming output, cancellation at any time, context compaction, and one-click launch from an incident.
</Card>
<Card title="Skills" icon="wrench" href="/en/ai-sre/skills">
  Skill packages that the agent can invoke, encapsulating reusable troubleshooting workflows. Scope can be set to account or team; once enabled, skills are loaded on demand within sessions.
</Card>
<Card title="Knowledge base" icon="book" href="/en/ai-sre/knowledge">
  Knowledge packs accessed via DUTY.md as the entry point and indexed through @-references, carrying service catalogs, runbooks, on-call paths, and other long-lived context — loaded in layers by account and team.
</Card>
<Card title="Connectors and MCP" icon="plug" href="/en/ai-sre/connectors">
  Connect external tools via the Model Context Protocol. MCP servers are not pre-connected; the agent connects, executes, and disconnects on demand at call time.
</Card>
<Card title="Subagents and A2A" icon="robot" href="/en/ai-sre/agents">
  Asynchronously dispatch subagents via `agent_dispatch` to handle subtasks in parallel, or delegate tasks to external remote agents via the A2A protocol, with automatic continuation upon completion.
</Card>
<Card title="Environments (BYOC)" icon="server" href="/en/ai-sre/environments">
  The execution plane for the agent: uses Flashduty-hosted cloud sandboxes by default, or deploy a persistent Runner on your own machine to bring troubleshooting into your private network.
</Card>
<Card title="Operational insight report" icon="gauge-high" href="/en/ai-sre/insight">
  Use /insight to review AI SRE sessions from the past 30 days, producing a quantified overview, a narrative of activity, and actionable operational improvement suggestions (read-only; does not apply changes automatically).
</Card>
</CardGroup>

## Console Navigation

---

After entering AI SRE, the top navigation is organized into the following four areas (menu names match the console):

| Area | Menu name | Purpose |
|------|-----------|---------|
| Chat | Chat | The primary workspace for collaborating with the agent on troubleshooting. The left panel shows the session list (with search, filtering, pinning, and archiving); the right panel shows the conversation and investigation process. |
| Plugins | Plugins | Manage extensible resources the agent can invoke, organized into three sub-tabs: **Skills**, **Agents** (subagents and A2A remote agents), and **MCP** (connectors). |
| Knowledge base | Knowledges | Manage Knowledge Packs. At most one per target: account-level (visible to all agents) plus per-team (loaded only in sessions belonging to that team). |
| Environments | Environments | Manage self-hosted Runners. The persistent process handles tool, Skill, and MCP invocations for the agent; sessions fall back to the cloud sandbox when no Runner is available. |

<Note>
Visibility of each area is controlled by account permission points: `AiSreChatVisit` (Chat), `AiSrePluginSkillsVisit` / `AiSrePluginAgentsVisit` / `AiSrePluginMcpVisit` (the three Plugins sub-tabs), `AiSreKnowledgesVisit` (Knowledge base), and `AiSreEnvironmentsVisit` (Environments). Areas without the corresponding permission are not displayed.
</Note>

## Quick Start

---

<Steps>
  <Step title="Activate access">
    Confirm that your account has a VPro or above subscription and has been added to the AI SRE beta whitelist (contact the sales team to request this).
  </Step>
  <Step title="Open AI SRE">
    In the Flashduty console side menu, open **AI SRE**. The default view is the Chat workspace.
  </Step>
  <Step title="Create a session">
    Click "New conversation" to create a session. Sessions use the `app_name=ai-sre` agent by default and automatically select an available environment (falling back to the cloud sandbox if none is available).
  </Step>
  <Step title="Ask in natural language">
    In the chat box, describe the issue you want to investigate — for example, an anomaly in a service, the root cause of an alert, or the blast radius of a change.
  </Step>
  <Step title="Review the investigation process and conclusions">
    The agent streams its planning, tool invocations, and intermediate findings, and ultimately delivers its conclusions. You can follow up at any time, cancel the session, or relaunch it with context from an incident or war room.
  </Step>
</Steps>

<Tip>
Reusable knowledge accumulated during an investigation can be saved as a Knowledge Pack so that subsequent sessions load it automatically. Frequently used troubleshooting workflows can be codified as Skill packages.
</Tip>
