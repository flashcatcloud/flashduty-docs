`monitedge` is configured through command-line flags. This page lists the flags, defaults, and tuning guidance for alert pushes, event titles, and automatic upgrades.

## Alert push flags

| Flag | Default | Description |
|------|---------|-------------|
| `alerter.serverURL` | `https://api.flashcat.cloud` | Flashduty SaaS endpoint address |
| `alerter.serverAPIKey` | — (required) | API Key used to authenticate with the SaaS |
| `alerter.serverTimeout` | `30s` | Per-request timeout for a single push attempt |
| `alerter.alertRuleDeliveryWorkers` | `8` | Concurrency of alert event pushes. Events of the same alert are pushed in order |
| `alerter.alertRuleEventQueueSize` | `16384` | Queue capacity of pending events for each concurrent channel |
| `alerter.alertRuleEventBatchSize` | `100` | Maximum number of events per batch push, from 1 to 100, and at most 4 MB per batch |
| `alerter.alertRuleDeliveryResponseBytes` | `8MB` | Maximum SaaS response size; a larger response fails the push |
| `alerter.serverSleep` | `3s` | A failed push is retried after 3 seconds, and the wait doubles on each retry up to 30 seconds; an event queued for more than 6 hours without delivery is dropped |

**Tuning guidance**:

- **High-throughput deployments** (many alert rules, high alert frequency): increase `alerter.alertRuleDeliveryWorkers` (for example, 16–32) to reduce backlog; raise `alerter.alertRuleEventQueueSize` as well if needed.
- **Constrained network or CPU**: lower `alerter.alertRuleDeliveryWorkers` (for example, 4) to limit outbound connections and avoid competing with other traffic.
- **High packet-loss or unreliable networks**: consider a larger `alerter.serverSleep` (for example, 10s) to reduce futile requests during congestion.

## Event title flag

| Flag | Default | Description |
|------|---------|-------------|
| `alerter.titleRule` | empty | How alert event titles are generated, for all rules on this engine. A value containing `{{` is rendered as a Go template with the same variables as the [description template](/en/monitors/alert-rules/description-template); otherwise label placeholders are replaced, preferably in `[key]` form such as `'[check] / [data_source_name]'`. Wrap the value in single quotes on the command line. When empty, the title is `check / data_source_name` (with ` - resource` appended when the event has a `resource` label). A `title` custom field on the rule takes precedence |

## Automatic upgrade flags

| Flag | Default | Description |
|------|---------|-------------|
| `alerter.disableAutoUpdate` | `false` | Disables server-pushed automatic upgrades. Set to `true` and the instance no longer performs automatic upgrades; container environments are detected and skipped automatically, and this flag takes precedence |
| `alerter.updateMirror` | `https://static.flashcat.cloud/monitedge` | Mirror root URL for automatic upgrade artifacts. The engine downloads the artifact and checksum file from `<mirror root>/releases/download/<vX.Y.Z>/`; offline or private-network environments must point this at an internal mirror |

Automatic upgrades take effect on Linux (systemd) deployments only and require the engine to reach the artifact mirror. If these conditions are not met, copy the **upgrade command** in the console and upgrade manually.
