When you need to adjust the configuration of a batch of alert rules uniformly, you can select multiple rules in the rule list and edit them together, instead of modifying them one by one. Batch operations support editing labels, annotations (custom fields), data sources, check frequency (cron pattern), rule timezone, effective time, query time offset, collaboration channels, repeat notification settings, debug logging, and more.

## Entry Point

1. Go to the alert rule list page;
2. Select the rules you want to modify;
3. Open the batch edit dialog and choose the **field** to modify;
4. Fill in the changes for that field and confirm.

## Batch Editing Labels / Annotations

Labels and annotations support two update modes:

| Update mode | Description |
|-------------|-------------|
| **Patch** (default) | Applies a list of operations on top of the existing content of the selected rules. Each operation either **sets a key-value pair** or **deletes a key**. Setting adds the key if it does not exist, or updates its value if it does; deleting removes only the specified key and leaves everything else unchanged |
| **Replace** | Replaces the entire labels or annotations map of the selected rules with what you enter; any pre-existing keys not included in the input are removed |

### Key/Value Suggestions

In patch mode, the system aggregates the keys and values already present on the selected rules as suggestions:

- Auto-completion is offered when entering a key or value, annotated with coverage across the selected rules (e.g. `3/10` means 3 of the 10 selected rules contain that value);
- Suggestions are for reference only — you can always type a brand-new key or value;
- Suggestions support at most **500 rules**. If more than 500 rules are selected, suggestions are not loaded, but you can still edit manually.

### Impact Preview

As you fill in operations, the dialog uses the suggestion statistics to show the impact of the change in real time, for example:

- Setting `key=value`: how many rules will gain the key, how many will be updated, and how many will remain unchanged;
- Deleting a key: how many rules will be affected, with the rest unchanged.

## Batch Update Results

After submission, the system updates rules one by one and returns a per-rule result:

- When everything succeeds, no per-rule message is returned and the changes take effect immediately;
- On partial failure, the dialog lists each failed rule's name together with its failure message, so you can fix the issue and retry; rules that succeeded are unaffected.

<Note>
Batch updates are applied per rule with no overall rollback. On partial failure, correct the cause shown in the failure messages and re-run the operation only for the failed rules.
</Note>
