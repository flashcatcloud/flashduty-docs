To experience Monitors features, there are three core steps:

<Steps>
<Step title="Install monitedge">
Deploy the alert engine to your private network
</Step>
<Step title="Create Data Source">
Configure the data sources to monitor
</Step>
<Step title="Create Alert Rules">
Define alert conditions and notification methods

This page takes you from installing the engine to your first working alert rule. For the complete field, limit, and operations reference, see [Alert rule reference](/en/monitors/alert-rules/rule-reference).

## Install monitedge

`monitedge` needs to be deployed in your private network. It is responsible for syncing alert rules from SaaS, periodically querying data sources, performing threshold evaluation, generating alert events, and pushing them to the SaaS.

**Menu Entry**: Data ingestion → Edge engines → Engine Installation/Upgrade

Supports Linux, Docker, and Kubernetes installation methods.

<Warning>
**Engine Cluster Name** is very important: `monitedge` instances with the same name form a cluster, sharing the alert rules between them to avoid single points of failure. See [Alert engine management](/en/monitors/engine/engine).

- Single cluster: Keep the default `default`
- Multiple clusters (for example, one in US-East datacenter, one in South China datacenter): Specify different names for each cluster
</Warning>

![Alert engine installation](https://docs-cdn.flashcat.cloud/imges/mon/64af7649b50f8ba705da9067afffc36a.png)

After installation, `monitedge` connects to the SaaS and periodically syncs alert rules. See [Alert engine management](/en/monitors/engine/engine#alert-engine-status) for engine status, online state, and version, and configure an [engine disconnection alert](/en/monitors/engine/engine-lost-alert) to be notified when an engine goes down.

## Create data source

**Menu Entry**: Data ingestion → Data Sources → New

![Create data source](https://docs-cdn.flashcat.cloud/imges/mon/3eee06165afe05405db6187205f7025c.png)

| Config Item | Description |
|--------|------|
| **Associated Alert Engine** | Specify which alert engine cluster performs data queries and alert evaluation for this data source; typically select a cluster in the same datacenter |
| **Data Source Connection URL** | The address for `monitedge` to connect to; must be an internal address accessible by `monitedge` |

## Create your first alert rule

**Menu Entry**: Rules → Alert Rules

Monitors organizes alert rules in a tree of groups, and every rule belongs to a group. The create / edit page is one form with six sections; this page only covers the fields that make a rule run. For each field's values, defaults, and limits, see [Alert rule reference](/en/monitors/alert-rules/rule-reference).

<Steps>
<Step title="Choose a group">
Create a group in the rule list first (for example, "Default / Database Alerts"), then create the rule inside it.
</Step>
<Step title="Name the rule">
The name must be unique within its group and cannot reference variables.
</Step>
<Step title="Select data sources">
Pick a data source type, then bind the rule to data sources by name wildcard (default `*`) or exact match; use at least one method.
</Step>
<Step title="Write a query">
Choose the query type and statement, and click **Usage guide** for help. For how table results map to fields, see [Query result field mapping](/en/monitors/alert-rules/query-result-fields).
</Step>
<Step title="Set alert conditions">
Enable **Threshold evaluation**, **Missing data**, or **Data exists**. Threshold evaluation needs at least one of Critical, Warning, and Info; after the **Matches** count (default 3) consecutive matches, the alert fires at that level.
</Step>
<Step title="Save the rule">
The remaining fields can keep their defaults: detection frequency `@every 15s`, rule timezone `Asia/Shanghai`, and all-day effective time. After you save, verify the alert as described in the next section.
</Step>
</Steps>

### AI query assistant

Once a data source type is selected, click **Write with AI** at the top right of a query input. The Query Assistant uses the rule's data source, query type, thresholds and other queries to generate or rewrite the statement.

- The statement and related parameters (such as the SLS project / logstore or Tencent CLS region / topic) are filled into the form. Click **Apply** on a result card to fill it in again.
- The assistant is available for main queries, recovery queries, related queries, the query preview, and PromQL in the entity tree.
- Applying does not save the rule; check that the statement matches the thresholds before saving.

### Alert recovery

The available recovery modes depend on the check mode. For every recovery mode, recovery condition, and related option, see [Alert rule reference](/en/monitors/alert-rules/rule-reference#alert-recovery).

## Verify the alert

When alert conditions trigger, the **Active alerts** column of the rule's row shows how many active alerts it currently has.

![Alert rules list page](https://docs-cdn.flashcat.cloud/imges/mon/6f1fad7d65b5aee6b89bf0f0a564a1be.png)

Click the number in the **Active alerts** column to switch to the **Active alerts** tab, filtered by that rule. It lists the active alerts that the rule currently produces. Historical alert events can be viewed in On-call. See [Active alerts](/en/monitors/alert-rules/active-alerts) for details.

The **Status** column shows the rule's runtime health; click the status label to open the runtime details. For each status value and what to do about it, see [Rule runtime details](/en/monitors/alert-rules/rule-reference#rule-runtime-details).

## More configuration and operations

The following topics are reference material; see [Alert rule reference](/en/monitors/alert-rules/rule-reference) for the full details.

<span id="append-label-syntax"></span>
### Additional label syntax

Additional labels are similar to Prometheus `labels` and are attached to every alert event the rule produces for filtering, routing, and inhibition. For the value syntax, supported variables, and limits, see [Alert rule reference](/en/monitors/alert-rules/rule-reference#additional-label-syntax).

### Rule runtime details

Choose **Runtime details** in the `⋮` menu at the end of a rule row to see the rule's runtime status, latest execution, alert instances, and execution history. For each status value and what to do about it, see [Alert rule reference](/en/monitors/alert-rules/rule-reference#rule-runtime-details).

### Import alert rules

**Menu Entry**: Alert Rules → Import. For the supported rule file formats, import configuration, pre-import checks, and results, see [Alert rule reference](/en/monitors/alert-rules/rule-reference#import-alert-rules).
