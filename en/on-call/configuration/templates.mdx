<Tip>**Plan requirement**: This feature requires an On-call Pro or higher subscription. [Learn more](https://flashcat.cloud/flashduty/price/)</Tip>

## Use cases

The system uses templates to render notifications when you create an incident manually, when one is generated automatically, and on reassignment, escalation, and reopen.

<Note>
The system uses [Golang template syntax](https://pkg.go.dev/html/template@go1.18.1) to parse data, supporting logic, loops, pipelines, and common functions. For more functions, refer to [sprig function library](https://github.com/flashcatcloud/sprig/tree/flashcat).
</Note>

<Warning>
For security, Flashduty disables the following sprig functions. Using them in a template causes a `function "xxx" not defined` parse error:

| Category | Disabled functions |
| :--- | :--- |
| Environment | `env`, `expandenv` |
| Network lookup | `getHostByName` |
| Cryptography | `bcrypt`, `htpasswd`, `derivePassword`, `encryptAES`, `decryptAES` |
| Certificate generation | `genPrivateKey`, `buildCustomCert`, `genCA`, `genCAWithKey`, `genSelfSignedCert`, `genSelfSignedCertWithKey`, `genSignedCert`, `genSignedCertWithKey` |
| Randomness | `randBytes`, `uuidv4`, `randAlphaNum`, `randAlpha`, `randAscii`, `randNumeric`, `randInt`, `shuffle` |
| Error raising | `fail` |

If you need a unique identifier inside a template, use incident variables such as `{{.ID}}` or `{{.Num}}`. If you need environment-specific values, pass them in with alert labels or field mappings instead of reading host environment variables from the template.
</Warning>

## Configuring templates

<Steps>
<Step title="Create Custom Template">
Go to **Template Management** page, click **Create Custom Template** or **Copy Default Template**
</Step>
<Step title="Edit Template Content">
Edit content by notification channel, can reference fields from the variable list below
</Step>
<Step title="Save Template">
Click **Save** to complete creation
</Step>
</Steps>

<Tip>
**System preset templates and read-only**: System preset templates and templates the current member has no permission to manage are always read-only on the detail page, marked **Built-in · Read-only** next to the title (a template you lack permission for shows no badge, but is equally uneditable). To make one your own, click **Copy as new template** in the top right and edit the copy, whose name is pre-filled as "Copy *original template name*"; copying requires the **Templates Manage** permission and On-call Pro.

For a template you can edit, the top right shows **Template settings** (gear icon), which changes the template name, team and description only — not the body. Delete sits in the **More actions** ⋯ menu; system preset templates have no such menu and cannot be deleted.
</Tip>

### Apply template

<Steps>
<Step title="Enter Escalation Rules">
Go to **Channel** → **Escalation Rules**, click **Edit**
</Step>
<Step title="Select Template">
In rule configuration, select **which template** to use for notifications
</Step>
<Step title="Save Configuration">
Click **Save** to complete configuration. See [Configure Escalation Rules](/en/on-call/channel/escalation-rule)
</Step>
</Steps>

## Preview and test send

The right side of the template detail page is the preview pane: it renders the current channel's content with the selected incident, followed by a line of diagnostics and any warnings the preview raises. The preview's title bar also holds **Send test**, which sends the editor's current content for real so you can see what the recipient gets.

<span id="preview-notices"></span>

### What the preview tells you

The preview renders the current channel's content with the incident selected under **Render with this incident's data**; with nothing selected it uses the system default data. When the editor is empty, the preview renders the channel's system default template and notes "No template content set, system default template will be used."

One line under the preview explains how this content was rendered:

| Field | Description |
| :--- | :--- |
| Channel format | The Feishu/Lark app shows **Feishu Card 2.0**; the WeCom bot shows **Markdown** or **Markdown v2**; other channels show nothing |
| Native tables: N / Markdown tables: N | How many tables in this render became native tables and how many stayed Markdown tables; a zero count is hidden |
| Used / limit | The content's byte count and the channel's size limit, e.g. `12.3 KB / 30.0 KB`; when the channel has no known limit, only the used bytes are shown |

The yellow notices above that line mean the template will be reshaped or rejected on a real send. Trim it before saving:

| Notice | Meaning |
| :--- | :--- |
| This channel doesn't render Markdown tables, so recipients see the raw text. Consider a list instead. | The Dingtalk, Slack and Telegram bots, the WeCom bot on Markdown v1, and the Dingtalk, Slack, WeCom and Teams apps do not render tables, so recipients see the unrendered table text; consider a list instead |
| Some tables can't be sent as native tables and will be sent as Markdown tables. | **Native tables** is on for the Feishu/Lark app, but a table here misses a native-table condition; see [Native tables](#native-tables) for the specific notices |
| A Feishu Markdown component supports up to 4 tables; additional tables may not display. | One Markdown component of the Feishu card 2.0 holds more than 4 tables sent as Markdown text (the ones not turned into native tables), so the extra tables may not show. Split the content across several Markdown components, or turn on **Native tables** |
| The content exceeds the channel's size limit | There are three variants, listed below |

When the content exceeds the channel's size limit, the notice is one of three:

| Notice | Meaning |
| :--- | :--- |
| The content exceeds the channel's size limit, so sending will fail, including real alerts. Please trim the template. | The channel refuses the message, so this notification is not delivered. You must trim the template, for example a Feishu/Lark card over 30 KB |
| The content exceeds the channel's size limit; the excess will be truncated. | The excess is truncated and the notification still goes out; per-channel limits are listed below |
| The content exceeds 4096 bytes, so a compact summary will be sent instead. | A WeCom bot Markdown v2 message over 4096 bytes is replaced by a compact summary, so nothing is lost |

### Send test

**Send test** sits in the preview's title bar. It renders the editor's current content (**unsaved changes included**) with the incident selected in the preview and sends it to the channel for real, so you can confirm what the recipient sees. It needs the **Templates Manage** permission; system preset templates can be test-sent too. The button is disabled while the template fails validation.

Supported channels: the five IM apps (Feishu/Lark, Dingtalk, WeCom, Slack, Teams), six group chat bots (Feishu/Lark, Dingtalk, WeCom, Slack, Telegram, Zoom) and email. SMS and voice are not offered — they are billed per message and the preview already equals what would be sent.

The content is the same one the preview shows: the editor's current content plus the selected incident's data (system default data when none is selected), with the same channel switches (card field visibility, the Feishu Card 2.0 table and blank-line switches, WeCom bot Markdown v2). When the editor is empty, the channel's system default template is sent.

Where each channel can send:

| Channel | Target | Notes |
| :--- | :--- | :--- |
| IM app | Myself / Group chat | The WeCom app only offers **Myself**: WeCom has no API to list the chats a bot has joined, and group messages go through the WeCom bot template |
| Group chat bot | Enter the robot address | The same address the notification rule takes, either a bare token or a full URL; Telegram also needs a Chat ID, Zoom a Verify token. These values are used for this send only and are never saved |
| Email | Your own account email | Cannot send when your account has no email address |

- **Myself**: requires your account to be linked to that IM integration; when it is not, the send button is disabled and members with permission can click the link to finish linking in the onboarding flow. The Slack app is the exception — no per-person linking is needed (it DMs workspace members directly), but the send still resolves you to a member of that workspace and shows "Your account isn't linked to this IM" if it cannot.
- **Group chat**: lists only chats this integration's bot has **already joined** (Slack by channel, Teams by team channel or group chat). Everyone in the chat receives the test message.
- When the channel has several integrations, pick one under **Integration** first; only enabled integrations are listed.

Test message markings:

- The incident title is prefixed with `[Test] ` (Chinese accounts get `[测试] `).
- A footer is appended: `Test message · Template "<name>" · Sent by <sender>`.
- Buttons on the card only answer "This is a test message. Its buttons do not change any incident." and neither acknowledge nor close anything; the **Create War Room** button does not appear in a test message.

The result is one of two:

| Channel | Prompt |
| :--- | :--- |
| IM app | `Sent to your Feishu DM` / `Sent to "<chat>"` |
| Group chat bots and email | "Submitted. It usually arrives within seconds; if not, check the address" |

For IM apps, "Sent to ..." means the message went out. For bots and email, "Submitted" only means the request was accepted, and a wrong address does not fail immediately.

Limits and common failures:

- Each member can send at most 5 test messages per minute; beyond that the console shows "Too many test sends. Try again later".
- A failure shows one of these messages:

| Message | Meaning |
| :--- | :--- |
| The template failed to render. Fix it first | Parse or execution error in the template |
| This channel doesn't support test sends | The channel does not offer test sends |
| The target is incomplete or invalid | No robot address, a Telegram test without a Chat ID, a Zoom test without a Verify token, or a chat that does not belong to the integration |
| The integration was not found. It may have been deleted or disabled | The integration is deleted or disabled, or is not an integration of this channel |
| Your account isn't linked to this IM | Your account is not linked to this IM, so it cannot DM you |
| Too many test sends. Try again later | More than 5 test messages in a minute |
| Address not allowed: only public http/https is supported | Robot addresses must be public `http`/`https`; a full URL pointing into a private network is refused. A bare token is joined to the vendor's URL by the platform and is not checked. This applies to SaaS only; private deployments are not restricted |
| The content exceeds the channel's size limit | The content exceeds the channel's size limit, such as the 30 KB Feishu card |
| The channel rejected the message: the channel's own error | The channel returned a failure; the message carries the channel's own error |

<Note>
How test sends differ from real notifications: when the template has a syntax error, a real notification silently falls back to the system default template and is still delivered, while a test send shows "The template failed to render. Fix it first" — that is the point, to surface template problems. Conversely, a test send leaves no notification record on the incident, so it never acknowledges or closes an incident and never creates a war room.
</Note>

### Card fields and bottom action buttons

The **Additional info** tab next to **Content** controls which system content appears at the bottom of the card. Switches available per channel:

| Switch | Feishu/Lark app | Dingtalk app | Slack app | Microsoft Teams | WeCom app |
| --- | --- | --- | --- | --- | --- |
| Channel, snooze deadline, severity, aggregated alert count, responders, details button | ✓ | ✓ | ✓ | ✓ | ✓ |
| AI analysis | ✓ | ✓ | ✓ | — | — |
| Create war room | ✓ | ✓ | ✓ | — | — |
| Keep custom actions after incident closure | ✓ | ✓ | ✓ | ✓ | — |

- **Create war room** (off by default): When it's on, the card shows a **👥 Create War Room** button. The button appears if the incident is open, has responders, and has no war room yet. Click it to create the group.
- **Keep custom actions after incident closure** (off by default): when it's on, you can run custom actions from the message card for 3 days after the incident closes. Otherwise, or after 3 days, run them from the incident details page.

Save the template for switch changes to take effect.

### Native tables

**Feishu Card 2.0** adds a **Native tables** switch (off by default, saved with the template). When it is on, GFM Markdown tables in the template are recognised and rendered as the card's native table component, so recipients see a pageable table instead of rows of text with `|`.

Native tables have the limits below. If a card has more than 5 native tables, or the card exceeds 30 KB, **every table on that card** is sent as Markdown text. Any other limit affects only the table that exceeds it, which is sent as Markdown text while the other tables stay native:

| Limit | Value |
| :--- | :--- |
| Native tables per card | At most 5 |
| Columns per table | At most 8 |
| Rows per table | At most 100 |
| Cell content | At most 2000 bytes per cell |
| Rows per page | 10 rows per page; the rest is paged inside the card |

When a table falls back, the preview shows a notice (see [What the preview tells you](#preview-notices)):

| Notice | Trigger |
| :--- | :--- |
| There are more tables than native tables allow, so all of them will be sent as Markdown tables. | The card would carry more than 5 native tables |
| A table has more columns than native tables allow, so it will be sent as a Markdown table. | A table has more than 8 columns |
| A table has more rows than native tables allow, so it will be sent as a Markdown table. | A table has more than 100 rows |
| A cell is too long, so the table will be sent as a Markdown table. | A cell is longer than 2000 bytes |
| A cell contains content native tables don't support, so the table will be sent as a Markdown table. | A cell holds Markdown beyond plain text and `<br>` line breaks, a header cell is empty, or a row's cell count differs from the header's |
| Native tables would push the card over its size limit, so Markdown tables will be sent instead. | Native tables would push the card past Feishu's size limit, so every table on the card is sent as Markdown |

The whole Feishu card is capped at **30 KB**. Beyond that Feishu refuses the message outright and the preview shows "The content exceeds the channel's size limit, so sending will fail, including real alerts. Please trim the template."; trim the template and send again.

Tables sent as Markdown text have one more limit: **a single Feishu Markdown component holds at most 4 tables**, and extra tables may not display. When you have many tables, turn on **Native tables** or split the content across several Markdown components.
</Tab>

## Bot templates

Template formats supported by group chat bots.

<Note>
These channels do not render Markdown tables and send them as raw text: the Dingtalk, Slack and Telegram bots, the WeCom bot on Markdown v1, and the Dingtalk, Slack, WeCom and Teams apps. The preview flags this. For those channels, rewrite tables as lists.
</Note>

<Tab title="WeCom Bot">
WeCom bots support both Markdown v1 and Markdown v2. Existing templates continue to use v1 by default. You can enable v2 per template without affecting other templates.

| Comparison | Markdown v1 | Markdown v2 |
| :--- | :--- | :--- |
| Enablement | Default format; no setup required | Enable **Use Markdown v2** in the WeCom bot template |
| Markdown support | Uses WeCom's legacy Markdown syntax ([syntax limitations](https://developer.work.weixin.qq.com/document/path/91770#markdown%E7%B1%BB%E5%9E%8B)) | Supports standard Markdown, including headings, lists, and tables |
| Link behavior | Links usually open in WeCom's built-in browser | Links usually open in the system default browser; the final behavior depends on the WeCom client version and settings |
| Message length | Up to 4000 bytes; excess content is truncated while preserving the details link | Up to 4096 bytes; an oversized runtime message is replaced with a compact message |
| @ mentions | Uses the bot @ mention settings in the escalation rule | Uses the same settings; the @ mention is sent only after the message body succeeds |

### Enable Markdown v2

<Steps>
<Step title="Open template management">
Open **Template Management**, then create a custom template or copy an existing template.
</Step>
<Step title="Select the WeCom bot template">
Select **WeCom Bot** under template content and enable **Use Markdown v2**.
</Step>
<Step title="Edit and save the template">
Edit the content using standard Markdown and save it. Flashduty stores the setting with this template, and it affects only notifications that use it.
</Step>
</Steps>

<Note>
Disabling the toggle switches the template back to Markdown v1. Existing v1 template content remains unchanged.
</Note>

<Warning>
Markdown v2 uses the UTF-8 byte length and allows up to **4096 bytes**. Dynamic fields can cause the final notification to exceed this limit. In that case, Flashduty sends a compact message marked “The original message was too long and has been shortened” instead of dropping the notification. The compact message retains the incident number, title, channel, severity, trigger time, resource, responders, details link, and acknowledge link.
</Warning>

## FAQ

<AccordionGroup>
<Accordion title="How do I know what Labels are available?">
- Manually created incidents have no labels
- Auto-created incidents have labels, same as the first merged alert's labels

Go to **Incident List** → view incident details to see all label information.
</Accordion>

<Accordion title="Configured custom template but default template was used instead?">
Passing the syntax check when you save a template does not guarantee that every incident renders. If rendering fails when a notification is sent, the system falls back to the default template.

<Tip>
Recommend checking if variable exists before referencing:

```go
// ❌ Wrong: Read label directly
{{.Labels.resource}}

// ✅ Recommended: Check then read
{{if .Labels.resource}}{{.Labels.resource}}{{end}}
```
</Tip>
</Accordion>

<Accordion title="Incident title has character escaping (like &gt;)?">
Use `toHtml` function to handle:

```go
// Escape HTML characters
{{toHtml .Title}}

// Render with first non-empty value
{{toHtml .Description .Title}}
```
</Accordion>

<Accordion title="How to convert time format?">
```go
// date function: Convert timestamp to readable format
{{date "2006-01-02 15:04:05" .StartTime}}

// ago function: Convert time difference to readable format (e.g., "5 minutes ago")
{{ago .StartTime}}
```
</Accordion>

<Accordion title="How to reference external variable inside for loop?">
Add `$` before external variable:

```go
{{range .Responders}}
  {{if eq $.Progress "Triggered"}}
    【Pending】{{.Email}}
  {{end}}
{{end}}
```
</Accordion>

<Accordion title="How to extract field value with . (like obj.instance)?">
Use `index` function:

```go
{{index .Labels "obj.instance"}}
```
</Accordion>

<Accordion title="How to extract labels from associated alerts and deduplicate?">
```go
// alertLabels: Get deduplicated array
{{alertLabels . "resource"}}

// joinAlertLabels: Deduplicate and join with delimiter as string
{{joinAlertLabels . "resource" ", "}}
```
</Accordion>

<Accordion title="How to iterate and print Labels?">
```go
// Complete iteration
{{range $k, $v := .Labels}}
  {{$k}} : {{toHtml $v}}
{{end}}

// Exclude single label
{{range $k, $v := .Labels}}
  {{if ne $k "resource"}}
    {{$k}} : {{toHtml $v}}
  {{end}}
{{end}}

// Exclude multiple labels
{{range $k, $v := .Labels}}
  {{if not (in $k "resource" "body_text")}}
    {{$k}} : {{toHtml $v}}
  {{end}}
{{end}}
```
</Accordion>

<Accordion title="How to extract info from JSON field?">
Use `jsonGet` function to extract values by path from valid JSON. Syntax reference at [gjson.dev](https://gjson.dev/).

```go
// Extract detail_url field from rule_note label
{{jsonGet .Labels.rule_note "detail_url"}}

// Extract name field of first element in JSON array
{{jsonGet .Labels.slice "0.name"}}

// Iterate array, match instanceId field where userId==7777
{{jsonGet .Labels.rule_note "#(userId==7777)#.instanceId"}}
```
</Accordion>

<Accordion title="How to get image URL?">
**imageSrcToURL**: Convert image_key or URL to accessible address (for Dingtalk/Slack App)

```go
{{ $root := . }}
{{ range $i, $v := .Images }}
  {{ $imageURL := imageSrcToURL $root $v.Src }}
  {{ if $imageURL }}![]({{$imageURL}}){{ end }}
{{ end }}
```

**transferImage**: Upload image to third-party platform (for Feishu/Lark App)

```go
{{ $root := . }}
{{ range $i, $v := .Images }}
  {{ $transferURL := transferImage $root $v.Src }}
  {{ if $transferURL }}![]({{$transferURL}}){{ end }}
{{ end }}
```

<Note>
Image size cannot exceed 10 MB, supports JPG, PNG, WEBP, GIF, BMP formats.
</Note>
</Accordion>
