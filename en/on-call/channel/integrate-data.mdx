Flashduty On-call doesn't generate alerts itself but serves as a unified alert center, receiving alert events from monitoring systems like Zabbix, Prometheus, Nightingale, and major cloud providers. Once integrated, you can use noise reduction, assignment, notification, analysis, and automation capabilities.

## Integration Methods

Flashduty On-call offers two alert integration methods:

| Comparison | Dedicated Integration | Shared Integration |
| :--- | :--- | :--- |
| Data Flow | Alerts go directly into the current channel | Distributed to one or more channels via routing rules |
| Configuration Difficulty | Out-of-the-box, no routing needed | Requires routing rule configuration |
| Typical Scenario | Single business team | Multiple businesses sharing monitoring platform |
| **Recommended Choice** | Just getting started, simple business | Alerts need to be distributed to different business channels based on conditions |

### Dedicated Integration

Integration created within a channel, alerts automatically enter that channel.

<Steps>
  <Step title="Enter Integration Page">
    Go to Channel Details → Configuration → Integrations → **Private integration**
  </Step>
  <Step title="Add Integration">
    Click **Add an integration**, select alert type
  </Step>
  <Step title="Configure Push URL">
    Copy the generated **Push URL** to your monitoring platform
  </Step>
</Steps>

<Frame caption="Dedicated Integration Configuration">
  <img src="https://download.flashcat.cloud/flashduty/doc/en/fd/how-1.png" alt="Dedicated Integration" />
</Frame>

<Note>
A dedicated integration belongs to the channel it was created in: **editing, enabling/disabling, and deleting** it requires the "Channels Manage" or "Integrations Manage" functional permission together with the data permission for that channel — only **account admins, the channel creator, or the channel's managing team** can operate. Other members see these buttons disabled, with the reason on hover.
</Note>

### Shared Integration

Global integration created in the Integration Center, distributes alerts to different channels via [routing rules](/en/on-call/integration/alert-integration/routing-rules).

<Steps>
  <Step title="Enter Integration Center">
    Go to Integration Center → Alert Events → **Add Integration**
  </Step>
  <Step title="Create Integration">
    Select alert type, set **Management Team** (optional)
  </Step>
  <Step title="Configure Push URL">
    Copy the generated **Push URL** to your monitoring platform
  </Step>
  <Step title="Configure Routing Rules">
    Configure **Routing Rules** to specify which channel alerts should be distributed to
  </Step>
</Steps>

<Warning>
Shared integrations must have at least one routing rule configured, otherwise alerts will be dropped. We recommend setting up a rule without filter conditions as a fallback to prevent alert loss.
</Warning>

## Browsing and Finding Integrations

The Integration Center groups the alert sources and change events it covers by category, so you can narrow the list with a category chip or search for the system you need.

The add-integration panel has one set of chips per tab, and each tab opens on its own default category:

| Tab | Category chips (in display order) | Default category |
| :--- | :--- | :--- |
| Alert Events | Generic, Popular, Cloud providers, Metrics & infrastructure, APM & observability, Event correlation & AIOps, Logs & error tracking, Security, Uptime & status pages, Jobs, delivery & app platforms, Network & hardware | **Popular** |
| Change Events | Generic, CI/CD & deploy, Source control, Config & feature flags, Infrastructure & platforms | **CI/CD & deploy** |

- Integrations with no registered category are collected under **Uncategorized**; a category with no entries is not shown.
- By default the panel keeps only **All**, **Generic**, the tab's default category, and the currently selected category; the rest collapse into **More N**, which expands on click.
- The search box matches across all categories (ignoring the selected chip) by integration name or type, and shows the hits as **Search results**; clearing the search returns you to the category you had selected.

### All integrations catalog

Clicking the **All** chip opens a full-screen catalog:

- The number next to the title is how many integrations the catalog covers, and the search box at the top searches all of them.
- The category rail on the left lists every category with its entry count; clicking one scrolls the right side to that category (and clears the search).
- The right side lays out cards by category (logo, name, and a two-line blurb); hovering a card reveals **Add**, which opens the new-integration page for that system.

At the bottom the catalog keeps a "Can't find your system?" fallback area with two ways out: connect it with a generic integration, or request an integration.

### Requesting an Integration

If the system you need is not covered yet, click **Submit a request** in the fallback area to tell us what to support. This entry point is available on Flashduty SaaS only; private deployments do not show it.

| Field | Required | Limit | Notes |
| :--- | :--- | :--- | :--- |
| System name | Yes | Up to 100 characters | For example `Checkmk`; a term you searched for in the catalog is prefilled here |
| Website or docs link | No | Up to 500 characters | Must start with `http://` or `https://` |
| Notes | No | Up to 2000 characters | Which alerts you want to receive, and how you handle them today |
| Work email | See notes | Up to 200 characters | Not needed when your account already has an email — we reply to that address; required otherwise |

After you submit, the dialog confirms that the request was received and explains that we will reply by email after review; until the request is supported, you can connect the system with a generic integration.

## Integration Features

Optional configurations for both integration methods, configurable on the integration details page:

| Feature | Description | Dedicated Integration | Shared Integration |
| :--- | :--- | :---: | :---: |
| Label Enhancement | Dynamically generate new labels through regex extraction, mapping tables, etc. | ✓ | ✓ |
| Alert Processing | Configure Pipeline to filter, modify, or drop alerts | ✓ | ✓ |
| Routing Rules | Distribute alerts to different channels based on conditions | ✗ | ✓ (Required) |

### Label Enhancement

After alerts enter the system, automatically add or modify labels for subsequent routing, searching, and analysis. Multiple enhancement methods supported:

- **Regex Extraction**: Extract key information from existing fields to generate new labels
- **Mapping Table**: Generate labels through predefined key-value mappings
- **Combination**: Add fixed label values to alerts

See [Label Enhancement](/en/on-call/integration/alert-integration/label-enhancement) for details.

### Alert Processing

Pre-process alerts through Pipeline, executing custom logic before alerts generate incidents:

- **Modify**: Adjust alert title, severity, description, and other attributes
- **Filter**: Drop unwanted alerts based on conditions

See [Alert Processing](/en/on-call/integration/alert-integration/alert-pipelines) for details.

### Routing Rules

Distribute alerts to different channels based on alert attributes (such as labels, severity, etc.):

- **Dedicated Integration**: No routing rules needed
- **Shared Integration**: Required, otherwise alerts will be dropped

See [Routing Rules](/en/on-call/integration/alert-integration/routing-rules) for details.

## Rate Limits

To ensure system stability, the gateway enforces the following rate limits on alert push APIs:

| Limit Dimension | Limit Value |
| :--- | :--- |
| **Per API** | 8000 requests/second (QPS) |
| **Per account** | 2000 requests/minute |
| **Per integration** | 2000 requests/minute |

<Note>
Exceeding any of these limits returns a `429` status code — please wait and retry. Contact technical support if you need higher limits.
</Note>

## FAQ

<AccordionGroup>
  <Accordion title="Not receiving alerts from shared integration?" icon="circle-question">
    1. Check if routing rules are configured
    2. Confirm the source platform is triggering alert events normally
  </Accordion>

  <Accordion title="Is there a limit on the number of integrations?" icon="circle-question">
    Currently no limit.
  </Accordion>

  <Accordion title="How are alert labels generated?" icon="circle-question">
    Flashduty On-call follows the "capture everything relevant" principle, putting key information into labels, description, or title. For dynamically generating other labels, configure [Label Enhancement](/en/on-call/integration/alert-integration/label-enhancement).
  </Accordion>

  <Accordion title="How is the alert title determined? Can it be modified?" icon="circle-question">
    Default is a combination of "Policy Name / Alert Resource". For customization, refer to [Reference Variables](/en/on-call/advanced/reference-variables).
  </Accordion>

  <Accordion title="How to see which integration an alert came from?" icon="circle-question">
    Go to Incident Details → Associated Alerts → **Alert Source**.
  </Accordion>

  <Accordion title="What happens to integrations after the subscription expires?" icon="circle-question">
    After the subscription expires, every integration (dedicated and shared) stops receiving alert events, a persistent subscription-expired banner appears at the top of the Integration Center, and the cards for adding a new integration are disabled (hover for the reason). Configured integrations are not deleted, and ingestion resumes automatically after renewal — no reconfiguration needed.
  </Accordion>
</AccordionGroup>
