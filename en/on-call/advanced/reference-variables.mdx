## Overview

By referencing variables from alert labels and attributes, you can modify and customize incident severity, title, description, and other information. This is primarily used in two scenarios:

<CardGroup cols={2}>
<Card title="Event API Reporting" icon="code">
When reporting custom alert events with the alert [Event API](/en/on-call/integration/alert-integration/alert-sources/standard-alert), you can use the `title_rule` field to customize the alert title.
</Card>
<Card title="Alert Pipeline" icon="filter" href="/en/on-call/integration/alert-integration/alert-pipelines">
Reference variables in alert pipelines to modify alert severity, title, description, and other information.
</Card>
</CardGroup>

### Event API example

```json
{
  "title_rule": "[TPL]${resource} / ${check}"
}
```

<Note>
Specifies `resource` and `check` labels as the alert title.
</Note>

## Variable reference methods

### Reference labels with `${var}`

Use `[TPL]` as prefix and `${}` to reference variables. Variable content is extracted from labels; if extraction fails, `<no value>` is used as a placeholder.

| Rule | Label Values | Generated Content |
| --- | --- | --- |
| `[TPL]${resource} / ${check}` | `{"resource": "127.0.0.1", "check": "cpu idle low"}` | 127.0.0.1 / cpu idle low |
| `[TPL]${resource} / ${check}` | `{"resource": "127.0.0.1"}` | 127.0.0.1 / `<no value>` |
| `[TPL]${resource} / Host Down` | `{"resource": "127.0.0.1"}` | 127.0.0.1 / Host Down |

### Reference with Go template syntax

Use `[TPL]` as prefix and `{{}}` to reference variables (can reference both labels and attributes); a missing label shows `<no value>`. Reference a specific label as `{{.Labels.name}}`.

| Rule | Variable Values | Generated Content |
| --- | --- | --- |
| `[TPL]{{.Labels.resource}} / {{.Labels.check}}` | `{"resource": "127.0.0.1", "check": "cpu idle low"}` | 127.0.0.1 / cpu idle low |
| `[TPL]{{.Labels.resource}} / {{.Labels.check}}` | `{"resource": "127.0.0.1"}` | 127.0.0.1 / `<no value>` |
| `[TPL]{{.EventSeverity}} / Host Down` | `{"EventSeverity": "Warning"}` | Warning / Host Down |

<Note>
The two syntaxes differ in data scope: `${name}` reads **only** from labels, not attribute fields, while `{{}}` can use the fields in the table below and labels. When a label is missing, both syntaxes show `<no value>`.
</Note>

#### Supported attributes

When you use `{{}}` syntax, you can reference these alert fields:

| Field | Description |
| --- | --- |
| `Title` | Alert title |
| `Description` | Alert description |
| `EventSeverity` | Severity (Critical / Warning / Info) |
| `EventStatus` | Event status (Critical / Warning / Info / Ok, where Ok indicates recovery) |
| `AlertKey` | The alert's unique key, used to merge events from the same series into a single alert |
| `TitleRule` | The title-generation rule supplied at report time |
| `Labels` | Label key-value set; access a specific label with `{{.Labels.xxx}}` |

<Tip>
**The alert description and any label value also support reference variables.** In an alert pipeline, the `Reset Description` (resetDescription) and `Reset Labels` (resetLabels) actions substitute variables in any content prefixed with `[TPL]`.
</Tip>

## FAQ

<AccordionGroup>
<Accordion title="What happens if a label doesn't exist when using labels to dynamically generate titles?">
With either `${}` or `{{}}`, a missing label shows as `<no value>` at that position in the title.

<Tip>
Even if a variable cannot be retrieved, it won't affect alert generation. You can debug with confidence.
</Tip>
</Accordion>
</AccordionGroup>
