This guide is for status pages that have already been created or migrated. It covers basic properties and display settings.

If you do not have a status page yet, first read [Get started with Flashduty Status Page](/en/on-call/statuspage/get-started) and complete creation or migration.

## Basic information

In **Settings → Basic Settings**, you can edit languages, the page title, and the status page URL at any time. The page title is usually your company, product, or service name so visitors can understand what the page represents.

### Language

Use the **Language** multi-select dropdown to choose **简体中文** and **English** (keep at least one selected; there is no default language). New status pages enable only your current console language by default, while existing status pages default to both languages.

When both languages are enabled, **Page Title** expands into a stacked dual-row input; when only one language is enabled, it stays a single line. Unchecking a language keeps its saved translations in the background so re-enabling it restores them intact. For all bilingual fields, symmetric fallback, and visitor behavior, see [Multilingual status pages](/en/on-call/statuspage/multilingual).

### Status page URL

This is the unique path segment in the status page access URL. You can change it after creation, but the URL must be unique within the same account for the same page type.

The system automatically converts the page title to a URL-safe format: lowercase, with non-alphanumeric characters replaced by hyphens. You can also specify it manually.

<Warning>
Changing the status page URL invalidates the previous access URL. For public status pages, plan the URL before launch to avoid breaking external links later.
</Warning>

## Branding settings

You can customize the status page branding to match your corporate identity.

### Logos and icons

| Setting | Description |
| --- | --- |
| **Logo** | Brand logo displayed at the top of the status page |
| **Dark Mode Logo** | Brand logo displayed in dark mode. Falls back to the main logo if not set |
| **Logo Link** | Target URL when users click the logo |
| **Favicon** | Small icon displayed in the browser tab |

### Page content

| Setting | Description |
| --- | --- |
| **Page Header** | Custom text displayed at the top of the status page; supports separate Chinese and English copy when both languages are enabled |
| **Page Footer** | Custom text displayed at the bottom of the status page; supports separate Chinese and English copy when both languages are enabled |
| **Custom Links** | Additional external links at the bottom of the status page; when both languages are enabled, each link supports a separate label and destination URL per language |
| **Contacts** | Contact information for getting help (`mailto:` address or `http(s)://` URL); shared across all languages |

Logos, dark mode logos, logo links, favicons, and contacts are language-independent. For bilingual fallback rules on headers, footers, and custom links, see [Multilingual status pages](/en/on-call/statuspage/multilingual).

## Custom domain

By default, status pages are accessed through a Flashduty-provided subdomain. To use your own domain, such as `status.yourcompany.com`, configure a custom domain. Custom domains are available only for **public status pages**; internal status pages do not offer this option in Basic Settings.

<Steps>
  <Step title="Enter the custom domain">
    Enter your custom domain in the status page settings.
  </Step>
  <Step title="Add the access entry record (CNAME)">
    In your DNS provider, add a CNAME record for the domain pointing to a Flashduty-managed access entry: `cn.statuspage.flashduty.com` for mainland China, `statuspage.flashduty.com` for international access. If your DNS provider supports GeoDNS, configure both for the same domain; otherwise, choose one.

    If you manage DNS with Cloudflare, use **DNS-only** mode instead of proxying the records. The mainland China entry requires an ICP filing connected through Alibaba Cloud. Use the international entry if your domain does not meet this requirement.

    You can also reach a managed entry through your own intermediate records; any hop in the chain that matches a managed entry counts as connected.
  </Step>
  <Step title="Add the certificate management record (CNAME)">
    Add a CNAME record under the `_acme-challenge` prefix. It delegates certificate validation to Flashcat-managed DNS and proves you control the domain. Use **Check configuration** to see the exact record name and target value.
  </Step>
  <Step title="Check the configuration">
    Click **Check configuration** in the status page settings to view the verification status of each record. Once both records pass, Flashduty issues, renews, and publishes the HTTPS certificate automatically, and the domain is served over HTTPS. You do not upload a certificate.
  </Step>
</Steps>

<Warning>
Custom domains must be globally unique across the platform. A domain cannot be used by another status page, and it cannot be the access domain of a [self-built WeCom app](/en/on-call/integration/instant-messaging/wecom#self) claimed by any account. If the domain is already held that way, the system rejects the configuration, even when your own account is the holder.
</Warning>

<Note>
**The first claimant keeps the domain; a released domain can be claimed again**

A domain belongs to its first claimant until the domain is released. After you delete the custom domain from a status page, or remove it from the WeCom self-built app integration, Flashduty reclaims the domain's certificate asynchronously. Until that cleanup finishes, the domain still counts as taken, so binding it to another status page or another account fails. Once cleanup finishes the domain is released, and any status page or account can claim it.
</Note>

**Migrating from the legacy entry**: if your custom domain still points to the legacy compatibility entry `statuspage.flashcat.cloud`, Flashduty issues and publishes the certificate in advance once the certificate management record passes verification. Switching DNS to a managed access entry then does not interrupt HTTPS. The console offers an **Upgrade to the cross-region entries** migration wizard for these domains. It runs in four steps: add the certificate authorization record, issue the certificate, switch DNS, and finish. Status page access is not interrupted during the process. To point DNS back at the legacy entry, click **Cancel migration** in the wizard and then **Retire managed certificate**. If you only switch DNS back without retiring the managed certificate, the legacy entry cannot renew its certificate. The domain becomes unreachable when the certificate expires.

## Display settings

Two display settings live on different settings pages.

### Data view (Settings → Appearance)

In **Settings → Appearance**, choose how event history is presented under **Data view**:

| Option | Description |
| --- | --- |
| **Calendar** | Displays historical events in a calendar layout for reviewing service status on specific days |
| **List** | Lists historical events chronologically for quickly browsing recent events |

<Note>
In both the calendar and list views, visitors can page back to the **earliest event recorded**, with **no 90-day limit**. The **90-day / 50-item** window applies **only to the [RSS/Atom feeds](/en/on-call/statuspage/subscriptions)**, not to the web page.
</Note>

### Availability display (Settings → Components & Groups)

On the **Components & Groups** settings page, **How should we show historical data for your components?** offers **Colored bars and uptime percentage**, **Colored bars only**, and **Nothing**. For what each option shows, see [Components and sections](/en/on-call/statuspage/components-sections#availability-display).

## Editing and deletion

You can edit languages, the page title, status page URL, branding settings, and display configuration at any time.

Deleting a status page permanently removes its associated data. This action cannot be undone.
