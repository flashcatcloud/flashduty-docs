Sign in to Flashduty through Keycloak using the SAML2.0 or OIDC protocol.

<Note>
This article does not cover deployment or explanation of Keycloak. For more information, see the [official documentation](https://www.keycloak.org/).
</Note>

## Protocol configuration

<Tabs>
<Tab title="SAML2.0 Protocol">

### 1. Choose the protocol

In the Flashduty console, go to **Platform → Organization → SSO**, turn on **Enable single sign-on**, and select **SAML 2.0** under **Protocol & connection**.

The **Assertion Consumer Service URL** that SAML 2.0 needs appears in **Flashcat service provider information** at the bottom of the page only after the configuration is saved once, so create the Keycloak client first and leave the callback URL for step 5.

### 2. Create client

Login to Keycloak console, path: **Clients → Create client**

- **Client Type**: Select SAML protocol
- **Client ID**: Enter `flashcat.cloud` (fixed value, cannot be changed)

![Create Client](https://docs-cdn.flashcat.cloud/images/png/437197.png)

Leave **Valid redirect URIs** empty for now: fill it in step 5, once you have the **Assertion Consumer Service URL**.

### 3. Configure client information

Change **Name ID format** to email type:

![Name ID format](https://docs-cdn.flashcat.cloud/images/png/437031.png)

Set **Client signature required** to disabled:

![Disable signature](https://docs-cdn.flashcat.cloud/images/png/437195.png)

<Warning>
Keycloak ships OpenID Connect `email` and `phone` scopes with the same names as the SAML scopes below. Delete them in **Client scopes** before you create the new ones.
</Warning>

**Create client scopes**: In **Client scopes → Create client scope**, create three scopes named `email`, `phone`, and `username`. For each, set **Protocol** to **SAML**, enter the scope name in **Name**, keep the other settings at their defaults, and save.

![Create scope](https://docs-cdn.flashcat.cloud/images/png/437033.png)

Completed result:

![Scope result](https://docs-cdn.flashcat.cloud/images/png/437034.png)

**Add the three scopes to the client**: Go to **Clients →** your client **→ Client scopes → Add client scope**, select `email`, `phone`, and `username`, then click **Add → Default**.

![Add scope 1](https://docs-cdn.flashcat.cloud/images/png/437037.png)

![Add scope 2](https://docs-cdn.flashcat.cloud/images/png/437038.png)

**Configure a mapper for each scope**: Open the scope, go to **Mappers → Configure a new mapper**, select **User Attribute** as the **Mapper type**, and fill in the fields below. The table uses `email`; configure `phone` and `username` the same way.

| Field | Value for `email` |
| --- | --- |
| Name | `email` |
| User Attribute | `email` |
| SAML Attribute Name | `email` |
| SAML Attribute NameFormat | `Basic` |

![Mapper 1](https://docs-cdn.flashcat.cloud/images/png/437057.png)

![Mapper 2](https://docs-cdn.flashcat.cloud/images/png/437058.png)

![Mapper 3](https://docs-cdn.flashcat.cloud/images/png/437060.png)

### 4. Download XML file

<Note>
The downloaded file is a compressed package. After extracting locally, there will be two xml files; only the `idp-metadata.xml` file is needed.
</Note>

Download locally from **Client → Action**:

![Download XML](https://docs-cdn.flashcat.cloud/images/png/437039.png)

### 5. Upload the metadata in Flashduty and save

1. In **Protocol & connection**, upload the extracted `idp-metadata.xml` under **Upload the IDP metadata document**. The first SAML 2.0 save requires this file; without it, clicking **Save** shows "Please upload metadata document first".
2. In **Member matching**, fill in the attribute names your identity provider returns, the same names as the three SAML scopes from step 3: **Email** `email`, **Username** `username`, **Phone** `phone`. **Email** is required; without it, **Username** and **Phone** must both be filled, otherwise the save is rejected (the API returns `configure either an email mapping, or both phone and name mappings`). See [SSO configuration](/en/platform/configure-sso#member-association) for the matching rules.
3. Click **Save**. Once it succeeds, **Flashcat service provider information** appears at the bottom of the page:

   ![Get ACS URL](https://docs-cdn.flashcat.cloud/images/png/437194.png)

4. Copy the **Assertion Consumer Service URL** back into the Keycloak client's **Valid redirect URIs** and save:

   ![Configure redirect](https://docs-cdn.flashcat.cloud/images/png/437029.png)

### 6. Create user and test login

Create user (must bind an email address):

![Create user](https://docs-cdn.flashcat.cloud/images/png/437041.png)

**Login test**: Visit `console.flashcat.cloud` and select SSO login. The SSO sign-in page defaults to **business email**: enter it, and Flashduty finds your organization and starts its authentication flow. If you only know the company domain, click **Sign in with company domain** and enter your organization's login domain. You set this domain under **Platform → Organization → Organization → Organization profile**. You can also initiate single sign-on directly at `{domain}.sso.flashcat.cloud`.

![Test login](https://docs-cdn.flashcat.cloud/images/png/437062.png)

</Tab>

<Tab title="OIDC Protocol">

### 1. Choose the protocol

In the Flashduty console, go to **Platform → Organization → SSO**, turn on **Enable single sign-on**, and select **OIDC** under **Protocol & connection**.

The **Redirect URL** that OIDC needs also appears in **Flashcat service provider information** only after the configuration is saved once, so create the client first and leave the callback URL for step 4.

### 2. Create client

Login to Keycloak console, create new Client:

- **Client Type**: Select OIDC protocol
- **Client ID**: No special requirements

![Create Client](https://docs-cdn.flashcat.cloud/images/png/437179.png)

**Client authentication**: Keep enabled

![Client authentication](https://docs-cdn.flashcat.cloud/images/png/437180.png)

Leave **Valid redirect URIs** empty for now: fill it in step 4, once you have the **Redirect URL**.

### 3. Get client information

- **Client ID**: The ID entered when creating the Client
- **Client Secret**: View in **Client Details → Credentials** card

![Client Secret](https://docs-cdn.flashcat.cloud/images/png/437186.png)

- **Issuer**: View in **Realm settings → Endpoints → OpenID Endpoint Configuration**

![Issuer](https://docs-cdn.flashcat.cloud/images/png/437187.png)

### 4. Configure Flashduty single sign-on

1. In **Protocol & connection**, fill in **Issuer**, **Client ID**, and **Client Secret**; keep the default **Scopes** of `openid`, `profile`, `email`, and `phone`.
2. In **Member matching**, fill in **Email** `email`, **Username** `preferred_username`, and **Phone** `phone_number` (Keycloak's `phone` scope provides `phone_number`). **Email** is required; without it, **Username** and **Phone** must both be filled, otherwise the save is rejected. See [SSO configuration](/en/platform/configure-sso#member-association) for the matching rules.
3. Click **Save**. Once it succeeds, **Flashcat service provider information** appears at the bottom of the page:

   ![Get Redirect URL](https://docs-cdn.flashcat.cloud/images/png/437183.png)

4. Copy the **Redirect URL** back into the Keycloak client's **Valid redirect URIs** and save:

   ![Configure redirect](https://docs-cdn.flashcat.cloud/images/png/437184.png)

<Tip>
After configuration, refer to step 6 of the SAML2.0 protocol for login testing.
</Tip>

</Tab>
</Tabs>
