[Authing](https://www.authing.cn/) is a provider of identity recognition and access control management. Through the Authing platform, you can login to the Flashduty management console using OIDC, SAML2.0, or CAS protocols.

## Preparation

<Steps>
<Step title="Login or Register Authing">
If you're a new user, you need to create a user pool first—follow the prompts to create one.
</Step>

<Step title="Create Application">
- Select standard web application
- Fill in application name
- Fill in authentication URL (the URL to redirect to during SSO login)

![Create application](https://docs-cdn.flashcat.cloud/images/png/436934.png)
</Step>

<Step title="Record Information">
![Application info](https://docs-cdn.flashcat.cloud/images/png/436952.png)

| Field | Description |
|---|---|
| App ID | Corresponds to Flashduty's Client ID |
| APP Secret | Corresponds to Flashduty's Client Secret |
| Issuer | Corresponds to Flashduty's Issuer |
| Authentication URL | The URL to redirect to during SSO login |
</Step>

## Protocol configuration

<Tabs>
<Tab title="OIDC Protocol">

### 1. Choose the protocol and fill in the connection settings

Open the [Flashduty](https://console.flashcat.cloud) console, go to **Platform → Organization → SSO**, turn on **Enable single sign-on**, and select **OIDC** under **Protocol & connection**.

Fill in the Authing application values:

| Flashduty field | What to enter |
| --- | --- |
| Issuer | The Authing application's Issuer |
| Client ID | The Authing application's App ID |
| Client Secret | The Authing application's App Secret |
| Scopes | Keep the defaults `openid`, `profile`, `email`, and `phone` |

### 2. Fill in member matching and save

In **Member matching**, fill in **Email** `email`, **Username** `username`, and **Phone** `phone_number`. **Email** is required; without it, **Username** and **Phone** must both be filled, otherwise the save is rejected (the API returns `configure either an email mapping, or both phone and name mappings`). See [SSO configuration](/en/platform/configure-sso#member-association) for the matching rules.

Click **Save**. Once it succeeds, **Flashcat service provider information** appears at the bottom of the page; copy the OIDC **Redirect URL** and paste it into **Authentication configuration → Login callback URL** in the Authing application, then save:

![Callback URL](https://docs-cdn.flashcat.cloud/images/png/436957.png)

### 3. Modify Authing configuration

Change id_token signing algorithm to **RS256**:

![Signing algorithm](https://docs-cdn.flashcat.cloud/images/png/436961.png)

On the **Login control** tab, select the account fields in the **Use for login** column (all are selected in the example):

![Login control](https://docs-cdn.flashcat.cloud/images/png/436964.png)

On the **Access authorization** tab, under **Application access control**, change the authorization of **Everyone** from **Deny** to **Allow**, then click **Change** in the confirmation dialog:

![Permission config](https://docs-cdn.flashcat.cloud/images/png/436967.png)

### 4. Create user and test login

<Note>
Flashduty associates members by email by default, so create users with an email address. New SSO configurations can also associate members by a stable user ID field — see [Single Sign-On configuration](/en/platform/configure-sso).
</Note>

Create user in Authing:

![Create user](https://docs-cdn.flashcat.cloud/images/png/436973.png)

After the configuration is saved, Flashduty's SSO page shows a copyable **Member sign-in address** at the top. Copy it and open it in a new window: it redirects to the Authing login page, and signing in with the new user returns you to the Flashduty console.

<Tip>
You can also visit `console.flashcat.cloud` and choose the SSO sign-in method.
</Tip>

</Tab>

<Tab title="SAML2.0 Protocol">

<Tip>
You can create a new application or modify an existing one. This demonstration modifies an existing application.
</Tip>

### 1. Turn on SAML2.0 in Authing

On the Authing application's **Protocol configuration** tab, switch the authorization configuration to **SAML2.0** and turn on **Enable SAML2 Provider**:

![Select SAML](https://docs-cdn.flashcat.cloud/images/png/436984.png)

Two addresses on this page matter: download the **SAML2 metadata document** for Flashduty to upload, and fill the **default ACS URL** with the **Assertion Consumer Service URL** once Flashduty has saved the configuration.

### 2. Choose the protocol in Flashduty and upload the metadata

Go to **Platform → Organization → SSO**, turn on **Enable single sign-on**, select **SAML 2.0** under **Protocol & connection**, and upload the SAML2 metadata document from the previous step under **Upload the IDP metadata document**:

![Download metadata](https://docs-cdn.flashcat.cloud/images/png/436990.png)

The first SAML 2.0 save requires this metadata document; without it, clicking **Save** shows "Please upload metadata document first".

### 3. Fill in member matching and save

In **Member matching**, fill in **Email** `email`, **Username** `username`, and **Phone** `phone`. **Email** is required; without it, **Username** and **Phone** must both be filled, otherwise the save is rejected. See [SSO configuration](/en/platform/configure-sso#member-association) for the matching rules.

Click **Save**. Once it succeeds, **Flashcat service provider information** appears at the bottom of the page; copy the **Assertion Consumer Service URL**.

### 4. Paste the ACS URL back into Authing

Paste the **Assertion Consumer Service URL** into the Authing application's **default ACS URL** and click **Save**:

![Save config](https://docs-cdn.flashcat.cloud/images/png/436989.png)

### 5. Test login

Follow the OIDC protocol login flow and start a test sign-in with the **Member sign-in address**.

</Tab>

<Tab title="CAS Protocol">

### 1. Choose the protocol and fill in the connection settings

Open the [Flashduty](https://console.flashcat.cloud) console, go to **Platform → Organization → SSO**, turn on **Enable single sign-on**, and select **CAS** under **Protocol & connection**.

| Flashduty field | What to enter |
| --- | --- |
| CAS address | The CAS IdP address on the Authing application's **Protocol configuration** tab, in the form `https://<user pool domain>/cas-idp/<app ID>` |
| CAS login path | `/login` |
| Skip TLS verification | Leave it off; you don't need it while Authing uses a trusted certificate |

### 2. Fill in member matching and save

In **Member matching**, fill in **Email** `email`, **Username** `username`, and **Phone** `phone_number`. **Email** is required; without it, **Username** and **Phone** must both be filled, otherwise the save is rejected. See [SSO configuration](/en/platform/configure-sso#member-association) for the matching rules.

Click **Save**. Once it succeeds, **Flashcat service provider information** appears at the bottom of the page; copy the CAS **Redirect URL** and paste it into **Authentication configuration → Login callback URL** in the Authing application, then save.

### 3. Modify Authing configuration

On the **Protocol configuration** tab, switch the authorization configuration to **CAS**, turn on **Enable CAS IdP**, enter `${user.email}` in **CAS user identifier**, and keep the other settings at their defaults.

On the **Login control** tab, select the account fields in the **Use for login** column (all are selected in the example):

![Login control](https://docs-cdn.flashcat.cloud/images/png/436964.png)

On the **Access authorization** tab, under **Application access control**, change the authorization of **Everyone** from **Deny** to **Allow**, then click **Change** in the confirmation dialog:

![Permission config](https://docs-cdn.flashcat.cloud/images/png/436967.png)

### 4. Create user and test login

<Note>
Flashduty associates members by email by default, so create users with an email address. New SSO configurations can also associate members by a stable user ID field — see [Single Sign-On configuration](/en/platform/configure-sso).
</Note>

Create user in Authing:

![Create user](https://docs-cdn.flashcat.cloud/images/png/436973.png)

After the configuration is saved, copy the **Member sign-in address** at the top of the Flashduty SSO page, open it in a new window, and sign in with the new user to reach the Flashduty console.

</Tab>
</Tabs>
