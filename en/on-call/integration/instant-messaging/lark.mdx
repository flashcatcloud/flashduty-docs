## Required permissions

The app's permissions fall into three groups, matching the groups in step 1 of the integration detail page:

- **Basic (required)**: alert notifications, card buttons, member linking, and War Room; 6 permissions.
- **Required to import war room chat history into post-mortems**: 1 permission.
- **Required to use AI SRE in Feishu**: 8 permissions, including `im:message.group_msg`, which it shares with the previous group.

That's 14 permissions in total. For an app connected by QR code, Flashduty requests them for you; for a manually connected app, import them in bulk as described in [1. Grant permissions](#step-permissions).

| Group | Official permission name | Purpose |
| :--- | :--- | :--- |
| Basic | `im:message` | Read and send direct and group messages |
| Basic | `im:message:send_as_bot` | Send alert notifications, War Room messages, and AI SRE replies as the bot |
| Basic | `im:message:update` | Update messages the app has sent |
| Basic | `im:chat` | Create and manage War Room chats, get chat information, and add chat members |
| Basic | `im:resource` | Upload and download images, files, and other message resources |
| Basic | `contact:user.id:readonly` | Get user IDs by phone number or email for member linking and War Room invitations |
| War Room post-mortem, AI SRE | `im:message.group_msg` | Read group chat history, for importing War Room chat history into post-mortems and for AI SRE group chat context |
| AI SRE | `im:message.p2p_msg:readonly` | Receive direct messages sent to the bot; without it, AI SRE can't receive direct-chat questions |
| AI SRE | `im:message.group_at_msg:readonly` | Receive group messages that mention the bot; without it, AI SRE can't receive group-chat questions |
| AI SRE | `im:message.reactions:read` | Query message reactions to mark AI SRE processing status |
| AI SRE | `im:message.reactions:write_only` | Add or delete message reactions to mark AI SRE processing status |
| AI SRE | `cardkit:card:write` | Create and update CardKit cards for AI SRE streaming replies |
| AI SRE | `contact:contact.base:readonly` | Get basic contact information to display sender names |
| AI SRE | `contact:user.base:readonly` | Get basic user information to display sender names |

## Create the Feishu/Lark app

When you create a Feishu/Lark integration in Flashduty, **Feishu/Lark app authorization** offers the options below. An app connected by QR code is managed by Flashduty, so you don't need to open the Feishu developer console. Lark and private Feishu deployments support only manually entered credentials, and so does an on-premises Flashduty deployment.

### Option 1: Create a new app by QR code (recommended)

1. Create a Feishu/Lark integration in Flashduty. **Feishu/Lark app authorization** defaults to **Create a new app (recommended)**.
2. Click **Save**, scan the QR code that appears with Feishu, and click **Create** on the Feishu confirmation page. Flashduty saves nothing until you confirm.
3. Wait for your Feishu admin to approve twice: first the app; once it's approved, Flashduty configures it, and then the configuration version. The integration detail page shows which approval is pending, offers **Review in Feishu Admin** and **Copy message for admin**, and checks the review result every 10 seconds.

<Tip>
If you are a Feishu organization admin, scan with your admin account so you can approve both reviews yourself right away.
</Tip>

Once both approvals pass, the integration is ready. Flashduty has configured event subscription, card callbacks, and login redirects, and set availability to all members, so you can skip the 5 steps in "Finish setup in Feishu" below.

Flashduty requests the [required permissions](#aisre-permissions) groups for the enhanced features you've turned on, plus `application:application:self_manage` and `application:application:patch` so it can update the app configuration and publish versions itself. When you later turn on War Room or AI SRE and new permissions are needed, the integration detail page shows **Enabled features need N more Feishu permissions**. Click **Submit for Feishu admin review**, and Flashduty adds the permissions and publishes a new version, which takes effect after an admin approves it. No new scan is needed.

### Option 2: Authorize an existing app by QR code

1. Create a Feishu/Lark integration in Flashduty, choose **Use an existing app** under **Feishu/Lark app authorization**, and enter the app's **App ID**.
2. Click **Save**, then scan with the Feishu account of the app's owner or a collaborator to let Flashduty manage the app.

After authorization, Flashduty manages the app the same way, and its status and pending approvals appear on the integration detail page.

### Option 3: Enter credentials manually

1. Visit the [Feishu developer console](https://open.feishu.cn/app) and create an enterprise custom app. The Lark developer console is at [open.larksuite.com](https://open.larksuite.com). You can use the [Flashduty official icon](https://flashduty-public.oss-cn-beijing.aliyuncs.com/icons/flashduty-20251216.png) as the app icon. See [Create Enterprise Custom App](https://open.feishu.cn/document/uYjL24iN/uMTMuMTMuMTM/development-guide/step1#132c1aac) in the Feishu documentation.

   ![Feishu/Lark: Create Custom App screenshot](https://docs-cdn.flashcat.cloud/images/png/d456a3be638252127dde907617d63fb7.png)

2. Go to the **Credentials & Basic Info** page and copy the `App ID` and `App Secret`.

   ![Feishu/Lark: Copy Credential Information screenshot](https://docs-cdn.flashcat.cloud/images/png/69f98fad9e5a076aac5f9b0058ebd8dc.png)

3. Go to Development Configuration → Events & Callbacks → **Encryption Strategy** and copy the `Verification Token`. We recommend also setting and copying an `Encrypt Key`.

   ![Feishu/Lark: Copy Event Callback Token Information screenshot](https://docs-cdn.flashcat.cloud/images/png/ac558d48464310fe27ef97912b298df1.png)

4. Create a Feishu/Lark integration in Flashduty. Under **Feishu/Lark app authorization**, click **Enter credentials manually**, fill in **App ID**, **App Secret**, **Verification Token**, and **Encrypt Key** (leave it empty if it isn't set in Feishu), and click **Save**. On save, Flashduty exchanges the App ID and App Secret for an access token with Feishu, so a wrong value is reported right away.

   - For Lark, turn on **Is Lark version**.
   - For a private Feishu deployment, turn on **Is on-premises deployment** and enter the **Endpoint**. Flashduty must be able to reach it.

After saving, follow the 5 steps in the next section, "Finish setup in Feishu". The step numbers on the integration detail page match that section.

### Switch to Flashduty-managed

A manually connected Feishu integration can be handed over to Flashduty, except for Lark, private Feishu deployments, and on-premises Flashduty deployments. On the integration detail page, click **Switch to Flashduty-managed** and scan with the Feishu account of the app's owner or a collaborator. After the switch, you no longer need the 5 steps in the next section, and permissions for new features are submitted to the Feishu admin for review automatically. The App Secret and the push URL stay the same, and alert notifications are not interrupted.

## Finish setup in Feishu

After connecting with manually entered credentials, complete these 5 steps in the Feishu developer console. Each step maps to one console page. Flashduty checks steps 1 and 3 and ticks them automatically; for the other 3 steps, click the matching button on the integration detail page when you're done.

<span id="step-permissions"></span>

### 1. Grant permissions

1. In step 1 of the integration detail page, click **Copy permission list (14)**.
2. Open **Permission Management**, choose **Batch actions › Batch import/export permissions**, paste the permission list, click **Next, confirm new permissions**, and confirm.
3. Return to the integration detail page and click **Check again**.

The step is ticked once the 6 basic permissions are granted. Grant the other two groups as needed; they don't affect the tick. Permissions take effect only after you publish in step 5.

![Feishu/Lark: Request App Permissions screenshot](https://docs-cdn.flashcat.cloud/images/png/d919be62107f6b9d0c662f440d620e61.png)

### 2. Add the web app and bot

1. Open **Add Features** and add **Web app** and **Bot**.

   ![Feishu/Lark: Enable and Configure App Capabilities screenshot](https://docs-cdn.flashcat.cloud/images/png/5ab84aec1593c7118782765676a51c6a.png)

2. In **Web app**, set both **Desktop homepage** and **Mobile homepage** to the address shown in step 2 of the integration detail page. See [Configure App Homepage URL](https://open.feishu.cn/document/uYjL24iN/uMTMuMTMuMTM/development-guide/step1#8366b844) in the Feishu documentation.

   ![Feishu/Lark: Configure web app homepage screenshot](https://docs-cdn.flashcat.cloud/images/png/d91efc598bda17e1bfcb367aec47c779.png)

3. You can use the [Flashduty official icon](https://flashduty-public.oss-cn-beijing.aliyuncs.com/icons/flashduty-20251216.png) as the app icon; upload it in **Credentials & Basic Info**.

Feishu doesn't report app features back, so click **I've added them** on the integration detail page when you're done.

### 3. Set up events and callbacks

Events and callbacks use the same request URL, shown in step 3 of the integration detail page. Feishu calls it to verify as soon as you save.

1. Open **Events & Callbacks**. On the **Event configuration** tab, choose **Send events to developer server**, paste the request URL and save, then add the event `im.message.receive_v1`.
2. Switch to the **Callback configuration** tab, paste the same request URL and save, then add the callback `card.action.trigger`.

The step is ticked automatically once Feishu verifies the request URL.

<Note>
If Feishu says the request URL failed verification, the Verification Token or Encrypt Key entered when you created the integration most likely differs from Feishu's **Encryption Strategy** page. Make them match on the integration edit page, then save again in Feishu.
</Note>

### 4. Set redirect URLs

Open **Security Settings** and add the two addresses shown in step 4 of the integration detail page (Web and Mobile) under **Redirect URLs**. They let people open Flashduty from Feishu messages without signing in again. See [Configure Redirect URL](https://open.feishu.cn/document/uYjL24iN/uYjN3QjL2YzN04iN2cDN?lang=zh-CN#c863e533) in the Feishu documentation.

Feishu doesn't report this setting back, so click **I've added them** on the integration detail page when you're done.

![Feishu/Lark: Add Redirect URL to Feishu/Lark App screenshot](https://docs-cdn.flashcat.cloud/images/png/00a7cdd10c09c90c2d7b2f0a99ee4d8d.png)

<span id="publish"></span>

### 5. Set visibility and publish

Open **Version Management & Release**, create a version with availability set to **All employees**, and submit it. It takes effect after the tenant admin approves it. Until then only you can use the app, and changes from steps 1–4 take effect only after publishing. Any later change to permissions, events, or callbacks needs another version. See [App Publishing and Usage](https://open.feishu.cn/document/uYjL24iN/uMTMuMTMuMTM/development-guide/step-4) in the Feishu documentation.

Click **I've published it** on the integration detail page when you're done.

![Feishu/Lark: Publish and Use App screenshot](https://docs-cdn.flashcat.cloud/images/png/6bbc285986808af14c29d0eb633a2bf7.png)

After publishing, you can open the app on **Mobile** or **Desktop** from the same entry: Feishu/Lark → Workspace → Search app name → **Open App**. The first visit requires signing in to link your Feishu/Lark and Flashduty accounts; later visits sign you in automatically.

![Feishu/Lark: Desktop screenshot](https://docs-cdn.flashcat.cloud/images/png/eed8557808874a0c488b958c4049ea72.png)

## Configure war room

After completing the previous steps, in the Flashduty On-call integration configuration page's **Enhanced Features** section, check **Enable War Room** to activate this feature—no additional configuration needed.

<Warning>
Only one IM integration can have War Room enabled at a time. If another IM integration (such as Dingtalk, Slack, or WeCom) has it on, turn it off there first.
</Warning>

## AI SRE controls

Configure the following AI SRE controls separately under **Enhanced Features**. They are enabled by default:

- **Allow AI SRE conversations in IM**: Available without enabling War Room. When enabled, people can @mention AI SRE in a group chat connected through this integration or start a direct conversation with the bot. When disabled, neither entry point triggers an AI SRE reply.
- **Use thread replies in normal group chats**: Available without enabling War Room. When enabled, each normal-group thread has an independent session; War Rooms still receive replies directly in the group.

These controls do not take effect until AI SRE is enabled for the account.

The automatic AI incident analysis that follows a War Room creation is no longer configured on this page: to start one when a War Room is created, add a rule in [Automations](/en/ai-sre/automations), choose the **War room created** trigger, and select the channels and severities to watch.

## Linked users

In the **Linked Users** tab of the integration detail page, you can view the linking status between team members and Feishu/Lark accounts, and quickly complete batch linking.

### View linking status

The list shows every team member and their linking status. Filter by **All / Linked / Unlinked**, or search by name or email.

### One-click linking

When unlinked members exist, click the **One-Click Link** button. The system will attempt to obtain Feishu/Lark account IDs by phone numbers or emails and automatically link them, equivalent to members logging into Flashduty using the same information on Feishu/Lark.

<Tip>
The system can only push Feishu/Lark message notifications after members complete linking. If linking fails, verify that the member's phone number or email matches their Feishu/Lark account.
</Tip>

## FAQ

<AccordionGroup>
<Accordion title="Messages cannot be delivered to individuals, operation log shows 'App not linked'?">
Go to Feishu/Lark → Workspace → Search app name → **Open App**, and sign in once to link your Feishu/Lark and Flashduty accounts. Flashduty needs this identity to deliver messages.
</Accordion>

<Accordion title="Message card buttons not working or showing errors?">
- Ensure account linking is complete. Go to Feishu/Lark → Workspace → Search app name → **Open App**, complete one login. If already logged in, try clicking the top-right menu, switch accounts, and re-login to link the account
- Ensure you've purchased sufficient Licenses. View License usage in Console → **Billing Center**
</Accordion>

<Accordion title="Escalation rule Feishu/Lark group chat list is empty?">
- Go to Feishu/Lark, add the created Flashduty bot to the target group chat
- Return to escalation rule configuration page, refresh and reselect the group chat list

![Feishu/Lark: Escalation rule Feishu/Lark group chat list is empty? screenshot](https://docs-cdn.flashcat.cloud/images/png/0e21e9e689855d9a636fb94848f58c13.png)
</Accordion>

<Accordion title="Feishu/Lark custom app API limits?">
**Call Limits:**

| **Feishu/Lark Version** | **Total Calls/Month** | **Refresh Time** |
| :---: | :---: | :---: |
| Basic Free | 10,000 | 1st of each month |
| Other versions | Unlimited | - |

**Rate Limits:**

| **Scenario** | **Limit** |
| :---: | :--- |
| All APIs | Max 50 calls/second per app |
| Send message API | Max 1000 calls/minute per app |
| Group bot Webhook | Max 100 calls/minute |
| Send to same user or group | Max 5 calls/second |
   
<Warning>
After exceeding API call limits, Feishu/Lark app cannot deliver messages properly. Use notification channels reasonably. See [Feishu/Lark official documentation](https://open.feishu.cn/document/uAjLw4CM/ugTN1YjL4UTN24CO1UjN/platform-updates-/custom-app-api-call-limit).
</Warning>
</Accordion>
