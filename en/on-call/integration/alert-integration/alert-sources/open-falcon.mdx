Sync Open-Falcon alert events to Flashduty through webhook.

<div className="hide">

## In Flashduty On-call
You can get the integration push URL in either of the following ways.

### Use a dedicated integration

Choose this option if all alerts go to one channel. It's the simpler setup.

<AccordionGroup>
  <Accordion title="View dedicated integration setup steps">
  
  1. In the Flashduty console, select **Channel** and open a channel
  2. Select **Configuration** → **Integrations** → **Private integration**, then click **Add integration**
  3. Choose **Falcon** integration, click **Save** to generate a card
  4. Open the generated integration card and copy the **Push URL**
  
</Accordion>
</AccordionGroup>

### Use a shared integration

Choose this option if you need to route alerts to different channels based on the alert payload.

<AccordionGroup>
  <Accordion title="View shared integration setup steps">
  
  1. In the Flashduty console, go to **Integration Center → Alert Events**
  2. Select **Falcon** integration:
        - **Integration Name**: Define a name for this integration
  3. Configure the default route and select a channel. You can add more rules under **Routing** after creation
  4. Click **Save** and copy the generated **Push URL**
    
</Accordion>
</AccordionGroup>
</div>

## Configure Falcon

Set the callback URL in every alert template that should send events, and bind the template to a host group.

<Steps>
<Step title="Set the callback URL in a Falcon alert template">

**Where**: Falcon Dashboard › Templates

| Field | Value |
| --- | --- |
| callback URL (required) | `{integration_url}` |

Open an alert template, enter the push URL in the callback input and click **Save**. Repeat for every alert template that needs to send events.

<img alt="drawing" width="600" src="https://download.flashcat.cloud/open-falcon-tmpls.png" />
<img alt="drawing" width="600" src="https://download.flashcat.cloud/saas-open-falcon-rule.png" />

Similarly, you can configure the same push URL for Expressions alert rules.

</Step>
<Step title="Bind the alert template to a host group">

**Where**: Falcon Dashboard › HostGroups › templates

On the host group's **templates** page, enter the template name and click **bind**. Skip this step if the template is already bound to the host group.

</Step>
<Step title="Trigger an alert and confirm">

Falcon has no entry to send a test callback, so wait for a real alert, or let a host bound to the template cross a threshold.

Go back to Flashduty. If the integration shows a **Latest event time**, the setup works. When the alert recovers, Falcon pushes an event with status OK to the same callback URL and Flashduty closes the matching alert, so no separate recovery notification is needed.
{/* console:
The checklist item "Receive the first event" is then complete as well.
*/}

</Step>
</Steps>
