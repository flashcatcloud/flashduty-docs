Sync Tencent Cloud Log Service (CLS) monitoring alerts to Flashduty through webhook.

<div className="hide">

## In Flashduty On-call
You can get the integration push URL in either of the following ways.

### Use a dedicated integration

Choose this option if all alerts go to one channel. It's the simpler setup.

<AccordionGroup>
  <Accordion title="View dedicated integration setup steps">
  
  1. In the Flashduty console, select **Channel** and open a channel
  2. Select **Configuration** → **Integrations** → **Private integration**, then click **Add an integration**
  3. Choose **Tencent Cloud CLS** integration and click **Save** to generate a card
  4. Open the generated integration card and copy the **Push URL**
  
</Accordion>
</AccordionGroup>

### Use a shared integration

Choose this option if you need to route alerts to different channels based on the alert payload.

<AccordionGroup>
  <Accordion title="View shared integration setup steps">
  
  1. In the Flashduty console, go to **Integration Center → Alerts**
  2. Select **Tencent Cloud CLS** integration:
        - **Integration Name**: Define a name for this integration
  3. Configure the default route and select a channel. You can add more rules under **Routing** after creation
  4. Click **Save** and copy the generated **Push URL**
    
</Accordion>
</AccordionGroup>
</div>

## Configure Tencent Cloud CLS

<Steps>
<Step title="Create a notification channel group in CLS">

**Where**: Tencent Cloud console › Cloud Log Service (CLS) › Monitoring Alerts › Notification Channel Groups › Create

| Field | Value |
| --- | --- |
| Name (required) | A name of your choice, for example `Flashduty` |
| Channel Type (required) | `Custom API Callback` |
| Callback URL (required) | `{integration_url}` |
| Request Method (required) | `POST` |

Click **OK** to save. Click **Add** to add more channels.

<img alt="Creating a notification channel group in Tencent Cloud CLS" width="600" src="https://fcpub-1301667576.cos.ap-nanjing.myqcloud.com/flashduty/integration/tencent-cls/tencent-cls-notify.png" />

</Step>
<Step title="Create an alert policy in CLS and link the channel group">

**Where**: Tencent Cloud console › Cloud Log Service (CLS) › Monitoring Alerts › Alert Policies › Create

| Field | Value |
| --- | --- |
| Alert Name (required) | A name of your choice |
| Log topic (required) | The log topic to monitor |
| Execution Statement (required) | Enter a query and select the query time range. Click **Preview** to check the results, then enter the trigger condition |
| Alert Level (required) | Critical, Warning, or Info, based on severity. Set the execution cycle as needed |
| Multi-dimensional Analysis (optional) | Runs an extra search on the raw logs when an alert fires and attaches the results to the notification. It doesn't affect the trigger condition |
| Alert notification › Notification Channel Group (required) | The channel group you created in the previous step |

<img alt="Creating an alert policy in Tencent Cloud CLS" width="600" src="https://fcpub-1301667576.cos.ap-nanjing.myqcloud.com/flashduty/integration/tencent-cls/tencent-cls-alert.png" />

</Step>
<Step title="Configure the custom callback content and confirm">

**Where**: Tencent Cloud console › Cloud Log Service (CLS) › Monitoring Alerts › Alert Policies › Create › Alert notification › Custom callback

After you link the channel group, the callback content settings appear:

| Field | Value |
| --- | --- |
| Request headers (optional) | Add request headers as needed |
| Request content (required) | Use the JSON below |

```json
{
    "uin": "{{escape .UIN}}",
    "nickname": "{{escape .Nickname}}",
    "region": "{{escape .Region}}",
    "alarm": "{{escape .Alarm}}",
    "alarm_id": "{{escape .AlarmID}}",
    "condition": "{{escape .Condition}}",
    "happen_threshold": "{{escape .HappenThreshold}}",
    "alert_threshold": "{{escape .AlertThreshold}}",
    "topic": "{{escape .Topic}}",
    "topic_id": "{{escape .TopicId}}",
    "level": "{{escape .Level}}",
    "label": {{.Label}},
    "start_time": "{{escape .StartTime}}",
    "start_time_unix": "{{escape .StartTimeUnix}}",
    "notify_time": "{{escape .NotifyTime}}",
    "notify_time_unix": "{{escape .NotifyTimeUnix}}",
    "notify_type": "{{escape .NotifyType}}",
    "consecutive_alert_nums": "{{escape .ConsecutiveAlertNums}}",
    "duration": "{{escape .Duration}}",
    "trigger_params": "{{escape .TriggerParams}}",
    "record_group_id": "{{escape .RecordGroupId}}",
    "detail_url": "{{escape .DetailUrl}}",
    "query_url": "{{escape .QueryUrl}}",
    "message": "{{escape .Message}}",
    "query_result": {{.QueryResult}},
    "query_log": {{.QueryLog}},
    "analysis_result": {{.AnalysisResult}}
}
```

After you save the alert policy, wait for it to fire. Return to Flashduty. If the integration shows a **latest event time**, the setup works.
{/* console:
The "first event received" item in the setup checklist turns green as well.
*/}

</Step>
</Steps>
