Sync Tencent Cloud Log Service (CLS) monitoring alerts to Flashduty through webhook.

<div className="hide">

## In Flashduty On-call
You can get the integration push URL in either of the following ways.

### Use a dedicated integration

Choose this option if all alerts go to one channel. It's the simpler setup.

<AccordionGroup>
  <Accordion title="View dedicated integration setup steps">
  
  1. In the Flashduty console, select **Channel** and open a channel
  2. Select **Configuration** → **Integrations** → **Private integration**, then click **Add integration**
  3. Choose **Tencent Cloud CLS** integration and click **Save** to generate a card
  4. Open the generated integration card and copy the **Push URL**
  
</Accordion>
</AccordionGroup>

### Use a shared integration

Choose this option if you need to route alerts to different channels based on the alert payload.

<AccordionGroup>
  <Accordion title="View shared integration setup steps">
  
  1. In the Flashduty console, go to **Integration Center → Alerts**
  2. Select **Tencent Cloud CLS** integration:
        - **Integration Name**: Define a name for this integration
  3. Configure the default route and select a channel. You can add more rules under **Routing** after creation
  4. Click **Save** and copy the generated **Push URL**
    
</Accordion>
</AccordionGroup>
</div>

## Configure Tencent Cloud CLS

<Steps>
<Step title="Create a notification channel group in CLS">

**Where**: Tencent Cloud console › Cloud Log Service (CLS) › Monitoring Alerts › Notification Channel Groups › Create

| Field | Value |
| --- | --- |
| Name (required) | A name of your choice, for example `Flashduty` |
| Channel Type (required) | `Custom API Callback` |
| Callback URL (required) | `{integration_url}` |
| Request Method (required) | `POST` |

Click **OK** to save. Click **Add** to add more channels.

</Step>
<Step title="Create an alert policy in CLS and link the channel group">

**Where**: Tencent Cloud console › Cloud Log Service (CLS) › Monitoring Alerts › Alert Policies › Create

| Field | Value |
| --- | --- |
| Alert Name (required) | A name of your choice |
| Log topic (required) | The log topic to monitor |
| Execution Statement (required) | Enter a query and select the query time range. Click **Preview** to check the results, then enter the trigger condition |
| Alert Level (required) | Critical, Warning, or Info, based on severity. Set the execution cycle as needed |
| Multi-dimensional Analysis (optional) | Runs an extra search on the raw logs when an alert fires and attaches the results to the notification. It doesn't affect the trigger condition |
| Alert notification › Notification Channel Group (required) | The channel group you created in the previous step |

## Payload

CLS posts the JSON object you configure in the notification channel group. Flashduty reads these fields:

| Field | Meaning | Use in Flashduty |
| :--- | :--- | :--- |
| `alarm` | Alert policy name | Alert title |
| `alarm_id` | Alert policy ID | Alert key |
| `level` | Alert level | Alert severity, label `level` |
| `notify_type` | Notification type | Treated as recovery when it is `2`, label `notify_type` |
| `message` | Alert message | Alert description |
| `query_result` | Query result | The first row is appended to the description |
| `condition` | Trigger condition | Appended to the description |
| `query_log` | Query log | The first log entry becomes the label `first_query_log` |
| `analysis_result` | Multi-dimensional analysis result | Label `analysis_result` (JSON) |
| `label` | Alert policy tags | Each key-value pair becomes a label with the same name |
| `topic`, `topic_id`, `region`, `uin`, `nickname` | Log topic and account details | Labels with the same names |
| `start_time`, `notify_time`, `consecutive_alert_nums`, `duration`, `trigger_params`, `happen_threshold`, `alert_threshold` | Alert context | Labels with the same names |
| `detail_url`, `query_url` | Detail and query links | Labels with the same names |

The alert description concatenates `message`, the first row of `query_result`, and `condition`, in that order. `alarm`, `alarm_id`, and `level` are required; a payload without any of them returns a parameter error.

## Alert key

Flashduty uses `alarm_id` as the Alert Key. Repeated triggers and the recovery notification of one alert policy carry the same `alarm_id` and land on one alert; each alert policy produces its own alert.

Changing the alert policy name, level, tags, or query does not change the Alert Key.

## Labels

| Label | Source |
| :--- | :--- |
| `alarm` | Alert policy name `alarm` |
| `level` | Alert level `level` |
| `notify_type` | Notification type `notify_type` |
| `topic` / `topic_id` | Log topic name and ID |
| `region` / `uin` / `nickname` | Region and account details |
| `happen_threshold` / `alert_threshold` | Trigger and alert thresholds |
| `consecutive_alert_nums` / `duration` / `trigger_params` | Consecutive trigger count, duration, and trigger parameters |
| `start_time` / `notify_time` | Alert start time and notification time |
| `detail_url` / `query_url` | Detail link and query link |
| `first_query_log` | JSON of the first entry in `query_log` |
| `analysis_result` | JSON of the multi-dimensional analysis result |
| Keys in `label` | Alert policy tags, written as labels with the same names |

Labels whose value is an empty string or the string `null` are dropped.

## Troubleshooting

- **An alert does not recover**: only a delivery whose `notify_type` is `2` counts as recovery. When the custom callback body omits `notify_type`, a recovery notification is treated as a trigger
- **Flashduty returns a parameter error**: `alarm`, `alarm_id`, and `level` are required, and `label` must be a JSON object — use `{{.Label}}` without `escape`, or the request body fails to parse
- **The severity is not what you expect**: `level` recognizes only `Info`, `Warn`, and `Critical` (case-sensitive); any other value is treated as Info
- **Labels are missing**: a callback variable with no value at push time renders as an empty string and is dropped, and a key in `label` whose value is the string `null` is dropped too
- **Alerts from one policy merge into one**: the Alert Key is `alarm_id`, so this is expected
