When you enable the RUM service, the system will automatically create this integration for you. This integration is used to collect alert events generated by the RUM service.

:::tips
You cannot modify or delete this integration. However, you can manage the label enrichment, alert pipeline, and routing rules under the integration.
:::

## Enable RUM alerts

<Steps>
<Step title="Turn on application alerts in RUM and pick channels">

**Where**: RUM › Application Management

Select the target application, then open **Alert Settings** on the left.

| Field | Value |
| --- | --- |
| Alert switch (required) | On |
| Delivery method (required) | `Flashduty channels` |
| Channels (required) | You can choose multiple channels. Alert notification rules follow the escalation rules under the channel, and you can set responders for the team to assign to responders when alerts occur |

![RUM Alert Integration: How to Enable RUM Alerts screenshot](https://docs-cdn.flashcat.cloud/images/png/b6ad24809a2ee8f0b3c0b38988b46030.png)

</Step>
<Step title="Confirm Flashduty receives alerts">

Let the application produce a new Issue (or wait for a real error; see [RUM Issue Alerting](/en/rum/error-tracking/issue-alerts) for the triggers). Return to Flashduty. If the integration shows a **latest event time**, the setup works. When the Issue is closed, a recovery event is sent and the alert recovers.
{/* console:
The "first event received" item in the setup checklist turns green as well.
*/}

</Step>
</Steps>

For more information, please refer to [RUM Issue Alerting](/en/rum/error-tracking/issue-alerts).
