Generate a unique Wecom robot address in Flashduty, and synchronize the occurrence and recovery of alerts through Wecom.

<div className="hide">

## Operation steps

### Create WeCom Bot Compatible integration

You can obtain a WeCom Bot Compatible integration address through either of these two methods:

#### Use a dedicated integration

Choose this option if all alerts go to one channel. It's the simpler setup.

<AccordionGroup>
  <Accordion title="View dedicated integration setup steps">
  
  1. In the Flashduty console, select **Channel** and open a channel
  2. Select **Configuration** → **Integrations** → **Private integration**, then click **Add an integration**
  3. Choose **WeCom Bot Compatible** integration and click **Save** to generate a card
  4. Click the generated card to view the **WeCom Bot Compatible Integration URL**, copy it for later use, and you're done
    
</Accordion>
</AccordionGroup>

#### Use a shared integration

Choose this option if you need to route alerts to different channels based on the alert payload.

<AccordionGroup>
  <Accordion title="View shared integration setup steps">
  
  1. In the Flashduty console, go to **Integration Center → Alert Events**
  2. Select **WeCom Bot Compatible** integration:
        - **Integration Name**: Define a name for the current integration
        - **Message Type**: Select Wecom alert message type, currently only Text and Post (rich text) are supported
        - **Push Mode**: Choose when to trigger or recover alerts for Wecom notifications
  3. Copy the **WeCom Bot Compatible Integration URL** for later use
  4. Configure the default route and select the corresponding channel (after integration creation, you can go to `Routes` to configure more routing rules)
    
</Accordion>
</AccordionGroup>
</div>

## Configure in the alert sender

<Steps>
<Step title="Choose the push mode of the WeCom Bot Compatible integration in Flashduty">

**Where**: Flashduty console › Integration Center › Alert Events › WeCom Bot Compatible (dedicated integration: Channel › Configuration › Integrations › Private integration › Add an integration)

| Field | Value |
| --- | --- |
| Integration Name (required) | A name of your choice |
| Message Type (required) | Text, Markdown or Markdown V2; other message types cannot be received |
| Push Mode (required) | See below |

Push modes:

- **Create a new alert for every message** (default)
- **Trigger or close alert based on rules**: for each new message, the system matches it against the rules from the next step, and matched messages trigger new alerts or close existing ones

The system generates a unique WeCom Bot Compatible integration URL `{integration_url}`, which is compatible with the WeCom robot message protocol. Save, then copy the URL for step 3.

</Step>
<Step title="Configure trigger and close rules in Flashduty">

**Where**: Flashduty console › Integration Center › Alert Events › WeCom Bot Compatible › Push Mode › Trigger or close alert based on rules

Only needed when you choose "Trigger or close alert based on rules".

| Setting | Value |
| --- | --- |
| Trigger rule (required) | At least one; matched messages trigger a new alert |
| Close rule (optional) | Matched messages close an existing alert |
| Alert Key extraction (required) | Choose the source (the message content) and enter a regex. The system uses it to find historical alerts for updates or closure |
| When no rule matches (optional) | Discard the message, or trigger it as a new alert |

Rule evaluation order: all close rules are checked first, then trigger rules; within each type, rules are checked in the configured order and the first match wins.

The Alert Key is generated from what the regex captures (multiple capture groups are joined with commas). If the regex does not match, has no capture group, or its first capture group is empty, extraction fails and the Alert Key is random, so a later close rule cannot close this alert, so alerts are not lost because of a configuration error. If no rule matches and you chose not to discard, the Alert Key is random, so every message is a new alert and nothing merges.

Configuration example:

- Receive all messages, close the alert when the message content contains **RESOLVED**, otherwise trigger a new alert
- Extract the Alert Key from the message content using the rule **/(.*)/**

<Note>
The regex extraction rule must be a **valid regular expression (RE2 syntax)**: on submit the frontend validates that it compiles, and an illegal regex (such as unsupported syntax) cannot be saved and shows "Please enter a valid regex". Only when the regex is valid but matches nothing does the system fall back to generating a random Alert Key.
</Note>

</Step>
<Step title="Change the WeCom robot webhook address to Flashduty in the alert sender">

**Where**: The place in the alert sender where the WeCom group robot webhook address is configured

| Field | Value |
| --- | --- |
| Webhook address (required) | `{integration_url}` |

After saving, the messages the sender posts to the WeCom robot go to Flashduty.

</Step>
<Step title="Send a test message and confirm">

**Where**: A terminal that can reach the Flashduty push URL

POST a message in the real message format to the push URL:

```bash
curl -X POST '{integration_url}' \
  -H 'Content-Type: application/json' \
  -d '{"msgtype":"markdown","markdown":{"content":"Flashduty integration test"}}'
```

For a text message use `{"msgtype":"text","text":{"content":"..."}}`. Other message types are rejected.

A few seconds later, go back to Flashduty. The integration shows a **latest event time**, which means the setup works. In rule mode, send another message that matches a close rule and extracts the same Alert Key to confirm the alert closes.
{/* console:
The checklist item "Receive the first event" is marked done at the same time.
*/}

</Step>
</Steps>

## No-event detection

In the integration card (edit and preview), the **No-event detection** setting is available below the base settings: if no valid event arrives within the configured interval, the system generates a Warning alert.

| Setting | Description |
| :--- | :--- |
| **Enable No-event detection** | Switch, off by default. When on, only upstream events that pass integration validation refresh the detection time |
| **Detection Interval (minutes)** | A Warning alert is generated if no valid event arrives within this interval. Must be an integer between 10 minutes and 48 hours (default 10 minutes) |
| **Auto-recover on new event** | Switch, on by default. When the next valid event arrives, the alert raised by no-event detection is recovered automatically |

### Notes
- WeCom Bot Compatible integration URL only supports Text, Markdown and Markdown V2 message types; other message types cannot be received
- Flashduty will generate a default alert title: "企业微信机器人告警". If you need to change the title, you can customize it using the [alert pipeline](/en/on-call/integration/alert-integration/alert-pipelines)

## Status and severity

Currently, all alerts pushed to Flashduty through the WeCom Bot Compatible integration are set to Warning severity. However, you can customize the severity using the [alert pipeline](/en/on-call/integration/alert-integration/alert-pipelines).
