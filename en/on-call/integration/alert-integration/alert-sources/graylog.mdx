Sync Graylog alert events to Flashduty through webhook.

<div className="hide">

## In Flashduty On-call
You can get the integration push URL in either of the following ways.

### Use a dedicated integration

Choose this option if all alerts go to one channel. It's the simpler setup.

<AccordionGroup>
  <Accordion title="View dedicated integration setup steps">
  
  1. In the Flashduty console, select **Channel** and open a channel
  2. Select **Configuration** → **Integrations** → **Private integration**, then click **Add integration**
  3. Choose **Graylog** integration and click **Save** to generate a card
  4. Open the generated integration card and copy the **Push URL**
  
</Accordion>
</AccordionGroup>

### Use a shared integration

Choose this option if you need to route alerts to different channels based on the alert payload.

<AccordionGroup>
  <Accordion title="View shared integration setup steps">
  
  1. In the Flashduty console, go to **Integration Center → Alert Events**
  2. Select **Graylog** integration:
        - **Integration Name**: Define a name for this integration
  3. Configure the default route and select a channel. You can add more rules under **Routing** after creation
  4. Click **Save** and copy the generated **Push URL**
    
</Accordion>
</AccordionGroup>
</div>

## In Graylog

<Steps>
<Step title="Create an HTTP Notification in Graylog">

**Where**: Graylog › Alerts › Notifications › Create Notification

| Field | Value |
| --- | --- |
| Title (required) | A name, for example `Flashduty` (you pick it by this name in the next step) |
| Description (optional) | A description |
| Notification Type (required) | `HTTP Notification` |
| URL (required) | `{integration_url}` |

<img alt="drawing" width="600" src="https://fcpub-1301667576.cos.ap-nanjing.myqcloud.com/flashduty/doc/graylog-2.png" />

The first time you enter this URL, Graylog requires it to be added to the URL whitelist:

<img alt="drawing" width="600" src="https://fcpub-1301667576.cos.ap-nanjing.myqcloud.com/flashduty/doc/graylog-3.png" />

Click Save to whitelist the URL:

<img alt="drawing" width="600" src="https://fcpub-1301667576.cos.ap-nanjing.myqcloud.com/flashduty/doc/graylog-1.png" />

After saving, submit Create.

<img alt="drawing" width="600" src="https://fcpub-1301667576.cos.ap-nanjing.myqcloud.com/flashduty/doc/graylog-5.png" />

</Step>
<Step title="Use the notification in a Graylog Event Definition">

**Where**: Graylog › Alerts › Event Definitions › Create or edit an Event Definition › Notifications

| Field | Value |
| --- | --- |
| Alert conditions (required) | Configure according to your business needs; omitted here |
| Notifications (required) | Click Add Notification, select the notification from the previous step (for example `Flashduty`), and click Done |

Then click Next until the definition is saved.

<img alt="drawing" width="600" src="https://fcpub-1301667576.cos.ap-nanjing.myqcloud.com/flashduty/doc/graylog-4.png" />

</Step>
<Step title="Trigger an alert and confirm Flashduty receives the event">

**Where**: Graylog › Alerts › Event Definitions

Let real log data meet the Event Definition's condition and wait for the event to fire. After a few seconds, go back to Flashduty. If the integration shows a **Latest event time**, the setup works.
{/* console:
The checklist item "Receive the first event" is then complete as well.
*/}

</Step>
</Steps>

## Status and severity

<div class="md-block">
  
| Graylog | Flashduty |
| --- | --- |
| 3 | Critical |
| 2 | Warning |
| 1 | Info |

</div>

An event priority other than 3, 2, or 1 is treated as Info. This integration receives no recovery events: Graylog events enter Flashduty at the severity matching their priority and are not recovered automatically. Turn on the auto-close timeout for the channel that receives this integration (**Flashduty console › Channels › Configuration › Settings › Advanced Settings**), 24 hours recommended; see [auto-close timeout](/en/on-call/channel/create-edit).
