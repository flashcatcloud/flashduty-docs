Sync Google Cloud Monitoring, Error Reporting, Security Command Center, and Cloud Billing budget alerts to Flashduty through a webhook or a Pub/Sub push subscription.

<div className="hide">

## In Flashduty On-call
You can get the integration push URL in either of the following ways.

### Use a dedicated integration

Choose this option if all alerts go to one channel. It's the simpler setup.

<AccordionGroup>
  <Accordion title="View dedicated integration setup steps">
  
  1. In the Flashduty console, select **Channel** and open a channel
  2. Select **Configuration** → **Integrations** → **Private integration**, then click **Add integration**
  3. Choose **Google Cloud Monitoring** integration and click **Save** to generate a card
  4. Open the generated integration card and copy the **Push URL**
  
</Accordion>
</AccordionGroup>

### Use a shared integration

Choose this option if you need to route alerts to different channels based on the alert payload.

<AccordionGroup>
  <Accordion title="View shared integration setup steps">
  
  1. In the Flashduty console, go to **Integration Center → Alert Events**
  2. Select **Google Cloud Monitoring** integration:
        - **Integration Name**: Define a name for this integration
  3. Configure the default route and select a channel. You can add more rules under **Routing** after creation
  4. Click **Save** and copy the generated **Push URL**
    
</Accordion>
</AccordionGroup>

## In Google Cloud

<div class="md-block">

The push URL of one **GCP Cloud Monitoring** integration accepts all of the following sources. No code runs in Google Cloud.

| Source | Delivery | Auto-recovery |
|---|---|---|
| Cloud Monitoring alerting policies | Webhook notification channel, or Pub/Sub notification channel + push subscription | Yes, when the incident closes |
| Error Reporting | Webhook notification channel | No |
| Security Command Center findings | Continuous export (NotificationConfig) to Pub/Sub + push subscription | Yes, when the finding becomes INACTIVE or is muted |
| Cloud Billing budgets | Budget connected to a Pub/Sub topic + push subscription | No |

Below, **push URL** means the integration push URL you copied earlier, that is, `{integration_url}`.

## Cloud Monitoring: webhook notification channel

Configure Cloud Monitoring alerting policies with the steps below; Error Reporting, Security Command Center and Cloud Billing budgets are configured in their own sections further down.

<Steps>
<Step title="Create a webhook notification channel in Cloud Monitoring">

**Where**: Google Cloud console › Monitoring › Alerting › Edit notification channels › Webhooks › Add New

<img alt="drawing" width="600" src="https://download.flashcat.cloud/flashduty/doc/google-cm-1.png" />

| Field | Value |
| :--- | :--- |
| Endpoint URL (Required) | `{integration_url}` (the URL is generated after you save the integration name on the current page) |
| Display Name (Required) | `Flashduty` |

Click **TEST CONNECTION** first, then **SAVE**.

<img alt="drawing" width="600" src="https://download.flashcat.cloud/flashduty/doc/google-cm-2.png" />

</Step>
<Step title="Use the Flashduty notification channel in an alerting policy">

**Where**: Google Cloud console › Monitoring › Alerting › create or edit a policy › Notifications and name

Configure the alert conditions according to your business requirements (omitted here). On the **Notifications and name** page, fill in:

| Field | Value |
| :--- | :--- |
| Use notification channel | Keep enabled |
| Notification channels (Required) | Select the **Flashduty** channel created in the previous step |
| Notify on incident closure | Check it, so that Flashduty receives the recovery notification when the incident closes |

Complete the other settings and save the policy.

<img alt="drawing" width="600" src="https://download.flashcat.cloud/flashduty/doc/google-cm-3.png" />

Metric alerts, uptime checks, log-based alerts, and PromQL alerts (Managed Service for Prometheus) are all sent by alerting policies and are configured the same way.

</Step>
<Step title="Trigger the policy and confirm">

**Where**: Google Cloud console › Monitoring › Alerting

Make the policy condition match for real (for example, lower the threshold temporarily) and confirm on the **Alerting** page that an incident is opened. After a few seconds, go back to Flashduty. If the integration shows a **Latest event time**, the setup works.
{/* console:
The checklist item "Receive the first event" is then complete as well.
*/}

Then restore the threshold, wait for the incident to close, and confirm that the Flashduty alert recovers automatically.

</Step>
</Steps>

## Cloud Monitoring: Pub/Sub notification channel

If your organization requires alerts to go through Pub/Sub, use a Pub/Sub notification channel. The Alert Key is the same as for the webhook channel (`incident_id`), so the two channels are interchangeable.

1. Create the topic and push subscription as described in [Create a Pub/Sub push subscription](#pubsub-subscription).
2. In `Alerting` → `EDIT NOTIFICATION CHANNELS`, click `ADD NEW` in the `Pub/Sub` section and enter the topic name.
3. As prompted, grant `service-<project number>@gcp-sa-monitoring-notification.iam.gserviceaccount.com` the `Pub/Sub Publisher` role on the topic.
4. Select this Pub/Sub channel in the alerting policy's `Notification channels` and check `Notify on incident closure`.

## Error reporting

Error Reporting sends notifications through Cloud Monitoring webhook notification channels (schema version 1.0). It supports webhooks only, not Pub/Sub.

1. Create a webhook notification channel as in step 1 of [Cloud Monitoring: webhook notification channel](#webhook-channel) (you can reuse the same **Flashduty** channel).
2. Open the `Error Reporting` page and click `Configure notifications`.
3. Select the **Flashduty** channel under `Notification channels` and save.

Error Reporting sends a notification when an error cannot be grouped with existing errors, and when an error group marked `Resolved` occurs again.

- One error group (same project, same error details link) maps to one alert. A notification for the same group merges into the alert while it is still open.
- Error Reporting sends no "resolved" notification, so the alert never recovers by itself. Close it in Flashduty.
- Alerts have Warning severity. To use another severity, append `&severity=Critical` (or `Info`) to the push URL.

## Security Command Center

Security Command Center (SCC) can only continuously export findings to Pub/Sub. A push subscription forwards them to Flashduty.

1. Create the topic and push subscription as described in [Create a Pub/Sub push subscription](#pubsub-subscription).
2. Grant the SCC service account the `Pub/Sub Publisher` role on the topic, then create a continuous export (NotificationConfig), for example:

```bash
gcloud scc notifications create flashduty-findings \
    --organization=<organization ID> \
    --location=global \
    --pubsub-topic=projects/<project ID>/topics/<topic name> \
    --filter='severity="HIGH" OR severity="CRITICAL"'
```

<Warning>
Do not add `state="ACTIVE"` to the filter. SCC only publishes finding updates that match the filter, so with `state="ACTIVE"` the update that makes a finding INACTIVE never arrives and the Flashduty alert cannot recover automatically.
</Warning>

- The finding's resource name, `finding.name`, is the Alert Key, so every update to one finding merges into one alert.
- The alert recovers when the finding's `state` becomes `INACTIVE` (remediated, resource deleted, or set by hand) or its `mute` becomes `MUTED`. It triggers again when the finding becomes `ACTIVE` or `UNMUTED`.
- Threat findings (for example, from Event Threat Detection) never become INACTIVE automatically. Change their state or mute them in SCC.

## Cloud Billing budgets

Budget alerts are available only as programmatic notifications through Pub/Sub.

1. Create the topic and push subscription as described in [Create a Pub/Sub push subscription](#pubsub-subscription).
2. Go to `Billing` → `Budgets & alerts`, create or edit a budget, and set threshold rules (actual and/or forecasted cost).
3. Under `Manage notifications`, check `Connect a Pub/Sub topic to this budget`, select the topic above, and save.

Cloud Billing publishes the budget's current status to the topic several times a day. The first message can take several hours. Flashduty handles the messages as follows:

- A message that exceeds no threshold creates no alert.
- Actual cost (`alertThresholdExceeded`) and forecasted cost (`forecastThresholdExceeded`) create separate alerts.
- The Alert Key combines the billing account, budget, budget period, cost type, and the highest threshold exceeded. Repeated messages for the same threshold merge into one alert. Crossing a higher threshold creates a new alert.
- Budget alerts never recover automatically. When a new budget period starts, alerts are tracked for the new period. Close alerts from the previous period by hand.

## Create a Pub/Sub push subscription

Sections II, IV, and V share these steps. One push subscription can carry several sources.

1. Go to `Pub/Sub` → `Topics` and click `CREATE TOPIC` (or use an existing topic).
2. In the topic, click `CREATE SUBSCRIPTION`:
    - **Delivery type**: select `Push`.
    - **Endpoint URL**: enter the integration push URL.
    - **Enable authentication**: leave unchecked. The `integration_key` in the push URL authenticates the request; Flashduty does not check Pub/Sub identity tokens.
    - **Enable payload unwrapping**: leave unchecked. Flashduty needs the message attributes (such as a budget's `budgetId`), which unwrapping drops.
3. Save the subscription.

Flashduty returns 200 and logs the message when a Pub/Sub message cannot become an alert (for example, an unknown format), so Pub/Sub does not redeliver it forever.

## Alert labels

<div class="md-block">

|Source|Main labels|
|---|---|
|Cloud Monitoring|`policy_name`, `check` (condition name), `resource_name`, `resource_type`, `resource_display_name`, `severity`, `url`, `threshold_value`, `observed_value`, plus resource labels, metric labels, metadata user/system labels, and policy user labels|
|Error Reporting|`project_id`, `service`, `service_version`, `exception_type`, `detail_link`, `request_method`, `request_url` (without query string), `response_status`|
|Security Command Center|`check` (category), `resource` (resourceName), `finding_name`, `finding_class`, `state`, `mute`, `severity`, `external_uri`, `notification_config`|
|Cloud Billing budgets|`budget_name`, `budget_id`, `billing_account_id`, `budget_amount`, `cost_amount`, `currency_code`, `cost_interval_start`, `threshold_type`, `threshold`|

Cloud Monitoring resource labels and metadata labels never overwrite an existing label with the same name.

## FAQ

<div class="md-block">

<AccordionGroup>
  <Accordion title="Does the Pub/Sub push subscription need authentication?">
  No. The `integration_key` in the push URL identifies the integration. Leave `Enable authentication` unchecked.
  </Accordion>
  <Accordion title="Why don't budget alerts appear?">
  - The first message can take several hours.
  - A message that exceeds no threshold creates no alert.
  - Check whether `Enable payload unwrapping` is checked on the push subscription. Unwrapping drops the message attributes, so Flashduty cannot identify the budget.
  </Accordion>
  <Accordion title="Why doesn't an SCC alert recover automatically?">
  Check whether the NotificationConfig filter contains `state="ACTIVE"`, and whether the finding is a threat finding, which never becomes INACTIVE automatically.
  </Accordion>
</AccordionGroup>

</div>
