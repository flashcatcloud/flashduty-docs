Sync Meraki alert events to Flashduty through webhook.

<div className="hide">

## In Flashduty On-call
You can get the integration push URL in either of the following ways.

### Use a dedicated integration

Choose this option if all alerts go to one channel. It's the simpler setup.

<AccordionGroup>
  <Accordion title="View dedicated integration setup steps">
  
  1. In the Flashduty console, select **Channel** and open a channel
  2. Select **Configuration** → **Integrations** → **Private integration**, then click **Add an integration**
  3. Choose **Meraki** integration, click **Save** to generate a card
  4. Open the generated integration card and copy the **Push URL**
  
</Accordion>
</AccordionGroup>

### Use a shared integration

Choose this option if you need to route alerts to different channels based on the alert payload.

<AccordionGroup>
  <Accordion title="View shared integration setup steps">
  
  1. In the Flashduty console, go to **Integration Center → Alert Events**
  2. Select **Meraki** integration:
        - **Integration Name**: Define a name for this integration
  3. Configure the default route and select a channel. You can add more rules under **Routing** after creation
  4. Click **Save** and copy the generated **Push URL**
    
</Accordion>
</AccordionGroup>
</div>

## Configure Meraki

<Steps>
<Step title="Add an HTTPS receiver in Meraki">

**Where**: Meraki Dashboard › Network-wide › Configure › Alerts › Webhooks › Add an HTTPS receiver

| Field | Value |
| --- | --- |
| Name (required) | `Flashduty` |
| URL (required) | `{integration_url}` |
| Shared secret (optional) | Leave empty |
| Payload template (optional) | Keep the default `Meraki (included)` |

Then click **Save**. The URL must be a publicly reachable HTTPS address with a certificate from a trusted CA; the Flashduty push URL meets this.

<img alt="HTTPS receiver configuration in Meraki" width="600" src="https://download.flashcat.cloud/flashduty/doc/meraki-5.png" />

</Step>
<Step title="Send alerts to the receiver in Meraki">

**Where**: Meraki Dashboard › Network-wide › Configure › Alerts

On the **Alerts** page, configure `Cellular gateway` and the other alert types as needed, and select the `Flashduty` receiver created in the previous step as the recipient of each alert type. Only the selected alert types are pushed to Flashduty.

</Step>
<Step title="Send a test and confirm">

**Where**: Meraki Dashboard › Organization › Configure › API & Webhooks › Webhooks › the receiver › Send test

Click **Send test**. The message `Webhook test was successful!` only shows that Meraki can reach the push URL; it does not prove the content is parsed like a real alert. Verify with a real alert: trigger one of the selected alert types, and a few seconds later the integration in Flashduty shows a **Latest event time**, which means the setup works.
{/* console:
The checklist item "Receive the first event" is then complete as well.
*/}

</Step>
</Steps>

## Status and severity

<div className="md-block">

| Meraki | Flashduty |
| ---------- | -------- |
| critical | Critical |
| warning | Warning |
| informational | Info |

Any other value is treated as Info. Meraki alert events carry no recovery status, so alerts do not close on their own; turn on the [auto-resolve timeout](/en/on-call/channel/create-edit) in the channel that receives this integration.

</div>
