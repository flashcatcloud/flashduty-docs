Generate a unique Feishu robot address in Flashduty, and synchronize the occurrence and recovery of alerts through Feishu.

<div className="hide">

## Operation steps

### Create Lark Bot Compatible integration

You can obtain a Lark Bot Compatible integration address through either of these two methods:

#### Use a dedicated integration

Choose this option if all alerts go to one channel. It's the simpler setup.

<AccordionGroup>
  <Accordion title="View dedicated integration setup steps">
  
  1. In the Flashduty console, select **Channel** and open a channel
  2. Select **Configuration** → **Integrations** → **Private integration**, then click **Add an integration**
  3. Choose **Lark Bot Compatible** integration and click **Save** to generate a card
  4. Click the generated card to view the **Lark Bot Compatible Integration URL**, copy it for later use, and you're done
    
</Accordion>
</AccordionGroup>

#### Use a shared integration

Choose this option if you need to route alerts to different channels based on the alert payload.

<AccordionGroup>
  <Accordion title="View shared integration setup steps">
  
  1. In the Flashduty console, go to **Integration Center → Alert Events**
  2. Select **Lark Bot Compatible** integration:
        - **Integration Name**: Define a name for the current integration
        - **Message Type**: Select Feishu alert message type, currently only Text and Post (rich text) are supported
        - **Push Mode**: Choose when to trigger or recover alerts for Feishu notifications
  3. Copy the **Lark Bot Compatible Integration URL** for later use
  4. Configure the default route and select the corresponding channel (after integration creation, you can go to `Routes` to configure more routing rules)
    
</Accordion>
</AccordionGroup>
</div>

## Configure in the alert sender

<Steps>
<Step title="Choose the push mode of the Lark Bot Compatible integration in Flashduty">

**Where**: Flashduty console › Integration Center › Alert Events › Lark Bot Compatible (dedicated integration: Channel › Configuration › Integrations › Private integration › Add an integration)

| Field | Value |
| --- | --- |
| Integration Name (required) | A name of your choice |
| Message Type (required) | text or post; other message types cannot be received |
| Push Mode (required) | See below |

Push modes:

- **Create a new alert for every message** (default)
- **Trigger or update alert based on message title**: for each new message, the system looks for an open alert with the same title; it updates the alert if found, otherwise triggers a new one
- **Trigger or close alert based on rules**: for each new message, the system matches it against the rules from the next step, and matched messages trigger new alerts or close existing ones

The system generates a unique Lark Bot Compatible integration URL `{integration_url}`, which is compatible with the Lark robot message protocol. Save, then copy the URL for step 3.

</Step>
<Step title="Configure trigger and close rules in Flashduty">

**Where**: Flashduty console › Integration Center › Alert Events › Lark Bot Compatible › Push Mode › Trigger or close alert based on rules

Only needed when you choose "Trigger or close alert based on rules".

| Setting | Value |
| --- | --- |
| Trigger rule (required) | At least one; matched messages trigger a new alert |
| Close rule (optional) | Matched messages close an existing alert |
| Alert Key extraction (required) | Choose the source (the message title or the message content) and enter a regex. The system uses it to find historical alerts for updates or closure |
| When no rule matches (optional) | Discard the message, or trigger it as a new alert |

Rule evaluation order: all close rules are checked first, then trigger rules; within each type, rules are checked in the configured order and the first match wins.

The Alert Key is generated from what the regex captures (multiple capture groups are joined with commas). If the regex does not match, has no capture group, or its first capture group is empty, extraction fails and the Alert Key is generated from the message title, so alerts are not lost because of a configuration error. If no rule matches and you chose not to discard, the Alert Key is generated from the message title, so messages with the same title merge into one alert.

Configuration example:

- Receive all messages, close the alert when the message content contains **RESOLVED**, otherwise trigger a new alert
- Extract the Alert Key from the message title using the rule **/(.*)/**

</Step>
<Step title="Change the Lark robot webhook address to Flashduty in the alert sender">

**Where**: The place in the alert sender where the Lark custom bot webhook address is configured

| Field | Value |
| --- | --- |
| Webhook address (required) | `{integration_url}` |

After saving, the messages the sender posts to the Lark robot go to Flashduty.

</Step>
<Step title="Send a test message and confirm">

**Where**: A terminal that can reach the Flashduty push URL

POST a message in the real message format to the push URL:

```bash
curl -X POST '{integration_url}' \
  -H 'Content-Type: application/json' \
  -d '{"msg_type":"post","content":{"post":{"zh_cn":{"title":"Flashduty integration test","content":[[{"tag":"text","text":"Flashduty integration test body"}]]}}}}'
```

A post message uses the `zh_cn` content, or `en_us` when `zh_cn` is absent; a request with neither is rejected. For a text message use `{"msg_type":"text","content":{"text":"..."}}`; the alert title is then always "Lark Alert".

A few seconds later, go back to Flashduty. The integration shows a **latest event time**, which means the setup works. In rule mode, send another message that matches a close rule and extracts the same Alert Key to confirm the alert closes.
{/* console:
The checklist item "Receive the first event" is marked done at the same time.
*/}

</Step>
</Steps>

### Notes
- Lark Bot Compatible integration URL only supports Text and post message types; other message types cannot be received
- When Feishu message type is Text, Flashduty will generate a default alert title "Feishu Alert"

## Status and severity

Currently, all alerts pushed to Flashduty through the Feishu(lark) integration are set to Warning severity. However, you can customize the severity using the [alert pipeline](/en/on-call/integration/alert-integration/alert-pipelines).

## Alibaba Cloud Message Center
<div class="md-block">

The "Robot Reception" feature in Alibaba Cloud's account Message Center can push account, product, and security notices to a custom webhook. Its data format can reuse the Feishu robot protocol, so it connects directly to the Lark Bot Compatible integration on this page.

1. Log in to Alibaba Cloud **Message Center**, go to **Robot Reception Management → Robot Management → Add Robot**
2. Select **Custom** for **Robot Platform**, enter the **Lark Bot Compatible Integration URL** from above for **Webhook Address**, and select **Format B (typically used by Feishu)** for **Data Format**
3. Complete the CAPTCHA verification and save

<Note>
Notices from Message Center are one-shot — there is no paired recovery message. Refer to "Push Mode" above and configure **Trigger or Update Alert Based on Message Title** or **Trigger or Close Alert Based on Rules** so alerts don't stay open forever.
</Note>

<Note>
If you're integrating Alibaba Cloud Monitor (CloudMonitor) alerts, use the [Alibaba Cloud Monitor CM Metrics Integration](/en/on-call/integration/alert-integration/alert-sources/aliyun-cm-metrics) directly for full dedup and recovery support.
</Note>

</div>
