Sync JD Cloud monitoring alert events to Flashduty On-call through webhook.

<div className="hide">

## In Flashduty On-call
You can get the integration push URL in either of the following ways.

### Use a dedicated integration

Choose this method when you don't need to route alert events to different channels — it's simpler.

<AccordionGroup>
  <Accordion title="View dedicated integration setup steps">
  
  1. In the Flashduty console, select **Channel** and open a channel
  2. Select **Configuration** → **Integrations** → **Private integration**, then click **Add an integration**
  3. Choose **JD Cloud Monitoring** integration and click **Save** to generate a card
  4. Open the generated integration card and copy the **Push URL**
  
</Accordion>
</AccordionGroup>

### Use a shared integration

Choose this option if you need to route alerts to different channels based on the alert payload.

<AccordionGroup>
  <Accordion title="View shared integration setup steps">
  
  1. In the Flashduty console, go to **Integration Center → Alert Events**
  2. Select **JD Cloud Monitoring** integration:
        - **Integration Name**: Define a name for this integration
  3. Configure the default route and select the corresponding channel (after creation, go to `Route` to configure more routing rules)
  4. Click **Save** and copy the newly generated **Push URL** for later use
  
</Accordion>
</AccordionGroup>
</div>

## In JD Cloud

<Steps>
<Step title="Create notification template">

**Where**: JD Cloud console › Cloud Monitoring › Alarm Management › Notice Templates › Create (or edit an existing template)

| Field | Value |
| --- | --- |
| Alert Callback (required) | Checked |
| URL (required) | `{integration_url}` |
| POST (required) | The JSON template below |

Template content for the `POST` input box:

   ```json
   {
     "resource_id": "${resourceId}",
     "request_id": "${requestId}",
     "metric": "${metric}",
     "current_value": "${currentValue}",
     "times": "${times}",
     "tags": "${tags}",
     "alert_time": "${alertTime}",
     "region": "${region}",
     "threshold": "${threshold}",
     "service_code": "${serviceCode}",
     "as_group_id": "${asGroupId}",
     "unhealthy_instance": "${unhealthyInstance}",
     "rule_policy_id": "${rulePolicyId}",
     "service_code_en": "${serviceCodeEN}",
     "service_code_cn": "${serviceCodeCN}",
     "level": "${level}",
     "resource_name": "${resourceName}",
     "ip_address": "${ipAddress}",
     "status": "${status}"
   }
   ```

Configure other options as needed and click **Save**.

</Step>

<Step title="Configure alert rules">

**Where**: JD Cloud console › Cloud Monitoring › Alarm Management › All Alarm Rules › Create (or edit an existing rule) › Notification Policy

| Field | Value |
| --- | --- |
| Notification Policy (required) | Select **Use Template** and choose the template created in the previous step |

Configure other options as needed and click **Save**.

</Step>

<Step title="Trigger an alert and confirm">

**Where**: JD Cloud console › Cloud Monitoring › Alarm Management › All Alarm Rules › your rule

JD Cloud Monitoring has no standalone callback test. Let the rule fire, or wait for a real alert.

Go back to Flashduty. If the integration shows a **Latest event time**, the setup works.
{/* console:
The checklist item "Receive the first event" is then complete as well.
*/}

</Step>
</Steps>
