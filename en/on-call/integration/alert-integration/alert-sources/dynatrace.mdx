Sync Dynatrace alert events to Flashduty through webhook.

<div className="hide">

## In Flashduty On-call
You can get the integration push URL in either of the following ways.

### Use a dedicated integration

Choose this option if all alerts go to one channel. It's the simpler setup.

<AccordionGroup>
  <Accordion title="View dedicated integration setup steps">
  
  1. In the Flashduty console, select **Channel** and open a channel
  2. Select **Configuration** → **Integrations** → **Private integration**, then click **Add an integration**
  3. Select **Dynatrace** integration and click **Save** to generate a card
  4. Open the generated integration card and copy the **Push URL**
  
</Accordion>
</AccordionGroup>

### Use a shared integration

Choose this option if you need to route alerts to different channels based on the alert payload.

<AccordionGroup>
  <Accordion title="View shared integration setup steps">
  
  1. In the Flashduty console, go to **Integration Center → Alert Events**
  2. Select **Dynatrace** integration:
        - **Integration Name**: Define a name for this integration
  3. Configure the default route and select a channel. You can add more rules under **Routing** after creation
  4. Click **Save** and copy the generated **Push URL**
    
</Accordion>
</AccordionGroup>
</div>

## Configure in Dynatrace

<Steps>
<Step title="Add a Custom integration notification in Dynatrace">

**Where**: Dynatrace › Settings › Integration › Problem notifications › Add notification

In the new Dynatrace UI, open **Settings** from the **Manage** section under **Apps** in the left navigation; in Dynatrace Classic it is **Settings Classic**.

| Field | Value |
| --- | --- |
| Notification type (required) | `Custom Integration` |
| Display name (required) | `Flashduty` |
| Webhook URL (required) | `{integration_url}` |
| Call webhook if problem is closed | Keep it on. If it is off, Flashduty receives no problem-closed notification and the alert does not recover |
| Alerting profile | Pick the Alerting profile that decides which problems trigger this notification |

<div style={{textAlign: "center"}}>
<img alt="Custom Integration basic settings" width="600" src="https://download.flashcat.cloud/flashduty/doc/dyn-4.png" />
</div>

</Step>
<Step title="Fill in the Custom payload in Dynatrace">

**Where**: Dynatrace › Settings › Integration › Problem notifications › Add notification › Custom payload

Enter the following in **Custom payload**:

```
{
    "State":"{State}",
    "PID":"{PID}",
    "ProblemTitle":"{ProblemTitle}",
    "ProblemImpact":"{ProblemImpact}",
    "ProblemDetails":"{ProblemDetailsText}",
    "ProblemURL":"{ProblemURL}",
    "ProblemSeverity":"{ProblemSeverity}",
    "ImpactedEntityNames":"{ImpactedEntityNames}",
    "Tags":"{Tags}"
}
```

<div style={{textAlign: "center"}}>
<img alt="Custom payload settings" width="600" src="https://download.flashcat.cloud/flashduty/doc/dyn-5.png" />
</div>

Click **Save changes**.

</Step>
<Step title="Send a test and verify with a real problem">

**Where**: Dynatrace › Settings › Integration › Problem notifications

Open the notification you just created and click **Send test notification**

**Send test notification** only proves that Dynatrace can reach `{integration_url}`. Whether the test body carries fields such as `PID` and `ProblemSeverity` depends on what Dynatrace actually sends, so do not treat it as a payload check. Produce a real problem in Dynatrace (or wait for an existing one to fire). A few seconds later, the integration in Flashduty shows a **Latest event time**, which means the setup works.
{/* console:
The "Receive first event" item in the setup checklist turns green as well.
*/}

When the problem closes, Dynatrace sends another notification with `State` set to `RESOLVED`, and the matching Flashduty alert recovers.

</Step>
</Steps>

## Status and severity

<div className="md-block">

| Dynatrace | Flashduty |
| --- | --- |
| AVAILABILITY | Critical |
| ERROR | Warning |
| PERFORMANCE | Info |
| RESOURCE_CONTENTION | Info |
| CUSTOM_ALERT | Info |
| Other or empty | Info |

</div>

## Alert Key and recovery

Flashduty uses `PID` (the Dynatrace problem ID) from the payload as the Alert Key, so repeated notifications for one problem merge into one alert. When `State` is `RESOLVED` the alert recovers; any other value triggers at the severity above. The alert title is "impacted entity names::problem title".
