Sync SolarWinds alert events to Flashduty through webhook.

<div className="hide">

## In Flashduty On-call
You can get the integration push URL in either of the following ways.

### Use a dedicated integration

Choose this option if all alerts go to one channel. It's the simpler setup.

<AccordionGroup>
  <Accordion title="View dedicated integration setup steps">
  
  1. In the Flashduty console, select **Channel** and open a channel
  2. Select **Configuration** → **Integrations** → **Private integration**, then click **Add integration**
  3. Choose **SolarWinds** integration, click **Save** to generate a card
  4. Open the generated integration card and copy the **Push URL**
  
</Accordion>
</AccordionGroup>

### Use a shared integration

Choose this option if you need to route alerts to different channels based on the alert payload.

<AccordionGroup>
  <Accordion title="View shared integration setup steps">
  
  1. In the Flashduty console, go to **Integration Center → Alert Events**
  2. Select **SolarWinds** integration:
        - **Integration Name**: Define a name for this integration
  3. Configure the default route and select a channel. You can add more rules under **Routing** after creation
  4. Click **Save** and copy the generated **Push URL**
    
</Accordion>
</AccordionGroup>
</div>

## Configure SolarWinds

SolarWinds has five alert types (Anomaly, Entity, Event, Log, Metric Group), each requiring its own alert channel, so create five webhook channels, one per type you use.

<Steps>
<Step title="Create a webhook notification service in SolarWinds">

**Where**: SolarWinds › Settings › Notification Services › Webhook › CREATE CONFIGURATION

| Field | Value |
| --- | --- |
| Method (required) | `POST` |
| Name (required) | Recommended format `Type_Flashduty`, for example `Anomaly_Flashduty` |
| Destination URL (required) | `{integration_url}` (generated after you enter an integration name in Flashduty and save) |
| Content Type (required) | `application/json` |
| Select Custom Body Template Based On The Alert Types (required) | The type you are creating, for example Anomaly Based Alert |
| HTTP POST Body | Generated by the system for the selected type. **Do not modify the generated template** |

Click **CREATE** when done.

<img alt="drawing" width="600" src="https://download.flashcat.cloud/flashduty/doc/sw-1.png" />

<img alt="drawing" width="600" src="https://download.flashcat.cloud/flashduty/doc/sw-2.png" />

Repeat to create webhook channels for the other types.

</Step>
<Step title="Use the channel in a SolarWinds alert policy">

**Where**: SolarWinds › Alerts › Alert Settings › create or edit a policy › Actions

Configure the alert rule as needed (omitted here). In the **Actions** section:

| Field | Value |
| --- | --- |
| Services (required) | `Webhook` |
| Configuration (required) | The channel from the previous step, for example `Anomaly_Flashduty` (its type must match the alert type) |
| Send an additional notification when the Alert is cleared | Keep enabled so Flashduty receives the recovery notification |

Click **Save** after completing the other settings.

<img alt="drawing" width="600" src="https://download.flashcat.cloud/flashduty/doc/sw-4.png" />

</Step>
<Step title="Trigger an alert and confirm">

**Where**: SolarWinds › Alerts › Alert Settings

The test notification SolarWinds offers when creating a webhook channel only proves that the Flashduty URL is reachable; it does not replace a real alert. Let an alert rule that uses the channel fire. After a few seconds, go back to Flashduty. If the integration shows a **Latest event time**, the setup works. When the condition clears, the alert recovers automatically.
{/* console:
The checklist item "Receive the first event" is then complete as well.
*/}

</Step>
</Steps>

## Status and severity

<div class="md-block">

| SolarWinds | Flashduty |
| --- | --- |
| Critical | Critical |
| Warning | Warning |
| Info | Info |

Any other value is treated as Info. When SolarWinds sends a cleared notification, the alert recovers.

</div>
