## In Flashduty On-call
You can get the integration key in either of the following ways.

### Use a dedicated integration

Choose this option if all alerts go to one channel. It's the simpler setup.

<AccordionGroup>
  <Accordion title="View dedicated integration setup steps">
  
  1. In the Flashduty console, select **Channel** and open a channel
  2. Select **Configuration** → **Integrations** → **Private integration**, then click **Add an integration**
  3. Choose **ElastAlert 2** integration and click **Save** to generate a card
  4. Open the generated integration card and copy the **Push URL**. The part after `integration_key=` is the integration key

</Accordion>
</AccordionGroup>

### Use a shared integration

Choose this option if you need to route alerts to different channels based on the alert payload.

<AccordionGroup>
  <Accordion title="View shared integration setup steps">
  
  1. In the Flashduty console, go to **Integration Center → Alert Events**
  2. Select **ElastAlert 2** integration:
        - **Integration Name**: Define a name for this integration
  3. Configure the default route and select a channel. You can add more rules under **Routing** after creation
  4. Click **Save** and copy the generated **Push URL**. The part after `integration_key=` is the integration key
    
</Accordion>
</AccordionGroup>
</div>


## In ElastAlert 2

### Configure ElastAlert 2 alerts
Follow the [ElastAlert Flashduty](https://elastalert2.readthedocs.io/en/latest/alerts.html#flashduty) push configuration document

1. Create or edit the alert rule file, for example `rules/elastalert2_alert.yaml`.
2. Fill in the `flashduty` alert type in the `alert` field.
3. Fill in the integration key in the `flashduty_integration_key` field.
4. The `flashduty_title` and `flashduty_event_status` are required fields, and other fields can be filled in as needed. For the field definitions, please refer to the following table.

Field|Required|Type|Definition
:-:|:-:|:-:|:---
| title       | Yes   | string | The alert title, it cannot exceed `512` characters.
| event_status | Yes   | string | The alert status. Enum values (capitalized): *Critical*：severe, *Warning*：warning, *Info*：reminder, *Ok*：recovery. When specified as Ok, it means automatic recovery of the alert.
| alert_key    | No   | string | The alert identifier, used to update or automatically recover existing alerts. You can customize this value, but it cannot exceed `255` characters. You can also rely on the system to automatically generate this value, which will be returned in the response. If you report a recovery event, this value must exist.                     
| description  | No   | string | The alert description
|   check     | No   | string | The alert check item
|   resource     | No   | string | The alert resource
|   service     | No   | string  | The alert service name
|   metric     | No   | string | The alert metric name
|   group     | No   | string | The alert group
|   cluster     | No   | string | The alert cluster
|   app     | No   | string | The alert application
|   env     | No   | string | The alert environment


```yaml

name: "elastalert2 alert"
type: "frequency"
index: "app-logs-*"
is_enabled: true
num_events: 1
realert:
  minutes: 1
terms_size: 50
scan_entire_timeframe: true
timeframe:
  minutes: 60
timestamp_field: "created_at"
timestamp_type: "unix_ms"
use_strftime_index: false
alert_subject: "{0} error on {1}"
alert_subject_args:
  - "service"
  - "host"
alert_text: "{0}"
alert_text_args:
  - "message"
filter:
  - query:
      query_string:
        query: "created_at:*"

# ------- Flashduty ----------------
alert: flashduty
flashduty_integration_key: "xxxx"
flashduty_title: "elastalert2 alert"
flashduty_event_status: "Warning"
flashduty_alert_key: "abc"
flashduty_description: "log error"
flashduty_check: "log error"
flashduty_resource: "10.1.1.1"
flashduty_service: "service1"
flashduty_metric: "error"
flashduty_group: "group1"
flashduty_cluster: "bj"
flashduty_app: "app1"
flashduty_env: "dev"
# ------- Flashduty ----------------
```

5. Restart ElastAlert and wait for the alert to trigger.
