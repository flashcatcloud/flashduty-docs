Veeam Service Provider Console (VSPC) sends alarm notifications by email. The Flashduty [email integration](/en/on-call/integration/alert-integration/alert-sources/email) receives these emails and creates alerts from the email title with rules, so no separate VSPC integration is needed: create an email integration in Flashduty, add its email address as an alarm recipient in VSPC, set the VSPC alarm email subject to the fixed format below, and configure the push rules.

<div className="hide">

## In Flashduty On-call

Get the integration email address in either of the two ways below. **In both cases choose the Email integration type**, not Veeam Service Provider Console.

### Use a dedicated integration

1. In the Flashduty console, select **Channels** and open a channel
2. Select **Settings** → **Integrations** → **Dedicated integrations** and click **Add integration**
3. Select **Email** and click **Save**
4. Open the new integration card, copy the **email address**, then configure the push rules below

### Use a shared integration

1. In the Flashduty console, go to **Integration Center → Alert Events**
2. Select **Email**, enter an integration name and copy the **email address**
3. Configure the push rules below
4. Set a default route, select a channel and click **Save**

</div>

## Configure push rules in Flashduty

VSPC emails carry no alarm ID. The subject format below puts the company, location and alarm name in the title, and the rule extracts these three parts as the Alert Key. Emails with the same company, location and alarm name merge into one alert. The alarm status is not part of the Alert Key, so when an alarm changes from Warning to Error the existing alert is updated instead of a new one being created.

1. Set **Push mode** to **Trigger or close alert based on rules**
2. Add the one rule below: the condition is **Email title** **Match** the given regex, the type is **Trigger alert**, and the Alert Key is extracted from the **Email title**
3. Under **Default rules**, choose: if none of the above rules match, **discard email**

Rule 1: trigger an alert

```
Condition: Email title  Match  /^VSPC (Error|Warning) \| /
Regex: /^VSPC (?:Error|Warning) \| (.+) \| (.+) \| (.+)$/
```

The default rule discards unmatched mail so that emails with the Information status don't create alerts.

## Configure Veeam Service Provider Console

The paths below come from the VSPC documentation and require administrator rights.

<Steps>
<Step title="Configure the email server and the alarm email subject">

**Where**: VSPC › Configuration › Server Settings › Email Server

| Item | Setting |
| --- | --- |
| SMTP server (required) | Server address, port, encryption |
| Frequency slider in the Alarms section (required) | `Emails on every event`. **Summary emails only** sends a daily digest, which the rules cannot process one alarm at a time |
| Subject in the Alarms section (required) | See below |

```
VSPC %alarmStatus% | %company% | %location% | %alarmName%
```

`%alarmStatus%`, `%company%`, `%location%` and `%alarmName%` are the variables VSPC supports in alarm notification subjects. A rendered subject looks like:

```
VSPC Error | Contoso | London | Backup job failed
```

The rules read only the email title; the body format does not affect matching.

</Step>
<Step title="Add the Flashduty email address as an alarm recipient">

**Where**: VSPC › Configuration › Templates › Predefined Alarms

By default VSPC sends alarm emails to location administrators and company administrators. To send them to Flashduty, select an alarm and click **Edit**, then click **Add** at the **Actions** step:

| Field | Value |
| --- | --- |
| Action (required) | `Send email notification` |
| Value (required) | The Flashduty email integration address |
| Condition (required) | `Errors and warnings` |

Repeat for every alarm you want to send.

</Step>
<Step title="Trigger an alarm and confirm">

First configure the Flashduty push rules above. VSPC has no entry to send a test alarm email, so wait for a real alarm, or let a monitored object raise a Warning or Error alarm.

Go back to Flashduty. If the integration shows a **Latest event time**, an email whose title starts with `VSPC Error |` or `VSPC Warning |` creates an alert, the setup works. VSPC sends no resolve email, so alerts close through the auto-resolve timeout or manually; see [Limitations](#limitations) below.
{/* console:
The checklist item "Receive the first event" is then complete as well.
*/}

</Step>
</Steps>

## Limitations

- **No resolve email**: by default VSPC sends email when a new alarm is raised or when an existing alarm changes to Error or Warning, so the rules cannot close alerts automatically. Turn on the [auto-resolve timeout](/en/on-call/channel/create-edit) in the channel that receives this integration; 24 hours is a reasonable start. You can also close alerts manually in Flashduty.
- **Object merging**: the subject variables do not include an object name, so alarms with the same name on different objects under the same company and location merge into one Flashduty alert.
- **Type and severity**: in Flashduty these alerts show the Email integration type, and their severity is always Warning. You can adjust it with [alert pipelines](/en/on-call/integration/alert-integration/alert-pipelines) based on `Error` in the title.
