Push alert events from Nightingale (n9e) or Flashcat to Flashduty through webhook. When an alert is triggered, send a trigger event to Flashduty; when an alert recovers, send a recovery event to Flashduty.

From Nightingale/Flashcat v8.0.0-beta.7 (inclusive), you can pick a channel directly in the alert notification rules and no longer need routing rules. Earlier versions push through a webhook callback URL and need routing rules in Flashduty.

<div className="hide">

## Prerequisites

<Tabs>
  <Tab title="In Nightingale/Flashcat">
    - You must have permission to modify **System Settings → Global Notifications** or **Alert Management → Alert Rules**
    - Your Nightingale server must be able to access the domain `api.flashcat.cloud`
  </Tab>
  <Tab title="In Flashduty">
    - You must have a Flashduty account with permission to create integrations
    - You need to create a channel and configure its escalation rule in advance
  </Tab>
</Tabs>

## Get the push URL in Flashduty

You can get the push URL in either of the following ways.

### Use a dedicated integration (recommended)

Choose this option if all alerts go to one channel. It's the simpler setup.

<AccordionGroup>
  <Accordion title="View dedicated integration setup steps">

  1. Log in to the [Flashduty console](https://console.flashcat.cloud), select **Channels**, and open the target channel's details page
  2. Select **Configuration** → **Integrations** → **Private integration**, click **Add an integration**, select the **Nightingale/Flashcat** integration, and click **Save**
  3. Open the generated integration card and copy the **Push URL**
  4. (Optional) Click **Edit** and enter the Nightingale console domain in **Console URL**. Flashduty then adds a Nightingale details link to new alerts

</Accordion>
</AccordionGroup>

### Use a shared integration

Choose this option when you need to route alerts to different channels based on the alert payload.

<AccordionGroup>
  <Accordion title="View shared integration setup steps">

  1. Log in to the [Flashduty console](https://console.flashcat.cloud) and select **Integration Center → Alert Events**
  2. Select the **Nightingale/Flashcat** integration and fill in:
        - **Integration Name**: a name for this integration
        - **Console URL**: (optional) the Nightingale console domain
  3. Configure the default route and select a channel. You can add more rules on the **Routing** page later
  4. Click **Save** and copy the generated **Push URL**

</Accordion>
</AccordionGroup>

</div>

## Configure Nightingale/Flashcat

<Steps>
<Step title="Add the Flashduty push URL in Nightingale">

<Tabs>
<Tab title="v8.0.0-beta.7 and later">

**Where**: Nightingale › Notification › Notification Channels › FlashDuty

In some v8 versions, **Notification Channels** is under the **Alerting** menu.

| Field | Value |
| --- | --- |
| Name (required) | A name of your choice, for example `Flashduty` |
| URL (required) | `{integration_url}` |
| Proxy (optional) | Your proxy address, if the Nightingale server reaches Flashduty through a proxy |
| Timeout (ms), Retries | Keep the defaults (5000 ms, 3 retries) |

Click **Save**.

<img alt="Adding the FlashDuty notification channel in Nightingale" width="600" src="https://download.flashcat.cloud/flashduty/doc/en/fd/n9e-1.png" />

</Tab>
<Tab title="v6–v8.0.0-beta.6">

**Where**: Nightingale › System Settings › Notification Settings › Callback URL

Enable a new webhook, enter `{integration_url}` in `URL`, and save. The global callback URL pushes all alert events. To push only some alert rules, skip this step and configure them per rule in step 3.

<img alt="Global webhook settings in Nightingale" width="500" src="https://download.flashcat.cloud/flashduty/doc/en/fc/fc-2.png" />

</Tab>
<Tab title="v5.4–v5.15">

**Where**: Nightingale server instance › etc/server.conf › [Alerting.Webhook]

Add the following to the `Alerting` section, save the file, and restart the n9e server to apply it. The global webhook pushes all alert events. To push only some alert rules, skip this step and configure them per rule in step 3.

```toml server.conf
[Alerting.Webhook]
Enable = true
Url = "{integration_url}"
BasicAuthUser = ""
BasicAuthPass = ""
Timeout = "5s"
Headers = ["Content-Type", "application/json", "X-From", "N9E"]
```

</Tab>
</Tabs>

</Step>
<Step title="Create a notification rule for Flashduty in Nightingale">

**Where**: Nightingale › Notification › Notification Rules › Add

Only v8.0.0-beta.7 and later need this step. Skip it on earlier versions.

| Field (under notification settings) | Value |
| --- | --- |
| Notification channel (required) | The Flashduty notification channel from the previous step |
| Channels (optional) | The Flashduty channels to send alerts to; multiple allowed. Leave empty to use the integration's default channel |
| Severity, time window, and label filters (optional) | Filter as needed |

Create the channels in [Flashduty](https://console.flashcat.cloud/channel) first and configure their escalation rules. Click **Save**.

<img alt="Configuring a notification rule in Nightingale" width="600" src="https://download.flashcat.cloud/flashduty/doc/en/fd/n9e-2.png" />

</Step>
<Step title="Link alert rules to Flashduty in Nightingale">

<Tabs>
<Tab title="v8.0.0-beta.7 and later">

**Where**: Nightingale › Alert Management › Alert Rules › Add or edit › Notification settings

Select the notification rule from the previous step and click **Save**.

<img alt="Selecting the notification rule in a Nightingale alert rule" width="600" src="https://download.flashcat.cloud/flashduty/doc/en/fd/n9e-3.png" />

</Tab>
<Tab title="v5–v8.0.0-beta.6">

**Where**: Nightingale › Alert Management › Alert Rules › Batch update alert rules › Callback URL

Skip this step if you set the global callback URL in step 1. Otherwise, select the alert rules to push, click **Batch update alert rules** in the upper right corner, select the **Callback URL** field in the pop-up, and enter `{integration_url}`.

<img alt="Setting the callback URL for alert rules in batch" width="500" src="https://download.flashcat.cloud/flashduty/doc/en/fc/fc-1.png" />

</Tab>
</Tabs>

</Step>
<Step title="Send a test notification from Nightingale and confirm">

**Where**: Nightingale › Notification › Notification Rules › your rule › Notification Test

On v8.0.0-beta.7 and later, click **Notification Test** and select a historical alert event to send. Earlier versions have no such entry, so wait for a new alert to fire.

After a few seconds, go back to Flashduty. If the integration shows a **Latest event time**, the setup works.

The checklist item "Receive the first event" is then complete as well.

</Step>
</Steps>

## No-event detection

In the integration card (edit and preview), the **No-event detection** setting is available below the alert push settings: if no valid event arrives within the configured interval, the system generates a Warning alert.

| Setting | Description |
| :--- | :--- |
| **Enable no-event detection** | Switch, off by default. When on, only upstream events that pass integration validation refresh the detection time |
| **Detection Interval (minutes)** | A Warning alert is generated if no valid event arrives within this interval. Must be an integer between 10 minutes and 48 hours (default 10 minutes) |
| **Auto-recover on new event** | Switch, on by default. When the next valid event arrives, the alert raised by no-event detection is recovered automatically |

## Status and severity

Nightingale/Flashcat to Flashduty alert severity mapping:

| n9e | Flashduty | Description |
| :---: | :---: | :--- |
| 1 | Critical | Critical |
| 2 | Warning | Warning |
| 3 | Info | Info |

## FAQ

<AccordionGroup>
  <Accordion title="Why am I not receiving alerts in Flashduty?">
    **In Flashduty**
    
    1. **Check the latest event time**: if the integration shows no **Latest Event Time**, Flashduty hasn't received any pushes. Check the Nightingale side first.
    
    2. **Check routing rules**: if you use a **Shared Integration**, confirm that you've configured **Routing Rules**. Without routing rules, the system rejects new pushes.

    **In Nightingale/Flashcat**
    
    1. **Confirm that alerts were generated**: go to **Alert Management → Alert History** and check for new alerts in **Triggered** status created after you configured the webhook.
    
    2. **Check the callback URL**: open the alert details and check that the **Callback URL** exactly matches the Flashduty push URL.
    
    3. **Check network access**: log in to the Nightingale server and confirm it can reach the `api.flashcat.cloud` domain.
    
    ```bash
    curl -I https://api.flashcat.cloud
    ```
    
    4. **Check error logs**: if the network is fine, look for related errors in the server logs.

    <Tip>
    If you still can't find the cause, contact Flashduty support.
    </Tip>
  </Accordion>
  
  <Accordion title="Why isn't the Flashduty incident closed after the alert recovers?">
    Check the following:
    
    1. The Nightingale alert rule sends recovery notifications
    2. The recovery event uses the same webhook callback URL as the trigger event
    3. The alert's unique identifier (fingerprint) stays the same between trigger and recovery
  </Accordion>
  
  <Accordion title="How do I test whether the integration works?">
    You can test it this way:
    
    1. Trigger a test alert in Nightingale manually
    2. After a few seconds, check whether the **Latest Event Time** in the Flashduty integration list updates
    3. Open the channel and confirm that the matching incident was created
</Accordion>
</AccordionGroup>
