Sync Skywalking alert events to Flashduty through webhook.

<div className="hide">

## In Flashduty On-call
You can get the integration push URL in either of the following ways.

### Use a dedicated integration

Choose this option if all alerts go to one channel. It's the simpler setup.

<AccordionGroup>
  <Accordion title="View dedicated integration setup steps">
  
  1. In the Flashduty console, select **Channel** and open a channel
  2. Select **Configuration** → **Integrations** → **Private integration**, then click **Add integration**
  3. Choose **Skywalking** integration and click **Save** to generate a card
  4. Open the generated integration card and copy the **Push URL**
  
</Accordion>
</AccordionGroup>

### Use a shared integration

Choose this option if you need to route alerts to different channels based on the alert payload.

<AccordionGroup>
  <Accordion title="View shared integration setup steps">
  
  1. In the Flashduty console, go to **Integration Center → Alert Events**
  2. Select **Skywalking** integration:
        - **Integration Name**: Define a name for this integration
  3. Configure the default route and select a channel. You can add more rules under **Routing** after creation
  4. Click **Save** and copy the generated **Push URL**
    
</Accordion>
</AccordionGroup>
</div>

## In Skywalking

<Steps>
<Step title="Add a level tag to the alarm rules">

**Where**: Skywalking OAP server › `./config/alarm-settings.yml` › `rules`

Log in to the Skywalking server and open `./config/alarm-settings.yml`. Add `tags.level` to each alarm rule; Flashduty uses it to set the severity.

| Key | Value |
| --- | --- |
| `tags.level` (Optional; `tags` is supported from v8.6.0, other versions can omit it) | `Critical`, `Warning` or `Info` (case-sensitive); a missing or other value is treated as Info |

```yaml
rules:
    endpoint_relation_resp_time_rule:
        expression: sum(endpoint_relation_resp_time > 1000) >= 2
        period: 10
        message: Response time of endpoint relation {name} is more than 1000ms in 2 minutes of last 10 minutes
        tags:
            level: Warning
```

</Step>
<Step title="Add the Flashduty webhook URL and restart">

**Where**: Skywalking OAP server › `./config/alarm-settings.yml` › bottom of the file

Pick the syntax for your Skywalking version; the URL is `{integration_url}`:

<Tabs>
<Tab title="v8.8.0 to v9.5.0">

```yaml
webhooks:
    - url: {integration_url}
```

</Tab>
<Tab title="v10.0.0">

```yaml
hooks:
  webhook:
    default:
      is-default: true
      urls:
        - {integration_url}
```

</Tab>
</Tabs>

Save the file and restart the Skywalking service to apply it.

</Step>
<Step title="Trigger an alarm and confirm">

**Where**: Skywalking OAP server › `./config/alarm-settings.yml`

Skywalking has no webhook test entry. Wait for the `expression` of a configured rule to match, which produces a real alarm.

After a few seconds, go back to Flashduty. If the integration shows a **Latest event time**, the setup works.
{/* console:
The checklist item "Receive the first event" is then complete as well.
*/}

</Step>
</Steps>

## Status and severity

<div class="md-block">
  
| Skywalking | Flashduty |
| --- | --- |
| Critical | Critical |
| Warning | Warning |
| Info | Info |
| Others or Empty | Info |

Skywalking sends no recovery notification, so Flashduty does not recover these alerts automatically. Turn on the auto-close timeout for the channel that receives this integration (**Flashduty console › Channels › Configuration › Settings › Advanced Settings**), 24 hours recommended; see [auto-close timeout](/en/on-call/channel/create-edit).

</div>
