## In Flashduty On-call
You can get the integration push URL in either of the following ways.

### Use a dedicated integration

Choose this option if all alerts go to one channel. It's the simpler setup.

<AccordionGroup>
  <Accordion title="View dedicated integration setup steps">
  
  1. In the Flashduty console, select **Channel** and open a channel
  2. Select **Configuration** → **Integrations** → **Private integration**, then click **Add integration**
  3. Select **Tencent Cloud Monitor CM** integration and click **Save** to generate a card
  4. Open the generated integration card and copy the **Push URL**
  
</Accordion>
</AccordionGroup>

### Use a shared integration

Choose this option if you need to route alerts to different channels based on the alert payload.

<AccordionGroup>
  <Accordion title="View shared integration setup steps">
  
  1. In the Flashduty console, go to **Integration Center → Alert Events**
  2. Select **Tencent Cloud Monitor CM** integration:
        - **Integration Name**: Define a name for this integration
  3. Configure the default route and select a channel. You can add more rules under **Routing** after creation
  4. Click **Save** and copy the generated **Push URL**
    
</Accordion>
</AccordionGroup>
</div>

## Configure Tencent Cloud Observability Platform (CM)

<Steps>
<Step title="Create a notification template in Tencent Cloud Observability Platform">

**Where**: Tencent Cloud console › Tencent Cloud Observability Platform (formerly Cloud Monitor) › 告警管理 (Alarm Management) › 告警配置 (Alarm Configuration) › 通知模板 (Notification Templates) › 新建通知模板 (New Notification Template)

| Field | Value |
| --- | --- |
| Template name (required) | A name of your choice, for example `Flashduty` |
| Notification type (required) | Tick both `Alarm triggered` and `Alarm recovered`. Without `Alarm recovered`, no recovery notification is sent |
| Notification language (required) | `English` (options: Chinese/English) |
| 接口回调 (API callback) › URL (required) | `{integration_url}`. A template holds at most 6 callback URLs |

Click **Complete**. Saving validates the callback URL once: an HTTP 200 response passes, with a 5-second timeout.

<img alt="Notification template in Tencent Cloud Observability Platform" width="600" src="https://download.flashcat.cloud/saas-tecent-cm-template.png" />

</Step>
<Step title="Add the template to your alert policies">

**Where**: Tencent Cloud console › Tencent Cloud Observability Platform (formerly Cloud Monitor) › 告警管理 (Alarm Management) › 告警配置 (Alarm Configuration) › 告警策略 (Alarm Policies) › 新建策略 (New Policy) / your policy › Edit › 告警通知模板 (Notification Template)

In every alert policy that should send events to Flashduty, add the notification template you created, then save the policy.

<img alt="Adding the notification template to an alert policy" width="600" src="https://download.flashcat.cloud/tecent-cm-rule.png" />

</Step>
<Step title="Confirm Flashduty receives events">

Saving the template validates the callback URL once but does not create a Flashduty event. Wait for a real alert from a linked policy.

If a push fails, Tencent Cloud retries up to 3 times with a 5-second timeout each. Repeat alerts also notify.

After an alert fires, return to Flashduty. If the integration shows a **latest event time**, the setup works.

</Step>

## Payload

Tencent Cloud Observability Platform posts a JSON object built from the notification template. Flashduty reads these fields:

| Field | Meaning | Use in Flashduty |
| :--- | :--- | :--- |
| `alarmLevel` | Alert level | Alert severity |
| `alarmStatus` | Alert status | Treated as recovery when it is `0` |
| `alarmType` | Alert type (`metric`, `event`, `prometheus`, and others) | Severity fallback and recovery check |
| `recoverTime` | Recovery time | Treated as recovery for `event` alerts when it is not `0` |
| `alarmObjInfo` | Alert object | Object details become `obj_` labels, and its dimensions take part in the Alert Key |
| `alarmPolicyInfo.policyId`, `policyName`, `policyType`, `policyTypeCName` | Alert policy details | Alert key (`policyId`), title (`policyName`), and labels with the same names |
| `alarmPolicyInfo.conditions` | Alert conditions | Title, Alert Key, and label `conditions` |
| `alarmPolicyInfo.tag`, `policyTags` | Resource tags and policy tags | Each key-value pair becomes a label with the same name |
| `alarmObjInfo.dimensions` | Object dimensions | Alert Key and labels starting with `obj_dimensions_` |
| `alarmObjInfo.tags` | Object tags | Each key-value pair becomes a label with the same name |
| `additionalMsg` | Additional information | Parsed as a `{key, value}` array and written as labels with the same names |
| `alarmObjInfo.summary`, `content` | Alert summary and content | Title and description of a `prometheus` alert |

`alarmStatus`, `alarmType`, `alarmObjInfo`, and `alarmPolicyInfo` are required; a payload missing any of them returns a parameter error. For types other than `prometheus`, the description appends the `objName` dimension and the current value after the title.

## Alert key

Flashduty builds the Alert Key from three parts: the alert policy ID `policyId`, the metric name `metricName` of each condition (`eventName` for event alerts) together with the product name `productName`, and the object dimensions `dimensions`.

For one policy, one object, and one alert condition, the trigger and recovery land on the same alert; a different policy or condition produces its own alert, and objects with dimensions (for example different instances) each get one too. Changing the alert level, the object name, or tags does not change the Alert Key.

## Status and severity
<div class="md-block">
  
When `alarmLevel` is present, Flashduty maps the alert severity as follows:

| Tencent Cloud Monitor `alarmLevel` | Flashduty |
| --- | --- |
| `Remind` | Info |
| `Warn` | Warning |
| `Serious` | Critical |

When `alarmLevel` is missing or unrecognized, Flashduty uses the default severity for the alert type:

| Tencent Cloud Monitor `alarmType` | Flashduty |
| --- | --- |
| `metric` | Warning |
| `event`, `prometheus`, and other types | Critical |

Recovery is evaluated independently: an `event` alert is resolved (OK) when `recoverTime` is not `0`; all other alert types are resolved (OK) when `alarmStatus` is `0`.

</div>

## Labels

| Label | Source |
| :--- | :--- |
| `check` | Alert policy name `policyName` |
| `policyId` / `policyType` / `policyName` / `policyTypeCName` | Alert policy details |
| `alarmType` / `alarmStatus` | Raw alert type and status |
| `obj_region` / `obj_namespace` / `obj_appId` / `obj_uin` | Object region, namespace, app, and account |
| `obj_city` / `obj_host` / `obj_operator` / `obj_taskName` | City, host, carrier, and task name for probe and host objects |
| `obj_operation` / `obj_service.name` / `obj_span.kind` / `obj_tapm.instance.key` | Operation, service, span kind, and instance for APM objects |
| `obj_instanceId` / `obj_level` | Instance ID and level for RUM objects |
| `obj_dimensions_<dimension>` | Each object dimension, for example `obj_dimensions_objName` |
| `resource` | Resource identifier: for CVM, the IP before `#` in `objName`; otherwise the first non-empty value of `objName`, `unInstanceId`, `InstanceName`, `deviceLanIp`, and `host` |
| `conditions` | JSON of the alert conditions, at most 4 entries |
| Resource tags, object tags, policy tags, and `additionalMsg` | Each key-value pair becomes a label with the same name |

Labels with an empty value or `<nil>` are dropped.

## Troubleshooting

- **An alert does not recover**: for `event` alerts, check that `recoverTime` is not `0`; for other types, check that `alarmStatus` is `0`. The notification template sends no recovery push unless both the trigger and the recovery notification types are selected
- **Flashduty returns a parameter error**: any missing `alarmStatus`, `alarmType`, `alarmObjInfo`, or `alarmPolicyInfo` produces the error
- **Different instances of one policy produce separate alerts**: when the object carries dimensions, the Alert Key includes them, so this is expected
- **The severity is not what you expect**: when `alarmLevel` is missing or not one of `Remind`, `Warn`, and `Serious`, the type decides — `metric` is Warning and every other type is Critical
- **A prometheus alert title is the summary**: a `prometheus` alert uses `summary` as the title and `content` as the description; other types build the title from the policy name and conditions
