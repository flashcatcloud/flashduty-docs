Sync Cloudflare alert events to Flashduty through webhook.

<div className="hide">

## In Flashduty On-call
You can get the integration push URL in either of the following ways.

### Use a dedicated integration

Choose this option if all alerts go to one channel. It's the simpler setup.

<AccordionGroup>
  <Accordion title="View dedicated integration setup steps">
  
  1. In the Flashduty console, select **Channel** and open a channel
  2. Select **Configuration** → **Integrations** → **Private integration**, then click **Add integration**
  3. Choose **Cloudflare** integration and click **Save** to generate a card
  4. Open the generated integration card and copy the **Push URL**
  
</Accordion>
</AccordionGroup>

### Use a shared integration

Choose this option if you need to route alerts to different channels based on the alert payload.

<AccordionGroup>
  <Accordion title="View shared integration setup steps">
  
  1. In the Flashduty console, go to **Integration Center → Alert Events**
  2. Select **Cloudflare** integration:
        - **Integration Name**: Define a name for this integration
  3. Configure the default route and select a channel. You can add more rules under **Routing** after creation
  4. Click **Save** and copy the generated **Push URL**
    
</Accordion>
</AccordionGroup>
</div>


## Configure Cloudflare

<Steps>
<Step title="Create a webhook destination in Cloudflare">

**Where**: Cloudflare dashboard › Alerts › Destinations › Webhooks › Create

In the older dashboard, **Alerts** is called **Notifications**.

| Field | Value |
| --- | --- |
| Name (required) | `Flashduty` |
| URL (required) | `{integration_url}` |
| Secret (optional) | Not needed. Flashduty authenticates with the `integration_key` in the push URL |

Select **Save and Test** to save.

</Step>

<Step title="Make a notification use the webhook in Cloudflare">

**Where**: Cloudflare dashboard › Alerts

Create or edit the notification you want to connect, and select the webhook from the previous step as its destination. After configuring the Webhook channel, you can use it in notification policies.

</Step>

<Step title="Verify">

**Where**: Cloudflare dashboard › Alerts › notification ⋯ menu › Test

**Save and Test** and Test only prove that Cloudflare can reach the URL. A successful test does not mean Flashduty received a usable alert event, so do not treat it as proof the integration works. Wait for a real notification to fire, then go back to Flashduty: when the integration shows a **Latest event time**, the setup works.
{/* console:
The "First event received" item on the integration checklist also turns done.
*/}

</Step>
</Steps>

## Status and severity

<div class="md-block">

Currently, all alerts pushed to Flashduty through the Cloudflare integration are set to Warning severity. However, you can customize the severity using the [alert pipeline](/en/on-call/integration/alert-integration/alert-pipelines).

Cloudflare notifications carry no recovery event, so alerts do not recover automatically; close them manually or enable [auto-close on timeout](/en/on-call/channel/create-edit) on the channel. The Alert Key is the `policy_id` (notification policy ID) in the payload, so repeated notifications of one policy merge into one alert; without a `policy_id` it is random and every notification is a new alert.

</div>
