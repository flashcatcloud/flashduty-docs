Sync UCloud CloudWatch alert events to Flashduty through webhook.

<div className="hide">

## In Flashduty On-call
You can get the integration push URL in either of the following ways.

### Use a dedicated integration

Choose this option if all alerts go to one channel. It's the simpler setup.

<AccordionGroup>
  <Accordion title="View dedicated integration setup steps">
  
  1. In the Flashduty console, select **Channel** and open a channel
  2. Select **Configuration** → **Integrations** → **Private integration**, then click **Add integration**
  3. Choose **UCloud CloudWatch** integration and click **Save** to generate a card
  4. Open the generated integration card and copy the **Push URL**
  
</Accordion>
</AccordionGroup>

### Use a shared integration

Choose this option if you need to route alerts to different channels based on the alert payload.

<AccordionGroup>
  <Accordion title="View shared integration setup steps">
  
  1. In the Flashduty console, go to **Integration Center → Alert Events**
  2. Select **UCloud CloudWatch** integration:
        - **Integration Name**: Define a name for this integration
  3. Configure the default route and select a channel. You can add more rules under **Routing** after creation
  4. Click **Save** and copy the generated **Push URL**
    
</Accordion>
</AccordionGroup>
</div>

## In UCloud

<Steps>
<Step title="Configure a notice template in UCloud CloudWatch">

**Where**: UCloud console › CloudWatch › Notice Management › Contact Template › Create (or edit an existing template)

| Field | Value |
| --- | --- |
| Webhook (required) | Checked |
| Callback Language (required) | `English` |
| Callback URL (required) | `{integration_url}` |
| Template name (required) | `Flashduty` or another name |

Configure other options as needed and click `Submit`.

![UCloud CloudWatch Alert Integration: Configure Notice Template screenshot](https://docs-cdn.flashcat.cloud/images/png/9e6ee0943b6f3ee6b942229bd456cf75.png)

</Step>

<Step title="Use the template in an alarm policy">

**Where**: UCloud console › CloudWatch › Alarm Management › Alarm Policy › Create (or edit an existing policy) › Notification Settings

| Field | Value |
| --- | --- |
| Notification Settings (required) | The notice template created in the previous step |

Configure other options as needed and click `Submit`.

</Step>

<Step title="Trigger an alert and confirm">

**Where**: UCloud console › CloudWatch › Alarm Management › Alarm Policy

UCloud CloudWatch has no standalone callback test. Let a rule in the policy fire, or wait for a real alert.

Go back to Flashduty. If the integration shows a **Latest event time**, the setup works.

## Payload

UCloud CloudWatch posts a JSON object built from the notification template. Flashduty reads these fields:

| Field | Meaning | Use in Flashduty |
| :--- | :--- | :--- |
| `MetricName` | Metric name | Metric name in the title, label `check`, Alert key |
| `ResourceId` | Resource ID | Alert key, label `resource_id` |
| `ResourceType` | Resource type | Resource type in the title, label `resource_type` |
| `StrategyId` | Alert policy ID | Alert key, label `strategy_id` |
| `RecoveryTime` | Recovery time | Treated as recovery when it is not `0` |
| `Region` / `Zone` | Region and availability zone | Labels `region` / `zone` |
| `Value` / `ValueUnit` | Metric value and unit | Labels `value` / `value_unit` |
| `Content` | Alert content | Alert description |

`AlarmTime`, `Duration`, and `SessionID` are not read; the alert time is when Flashduty receives the push. The alert title is `MetricName / ResourceType`, for example `CPUUtilization / UHost`.

## Alert key

Flashduty builds the Alert Key from `ResourceId`, `MetricName`, and `StrategyId`. A trigger and its recovery for the same resource, metric, and alert policy land on one alert; several policies on the same resource produce one alert each.

Changing the alert content, the metric value, or the availability zone does not change the Alert Key.

## Status and severity
Currently, all UCloud CloudWatch alert events pushed to Flashduty have a severity of Warning. You can customize the severity through [Alert Processing Pipeline](/en/on-call/integration/alert-integration/alert-pipelines).

## Labels

| Label | Source |
| :--- | :--- |
| `check` | Metric name `MetricName` |
| `resource_id` | Resource ID `ResourceId` |
| `resource_type` | Resource type `ResourceType` |
| `strategy_id` | Alert policy ID `StrategyId` |
| `region` / `zone` | Region and availability zone |
| `value` / `value_unit` | Metric value and unit |

This integration writes no `resource` label, so route on `resource_id` instead.

## Troubleshooting

- **An alert does not recover**: only a push whose `RecoveryTime` is not `0` counts as recovery. When the notification template sends triggers but no recovery, turn on the auto-close timeout for the channel that receives this integration
- **Every alert has Warning severity**: this integration always pushes Warning; adjust it with an [alert processing pipeline](/en/on-call/integration/alert-integration/alert-pipelines)
- **The title shows `$resource_type`**: the payload has no `ResourceType`, and the title rule keeps the placeholder when it cannot resolve the label
- **Alerts from different policies do not merge**: the Alert Key includes `StrategyId`, so several policies on one resource produce separate alerts
- **Routing by resource does not work**: this integration has no `resource` label; match on `resource_id`
