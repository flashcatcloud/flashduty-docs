Sync Nagios alert events to Flashduty through webhook.

<div className="hide">

## In Flashduty On-call
You can get the integration push URL in either of the following ways.

### Use a dedicated integration

Choose this option if all alerts go to one channel. It's the simpler setup.

<AccordionGroup>
  <Accordion title="View dedicated integration setup steps">

  1. In the Flashduty console, select **Channel** and open a channel
  2. Select **Configuration** → **Integrations** → **Private integration**, then click **Add integration**
  3. Choose **Nagios** integration and click **Save** to generate a card
  4. Open the generated integration card and copy the **Push URL**

</Accordion>
</AccordionGroup>

### Use a shared integration

Choose this option if you need to route alerts to different channels based on the alert payload.

<AccordionGroup>
  <Accordion title="View shared integration setup steps">

  1. In the Flashduty console, go to **Integration Center → Alert Events**
  2. Select **Nagios** integration:
        - **Integration Name**: Define a name for this integration
  3. Configure the default route and select a channel. You can add more rules under **Routing** after creation
  4. Click **Save** and copy the generated **Push URL**

</Accordion>
</AccordionGroup>
</div>

## Configure Nagios

Nagios paths differ between systems and installation methods; adjust the paths below to your environment.

<Steps>
<Step title="Download the notification script on the Nagios Server">

**Where**: A terminal on the Nagios Server host, in the Nagios plugin directory

The download URL requires a `Referer` header and returns 403 without it, so keep the `--header` argument in the commands.

<Tabs>
<Tab title="Debian/Ubuntu">

The directory is usually `/usr/lib/nagios/plugins/`:

```bash
cd /usr/lib/nagios/plugins/
wget --header="Referer: https://console.flashcat.cloud" https://download.flashcat.cloud/flashduty/integration/nagios/send_to_flashduty.sh
chmod +x send_to_flashduty.sh
```

</Tab>
<Tab title="RHEL/CentOS">

The directory is usually `/usr/lib64/nagios/plugins/`:

```bash
cd /usr/lib64/nagios/plugins/
wget --header="Referer: https://console.flashcat.cloud" https://download.flashcat.cloud/flashduty/integration/nagios/send_to_flashduty.sh
chmod +x send_to_flashduty.sh
```

</Tab>
<Tab title="Source install">

The directory is usually `/usr/local/nagios/libexec/`:

```bash
cd /usr/local/nagios/libexec/
wget --header="Referer: https://console.flashcat.cloud" https://download.flashcat.cloud/flashduty/integration/nagios/send_to_flashduty.sh
chmod +x send_to_flashduty.sh
```

</Tab>
</Tabs>

<Note>The script uses `curl`, so make sure curl is installed on the Nagios Server. It also needs bash 4 or later (it uses `declare -A`).</Note>

</Step>
<Step title="Download and edit flashduty.cfg">

**Where**: A terminal on the Nagios Server host, in the Nagios config directory › `flashduty.cfg`

<Tabs>
<Tab title="Debian/Ubuntu">

The directory is usually `/etc/nagios3/conf.d/`:

```bash
cd /etc/nagios3/conf.d/
wget --header="Referer: https://console.flashcat.cloud" https://download.flashcat.cloud/flashduty/integration/nagios/flashduty.cfg
```

</Tab>
<Tab title="RHEL/CentOS">

The directory is usually `/etc/nagios/objects/`:

```bash
cd /etc/nagios/objects/
wget --header="Referer: https://console.flashcat.cloud" https://download.flashcat.cloud/flashduty/integration/nagios/flashduty.cfg
```

</Tab>
<Tab title="Source install">

The directory is usually `/usr/local/nagios/etc/objects/`:

```bash
cd /usr/local/nagios/etc/objects/
wget --header="Referer: https://console.flashcat.cloud" https://download.flashcat.cloud/flashduty/integration/nagios/flashduty.cfg
```

</Tab>
</Tabs>

Edit the downloaded `flashduty.cfg`:

| Location | Change |
| --- | --- |
| `pager` (required) | Replace `<YOUR_FLASHDUTY_PUSH_URL>` with `{integration_url}` |
| Both `command_line` entries (as needed) | The file hard-codes `/usr/local/nagios/libexec/send_to_flashduty.sh`; if the script is in another directory, change the path in both `command_line` entries |

Example configuration:

```
define contact {
    contact_name                    Flashduty
    alias                           Flashduty Alert Receiver
    service_notification_commands   notify-service-by-Flashduty
    host_notification_commands      notify-host-by-Flashduty
    service_notification_options    w,u,c,r
    host_notification_options       d,u,r
    service_notification_period     24x7
    host_notification_period        24x7
    pager                           {integration_url}
}

define command {
    command_name    notify-host-by-Flashduty
    command_line    /usr/local/nagios/libexec/send_to_flashduty.sh type=HOST WEBHOOK_URL="$CONTACTPAGER$" hostname="$HOSTNAME$" state="$HOSTSTATE$" output="$HOSTOUTPUT$" notification_type="$NOTIFICATIONTYPE$" time="$LONGDATETIME$" host_address="$HOSTADDRESS$" host_alias="$HOSTALIAS$" check_command="$HOSTCHECKCOMMAND$"
}

define command {
    command_name    notify-service-by-Flashduty
    command_line    /usr/local/nagios/libexec/send_to_flashduty.sh type=SERVICE WEBHOOK_URL="$CONTACTPAGER$" hostname="$HOSTNAME$" state="$SERVICESTATE$" output="$SERVICEOUTPUT$" notification_type="$NOTIFICATIONTYPE$" time="$LONGDATETIME$" host_address="$HOSTADDRESS$" service_desc="$SERVICEDESC$" host_alias="$HOSTALIAS$" max_attempts="$MAXSERVICEATTEMPTS$"
}
```

Parameters:
- `pager`: the Flashduty push URL, the integration push URL from the Flashduty console
- `command_line`: the script path defaults to `/usr/local/nagios/libexec/send_to_flashduty.sh`; change it if the script is elsewhere
- `service_notification_options`: service notification options, w=warning, u=unknown, c=critical, r=recovery
- `host_notification_options`: host notification options, d=down, u=unreachable, r=recovery

Keep `r` (recovery): Flashduty closes alerts on the recovery notification.

<Tip>To carry more information in alerts, append `key=value` arguments to the end of `command_line`, for example `environment="production" region="$_HOSTREGION$"`. They are pushed to Flashduty as labels.</Tip>

</Step>
<Step title="Include the config file and add the contact to a contact group">

**Where**: `nagios.cfg` and `contacts.cfg`

First include the Flashduty config file in the main Nagios config:

<Tabs>
<Tab title="Debian/Ubuntu">

Debian/Ubuntu normally loads every file under `/etc/nagios3/conf.d/` automatically, so no manual include is needed.

</Tab>
<Tab title="RHEL/CentOS">

Edit `/etc/nagios/nagios.cfg` and add:

```
cfg_file=/etc/nagios/objects/flashduty.cfg
```

</Tab>
<Tab title="Source install">

Edit `/usr/local/nagios/etc/nagios.cfg` and add:

```
cfg_file=/usr/local/nagios/etc/objects/flashduty.cfg
```

</Tab>
</Tabs>

Then edit the contacts file and add the Flashduty contact to the `admins` contact group (or the group you use):

<Tabs>
<Tab title="Debian/Ubuntu">

`/etc/nagios3/conf.d/contacts_nagios2.cfg`

</Tab>
<Tab title="RHEL/CentOS">

`/etc/nagios/objects/contacts.cfg`

</Tab>
<Tab title="Source install">

`/usr/local/nagios/etc/objects/contacts.cfg`

</Tab>
</Tabs>

Find the contact group definition and add Flashduty to its members:

```
define contactgroup {
    contactgroup_name       admins
    alias                   Nagios Administrators
    members                 nagiosadmin,Flashduty
}
```

</Step>
<Step title="Validate, restart and confirm">

**Where**: A terminal on the Nagios Server host

Validate the configuration first, then restart the Nagios service once it passes:

<Tabs>
<Tab title="Debian/Ubuntu">

```bash
/usr/sbin/nagios3 -v /etc/nagios3/nagios.cfg
# restart after it passes
systemctl restart nagios3
```

</Tab>
<Tab title="RHEL/CentOS">

```bash
/usr/sbin/nagios -v /etc/nagios/nagios.cfg
# restart after it passes
systemctl restart nagios
```

</Tab>
<Tab title="Source install">

```bash
/usr/local/nagios/bin/nagios -v /usr/local/nagios/etc/nagios.cfg
# restart after it passes
systemctl restart nagios
```

</Tab>
</Tabs>

After the restart, alerts detected by Nagios are pushed to Flashduty automatically. To verify right away, run the script by hand from its directory: send a critical alert first, then a recovery:

```bash
./send_to_flashduty.sh type=SERVICE WEBHOOK_URL="{integration_url}" hostname="test-host" state="CRITICAL" output="Flashduty test" service_desc="test-service"
./send_to_flashduty.sh type=SERVICE WEBHOOK_URL="{integration_url}" hostname="test-host" state="OK" output="Flashduty test" service_desc="test-service"
```

The script discards curl's output, so a failed push shows no message; if Flashduty receives nothing, first check with `curl` from that host that the push URL is reachable. A few seconds later the integration in Flashduty shows a **Latest event time**, which means the setup works.
{/* console:
The checklist item "Receive the first event" is then complete as well.
*/}

</Step>
</Steps>

## Status and severity

<div className="md-block">

Nagios to Flashduty severity mapping:

| Nagios | Flashduty |
| --- | --- |
| CRITICAL | Critical |
| DOWN | Critical |
| UNREACHABLE | Critical |
| WARNING | Warning |
| OK | Ok |
| UP | Ok |
| UNKNOWN | Info |

Any other value is treated as Info.

</div>
