Synchronize Zabbix alert events to Flashduty through webhook (supports Zabbix 3.x ~ 7.x versions, with different configuration requirements).

<div className="hide">

## In Flashduty On-call

You can get the integration push URL in either of the following ways.

### Use a dedicated integration

Choose this option if all alerts go to one channel. It's the simpler setup.

<AccordionGroup>
  <Accordion title="View dedicated integration setup steps">
  
  1. In the Flashduty console, select **Channel** and open a channel
  2. Select **Configuration** → **Integrations** → **Private integration**, then click **Add an integration**
  3. Choose **Zabbix** integration, click **Save** to generate a card
  4. Open the generated integration card and copy the **Push URL**
  
</Accordion>
</AccordionGroup>

### Use a shared integration

Choose this method when you need to route alerts to different channels based on alert event payload information.

<AccordionGroup>
  <Accordion title="View shared integration setup steps">
  
  1. In the Flashduty console, go to **Integration Center → Alert Events**
  2. Select **Zabbix** integration:
        - **Integration Name**: Define a name for this integration
  3. Configure the default route and select a channel. You can add more rules under **Routing** after creation
  4. Click **Save** and copy the generated **Push URL**
    
</Accordion>
</AccordionGroup>
</div>

## In Zabbix

Select the tab that matches your Zabbix version (7.x, 5.x–6.x, or 3.x–4.x). The steps are the same for every version; only the menu paths, parameters, and screenshots differ.

### Step 1: Define Flashduty Media type

Media type is a transport channel used for sending notifications and alerts in Zabbix.

The download address requires a `Referer` header and returns 403 without it. Keep the `--header` option in the commands.

<Tabs>
  <Tab title="Version 7.x">

1. Enter the terminal and download the complete configuration using the following command:

   ```
   wget --header="Referer: https://console.flashcat.cloud" https://download.flashcat.cloud/flashduty/integration/zabbix/zbx_mediatype_flashcat_v7.yml
   ```

2. Log in to the Zabbix console, select `Alert > Media Types`, click the Import button in the top right corner, enter the editing page, select the configuration file downloaded above, and click Import to complete the import
3. Return to the Media Types page to see the imported media type. Click the name to enter the editing page, complete the URL, zabbix_url, and HTTPProxy content:

   - `URL`: the webhook push URL. Paste the integration push URL.
   - `zabbix_url`: the Zabbix console address. If your console sits behind a Tomcat or NGINX forwarding path, include the path. Flashduty appends parameters such as trigger_id to build alert detail links.
   - `HTTPProxy`: if your Zabbix server can't reach Flashduty directly, set this parameter to a proxy address.

   <img alt="Version 7.x: complete the URL, zabbix_url, and HTTPProxy of the media type" width="600" src="https://download.flashcat.cloud/flashduty/doc/zabbix-2.png" />

4. Click Update to save the configuration

  </Tab>
  <Tab title="Version 5.x–6.x">

1. Enter the terminal and download the complete configuration using the following command:

   ```
   // 5.x version XML configuration:
   wget --header="Referer: https://console.flashcat.cloud" https://download.flashcat.cloud/flashduty/integration/zabbix/zbx_mediatype_flashcat_v5.xml
   ```

2. Log in to the Zabbix console, select `Administration > Media Types`, click the Import button in the top right corner, enter the editing page, select the configuration file downloaded above, and click Import to complete the import
3. Return to the Media Types page to see the imported media type. Click the name to enter the editing page, complete the URL, zabbix_url, and HTTPProxy content:

   - `URL`: the webhook push URL. Paste the integration push URL.
   - `zabbix_url`: the Zabbix console address. If your console sits behind a Tomcat or NGINX forwarding path, include the path. Flashduty appends parameters such as trigger_id to build alert detail links.
   - `HTTPProxy`: if your Zabbix server can't reach Flashduty directly, set this parameter to a proxy address.

   <img alt="Version 5.x–6.x: complete the URL, zabbix_url, and HTTPProxy of the media type" width="600" src="https://download.flashcat.cloud/media.png" />

4. Click Update to save the configuration

  </Tab>
  <Tab title="Version 3.x–4.x">

1. Log in to the Zabbix console, select `Administration > Media Types`, click `Create media type` button in the top right corner to enter the editing page
2. On the editing page, select `Script` for Type, then add the following parameters in this order. The script reads parameters by position, so don't change the order, and leave a parameter empty if it has no value:

   - `{ALERT.SUBJECT}`: Alert title, keep as first parameter
   - `{ALERT.MESSAGE}`: Alert message, keep as second parameter
   - `Flashduty webhook push URL`: the integration push URL. Keep it as the third parameter.
   - `Zabbix console address`: used to build alert detail links. Include the Tomcat or NGINX forwarding path if you use one. Leave it empty if you don't need links, and keep it as the fourth parameter.
   - `HTTPProxy`: if your Zabbix server can't reach Flashduty directly, set this parameter to a proxy address. Leave empty if none, keep as fifth parameter

   <img alt="Version 3.x–4.x: create a Script-type media type" width="600" src="https://download.flashcat.cloud/flashduty/integration/zabbix/v4_create_fd_media_type.jpg" />

3. Fill in `send-to-flashduty.sh` for `Script name`
4. Click Update to save the configuration
5. Log in to the Zabbix server host, execute the following commands:

   ```
   #1. Enter alert script loading directory (specific address configured in Zabbix Server configuration file `AlertScriptsPath` variable, usually `/usr/lib/zabbix/alertscripts`)
   cd /usr/lib/zabbix/alertscripts

   #2. Download script
   wget --header="Referer: https://console.flashcat.cloud" https://download.flashcat.cloud/flashduty/integration/zabbix/send-to-flashduty.sh

   #3. Change script to executable status
   chmod +x send-to-flashduty.sh
   ```

6. Note that the script uses the `curl` and `jq` commands. Ensure that the Zabbix server process can find and execute them, and install them if needed

  </Tab>
</Tabs>

### Step 2: Associate media type with user

The media type must be associated with a user to send events. The user must have at least read permission for hosts. It is recommended to associate directly with the Admin user. Taking the Admin user as an example:

1. Log in to the Zabbix console, open the user list (`Users > Users` for 7.x; `Administration > Users` for 3.x–6.x), select Admin user, select media, select Add to enter the editing window:

   - Type: Select the Flashduty media type created above
   - Send To: Fill in `Flashduty` for 7.x; fill in `N/A` for 3.x–6.x
   - Keep other configurations unchanged using default settings

2. Click Add button to exit the add media window
3. Click Update button to exit the edit user page

### Step 3: Create action

Sending notifications is one of the operations executed by actions in Zabbix. Therefore, to establish a notification, log in to the Zabbix console, open the action list (`Alerts > Actions > Trigger actions` for 7.x; `Configuration > Actions` for 3.x–6.x), then:

1. Click `Create action` to enter the action editing page

   - Name: Fill in "Send To Flashduty"

2. Select `Operations`, add notification sending configurations for three scenarios respectively (for 3.x–4.x, update the notification user configurations):

   - In the Operations configuration item, click Add button to enter the configuration window
   - Send to users: Select the user newly created or configured above
   - Send only to: Select Flashduty media type
   - Keep other configurations as default
   - Click Add button to complete this configuration item
   - Repeat the above steps to complete the configuration of `Recovery operations` and `Update operations`

3. 3.x–4.x only: select `Operations`, update notification content configurations for three scenarios respectively. In the Default Message configuration item, **completely copy the following content and paste it after the default content**. Flashduty parses this text after receiving events to find alert attribute information. Then repeat the above steps for `Recovery operations` and `Update operations`:

   ```
   -----Flashduty Required Starts-----event_severity={TRIGGER.SEVERITY}||event_name={TRIGGER.NAME}||event_id={EVENT.ID}||event_tags={EVENT.TAGS}||event_ack={EVENT.ACK.STATUS}||event_value={EVENT.VALUE}||trigger_id={TRIGGER.ID}||trigger_desc={TRIGGER.DESCRIPTION}||trigger_expr={TRIGGER.EXPRESSION}||host_group={TRIGGER.HOSTGROUP.NAME}||host_ip={HOST.IP}||host_name={HOST.NAME}||item_name={ITEM.NAME}||item_value={ITEM.VALUE}-----Flashduty Required Ends-----
   ```

### Step 4: Send events to Flashduty

Log in to the Zabbix console, select `Monitoring > Problems` to view the latest alert list.

1. Click Actions, you can see the message notification results in the popup
2. Find the Flashduty corresponding log, if the Status is `Sent`, it means the notification was successful. Otherwise, troubleshoot according to the prompts
3. Return to the integration list. If the integration shows a latest event time, the setup works

## Status and severity

Zabbix to Flashduty alert severity mapping:

| Zabbix | Flashduty |
| -------------- | --------- |
| Disaster | Critical |
| High | Critical |
| Average | Warning |
| Warning | Warning |
| Information | Info |
| Not classified | Info |
