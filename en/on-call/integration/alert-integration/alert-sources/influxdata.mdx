<div className="hide">

## In Flashduty On-call
You can get the integration push URL in either of the following ways.

### Use a dedicated integration

Choose this option if all alerts go to one channel. It's the simpler setup.

<AccordionGroup>
  <Accordion title="View dedicated integration setup steps">
  
  1. In the Flashduty console, select **Channel** and open a channel
  2. Select **Configuration** → **Integrations** → **Private integration**, then click **Add integration**
  3. Choose **Influxdata** integration, click **Save** to generate a card
  4. Open the generated integration card and copy the **Push URL**
  
</Accordion>
</AccordionGroup>

### Use a shared integration

Choose this option if you need to route alerts to different channels based on the alert payload.

<AccordionGroup>
  <Accordion title="View shared integration setup steps">
  
  1. In the Flashduty console, go to **Integration Center → Alert Events**
  2. Select **Influxdata** integration:
        - **Integration Name**: Define a name for this integration
  3. Configure the default route and select a channel. You can add more rules under **Routing** after creation
  4. Click **Save** and copy the generated **Push URL**
    
</Accordion>
</AccordionGroup>
</div>

## In Influxdata

Supports Influxdata versions 1.x ~ 2.x, with different configurations for each version, described in the tabs of each step.

<Steps>
<Step title="Create a push channel in Influxdata">

<Tabs>
<Tab title="Version 2.x">

**Where**: InfluxDB console › Alerts › Alerts › Notification Endpoints › Create

| Field | Value |
| --- | --- |
| Destination (required) | `HTTP` |
| Name (required) | `Flashduty` |
| HTTP Method (required) | `POST` |
| URL (required) | `{integration_url}` |
| Auth method (optional) | `None` |

Click **Create Notification Endpoint** after filling in.

<img alt="drawing" width="600" src="https://download.flashcat.cloud/flashduty/doc/influxdb-1.png" />

</Tab>
<Tab title="Version 1.x">

**Where**: Chronograf › Alerting › Alert Rules › the alert rule to synchronize › Alert Rule Builder › Alert Handlers

| Field | Value |
| --- | --- |
| Alert Handlers (required) | Select `Add Another Handler` and choose the `post` type |
| HTTP endpoint (required) | `{integration_url}` |

<img alt="drawing" width="600" src="https://download.flashcat.cloud/influxdb-alert-rule.png" />

</Tab>
</Tabs>

</Step>
<Step title="Use the channel in Influxdata">

<Tabs>
<Tab title="Version 2.x">

**Where**: InfluxDB console › Alerts › Alerts › Notification Rules › Create

| Field | Value |
| --- | --- |
| About (required) | Configure the name and schedule as needed |
| Conditions (required) | Configure as needed; set **When status is equal to** to the status to push |
| Message (required) | Select the `Flashduty` endpoint created in the previous step |

Click **Create Notification Rule** after filling in. A notification rule pushes only when the status equals the selected one. To recover alerts in Flashduty automatically, create another rule with status `OK` that uses the same `Flashduty` endpoint.

<img alt="drawing" width="600" src="https://download.flashcat.cloud/flashduty/doc/influxdb-2.png" />

</Tab>
<Tab title="Version 1.x">

**Where**: Chronograf › Alerting › Alert Rules › Alert Rule Builder

Click **Save Rule** to save the rule. When an alert recovers, Kapacitor pushes an event with level `OK`, and the corresponding alert in Flashduty recovers automatically.

</Tab>
</Tabs>

</Step>
<Step title="Trigger an alert and confirm Flashduty receives the event">

**Where**: InfluxDB console › Alerts › Alerts › Notification Rules (2.x); Chronograf › Alerting › Alert Rules (1.x)

Neither version has an entry that sends a test event directly, so wait for the rule to be triggered by real data. After a few seconds, go back to Flashduty. If the integration shows a **Latest event time**, the setup works and events are being received.
{/* console:
The checklist item "Receive the first event" is then complete as well.

</Step>
</Steps>

## Using Kapacitor directly (without Chronograf)

The `post` handler in Chronograf is Kapacitor's `post` event handler. When using Kapacitor directly, add `.post('<push URL>')` to the `alert()` node of the TICKscript, or use a topic handler (`kind: post`, with the push URL in `options.url`). For the full steps, see [Kapacitor Alert Integration](/en/on-call/integration/alert-integration/alert-sources/kapacitor).

## Status and severity

<div className="md-block">
  
Mapping relationship between Influxdata alert events and Flashduty alert severity:

| Influxdata 1.x (`level`) | Flashduty |
| ---------- | -------------- |
| CRITICAL | Critical |
| WARNING / WARN | Warning |
| INFO | Info |
| OK | Ok (recovery; severity taken from the event's `previousLevel`) |

Requests with any other 1.x `level` are rejected.

| Influxdata 2.x (`_level`) | Flashduty |
| ---------- | -------------- |
| crit | Critical |
| warn | Warning |
| info | Info |
| ok | Ok (recovery) |
| Any other value (such as unknown) | Info |

</div>
