Sync Volcengine RTC alert events to Flashduty through webhook.

<div className="hide">

## In Flashduty On-call
You can get the integration push URL in either of the following ways.

### Use a dedicated integration

Choose this option if all alerts go to one channel. It's the simpler setup.

<AccordionGroup>
  <Accordion title="View dedicated integration setup steps">
  
  1. In the Flashduty console, select **Channel** and open a channel
  2. Select **Configuration** → **Integrations** → **Private integration**, then click **Add an integration**
  3. Choose **Volcengine RTC** integration and click **Save** to generate a card
  4. Open the generated integration card and copy the **Push URL**
  
</Accordion>
</AccordionGroup>

### Use a shared integration

Choose this option if you need to route alerts to different channels based on the alert payload.

<AccordionGroup>
  <Accordion title="View shared integration setup steps">
  
  1. In the Flashduty console, go to **Integration Center → Alert Events**
  2. Select **Volcengine RTC** integration:
        - **Integration Name**: Define a name for this integration
  3. Configure the default route and select a channel. You can add more rules under **Routing** after creation
  4. Click **Save** and copy the generated **Push URL**
    
</Accordion>
</AccordionGroup>
</div>

## Configure in Volcengine RTC

<Steps>
<Step title="Create an alert rule in the Volcengine RTC console and enter the callback URL">

**Where**: Volcengine console › Real-Time Communication › Monitoring › Alert Notifications › Alert Rules › Create Rule

| Field | Value |
| --- | --- |
| Alert rule (required) | Choose the rule type (metric / real-time / event) and set the metrics and thresholds as needed |
| Alert Callback (required) | Check it and enter `{integration_url}` in the address box |
| Other options (optional) | Configure as needed |

Click `Confirm` to finish.

![Volcengine RTC alert rule with Alert Callback checked and the push URL entered](https://docs-cdn.flashcat.cloud/images/png/21908f6a040f61ad2e8091226874fe97.png)

</Step>
<Step title="Enable the rule and confirm">

**Where**: Volcengine console › Real-Time Communication › Monitoring › Alert Notifications › Alert Rules

Find the new rule in the list and click `Enable`. The rule takes effect only after it is enabled. Wait for the rule to trigger (you can lower the threshold temporarily to trigger it once).

Back in Flashduty, the integration shows a **Latest event time**, which means the setup works.
{/* console:
The checklist item "Receive the first event" also turns green.
*/}

</Step>
</Steps>

## Severity and event handling

Volcengine RTC alert callbacks carry no level: whether the rule level is Critical, Warning or Notice, Flashduty always maps it to Warning.

- Every push gets a fresh alert key, so each callback is a separate alert.
- The callback contains no recovery notice, so alerts never recover automatically and must be closed manually in Flashduty, or by using no-event detection to close alerts that receive no new events for a long time.
- The alert title is `check::alert_type`.

You can customize the severity through [Alert Processing Pipeline](/en/on-call/integration/alert-integration/alert-pipelines).
