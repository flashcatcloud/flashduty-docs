Sync Splunk alert events to Flashduty through webhook.

<div className="hide">

## In Flashduty On-call
You can get the integration push URL in either of the following ways.

### Use a dedicated integration

Choose this option if all alerts go to one channel. It's the simpler setup.

<AccordionGroup>
  <Accordion title="View dedicated integration setup steps">
  
  1. In the Flashduty console, select **Channel** and open a channel
  2. Select **Configuration** → **Integrations** → **Private integration**, then click **Add integration**
  3. Choose **Splunk** integration and click **Save** to generate a card
  4. Open the generated integration card and copy the **Push URL**
  
</Accordion>
</AccordionGroup>

### Use a shared integration

Choose this option if you need to route alerts to different channels based on the alert payload.

<AccordionGroup>
  <Accordion title="View shared integration setup steps">
  
  1. In the Flashduty console, go to **Integration Center → Alert Events**
  2. Select **Splunk** integration:
        - **Integration Name**: Define a name for this integration
  3. Configure the default route and select a channel. You can add more rules under **Routing** after creation
  4. Click **Save** and copy the generated **Push URL**
    
</Accordion>
</AccordionGroup>
</div>

## In Splunk

<Steps>
<Step title="Save a search as an alert in Splunk">

**Where**: Splunk Web › Search & Reporting › Search › Save As › Alert

In the `Search & Reporting` app, search for the keywords you want to monitor (for example "error"), then choose `Alert` from the save menu in the upper right corner to configure the search as a monitoring item.

<img alt="Save As menu on the Splunk search results page with Alert selected" width="600" src="https://download.flashcat.cloud/flashduty/doc/splunk-1.png" />

In the popup, enter a name and configure the `set up` and `Triggering conditions` sections according to your needs.

</Step>
<Step title="Add a webhook trigger action to the alert">

**Where**: Splunk Web › Save As Alert dialog › Trigger Actions › Add Actions › Webhook

| Field | Value |
| --- | --- |
| Add Actions (Required) | Select `Webhook` |
| URL (Required) | `{integration_url}` |

Click `Save` to finish the alert configuration.

<img alt="Adding a Webhook action in the Save as Alarm dialog" width="600" src="https://download.flashcat.cloud/flashduty/doc/splunk-2.png" />

<img alt="Webhook action URL filled in with the Flashduty push URL" width="600" src="https://download.flashcat.cloud/flashduty/doc/splunk-3.png" />

Splunk Enterprise 9.0 and later and Splunk Cloud Platform 8.2203 and later require the webhook URL to be on the webhook allow list, otherwise the request is not sent. A user with the `admin` role or the `edit_webhook_allow_list` capability can add it; see the [Splunk documentation](https://help.splunk.com/en/splunk-enterprise/alert-and-respond/alerting-manual/9.4/configure-webhook-allow-list).

</Step>
<Step title="Trigger the alert and confirm">

**Where**: Splunk Web › Search & Reporting › Alerts

The Splunk webhook action has no test button. Wait for the alert to match its trigger condition, which produces a real alert. Splunk alerts always arrive as Warning and produce no recovery event (see "Status and severity" below).

After a few seconds, go back to Flashduty. If the integration shows a **Latest event time**, the setup works.
{/* console:
The checklist item "Receive the first event" is then complete as well.
*/}

</Step>
</Steps>

## Payload

A Splunk webhook action posts one JSON object each time it triggers. Flashduty reads these fields:

| Field | Meaning | Use in Flashduty |
| :--- | :--- | :--- |
| `sid` | Search job ID | Alert key |
| `search_name` | Search or alert name | Search name in the title, label `check` |
| `app` | App the search belongs to | App name in the title, label `app` |
| `result._raw` | Raw matched event | Alert description |
| `results_link` | Link to the search results | Label `results_link` |
| `result.source` | Log source | Label `source` |
| `result.sourcetype` | Source type | Label `source_type` |
| `result.splunk_server` | Indexer | Label `splunk_server` |

The alert title is `app / search_name`, for example `search / test_alert`. Other fields in `result` (for example `host`, `index`, and custom fields) are not written to labels.

## Alert key

Flashduty uses `sid` as the Alert Key. Several deliveries from one search job share the same `sid` and merge into one alert; a scheduled alert starts a new search job on every run, so each run has a different `sid` and opens its own alert.

Changing the search name, the app, or any field in `result` does not change the Alert Key; an empty `sid` makes Flashduty return a parameter error.

## Status and severity

<div class="md-block">
Since Splunk alert events don't differentiate severity levels, all alert events pushed from Splunk to Flashduty will have a Warning status and won't include recovery events. Turn on the auto-close timeout for the channel that receives this integration (**Flashduty console › Channels › Configuration › Settings › Advanced Settings**), 24 hours recommended; see [auto-close timeout](/en/on-call/channel/create-edit).
</div>

## Labels

| Label | Source |
| :--- | :--- |
| `check` | Search or alert name `search_name` |
| `app` | App `app` |
| `results_link` | Search results link `results_link` |
| `source` | Log source `result.source`, not a fixed `splunk` |
| `source_type` | Source type `result.sourcetype` |
| `splunk_server` | Indexer `result.splunk_server` |

Labels with empty values are not written.

## Troubleshooting

- **Every trigger opens a new alert**: the Alert Key is the search job ID, and a scheduled alert starts a new search job on every run. This is expected; Splunk sends no recovery events, so turn on the auto-close timeout for the channel
- **The title shows `$app`**: the payload has no `app` field, for example when a script posts to the push URL instead of a Splunk alert action. The placeholder stays in the title as written
- **Alerts do not recover**: a Splunk webhook action sends trigger events only, never recovery events. Turn on the auto-close timeout for the channel that receives this integration
- **Splunk sends no request**: Splunk Enterprise 9.0 and later and Splunk Cloud Platform 8.2203 and later require the push URL in the webhook allow list. Add it there, then trigger the alert again
- **Flashduty returns a parameter error**: the request body must be a valid JSON object with a non-empty `sid`
