Sync OpManager alert events to Flashduty through webhook.

<div className="hide">

## In Flashduty On-call
You can get the integration push URL in either of the following ways.

### Use a dedicated integration

Choose this option if all alerts go to one channel. It's the simpler setup.

<AccordionGroup>
  <Accordion title="View dedicated integration setup steps">
  
  1. In the Flashduty console, select **Channel** and open a channel
  2. Select **Configuration** → **Integrations** → **Private integration**, then click **Add an integration**
  3. Select **OpManager** integration and click **Save** to generate a card
  4. Open the generated integration card and copy the **Push URL**
  
</Accordion>
</AccordionGroup>

### Use a shared integration

Choose this option if you need to route alerts to different channels based on the alert payload.

<AccordionGroup>
  <Accordion title="View shared integration setup steps">
  
  1. In the Flashduty console, go to **Integration Center → Alert Events**
  2. Select **OpManager** integration:
        - **Integration Name**: Define a name for this integration
  3. Configure the default route and select a channel. You can add more rules under **Routing** after creation
  4. Click **Save** and copy the generated **Push URL**
    
</Accordion>
</AccordionGroup>
</div>

## Configure OpManager

<Steps>
<Step title="Create a webhook notification profile in OpManager">

**Where**: OpManager › Settings › Notifications › Add Profile › Invoke a Webhook

<img alt="Adding an Invoke a Webhook profile in OpManager" width="600" src="https://download.flashcat.cloud/flashduty/doc/opm-1.png" />

On the Webhook editing page, fill in:

| Field | Value |
| --- | --- |
| Request method under Hook URL (required) | `POST` |
| URL (required) | `{integration_url}` |
| Data Type (required) | `raw` |
| Payload Type (required) | `JSON` |
| Body Content (required) | The JSON below |
| Request Headers | Keep the default |
| Time Out (required) | In seconds; the UI default is 15 |

Set `Body Content` to:

```json
{
     "alarmid":"$alarmid",
     "message":"$message",
     "displayName":"$displayName",
     "category":"$category",
     "severity":"$stringseverity",
     "strModTime":"$strModTime",
     "eventType":"$eventType",
     "entity":"$entity",
     "lastPolledValue":"$lastPolledValue",
     "Intf_ifDescr":"$IntfField(ifDescr)",
     "Intf_displayName":"$IntfField(displayName)",
     "Intf_ifAlias":"$IntfField(ifAlias)",
     "Intf_ifName":"$IntfField(ifName)",
     "Intf_ipAddress":"$IntfField(ipAddress)",
     "Intf_physMedia":"$IntfField(physMedia)",
     "Intf_ifIndex":"$IntfField(ifIndex)",
     "Intf_ifCircuitID":"$IntfField(ifCircuitID)",
     "Intf_ifSpeedIn":"$IntfField(ifSpeedIn)",
     "Intf_ifSpeedOut":"$IntfField(ifSpeedOut)",
     "Intf_lineID":"$IntfCustomField(Circuit ID)",
     "Intf_note":"$IntfCustomField(Comments)",
     "Intf_contacts":"$IntfCustomField(Contact Name)",
     "Intf_SLA":"$IntfCustomField(SLA)",
     "Custom_building":"$CustomField(Building)",
     "Custom_cabinet":"$CustomField(Cabinet)",
     "Custom_note":"$CustomField(Comments)",
     "Custom_contacts":"$CustomField(Contact Name)",
     "Custom_department":"$CustomField(Department)",
     "Custom_floor":"$CustomField(Floor)",
     "Custom_serial":"$CustomField(SerialNumbe)",
     "Monitor_monitorName":"$MonitorField(monitorName)",
     "Monitor_instance":"$MonitorField(instance)",
     "Monitor_protocol":"$MonitorField(protocol)",
     "Device_type":"$DeviceField(type)",
     "Device_ipAddress":"$DeviceField(ipAddress)",
     "Device_isSNMP":"$DeviceField(isSNMP)",
     "Device_hardDiskSize":"$DeviceField(hardDiskSize)",
     "Device_ramSize":"$DeviceField(ramSize)"
}
```

Keep the JSON keys exactly as shown; Flashduty reads only these keys. Additional custom fields are not supported: even if you reference other fields in Body Content, they do not take effect.

Click next when done.

<img alt="Time Out setting of the webhook in OpManager" width="600" src="https://download.flashcat.cloud/flashduty/doc/opm-2.png" />

</Step>
<Step title="Set the criteria and the clear notification">

**Where**: OpManager › Settings › Notifications › Add Profile › Invoke a Webhook › Choose the criteria

Check `Notify when the alarm is cleared`. OpManager then sends one more notification when the alarm clears, and Flashduty uses it to resolve the alert. Configure the other criteria as needed.

<img alt="Notify when the alarm is cleared checked in OpManager" width="600" src="https://download.flashcat.cloud/flashduty/doc/opm-3.png" />

Click next, select the devices to apply the profile to and move them to the selected devices window with the right arrow, then click next. Configure `Time Window`, `Delayed Trigger` and `Recurring Trigger` as needed, then click next.

</Step>
<Step title="Save the profile and confirm">

**Where**: OpManager › Settings › Notifications

Name the profile `Flashduty` and click `Save`. Then let one of the selected devices raise a real alarm. A few seconds later the integration in Flashduty shows a **Latest event time**, which means the setup works.
{/* console:
The checklist item "Receive the first event" is then complete as well.
*/}

</Step>
</Steps>

## Status and severity

<div className="md-block">

| OpManager | Flashduty |
| ---------- | -------- |
| Critical | Critical |
| Service Down | Critical |
| Trouble | Warning |
| Attention | Info |
| Clear | Ok (alert recovers) |

Any other value is treated as Info.

</div>
