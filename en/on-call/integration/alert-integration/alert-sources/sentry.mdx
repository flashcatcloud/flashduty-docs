Sync Sentry alert events to Flashduty through webhook.

<div className="hide">

## In Flashduty On-call
You can get the integration push URL in either of the following ways.

### Use a dedicated integration

Choose this option if all alerts go to one channel. It's the simpler setup.

<AccordionGroup>
  <Accordion title="View dedicated integration setup steps">
  
  1. In the Flashduty console, select **Channel** and open a channel
  2. Select **Configuration** → **Integrations** → **Private integration**, then click **Add an integration**
  3. Select **Sentry** integration and click **Save** to generate a card
  4. Open the generated integration card and copy the **Push URL**
  
</Accordion>
</AccordionGroup>

### Use a shared integration

Choose this option if you need to route alerts to different channels based on the alert payload.

<AccordionGroup>
  <Accordion title="View shared integration setup steps">
  
  1. In the Flashduty console, go to **Integration Center → Alert Events**
  2. Select **Sentry** integration:
        - **Integration Name**: Define a name for this integration
  3. Configure the default route and select a channel. You can add more rules under **Routing** after creation
  4. Click **Save** and copy the generated **Push URL**
    
</Accordion>
</AccordionGroup>
</div>

## Configure in Sentry

Sentry provides two types of alert mechanisms: Issue Alerts and Metric Alerts. While Issue Alerts support notifications through WebHooks in Integrations, Metric Alerts are limited to using Internal Integration for alert notifications. Notably, Internal Integration works with both Metric Alerts and Issue Alerts. Given the versatility of Internal Integration, we've chosen to standardize on this approach rather than relying on WebHooks separately, thus simplifying alert notification configuration.

<Steps>
<Step title="Create an Internal Integration in Sentry">

**Where**: Sentry › Settings › Developer Settings › Custom Integrations › Create New Integration › Internal Integration

In older Sentry versions the entry is **Settings → Custom Integrations**.

| Field | Value |
| --- | --- |
| Name (required) | `Flashduty` |
| Webhook URL (required) | `{integration_url}` |
| Alert Rule Action (required) | Turn it on, configured as shown below |
| PERMISSIONS › Issue & Event (required) | `Read` |
| WEBHOOKS › issue (required) | Check it. **Do not check error and comment** |

<img alt="Alert Rule Action settings of the Internal Integration" width="600" src="https://fcpub-1301667576.cos.ap-nanjing.myqcloud.com/flashduty/doc/sentry-1.png" />

After configuration, click **Save Changes** to complete the setup.

<img alt="Webhooks settings of the Internal Integration" width="600" src="https://fcpub-1301667576.cos.ap-nanjing.myqcloud.com/flashduty/doc/sentry-2.png" />

**Special notes about WEBHOOKS configuration:**

1. After checking **issue**, Flashduty can receive resolved events for issues, meaning when manually triggering resolved for an issue in the issue list, we will automatically recover the associated incident in Flashduty.
2. Other issue events such as create, assigned, archived, and unresolved are not supported.
3. If error and comment are also checked, Flashduty will not receive or process these types of events.

</Step>
<Step title="Use Flashduty in a Sentry alert rule">

**Where**: Sentry › Alerts › Create Alert

1. Select the type of Alert to create, such as Issue.

   <img alt="Select the alert type" width="600" src="https://fcpub-1301667576.cos.ap-nanjing.myqcloud.com/flashduty/doc/sentry-3.png" />

2. Configure trigger conditions as needed.
3. Under **THEN perform these actions**, **Add action** and select **Send a notification via**.

   <img alt="Add the Send a notification via action" width="600" src="https://fcpub-1301667576.cos.ap-nanjing.myqcloud.com/flashduty/doc/sentry-4.png" />

4. Select the **Flashduty** integration added above as the notification channel.

   <img alt="Select the Flashduty notification channel" width="600" src="https://fcpub-1301667576.cos.ap-nanjing.myqcloud.com/flashduty/doc/sentry-5.png" />

5. Configure other options as needed and click **Save Rule**.

</Step>
<Step title="Trigger a real alert and verify">

Let the rule match a real issue or metric alert. A few seconds later, the integration in Flashduty shows a **Latest event time**, which means the setup works. Then mark that issue as resolved in Sentry's issue list and confirm the matching Flashduty alert recovers.
{/* console:
The "Receive first event" item in the setup checklist turns green as well.
*/}

</Step>
</Steps>

## Alert Key and recovery

Flashduty computes the Alert Key from the object Sentry pushes: `metric_alert.id` for a metric alert, `event.issue_id` for an issue alert, and `issue.id` for an issue-resolved event. A notification whose `action` is `resolved` recovers the matching alert; a notification whose `action` is not in the table above (for example created or assigned) is rejected.
