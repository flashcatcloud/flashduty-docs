Flashduty On-call receives alerts that external systems push or that Flashduty pulls through alert integrations. The generic methods that do not depend on a specific tool come first, followed by every alert integration sorted by name. You can also search for a tool name with Ctrl K.

## Before you start

Every integration can be connected as a **dedicated integration** (alerts go straight into one channel) or a **shared integration** (alerts are routed to channels by routing rules). See [Integrate Data](/en/on-call/channel/integrate-data) and [Routing Rules](/en/on-call/integration/alert-integration/routing-rules).

## Setup checklist

After you save an alert integration that has a push URL, a **Finish setup** checklist appears at the top of the **Receive** tab, with **N/5 done** on the right. It splits the path into five steps and uses whether a real event has arrived to show whether your upstream is connected. Until the first event arrives, the checklist takes the place of the integration settings on that tab. Email and pull-type integrations have no push URL and don't show this checklist.

| Step | When it counts as done |
| :--- | :--- |
| **Create the integration** | The integration is saved. This step is always done; when you open the integration from the integration center, it also lists the channel under **Goes to**, which you can change with **Edit routes** |
| **Add the push URL to your upstream tool** | Any event arrives |
| **Receive the first event** | Same as above |
| **Label enrichment** (optional) | At least one label enrichment rule is configured |
| **Alert pipeline** (optional) | At least one alert pipeline rule is configured |

Receiving an event means the push URL is already set correctly, so steps 2 and 3 complete together and the checklist starts at **1/5 done**. The checklist has three states:

- **Waiting for the first event**: while no event has arrived and the checklist is expanded, step 3 shows **Waiting… mm:ss so far.**, counted from when you opened the page. Alerts, recoveries and test notifications from upstream all count, including events dropped by the alert pipeline.
- **Configured, wait for a real alert**: after you select **Configured, wait for a real alert** in step 3, the checklist collapses to one **Waiting for the first event** line and the integration settings show again. Select **Show setup checklist** to open it again. The collapsed state is kept per integration in this browser, so the integration stays collapsed the next time you open it.
- **Connected**: once the first event arrives, the checklist collapses to one **Connected** line above the integration settings, followed by the **Latest event** time and how many optional steps are left (**All done** when both are configured). Select **Expand** to see all five steps, then **Hide checklist** to collapse it again.

Step 2 shows this integration's own push URL; copy it into your upstream tool. The [Standard Alert Event](/en/on-call/integration/alert-integration/alert-sources/standard-alert) and [Prometheus Alertmanager](/en/on-call/integration/alert-integration/alert-sources/prometheus) integrations also offer **Copy curl command** in step 3: the sample request already carries this integration's push URL, so running it on the upstream host checks both the push URL and the network without waiting for a real alert.

While you set the integration up, the right-hand column shows its setup docs. After the first event arrives, the column shows **First event** instead: the event's time, severity, title, description, and every label, and **View setup docs** switches back to the docs. The checklist refreshes on its own — every 5 seconds while it waits for the first event, and every 30 seconds afterwards to update the **Latest event** time — so you don't need to reload the page.
