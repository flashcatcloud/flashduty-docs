---
title: "Privacy protection"
description: "Protect sensitive data in Flashduty RUM session replay by configuring privacy levels for text, inputs, and page elements."
---

To meet privacy requirements for different scenarios, the session replay feature has built-in flexible privacy protection strategies. By configuring the `defaultPrivacyLevel` field, developers can control data collection sensitivity, supporting modes from displaying all text (except passwords) to completely hiding page text, ensuring user data security and compliance.

<Warning>
The following inputs are treated as sensitive and **are masked under every privacy setting**: inputs whose `type` is `password`, `email`, `tel`, or `hidden`, and inputs whose `autocomplete` is `cc-*` (payment card data) or `*-password`.
</Warning>

## Privacy policies

<Tabs>
  <Tab title="Mask All Text">
    Configure `defaultPrivacyLevel: "mask"` to completely hide all text content on the page, preserving only operation behavior and page structure. Suitable for scenarios with high data privacy requirements.

    ```javascript
    window.FC_RUM.init({
      applicationId: "YOUR_APPLICATION_ID",
      clientToken: "YOUR_CLIENT_TOKEN",
      // ...
      sessionReplaySampleRate: 10,
      defaultPrivacyLevel: "mask",
      // ...
    });
    ```

## Configuration comparison

| Configuration Value | Page Text | Input Content | Password Fields | Applicable Scenarios |
|--------|----------|------------|----------|----------|
| `mask` | Hidden | Hidden | Hidden | High privacy requirement scenarios |
| `mask-user-input` | Shown | Hidden | Hidden | Protect user input |
| `allow` | Shown | Shown | Hidden | Complete interaction details |

## Set the privacy level for a specific element

`defaultPrivacyLevel` applies to the whole page. To hide or mask only a specific area (such as an account balance, an ID number, or an order details panel), add the `data-dd-privacy` attribute or a `dd-privacy-<level>` class to that element. Both forms behave the same. The level applies to the element and all of its descendants.

| Attribute | Class | Replay result |
|----------|----------|----------|
| `data-dd-privacy="hidden"` | `dd-privacy-hidden` | The element is not recorded at all and appears as a placeholder of the same size |
| `data-dd-privacy="mask"` | `dd-privacy-mask` | The element structure is kept; text and input values are replaced with `x` |
| `data-dd-privacy="mask-user-input"` | `dd-privacy-mask-user-input` | Only input values are masked; other text is shown |
| `data-dd-privacy="allow"` | `dd-privacy-allow` | Text and input values are shown (except for always-masked fields) |

### Example: hide an element

```html
<!-- Option 1: attribute -->
<div class="account-balance" data-dd-privacy="hidden">
  Balance: $12,345.67
</div>

<!-- Option 2: class, for component libraries that don't accept custom HTML attributes -->
<div class="account-balance dd-privacy-hidden">
  Balance: $12,345.67
</div>
```

The same works in frameworks such as React:

```jsx
<section data-dd-privacy="hidden">
  <UserProfile />
</section>
```

### Example: reveal an area while the page is masked

The page uses `defaultPrivacyLevel: "mask"`, but non-sensitive areas such as the navigation bar should stay readable in replays:

```html
<nav data-dd-privacy="allow">
  <a href="/orders">My orders</a>
  <a href="/settings">Settings</a>
</nav>
```

### How the levels apply

- **Child elements inherit their parent's level.** A child can override it with its own `data-dd-privacy`, for example setting `allow` on an element inside a `mask` area.
- **`hidden` cannot be overridden.** Once a parent is set to `hidden`, setting `allow` on anything inside it has no effect.
- **Some inputs are always masked.** Inputs whose `type` is `password`, `email`, `tel`, or `hidden`, and inputs whose `autocomplete` is `cc-*` (payment card data) or `*-password`, are masked even when set to `allow`.
- Privacy rules are applied in the browser. Hidden or masked content is never uploaded and cannot be recovered later.
