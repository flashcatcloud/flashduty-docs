---
title: "Replay records"
description: "View and filter Flashduty RUM session replay records to reproduce user journeys and investigate performance or error issues."
---

Flashduty RUM's session replay feature helps developers quickly locate issues, analyze user behavior, and optimize product experience by intuitively recreating user operation paths. Integrated into the RUM SDK, it can be enabled with simple configuration, supporting flexible sampling strategies and privacy rule settings.

## Session list

In the "Session Replay" menu, you can view recent session records, sorted by time in descending order by default.

**Supported Features:**
- Sort by session duration, view count, action count, exception count, and other fields
- Rich filter conditions (such as time range, page, tags)

Click on any record to open the player panel:

| Area | Description |
|------|------|
| **Information Display Area** | Shows session visit time, start and end pages, tags, and other contextual information |
| **Playback Area** | Recreates operation path from user's perspective, clearly showing user interaction details |
| **Playback Control Area** | Provides playback control functions for easy operation |

For quick browsing, only replays with duration **greater than 3 seconds** are shown in the list.

## Player

The player supports play, pause, fast forward, rewind, replay, speed control, fullscreen, and seek functions, with keyboard shortcut support to improve efficiency.

If the replay data cannot be loaded, the player shows **Failed to load replay data** with a **Retry** button that fetches the session's replay data again.

<Frame>
  <img src="https://docs-cdn.flashcat.cloud/imges/png/c43b87b7764c5b0a136b0d721eb538cf.png" alt="Player Interface" />
</Frame>

During playback, the timeline marks user actions (Action) and exceptions (Error) with different colored icons, allowing quick overview of key events in the session.

Canvas chart content is not recorded: during replay those areas show the placeholder **Canvas content is not recorded**, while the rest of the page replays normally.

<Tip>
By default, the player automatically skips inactive segments to improve viewing efficiency. You can also disable this feature through configuration to play completely in actual time sequence.
</Tip>

## Devtools

Clicking a record in the session replay list opens the player in a sidebar on the right by default. The sidebar holds only the session header and the player, not the Devtools:

- Select **View Session Details** in the player header to open the detail page in a new tab.
- Or select the settings button at the top right of the list, switch **Detail Display** to **Page**, and clicking a record then goes straight to the detail page.

The Devtools on the right of the detail page has four tabs: Events, Error, Network, and Attributes.

<Tabs>
  <Tab title="Events Tab">
    Shows all user operations in the session, supporting the following features:

    - Toggle between relative time and absolute time display
    - Filter by event type (such as clicks, page navigation)
    - Click on a specific event, and the player will automatically jump to the corresponding timestamp

    With **Capture additional sessions on error** on, an **error-captured session** keeps only a small slice of detail before the error. Turn it on with **Capture additional sessions on error** on the **Remote configuration** tab of the application details; see [Remote configuration](/en/rum/quickstart/app-management#remote-configuration). The event counts above cover the whole session, so the list shows fewer events than those numbers.

    <Frame>
      <img src="https://docs-cdn.flashcat.cloud/imges/png/e903b09dd88de3837e9c88959181dba9.png" alt="Event Timeline" />
    </Frame>
  </Tab>
  <Tab title="Error Tab">
    Lists all exceptions and issues in the session, supporting click-through to detailed error information for quick identification and analysis.
  </Tab>
  <Tab title="Network Tab">
    Displays detailed information about all network requests during the session, helping you analyze resource loading and API call behavior.

    **Supported Features:**
    - Filter by resource type: XHR and Fetch requests are selected by default, but you can also view Image, JS, CSS, Font, Document, Media, and other static resource types
    - Toggle between relative time and absolute time display
    - Search request records by status code or URL. Status code search supports advanced syntax, for example `200` (match successful requests), `-200` (exclude 200), `>=400` (match error requests), and multi-condition combinations (such as `-200 -202`)
    - Click any request record to open the resource detail sidebar with complete timing information

    Each request record displays the following fields:

    | Field | Description |
    |-------|-------------|
    | Time | When the request occurred |
    | Status Code | HTTP response status code |
    | Type | Resource type (XHR, Fetch, Image) |
    | Method | HTTP request method (GET, POST) |
    | URL | Full request address |
    | Size | Response body size |
  </Tab>
  <Tab title="Attributes Tab">
    Shows session contextual information (such as device, browser, geographic location), helping developers gain deep understanding of the problem background for precise identification.
  </Tab>
</Tabs>

### Boundary row in an error-captured session

An error-captured session keeps only a small slice of detail before the error. In the viewer, open an event's details and switch to the **Session** tab. The full session timeline gains an extra row marked "⋯" where the stored detail begins. It states when the stored detail begins, or reads "error-captured session, only a small slice before the error was kept". The row usually sits between two events. When every event is on the collected side of the boundary, it sits at one end of the timeline: first when the timeline runs oldest to newest, last when it runs newest to oldest. When the session has nothing but view events (or no other events), the row has no time, reads "error-captured session, only a small slice before the error was kept", and leads the list. You can't click this row, and it doesn't appear when you drill into a single event; the Events tab of the replay page does not show it.
