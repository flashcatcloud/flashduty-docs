Use the RUM **Explorer** to search and analyze the RUM events your applications report. You can browse complete session paths, investigate slow pages, resources, or actions, and troubleshoot errors and long tasks. You can also aggregate events into charts (see [Analytics](./analytics)).

## Select an application

Use the application selector in the top navigation bar to pick an application; the Explorer then shows only that application's RUM data. Switch applications to switch data views.

## Search and filter

Enter query conditions in the search bar and choose a visualization type to search and filter RUM events. For query syntax, see the [Data Query Guide](./data-query).

## View event details

Click a data item to open its details and see the RUM event from several angles:

- View data relationships, drill down into data, or view parent node details
- View resource traces and correlate with existing monitoring system traces

For Electron sessions, the event list marks main-process events with a "Main Process" badge, and rows without it are renderer events. The event detail panel also adds a virtual `process` attribute (`main` / `renderer`) in the Other attribute group.

## Platform-aware view metrics

In a View's detail panel, the metric cards on the **Performance** tab adapt to the View's platform. You see only the metrics that platform reports.

| Platform | Performance Metric Cards |
|----------|--------------------------|
| **Browser (Web)** | `LCP`, `FCP`, `INP`, `CLS` |
| **Native (Android / iOS)** | `refresh_rate`, `cpu_ticks`, `memory` |
| **WeChat Mini Program** | `first_render`, `lcp`, `fcp`, `onload_to_onshow`, `onshow_to_onready` |
| **Electron** | Renderer views show Web metrics; main-process views have no page performance metrics and the panel shows an explanation instead |

<Note>
The platform is determined by the View event's own `source` field — no manual switching needed. For Mini Programs, `onload_to_onshow` and `onshow_to_onready` cover the two segments of the page lifecycle and help diagnose slow cold starts.
</Note>

The event table column picker can also add these Mini Program-only fields: `view_first_render`, `view_onload_to_onshow`, `view_onshow_to_onready`.

## Saved views

Save the current query state as a view to switch quickly between analysis scenarios. Each account can create up to **20** saved views, and views are only visible to you.

### What a view saves

| Saved Item | Description |
|------------|-------------|
| **Time Range** | The currently selected time filter |
| **Query Type** | The currently selected event type (for example, Sessions, Views, Actions, Errors) |
| **Query Statement** | The DQL filter conditions in the search bar |
| **Custom Columns** | The column configuration of the data table |

### View operations

| Action | How |
|------|------|
| **Create** | Click the view menu at the top of the Explorer, select "Save as New View", and enter a name (names must be unique) |
| **Switch** | Click the target view in the view menu; the Explorer restores its time range, query type, query statement, and columns |
| **Edit** | Select "Edit View" from the target view's action menu to rename it; after changing the current view's query conditions, use "Save Changes" to update the view |
| **Delete** | Select "Delete View" from the view list or action menu; deleting the active view switches back to the default view |
| **Share** | Select "Copy Link" from the action menu; team members who open the link see the same query view |
| **Reset** | Select "Switch to Default View" from the action menu to clear all filters |

## Event export

The event table in the Sessions Explorer provides a **CSV Export** button that exports the data under the current filter conditions and column configuration.

- **Export limit**: A single export caps at 5000 rows. If the filtered data exceeds the limit, a toast notification appears after export completes, indicating that the first N rows were exported and more data remains.
- **Column matching**: Exported columns match the current event type's column settings — names, order, and units follow the on-screen configuration. When field metadata is not yet loaded, the export uses raw field names and bare values.
- **Cancel export**: Clicking the button again during an export cancels it; any fetched data is not saved.
- **Scope**: All view types in the Sessions Explorer event table support export.
