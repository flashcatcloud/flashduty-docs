A heatmap answers, for a single page, where users click, which elements they keep clicking, and how far down they scroll. It has three views, sharing one page picker and viewport-width split.

## Pick a page and a viewport width

- **Page**: search by page name or path. Where the application named its views, the entry shows the name followed by the path, for example "Product detail /product/detail"; otherwise it shows the path alone. Each entry carries its view count for the time range.
- **Screen width**: **All widths**, **Wide > 1280**, or **Mobile < 768**. Desktop and mobile clicks usually land very differently on the same page, so compare them separately.

## Click map

The click map draws click positions over a session replay frame, in redder shades where clicks concentrate. It depends on replay data and is therefore available for **Web** and **Electron** applications only; the replay sampling rate is set in **Application settings**.

States you may see:

- **No session replay in the selected time range**: there is no replay frame to draw on for that range. Widen the range or raise the replay sampling rate. The element ranking on the left doesn't depend on replay and still works.
- **Too many clicks; only the most recent are drawn**: the map keeps only the most recent positions.
- **Backdrop from a replay at a given time; older clicks may be misplaced**: the backdrop is one replay frame, so clicks recorded before a redesign no longer line up with the current page.
- **Click positions collected since a given date**: earlier clicks have no position and count in the element ranking only.

## Element ranking

The element ranking doesn't depend on replay. It counts the clicked elements of the selected page, with columns for element, clicks, frustration-click rate and post-click error rate, sortable by **Clicks**, **Frustration rate** or **Post-click error rate**.

- Elements sharing the same text are merged; an element without text shows its position identifier.
- The header shows the total clicks in the selected range.
- Frustration clicks are rage clicks plus dead clicks. The post-click error rate counts only errors that can be tied to that click.
- An element with fewer than 100 clicks shows no rates and is labelled **Small sample**, with a note below the table.

## Scroll depth

Scroll depth splits the page height into 10 bands, each row showing the share of views that scrolled that far.

- Only views carrying scroll data are counted, and the coverage is stated; older SDKs don't report scroll depth.
- When the page's average height fits in one screen, scroll depth means nothing, and the page says so.

## Comparing dropped and converted sessions

Brought in from a funnel, the page can show the **Dropped** or **Converted** cohort only, and compare the two:

1. In [Funnels](/en/rum/behavior-analysis/funnel), select **Compare clicks on heatmap** in a step's drop-off analysis, or pick the funnel and step range on this page.
2. Switch the cohort to **Dropped** or **Converted**; the header shows how many of that cohort visited this page.
3. The element click comparison table lists each group's click share and the **Difference**. The share is the portion of the cohort that visited this page and clicked the element; the difference is dropped minus converted, in percentage points, so a positive value means the dropped cohort clicks it more.
4. When the two groups don't differ noticeably, the page suggests the drop-off cause lies elsewhere and points back at the factors and exits in the drop-off analysis.

If either group is too small to compare, the table lists only the other group, and a small group's shares are marked indicative. **AI analyse the difference** hands the two groups' clicks to AI SRE.

## Unsupported cases

Applications that aren't Web or Electron have no click map and no scroll depth; opening the page says **This application type does not support the click map**, and the element ranking on the left works as usual.
