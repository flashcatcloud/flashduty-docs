### License 模式详解

与 PagerDuty 等产品对**所有用户**收费不同，Flashduty 采用 **License（活跃用户）** 计费模式——只有需要**查看和处理故障**的成员才需要 License，其他成员无需付费也能接收告警通知。

#### 谁需要 License？

| 角色 | 是否需要 License | 说明 |
| --- | :---: | --- |
| 值班工程师 | ✅ | 需要查看故障详情、认领和处理故障 |
| 团队 Leader | ✅ | 需要查看故障、配置分派策略和值班表 |
| 被通知的开发 / 运维 | ❌ | 只需被动接收通知，无需登录平台操作 |
| 管理层 | ❌ | 通过分析看板或状态页了解全局状态即可 |
| 外部协作方 | ❌ | 通过 Webhook、邮件或状态页获取信息 |

<Tip>
**大团队成本优势**：在实际场景中，100 人的技术团队通常只有 10~20 人需要日常参与故障处理，其余成员只需接收通知。这意味着您可能只需购买 10~20 个 License，而不是为全部 100 人付费——**成本可降低 80%~90%**。
</Tip>

#### 为什么选择 License 模式？

传统的按人头收费（如 PagerDuty）要求所有需要接收通知的用户都购买席位，这在实践中造成了两个问题：

1. **成本浪费**：大部分团队成员只需要在故障发生时收到通知，不需要登录平台查看或处理故障，但仍需为每人支付全额席位费
2. **通知覆盖不足**：为控制成本，企业往往限制通知范围，导致关键信息无法触达相关人员

Flashduty 的 License 模式将**故障处理能力**和**通知接收能力**解耦：

- **持有 License 的成员**：拥有完整的故障查看、处理、配置等权限
- **无 License 的成员**：可以被动接收所有告警通知（邮件、短信、电话、IM），共享租户通知额度，确保信息触达不受限制

这样既保证了通知的全面覆盖，又显著降低了总拥有成本。

## 付款与充值

---

费用中心仅对 SaaS 版本开放，私有化部署不提供该入口。在左侧菜单进入 **费用中心**，页面标题为 **账单**，下设 **充值** 与 **收支明细** 两个页签；菜单中还可以进入 **订阅** 和 **消费概览**。

### 可用余额的构成

**可用余额 = 现金余额 + 赠送金余额 − 冻结金额**。冻结金额包含未完成订单占用的资金，没有实际消耗，订单解冻后可正常使用。

### 充值渠道

**充值** 页签提供三种渠道：

| 渠道 | 说明 | 币种 |
| --- | --- | --- |
| **在线充值** | 支付宝或 Stripe，实时到账 | CNY、USD |
| **对公转账** | 企业网银汇款，约 1 个工作日到账 | CNY |
| **云市场** | 用已有的云预算下单，走已有的采购流程 | CNY 充值、USD 订阅 |

**在线充值** 中可选 **支付宝**（人民币结算，可任选金额）或 **Stripe**（国际信用卡、借记卡等）。

- **支付宝**：预设面额 ¥100 / ¥300 / ¥500 / ¥1,000 / ¥3,000 / ¥5,000，也可自定义金额，范围 0.01–100,000 元，最多两位小数。
- **Stripe**：以美元结算，可选面额由服务端下发（默认 $50 / $100 / $200 / $500 / $1,000），自定义金额范围 0.5–10,000 美元，最多两位小数。充值金额按**固定汇率**折算为人民币余额入账（默认 1 USD = 7 CNY，由部署配置决定），每个美元面额下方会直接显示精确折算后的人民币金额，不是估算值。
- Stripe 渠道需要在服务端配置支付密钥才会出现；未配置时账户只见支付宝。
- **默认选中的渠道跟随界面语言**：中文界面默认支付宝，非中文界面默认 Stripe。两者都可在提交前手动切换。

### 绑定银行卡与自动扣款

通过 Stripe 支付一次即会自动保存该卡，此后**到期续费余额不足时系统会自动从该卡扣款**，随时可在 **可用余额** 中删除。关于自动扣款：

- **没有独立的开关**：只要账户上保存了有效的卡，且未触发停止条件，续费余额不足时就会自动扣款
- **扣款金额**：等于本次续费询价的差额（应付费用减去当前余额，含用量导致的负余额），向上取整为整美元
- **频率上限**：每个账户每 24 小时最多自动扣款一次
- **停止条件**：连续扣款失败达到 3 次即停止自动扣款，页面会提示「已连续失败 N 次，已停止自动扣款」。用 Stripe 重新充值一次即可更换银行卡
- **删除卡片**：在 **可用余额 → 自动化 → 自动扣款** 中点击 **删除卡片**，删除后续费不再自动扣款，需重新用 Stripe 充值绑定。该操作需要 **费用管理** 权限
- 中文界面在尚未绑定卡片时不展示「自动扣款」这一行，英文界面始终展示并提供绑定入口

### 余额不足提醒

在 **可用余额 → 自动化 → 余额不足提醒** 中开启并设置阈值，可用余额低于该金额时通过 **短信 + 邮件** 通知。阈值必须不小于 1 元；关闭提醒会同时清除已设置的阈值。该设置需要 **费用管理** 权限。

### 云市场下单

云市场支持 **阿里云市场**、**华为云市场**、**蓝云市场** 与 **AWS Marketplace**，按三步完成：

<Steps>
  <Step title="获取账户 ID">
    在充值页复制你的 **账户 ID**。
  </Step>
  <Step title="去云市场下单">
    **下单时必须把账户 ID 填进订单备注**，这是平台把这笔订单认回你账户的唯一依据，漏填会导致额度无法入账。
  </Step>
  <Step title="等待生效">
    订单通常在 1 个工作日内生效，额度到账后会出现在 **收支明细** 里。
  </Step>
</Steps>

<Note>
通过 AWS Marketplace 购买的是 On-call 席位授权，**不增加账户余额**；下单后会自动完成绑定，无需填写账户 ID，且绑定后订阅不能升配也不能降配，请按所需席位数一次买对。
</Note>

### 对公转账

选择 **对公转账** 后，页面展示收款账户名称、开户银行与银行账号。汇款时**必须把账户 ID 填在备注里**，否则款项无法认回你的账户。汇款通常在 1 个工作日内入账。

### 收支明细与发票

**收支明细** 页签逐条列出 **时间**、**类型**、**描述**、**交易金额**、**发票** 与 **余额**，其中余额区分 **现金** 与 **赠送金**。收入包含 **充值**，支出包含 **下单**、**消耗**、**退货** 与 **提现**。

- 系统自动从银行卡扣款的流水，描述会标注为自动充值（Auto top-up），与你手动发起的 Stripe 充值区分开
- **发票** 列仅对已开具的 Stripe 充值订单显示直链；支付宝、对公转账与云市场等渠道需提交开票申请单，默认开具电子专票
- 需要加急或开票时，可通过 **可用余额** 下方的 **申请开票** 入口提交

## 常见问题

---

<AccordionGroup>
  <Accordion title="On-call 如何计算活跃用户？">
    当月使用商业化功能（查看或处理故障）的用户即为活跃用户。**仅接收告警通知不算作活跃用户**。每个月度周期结束后：
    - 固定 License 保持有效
    - 临时 License 自动释放
    - 成员被删除时，其 License 自动释放
  </Accordion>

  <Accordion title="我的团队需要购买多少个 License？">
    只有需要**登录平台查看故障详情、认领和处理故障**的成员才需要 License。仅需接收告警通知的成员无需 License。

    **估算方法**：统计您团队中参与日常值班和故障响应的核心人员数量，通常为：
    - 一线值班工程师
    - 参与故障处理的团队 Leader
    - 需要在平台上配置分派策略、值班表的管理员

    **实际案例**：以 100 人技术团队为例，通常只有 10~20 人需要日常登录平台处理故障，其余 80~90 人只需在相关故障发生时收到通知。因此只需购买 10~20 个 License，**相比全员付费可节省 80%~90% 的费用**。
  </Accordion>

  <Accordion title="没有 License 的成员能做什么？">
    - **可以**：被动接收告警消息（邮件、短信、电话、IM），被分派策略引用为通知对象，共享租户通知额度
    - **不可以**：查看/处理故障，进行任何平台配置操作

    在分派策略中可以选择将故障通知给没有 License 的成员，但该成员无法对故障进行操作。这意味着您可以将整个团队纳入通知范围，而无需为每个人购买 License。
  </Accordion>

  <Accordion title="RUM 会话如何计算？">
    - **会话分析**：每次用户访问应用的完整会话，包含页面浏览、资源加载、异常等数据
    - **会话重放**：记录用户操作行为的会话，用于回放用户交互过程
    
    两者独立计费，按实际产生的会话数量统计。
  </Accordion>

  <Accordion title="是否支持私有化部署？">
    支持。Flashduty 提供**私有化部署版**（On-Premises），功能与专业版一致，并额外支持：
    - 数据本地存储
    - 内部系统集成
    - 无公网依赖

    <Warning>
    私有化部署有较高的维护成本，收费模式与 SaaS 不同。如无特殊需求，推荐使用云服务。
    </Warning>

    如需私有化版本，请联系我们获取报价。
  </Accordion>

  <Accordion title="是否支持试用？">
    支持。On-call 专业版提供免费试用，试用期间可体验全部专业版功能。如需申请试用，请联系销售团队。
  </Accordion>
</AccordionGroup>
