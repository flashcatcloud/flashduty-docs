查询工作台（Explore）是 Flashduty Monitors 中的即席查询界面，用于在不创建告警规则的前提下对数据源执行临时查询。支持 Prometheus、Loki、VictoriaLogs、阿里云 SLS、腾讯云 CLS 以及 MySQL、PostgreSQL、Oracle、ClickHouse、Elasticsearch 等数据源。

## 访问入口

- **从数据源列表**：进入 **监控 → 数据源**，点击目标数据源行的「查询工作台」入口。
- **直接 URL**：访问 `/monit/explore`，在页面内选择数据源。
- **从故障/告警标签**：在故障详情或告警详情的标签区域，查询类标签行右侧的「去查询」图标会带着告警触发时的查询和时间窗口直接打开工作台。

## 查询类型

不同数据源支持不同的查询类型，在编辑器上方切换：

| 数据源 | 查询类型 | 说明 |
|--------|---------|------|
| Prometheus | 图表 + 原始 | 同时展示折线图和原始样本 |
| Prometheus | 仅图表 | 只展示折线图（range 查询） |
| Prometheus | 仅原始 | 只展示原始样本（instant 查询） |
| Loki | Range | 区间查询，返回时间范围内的日志行 |
| Loki | Instant | 即时查询，返回当前时刻匹配的日志行 |
| VictoriaLogs | 原始日志 | 返回原始日志行 |
| VictoriaLogs | 即时统计 | 返回即时聚合统计 |
| VictoriaLogs | 趋势统计 | 返回区间趋势统计 |
| SLS / CLS | — | 无查询类型选择器，由供应商分类日志/表格 |
| MySQL / PostgreSQL / Oracle / ClickHouse / ES | — | SQL/查询表达式直接执行 |

> 查询在路由到 Edge 执行前会先经过语法校验：Prometheus 数据源的查询表达式必须通过 PromQL/MetricsQL 语法检查，非法表达式会被提前拒绝并返回解析器错误详情，不会下发执行；其他数据源类型不受此校验影响。

## 结果展示

结果区域根据数据源和查询类型自动布局：

- **Prometheus**：上下分屏，上方折线图（Graph）、下方原始样本（Raw），支持拖拽分隔。
- **其他数据源**：单结果区，根据查询类型展示日志视图、表格视图或样本视图。

### 图表功能

- **拖拽缩放**：在折线图上拖选时间段可缩放至该范围。
- **曲线图例筛选**：图例区支持按标签值搜索和按 metric 名称分组；超过展示上限的曲线会折叠，点击展开。
- **Tooltip**：悬停查看各曲线在该时间点的值，超出展示上限的曲线会在 Tooltip 中汇总提示。

### 日志时间分布

当查询类型包含日志时，结果区上方会展示日志时间分布图：

- 时间范围 ≤ 24 小时：自动加载。
- 24 小时 – 30 天：需手动点击加载。
- 超过 30 天：不支持加载。

### 日志视图

日志类查询的结果以行为单位展示，每行包含时间、正文及字段摘要。若本批结果中存在每行取值都相同的字段（公共字段，如 Loki 的 stream labels），这些字段默认会逐行展示在摘要中，但会重复占据每行的宽度。

- 工具条上的 **公共字段** 按钮会列出本批结果中每行相同的字段及其取值；勾选浮层中的 **行内隐藏** 后，这些公共字段将从行内摘要中折叠，行内只保留有差异的内容（并显示「+N 个字段」提示）
- **行内隐藏** 默认关闭（公共字段默认展示）；该开关为会话内状态，不持久化，刷新页面后恢复默认展示
- 点击行可展开详情，详情始终展示该行的全部字段，不受 **行内隐藏** 开关影响

## 查询参数

除查询表达式外，部分数据源支持私有参数：

| 参数 | 适用数据源 | 说明 |
|------|-----------|------|
| 返回条数（limit） | Loki / VictoriaLogs | 限制返回行数 |
| 最小 step（秒） | Prometheus | 自动 step 的下限 |
| 检索方向 | Loki / VictoriaLogs | 最新优先或最早优先 |
| 项目 / 日志库 | SLS | 必填，拼入请求地址 |
| 地域 / 日志主题 / 语法 | 腾讯云 CLS | 必填 |
| PowerSQL | SLS | 开启 PowerSQL 模式 |
| 时间宏 | SQL 数据源 | `$__timeFilter(列名)`、`$__timeFrom()`、`$__timeTo()` 让时间范围生效 |

## AI 生成查询

查询语句输入框的右上角有一颗 AI 按钮，鼠标悬停或聚焦输入框时显示。点开后在对话面板里用自然语言描述你要查什么，助手会给出**一条**可直接使用的语句，并说明这条语句的含义、以及仍需你自己决定的部分。

助手在回答前先读当前编辑器：所在场景、数据源类型、数据源私有参数、你正在写的那条语句草稿，以及工作台当前的时间范围——对话过程中你改了数据源或查询类型，它读到的也会跟着变。它还可以先探测真实数据（列出可用的指标名、试跑一次查询看返回的标签）再落笔，并对最终给出的语句做一次语法校验；校验不通过的语句不会交付。

回填时整条查询一起落位：**语句、数据源私有参数、查询类型，必要时还包括数据源**——如果生成的语句是给另一个数据源写的，回填会先切到那个数据源再写入，你也可以选择回填后直接执行。

同一颗按钮出现在各个 QL 编辑器的语句输入框上，助手按场景理解你的意图：

| 场景 | 入口 |
|------|------|
| 查询工作台（`scene=explore`） | 本页的查询语句输入框 |
| 告警规则查询（`scene=rule_query`） | 告警规则的查询语句输入框（含查询预览弹窗） |
| 恢复条件（`scene=rule_recover`） | 恢复条件语句输入框 |
| 关联查询（`scene=rule_relate`） | 关联查询语句输入框 |
| 实体类别配置（`scene=entity_def`） | 实体类别的发现 PromQL 输入框 |
| 实体告警规则（`scene=entity_rule`） | 实体告警规则的告警条件 PromQL 输入框 |

该能力由 AI 后端应用 `query-assistant` 提供；它创建的会话默认为 incognito，不会出现在会话历史列表中。

## 用数据源工具以编程方式查询

工作台的查询能力同时也是数据源工具入口上的查询工具：`POST /monit/datasource/tools/invoke` 的 `tool` 取 `<type>.query`，`type` 与工作台支持的数据源类型一致（`prometheus`、`mysql`、`postgres`、`oracle`、`clickhouse`、`elasticsearch`、`loki`、`victorialogs`、`sls`、`tencent_cls`）。查询走的是工作台同一条执行路径，所以语法校验、结果结构和 Edge 版本要求都与工作台一致；工具的 `type` 前缀必须与所选数据源的类型相同，不一致返回 `invalid_request`。

参数为 `expr` 加 `execution`：

| 字段 | 类型 | 说明 |
|------|------|------|
| `expr` | string | 查询语句，语法与工作台一致 |
| `execution` | object | 必填，说明这次查询怎么跑 |

`execution` 的字段与模式约束：

| 字段 | 类型 | 说明 |
|------|------|------|
| `kind` | string | `instant`（即时，只接受 `to_ms`）、`range`（区间，需 `from_ms`、`to_ms`、`max_data_points`，可选 `min_step_seconds`）、`window`（窗口，需 `from_ms`、`to_ms`） |
| `from_ms` / `to_ms` | number | 毫秒时间戳 |
| `max_data_points` | number | 区间查询的数据点上限，2–5000，`range` 模式必填 |
| `min_step_seconds` | number | 自动 step 的下限（秒），`range` 模式可选 |

区间查询下发给 Edge 的 `step_seconds` 由服务端按 `from_ms`、`to_ms`、`max_data_points`（以及可选的 `min_step_seconds`）推导，不需要也不应自己传。

各数据源类型的 `kind` 与额外字段：

| 数据源类型 | 可用 `kind` | 额外要求 |
|-----------|------------|----------|
| `prometheus`、`loki` | `instant` 或 `range` | Prometheus 的 `instant` 只接受 `to_ms` |
| `victorialogs` | 三种都可用，字段必须齐全 | 必须带 `from_ms`；`limit`、`direction` 只在 `window` 模式下有效。工作台的映射：原始日志用 `window`、即时统计用 `instant`、趋势统计用 `range` |
| `mysql`、`postgres`、`oracle`、`clickhouse`、`elasticsearch`、`sls`、`tencent_cls` | 仅 `window` | SLS 必填 `project`、`logstore`，可选 `powersql`；腾讯云 CLS 必填 `region`、`topic_id`、`syntax`（`cql` 或 `lucene`） |

日志类数据源还可以带 `limit` 与 `direction`，语义同工作台的 返回条数 / 检索方向（`direction` 取 `latest` 或 `earliest`；`limit` 对 SLS 上限 100，其余日志类上限 1000）。参数中未列出的字段会被忽略，已知字段显式传 `null` 会被拒绝。结果外层为 `datasource_id`、`tool`、`data`，其中 `data` 与工作台返回的 `explore_result.v1` 结构相同（`samples`、`frames` 或 `logs`）。与工作台一样，该入口要求数据源 `enabled=true`。

完整参数清单、错误码与请求示例见 [数据源工具调用](/zh/api-reference/monitors/data-sources/monit-datasource-tools-invoke)；命令行对应 `flashduty monit-query <datasource-id> --tool '<type>.query'`，用法见 [CLI](/zh/developer/cli)。

## 查询历史

每次成功执行的查询会自动存入查询历史，仅保存查询表达式，不含时间范围和结果。历史按数据源隔离，存储在浏览器本地，最多保留 200 条。超出 200 条时最早的记录会被淘汰；查询表达式过大时不会存入历史但查询本身已成功执行。可以在历史面板中删除单条或清空当前数据源的全部历史。

## 分享与 URL 状态

工作台会将当前数据源、查询表达式、时间范围和查询类型编码到 URL 参数中。复制浏览器地址栏即可分享当前查询状态，打开链接后会自动恢复。若链接中的数据源不存在、已停用或无权限，页面会提示且不自动执行。

## Edge 版本要求

查询工作台依赖 monit-edge 执行实际查询。若数据源所在集群的 Edge 版本过低或版本不一致（混合版本），页面会显示升级提示并禁用查询。需要将集群内所有 Edge 升级至要求版本后才能使用。
