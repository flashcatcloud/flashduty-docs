Monitors 支持在告警规则列表中批量导出规则为 YAML 文件，也支持从多种来源的规则文件导入告警规则，方便您在环境之间迁移规则，或从 Prometheus、Nightingale 迁移到 Flashduty。

## 导出告警规则

**操作入口**：在告警规则列表中勾选需要导出的规则，点击底部批量操作栏中的「导出」按钮。

系统会将所选规则打包为一个规则文件（Flashduty Rules YAML 格式，默认文件名 `alert-rules.yaml`），并在导出抽屉中展示文件内容。您可以：

- **下载**：将规则文件保存到本地
- **复制**：将文件内容复制到剪贴板

<Note>
导出接口一次导出所选的全部规则，导出结果中包含规则数量。文件内容为 YAML，可直接用于后续导入。
</Note>

## 导入告警规则

**操作入口**：在告警规则列表页面右上角点击「导入」按钮（需要告警规则创建权限）。导入的规则会创建到当前选中的文件夹下。

### 支持的文件格式

上传一个 `.yaml`、`.yml` 或 `.json` 文件（大小不超过 1 MB），系统会自动识别来源格式：

| 来源类型 | 说明 |
|---------|------|
| **Flashduty Rules YAML** | 通过「导出」功能生成的规则文件 |
| **Flashduty 规则 JSON** | 旧版 Flashduty 规则 JSON 导出文件 |
| **Prometheus Rules YAML** | Prometheus 原生告警规则文件 |
| **Nightingale 规则 JSON** | Nightingale v6-v9 告警规则 JSON 文件 |

### 导入流程

导入采用「先预检、后提交」的两步流程：

1. **上传文件并预检**：选择文件后，系统会自动执行预检并展示「预检结果」，列出文件中每条规则的状态与说明，同时显示识别出的来源类型，以及可导入 / 跳过 / 无效的规则数量统计。
2. **确认导入项并提交**：在预检结果表格中勾选需要导入的规则（默认勾选全部「可导入」的规则），配置导入选项后点击「导入」完成提交。提交前系统会再次校验所选规则的实时状态；提交完成后会展示导入结果：成功、跳过、无效的规则数量。

预检结果中每条规则的状态含义如下：

| 状态 | 说明 |
|------|------|
| **可导入**（Ready） | 规则校验通过，可以导入 |
| **跳过**（Skipped） | 规则被跳过，例如与现有规则同名且冲突策略为「跳过同名规则」，具体原因见「说明」列 |
| **无效**（Invalid） | 规则存在错误，无法导入，具体原因见「说明」列 |

「说明」列会展示该条规则的具体提示信息。提示分为两级：**警告**（warning）表示规则可以导入但存在有损转换或需注意的行为；**错误**（error）表示规则无法导入。

### 导入选项

| 选项 | 说明 |
|------|------|
| **同名规则处理方式** | 目标文件夹中已存在同名规则时的处理方式：<br/>- **跳过同名规则**（默认）：同名规则不导入，预检中标记为「跳过」<br/>- **创建副本**：以副本形式导入同名规则 |
| **导入后启用规则** | 仅当来源类型为 Flashduty Rules YAML 时可配置。默认关闭，导入的规则保持停用；其他来源类型的规则启用状态由系统决定 |
| **事件推送给 Flashduty 的协作空间** | 选择导入规则告警事件推送的目标协作空间（channel），默认为空 |

<Tip>
导入完成后，列表会自动刷新。如果一条规则都没有被导入，导入弹窗会保持打开并展示跳过 / 无效原因，方便您调整选项后重试。
</Tip>

## Nightingale 规则导入说明

Nightingale 与 Flashduty 告警规则的能力模型存在差异，导入 Nightingale 规则 JSON 时系统会自动进行格式转换，部分配置无法完整保留。请注意以下默认行为与有损转换：

- **导入后统一保持停用**：所有 Nightingale 规则导入后均为停用状态，请检查数据源匹配和转换警告后再手动启用。

导入过程中可能出现的转换警告包括：

| 警告 | 说明 |
|------|------|
| Doris 数据源映射 | Doris 已映射为 MySQL，并将匹配全部 MySQL 类数据源 |
| 多级别条件裁剪 | 仅保留最高级别告警条件，其余条件已丢弃 |
| 级别抑制未保留 | Nightingale 的级别抑制配置未保留 |
| 查询关联未保留 | Nightingale 的查询关联配置未保留 |
| 恢复语义近似转换 | Nightingale 的恢复语义已按 AlertRule 能力近似转换 |
| 恢复通知未保留 | 是否发送恢复通知未保留，将使用 AlertRule 生命周期行为 |
| 通知配置未保留 | Nightingale 的通知目标、回调和通知流水线未保留 |
| 扩展配置未保留 | Nightingale 的扩展、事件重标记或任务模板配置未保留 |
| 时区转换 | Local 时区已转换为 Asia/Shanghai |
| 评估间隔默认值 | 缺少评估间隔时，持续时间按 15 秒间隔换算 |
| 生效时间规范化 | 全天生效时间已转换为 00:00-23:59 |
| 重复通知近似 | 无限重复通知已按 AlertRule 最大重复次数近似处理 |

<Warning>
Nightingale 规则导入涉及上述有损转换，请逐条检查预检结果中的警告信息，确认转换结果符合预期后再提交导入，并在导入后手动验证规则行为。
</Warning>
