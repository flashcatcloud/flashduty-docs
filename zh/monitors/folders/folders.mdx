Monitors 使用树形分组结构来组织和管理告警规则。文档的菜单和页面标题称这一层级为「文件夹管理」，控制台的按钮、对话框和提示则一律称「分组」。每条告警规则都必须归属于某个分组，您可以通过层级结构进行分类管理，并为不同层级配置团队访问权限。

**菜单入口**：告警规则（左侧分组树）

## 分组树

页面左侧展示分组树形结构。您可以：

- **选择分组**：点击分组查看其详情和所属的告警规则
- **层级嵌套**：支持多级嵌套，满足复杂的组织结构需求

分组下有规则需要注意时，树节点前的分组图标会换成一个红色警告图标。触发条件是分组内至少有一条规则仍在产生活跃告警，或运行状态为 **执行异常**、**状态已过期**、**Edge 离线**、**未匹配数据源** 之一。这个标记会向上继承：子分组有问题，它的所有上级分组也会显示图标，所以从折叠起来的顶层分组就能看出哪一支需要展开排查。运行正常、等待运行状态、非生效时间、配置待生效和已停用的规则不会触发标记，标记也只统计您有查询权限的分组和规则。

树顶的 **我的 / 全部** 切换决定显示哪些分组：

| 范围 | 显示内容 |
|------|---------|
| **我的**（默认） | 您所在团队的分组、您创建的分组，以及它们的子分组 |
| **全部** | 账户下的全部分组。不可编辑的分组显示锁图标，只能查看 |

您的选择会被记住。从链接打开其他团队的分组或规则时，页面临时切到 **全部**，本次访问结束后恢复您原来的选择。

## 分组操作

| 操作 | 入口 |
|------|------|
| **新建顶层分组** | 点击树顶搜索框右侧的 **+**，新分组直接创建在根节点下 |
| **新建子分组** | 打开分组右侧的 `⋮` 菜单，选择 **新增子分组** |
| **新建同级分组** | 打开分组右侧的 `⋮` 菜单，选择 **新增同级分组** |
| **编辑名称、备注与关联团队** | 打开分组右侧的 `⋮` 菜单选择 **编辑分组**，或选中分组后点击详情头部的编辑图标 |
| **删除分组** | 打开分组右侧的 `⋮` 菜单选择 **删除分组**，或选中分组后点击详情头部的删除图标，二次确认后删除 |
| **调整层级** | 把分组拖到另一个分组上成为它的子分组，或拖到两个分组之间的间隙成为同级分组。只读分组不能作为拖动目标，自身也不能拖动 |

新建和编辑分组时填写 **分组名称**（必填）、**备注** 和 **关联团队**。关联团队会层级继承：当前分组的关联团队对其所有子孙分组同样有权限。

## 分组详情

选中分组后，右侧展示该分组的详细信息：

| 属性 | 说明 |
|------|------|
| **名称** | 分组名称，有权限的用户可点击编辑图标修改 |
| **创建人** | 创建该分组的用户 |
| **更新人** | 最后修改该分组的用户 |
| **更新时间** | 最后修改时间 |
| **备注** | 分组的补充说明，有权限的用户可点击编辑图标修改 |

## 移动规则到其他分组

您可以把告警规则移到别的分组。规则本身不变，只是换了归属。

- **单条规则**：点击行尾 `⋮` 菜单里的 **移动**。
- **多条规则**：勾选规则后，点击列表上方的 **移动**。
- **在规则编辑页**：打开规则后，区块 1 的 **所属分组** 是一个下拉框，选中目标分组并保存即完成移动。

两种入口都打开 **移动到其他分组** 对话框：

| 操作 | 说明 |
|------|------|
| **搜索分组** | 输入关键词按名称过滤分组树，命中结果保留完整层级路径 |
| 选择分组 | 在树里点击目标分组 |
| **确定** | 选中的就是规则当前所在的分组时，按钮保持禁用 |

分组树加载失败时会显示 `加载分组失败` 和 **重试**。移动成功后提示 `移动成功`，列表自动刷新；失败时提示 `移动失败`，规则仍留在原分组。

## 团队访问控制

分组支持基于团队的访问控制，通过为分组绑定团队来限制操作权限。

### 各分组管理团队

分组详情下方的 **各分组管理团队** 表格展示从当前分组到根节点的完整路径，以及每个层级绑定的团队。

| 列信息 | 说明 |
|--------|------|
| **分组** | 从根节点到当前分组的完整路径 |
| **管理团队** | 该层级绑定的团队，有权限的用户可点击编辑图标修改 |

### 权限判定规则

查看和编辑分开判定。账户内的所有成员都能查看全部分组及其中的规则；能否编辑（新建、改名、删除、移动、克隆，以及修改分组里的规则和仪表盘）按以下规则判定：

1. **主体账号**与 **Admin** 可以编辑所有分组
2. 分组或其任何父级分组的创建者可以编辑
3. 分组或其任何父级分组绑定了团队时，该团队的成员可以编辑

不满足以上规则的分组只读；链路上没有绑定任何团队的分组，只有主体账号、Admin 和创建者可以编辑。

没有编辑权限的分组在树上显示锁图标，鼠标停留提示「只读：不在该分组授权的团队中」。这类分组仍可打开并查看其中的规则和仪表盘，但新建、编辑、删除、移动、克隆入口置灰，也不能作为移动或克隆的目标分组。

<Tip>
建议为顶层分组绑定团队，子分组会自然继承访问范围。这样可以实现按部门或按项目划分告警规则的管理权限。
</Tip>
