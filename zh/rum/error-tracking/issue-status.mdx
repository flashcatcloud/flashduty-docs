在异常追踪中，所有 Issue 都有一个状态，帮助您对问题进行分类和优先级排序。

## 状态类型

| 状态 | 说明 |
|------|------|
| **待处理** | 需要关注的新问题或复现的问题 |
| **处理中** | 已分类且需要修复的问题，可立即或稍后处理 |
| **已忽略** | 不需要进一步调查或处理的问题 |
| **已解决** | 已修复且不再发生的问题；按复现后的处理方式分为**已解决**与**在下一版本中解决**两种（见[解决方式](#解决方式)） |

<Info>
所有新发现的 Issue 初始状态为**待处理**。Flashduty 会根据特定条件自动更新状态，您也可以手动调整。
</Info>

## 自动解决 Issue

Flashduty 会自动将不活跃或已解决的 Issue 标记为**已解决**：

<AccordionGroup>
  <Accordion title="基于版本自动解决">
    如果 Issue 最后一次报告的版本已超过 14 天，且新版本中未再次出现该错误，系统会自动将其解决。
  </Accordion>
  <Accordion title="基于时间自动解决">
    如果未设置 `version` 标签，当 Issue 在过去 14 天内没有新错误报告时，系统会自动将其解决。
  </Accordion>
</AccordionGroup>

<Tip>
正确配置应用程序的 `version` 标签对于准确识别已解决的 Issue 至关重要。
</Tip>

## 自动重新打开 Issue

Flashduty 具备 Issue 检测功能，当已解决的 Issue 再次出现、且满足该 Issue **解决方式**设定的条件时，系统会自动重新打开并标记为**待处理**状态，并添加**问题复现**标签。

### 什么是问题复现？

复现指的是先前已修复的问题再次出现，常见场景是代码更新后意外回归。Flashduty 的回归检测可自动识别这些情况，将相关 Issue 重新打开，而不是创建重复的 Issue，从而保留问题的完整上下文和历史记录。

### 复现检测机制

错误被聚合进**已解决**的 Issue 时，是否判定为复现取决于该 Issue 的**解决方式**（见下文[解决方式](#解决方式)）：

<Warning>
- 解决方式为**在下一版本中解决**（默认）：只有该 Issue 之前未出现过的新版本中再次出现才触发检测
- 解决方式为**已解决**：任何再次出现都触发检测，同一版本内的重复出现同样算复现
- 错误未携带 `version` 标签时，两种解决方式都会触发检测
- 错误的发生时间早于该 Issue 的解决时间时不会触发（重复上报，或 SDK 离线缓存后补传的旧错误）
</Warning>

一旦检测到问题复现，Flashduty 会：

<Steps>
  <Step title="变更状态">
    自动将 Issue 状态变更为**待处理**
  </Step>
  <Step title="添加标签">
    为 Issue 添加**问题复现**标签，便于快速识别
  </Step>
</Steps>

### 关联版本配置

复现检测会考虑错误发生的服务版本信息：解决方式为**在下一版本中解决**（默认）时，只有在 Issue 标记为**已解决**之后的、之前未出现过的新版本中才会触发检测；解决方式为**已解决**时不比较版本，同一版本中再次出现也会触发。

```javascript
window.FC_RUM.init({
  applicationId: "<YOUR_APPLICATION_ID>",
  clientToken: "<YOUR_CLIENT_TOKEN>",
  service: "<SERVICE_NAME>",
  env: "<ENV_NAME>",
  version: "1.0.0", // 确保设置正确的版本号
});
```

<Note>
如果不设置版本标签，当已解决的 Issue 再次发生错误时，系统仍会将其标记为「问题复现」，但无法确定是否在新版本中发生。
</Note>

## 解决方式

在状态下拉里，**已解决**按「该错误再次出现时如何处理」拆成两个选项，两者的状态都是已解决：

| 下拉选项 | 复现时的行为 |
|------|------|
| **已解决** | 之后再出现就重新打开：同一版本内的再次出现同样会重开 |
| **在下一版本中解决** | 只有新版本再出现才重新打开：仅该 Issue 之前未出现过的新版本中再次出现才重开 |

- 两个选项可随时在状态下拉里互相切换；只切换解决方式不改动 Issue 的统计数据，也不改变告警状态。
- 新建 Issue 默认是**在下一版本中解决**，系统自动解决 Issue 时也使用这一方式。
- 错误未携带 `version` 标签时，两种解决方式都会重开：没有版本信息就无从区分修复前后的代码。
- 重开时 Issue 会被置为**待处理**并标记「问题复现」，同时记录复现发生的时间与版本。列表中状态单元格受宽度限制，两种解决方式都显示为**已解决**；详情面板会在**已解决**旁额外标出「在下一版本中解决」。

## 手动更新状态

您可以在任何显示 Issue 的地方手动更新其状态，包括 Issue 列表或详情面板。

<Frame caption="手动更新 Issue 状态">
  <img src="https://docs-cdn.flashcat.cloud/images/png/a57c54a6a28915dec4480a9db9411e30.png" alt="手动更新状态" style={{maxWidth: "600px", margin: "0 auto", display: "block"}} />
</Frame>

只需点击当前状态，然后从下拉菜单中选择新状态即可。下拉中共 5 个选项：**待处理**、**处理中**、**已解决**、**在下一版本中解决**、**已忽略**；两个「已解决」选项下方会显示各自的重开说明，区别见[解决方式](#解决方式)。

## 最佳实践

- **持续监控**：定期检查**待处理**状态的 Issue，确保新问题和回归问题得到及时处理
- **版本管理**：始终为应用程序配置正确的版本标签，以便系统能准确识别已解决的问题
