Flashduty 将相同原因的错误事件聚合为一个 Issue，减少需要处理的条数。聚合默认开启，无需配置。

## 聚合规则

新错误事件按以下顺序归入 Issue：

1. 与已有 Issue 的指纹相同，归入该 Issue。
2. 指纹不同但错误相似，归入最相似的 Issue。
3. 没有相似的 Issue，创建新 Issue。

Android NDK 原生崩溃、Electron 进程终止事件（`RenderProcessGone`、`ChildProcessGone`）和 Flutter、React Native 应用中的 NDK 崩溃只按指纹聚合，不做相似度归并。这类事件的错误消息几乎相同，按相似度归并会把不同位置的崩溃合为一个 Issue。

## 默认指纹

当错误事件没有携带指纹时，Flashduty 用以下属性计算指纹。Web 应用接入 SDK 的方法见 [Web SDK 接入](/zh/rum/sdk/web/sdk-integration)。

| 属性 | 说明 |
|------|------|
| `service` | 错误发生的服务 |
| `env` | 错误发生的环境 |
| `error.type` | 错误的类型分类 |
| `error.message` | 错误的描述文本。Android NDK 原生崩溃还会计入堆栈中最顶层的应用层原生帧，系统库帧不参与，因此同一崩溃位置始终聚合为同一 Issue。 |

<Tip>
计算指纹时，Flashduty 会忽略堆栈帧中的版本号、ID、日期等动态参数。
</Tip>

## 自定义指纹

若默认聚合无法满足需求，您可以通过提供自定义指纹（fingerprint）完全控制错误的聚合行为。

<Warning>
自定义指纹的优先级高于默认指纹。
</Warning>

<Tabs>
  <Tab title="手动添加指纹">
    在手动报告错误时，通过 `addError` 添加自定义指纹：

    ```javascript
    window.FC_RUM.addError(new Error("My error message"), {
      source: "custom",
      fingerprint: "my-custom-grouping-fingerprint",
    });
    ```
  </Tab>
  <Tab title="使用 beforeSend 回调">
    通过 `beforeSend` 回调动态设置指纹：

    ```javascript
    window.FC_RUM.init({
      applicationId: "<YOUR_APPLICATION_ID>",
      clientToken: "<YOUR_CLIENT_TOKEN>",
      service: "<SERVICE_NAME>",
      env: "production",
      beforeSend: (event) => {
        if (event.type === "error") {
          event.error.fingerprint = "my-custom-grouping-fingerprint";
        }
        return true;
      },
    });
    ```
  </Tab>
</Tabs>

<Note>
- 自定义 fingerprint 必须为字符串类型
- 相同服务中具有相同 fingerprint 的错误将被归入同一 Issue
- 不同服务的错误即使 fingerprint 相同也会被归入不同 Issue
- 可用 `beforeSend` 回调过滤无关错误，见下文“第三方脚本错误过滤”
</Note>

## Web 特定注意事项

<AccordionGroup>
  <Accordion title="SourceMap 集成">
    上传 `sourcemap` 文件以解码压缩后的堆栈跟踪，确保聚合后的错误堆栈可映射到原始源代码。

    ```bash
    flashcat-cli sourcemaps upload \
      --service my-service \
      --release-version 1.0.0 \
      --minified-path-prefix /assets \
      --api-key your-api-key \
      ./dist
    ```
  </Accordion>
  <Accordion title="第三方脚本错误过滤">
    SDK 不会自动过滤浏览器扩展或第三方脚本产生的错误。如需排除，请在 `beforeSend` 中配置：

    ```javascript
    beforeSend: (event) => {
      if (
        event.type === "error" &&
        event.error.message.includes("ThirdPartyScript")
      ) {
        return false; // 丢弃该错误
      }
      return true;
    };
    ```
  </Accordion>
</AccordionGroup>

## 查看聚合结果

在 Flashduty 平台，导航至「异常追踪」，查看聚合后的 Issue 列表。点击应用卡片上的 **Issue** 数字，可直达该应用最近 24 小时、状态为「全部」的 Issue 列表，条数与卡片一致。

每个 Issue 包含：

| 内容 | 说明 |
|------|------|
| 错误消息和堆栈跟踪 | 若上传了 `sourcemap`，会显示原始源代码位置 |
| 用户会话时间线 | 触发错误的操作路径 |
| 元数据 | 浏览器类型、版本号等 |
