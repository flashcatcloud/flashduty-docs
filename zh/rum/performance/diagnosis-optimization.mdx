优化页面基于真实用户流量，用核心网页指标和 Flashduty 自定义加载时间指标，从用户视角排查页面加载慢的根因。指标可按浏览器、地区、应用版本等维度拆分，帮助您跟踪趋势、找到受影响最多的用户群体。

## 诊断优化流程

在 **性能监控** 菜单下进入优化页面，或从分析看板中的性能数据跳转过来。

<Steps>
  <Step title="指标选择">
    选择页面和指标后，便可开始做性能数据洞察：

    1. 点击指标卡片选择要洞察的指标
    2. 在「显示筛选细分」中选择一个组
    3. 在不同的百分位数处评估指标（例如 p75 表示第 75 个百分位数值）

    指标卡片按应用平台自适应展示，确保展示的是该平台真正上报的指标：

    | 平台 | 指标卡片 |
    |------|----------|
    | **浏览器（Web）/ Electron（渲染进程）** | `LCP`、`FCP`、`INP`、`CLS` |
    | **微信小程序** | `first_render`（首次渲染）、`lcp`、`fcp`、`onload_to_onshow`、`onshow_to_onready` |

    <Note>
    平台由应用类型决定，切换应用后指标卡片和树图（指标视角）的指标下拉会随之刷新。小程序的 `onload_to_onshow` 与 `onshow_to_onready` 对应页面生命周期的两段耗时，可用于排查冷启动慢。
    </Note>
  </Step>
  <Step title="数据查看">
    调整聚合方式或筛选条件，比较该指标在不同条件下的表现。

    <Frame>
      <img src="https://docs-cdn.flashcat.cloud/images/png/65dd3ca92d67ae9175955502d91552dc.png" alt="数据查看" />
    </Frame>
  </Step>
  <Step title="问题诊断">
    在问题诊断部分，您可以看到用户在页面上遇到的可能影响指标性能的资源和错误。

    <Frame>
      <img src="https://docs-cdn.flashcat.cloud/imges/png/279908df6509c39e433bd24a39df1ff2.png" alt="问题诊断" />
    </Frame>

    <Tip>
    例如，对于最大内容绘制（LCP），您可以查看在触发 LCP 之前加载的资源。由于 LCP 是最大元素在页面上加载所需时间的指标，您可以从资源加载和解决错误两个方面进行问题诊断。
    </Tip>
  </Step>
  <Step title="查看事件样本">
    如果在资源分析阶段无法更准确地定位到关键信息，您可在事件样本区块中选取合适的事件样本进行更详细的上下文分析。

    <Frame>
      <img src="https://docs-cdn.flashcat.cloud/imges/png/04c160de32f11fd695e0a30cfca05af8.png" alt="事件样本" />
    </Frame>
  </Step>
</Steps>

## 优化方向

<Tabs>
  <Tab title="优化资源加载">
    资源加载分析面板展示当前视图下所有资源的详细加载信息，帮助您识别性能瓶颈。

    您可以通过「全部资源」和「阻塞资源」两个选项卡切换查看范围：
    - **全部资源**：展示视图中加载的所有资源
    - **阻塞资源**：仅展示标记为 `blocking` 的渲染阻塞资源，这些资源会延迟页面的首次渲染

    资源列表包含以下字段：

    | 字段 | 说明 |
    |------|------|
    | URL GROUP | 资源的 URL 路径分组 |
    | TYPE | 资源类型（如 JS、CSS、Image 等） |
    | AVG CLIENT SIZE | 平均客户端资源大小 |
    | AVG TRANSFER SIZE | 平均传输大小（如传输大小明显小于客户端大小，说明部分采样命中了缓存） |
    | AVG START TIME | 平均开始加载时间 |
    | AVG DURATION | 平均加载耗时，并以色条按真实时间偏移展示各加载阶段：重定向、Service Worker、排队等待、DNS 解析、建立连接（含 TLS 握手）、等待响应（首字节）与下载 |

    悬停在耗时色条上可查看各阶段耗时。某一阶段占比达到 50% 及以上时，卡片会标出 **主要耗时** 阶段并给出优化建议，帮助判断慢在网络连接、服务器响应还是资源大小（TLS 握手属于建立连接阶段，不会单独成为主要耗时）。

    <Tip>
    已配置 [Link 集成 - 内置 Tracing](/zh/rum/quickstart/app-management#link-集成) 且资源带有 trace_id 时，还可一键下钻到对应的链路。若浏览器未暴露阶段耗时（常见于跨域资源缺少 `Timing-Allow-Origin` 响应头），色条区域会显示 **阶段耗时不可用**。
    </Tip>
  </Tab>
  <Tab title="解决错误">
    关注反复出现的错误，这些异常同样会拖慢页面性能。
  </Tab>
  <Tab title="瀑布图分析">
    - 瀑布图显示了在捕获指标时事件的时间线
    - 向下滚动可查看页面活动其余部分的上下文
    - 使用左上角的下拉菜单选择另一个示例事件
    - 单击展开瀑布中的任何事件以查看侧边面板
    - 通过筛选事件类型和各筛选项来选取合适的事件集合进行问题分析
  </Tab>
</Tabs>
