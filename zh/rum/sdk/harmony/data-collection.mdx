HarmonyOS SDK 将 RUM 数据组装为 NDJSON 批次并上报到 Flashduty。SDK 采集 view、action、resource 和 error 四类 RUM 事件；崩溃和卡死会作为带 `is_crash` 标记的 error 事件进入同一条管道。

## 默认上下文

SDK 初始化后，会为每条事件附加通用上下文。

| 字段 | 来源 | 说明 |
|------|------|------|
| `source` | 固定值 | 固定为 `harmony` |
| `service` | `ConfigurationBuilder.setService()` 或应用 bundle id | 服务名称，用于按服务筛选 |
| `version` | HarmonyOS bundle 信息 | 应用版本号 |
| `application.id` | `RumConfigurationBuilder(applicationId)` | RUM 应用 ID |
| `session.id` | SDK 生成 | 用户会话 ID |
| `os.name` / `os.version` / `os.version_major` | `@kit.BasicServicesKit.deviceInfo` | 操作系统名称、完整版本（如 `OpenHarmony-6.1.1.125`）和主版本号（如 `6`） |
| `device.brand` / `device.model` / `device.type` | `deviceInfo` | 设备品牌、型号和类型 |
| `connectivity.status` | SDK 网络上下文 | `connected` / `not_connected` / `maybe`（`maybe` 对应 schema 的 unknown，权限缺失或接口不可用时使用） |
| `connectivity.interfaces` | SDK 网络上下文 | 当前网络接口，取值 `wifi` / `cellular` / `ethernet` / `other`，未知时为空数组 |
| `usr.id` / `usr.name` / `usr.email` | `setUserInfo()` | 已识别用户信息；服务端不接收其他用户字段 |
| `usr.anonymous_id` | SDK 持久化生成 | 匿名设备标识，随每条事件上报，用于在用户未登录时串联会话；`NOT_GRANTED` 状态下不会生成或写入 |
| `context.*` | 全局属性或单事件属性 | 自定义业务上下文 |

<Note>
`clientToken` 只用于上报鉴权，不会写入 RUM 事件。
</Note>

## 会话规则

SDK 按会话进行采样和生命周期管理。

| 规则 | 当前行为 |
|------|----------|
| 会话采样 | 创建会话时按 `sessionSampleRate` 做一次随机采样；未命中的会话不会写出事件 |
| 空闲超时 | 15 分钟无真实事件后过期；keep-alive 不会刷新空闲时间 |
| 最大时长 | 单个会话最长 4 小时 |
| 视图保活 | 活跃 view 每 30 秒刷新一次 `time_spent` |
| 启动条件 | `keepAlive` 不会创建新会话，只有真实 view、action、error 或 resource 事件会创建会话 |

## View 事件

View 表示用户正在查看的页面或业务视图。您可以通过自动路由追踪或手动 API 生成 view。

```ts
import { GlobalRumMonitor } from '@flashcatcloud/rum';

const monitor = GlobalRumMonitor.get();

monitor.startView('product-detail', 'ProductDetail', {
  'view.url': 'pages/ProductDetail'
});

monitor.stopView('product-detail');
```

会话还没有 view 时发生的 action、resource 或 error 会记入名为 `ApplicationLaunch` 的 view，例如在用户同意隐私弹窗后才启用 RUM、首个页面已经显示的情况。应用的第一个 view 开始后会替换它。两个 view 之间，或系统报告为后台启动时，不会开启该 view，这些事件会被丢弃。需要 SDK 0.8.1 及以上。

View 事件包含：

| 字段 | 说明 |
|------|------|
| `view.id` | SDK 生成的唯一视图 ID |
| `view.name` | 视图名称 |
| `view.url` | 优先使用属性中的 `view.url`，否则使用 view key |
| `view.time_spent` | 从 view 开始到当前更新的耗时，单位为纳秒 |
| `view.is_active` | 当前视图是否仍处于活动状态 |
| `view.action.count` | 当前 view 下 action 数量 |
| `view.error.count` | 当前 view 下 error 数量 |
| `view.resource.count` | 当前 view 下 resource 数量 |
| `view.crash.count` | 当前 view 下的崩溃数量，用于计算 crash-free rate。卡死（`error.category: ANR`）不计入，只计入 `view.error.count` |
| `_dd.document_version` | 同一 view 的更新版本号 |

## Action 事件

Action 表示用户操作。即时操作通过 `addAction()` 记录，带耗时的操作通过 `startAction()` 和 `stopAction()` 记录。

```ts
import {
  GlobalRumMonitor,
  RumActionType
} from '@flashcatcloud/rum';

const monitor = GlobalRumMonitor.get();

monitor.addAction(RumActionType.TAP, 'pay_button');

monitor.startAction(RumActionType.SCROLL, 'feed_scroll');
monitor.stopAction(RumActionType.SCROLL, 'feed_scroll');
```

支持的 action 类型：

| 枚举 | 值 |
|------|----|
| `RumActionType.TAP` | `tap` |
| `RumActionType.SCROLL` | `scroll` |
| `RumActionType.SWIPE` | `swipe` |
| `RumActionType.CLICK` | `click` |
| `RumActionType.BACK` | `back` |
| `RumActionType.CUSTOM` | `custom` |

Action 事件包含 `action.id`、`action.type`、`action.target.name` 和 `action.loading_time`。通过 `FlashcatRum.trackTap()` 自动记录的操作类型为 `tap`。

## Resource 事件

Resource 表示网络请求。SDK 会在以下场景生成 resource：

- 使用 `rcp` session 并添加 `FlashcatTrace.interceptor()`
- 使用 `FlashcatHttp.request()` 包装 `@kit.NetworkKit` 请求
- 使用 `@flashcatcloud/axios` 的 `trackAxios()` 接入 axios 实例
- 用 `FlashcatTrace.startTracedResource()` 接入其他网络栈

以上四种都需要启用 `setTrackNetworkRequests(true)`。此外还可以通过
`GlobalRumMonitor.get().startResource()` 和 `stopResource()` 手动记录，该方式不受此开关影响。

```ts
import {
  GlobalRumMonitor,
  RumResourceKind,
  RumResourceMethod
} from '@flashcatcloud/rum';

const monitor = GlobalRumMonitor.get();

monitor.startResource('order-request', RumResourceMethod.GET, 'https://api.example.com/orders');
monitor.stopResource('order-request', 200, 2048, RumResourceKind.NATIVE);
```

Resource 事件包含：

| 字段 | 说明 |
|------|------|
| `resource.id` | SDK 生成的资源 ID |
| `resource.type` | 资源类型；自动网络采集会按响应 `Content-Type` 归类，无法识别时使用 `native` |
| `resource.url` | 请求 URL |
| `resource.method` | 请求方法 |
| `resource.status_code` | HTTP 状态码 |
| `resource.size` | 响应体大小，单位为字节 |
| `resource.duration` | 请求耗时，单位为纳秒 |
| `resource.provider` | 请求一方域名（Trace 配置的 `setFirstPartyHosts()`）时写入 `{ type: "first party", domain: <host> }`。这类请求失败时，`error.resource` 中同样写入该字段 |
| `resource.dns` / `resource.connect` / `resource.ssl` / `resource.first_byte` / `resource.download` | 请求各阶段的 `{ start, duration }`，单位为纳秒，`start` 从请求开始计算。复用连接的请求没有 `dns` 和 `connect`，http 请求没有 `ssl` |
| `resource.redirect` | 发生重定向的请求只上报该阶段，不上报其他阶段 |
| `_dd.trace_id` / `_dd.span_id` | 当请求注入了 `traceparent` 时写入，用于关联后端 Trace |

请求阶段需要 SDK 0.8.0 及以上，只在网络库提供计时时上报：通过 `FlashcatHttp` 发起的请求，以及 rcp session 设置了 `requestConfiguration.tracing.collectTimeInfo` 时经过拦截器的请求。通过 axios、`startTracedResource()` 或手动 API 上报的请求，以及跨越后台时段、没有耗时的请求，不带请求阶段。

自动网络采集的资源类型映射：

| 响应 `Content-Type` | `resource.type` |
|---------------------|-----------------|
| `image/*` | `image` |
| `video/*` / `audio/*` | `media` |
| `font/*` | `font` |
| `text/css` | `css` |
| `text/javascript` | `js` |
| 其他或缺失 | `native` |

如果请求失败，SDK 会生成 `source: "network"` 的 error 事件，并在 `error.resource` 中附带请求方法、状态码和 URL。

## Error 事件

Error 表示手动上报错误、未捕获 ArkTS 异常、未处理的 Promise rejection、网络错误、崩溃或卡死。

```ts
import {
  GlobalRumMonitor,
  RumErrorSource
} from '@flashcatcloud/rum';

GlobalRumMonitor.get().addError(
  'checkout failed',
  RumErrorSource.CUSTOM,
  'at checkout'
);
```

支持的 error source：

| 枚举 | 值 | 说明 |
|------|----|------|
| `NETWORK` | `network` | 网络请求失败 |
| `SOURCE` | `source` | ArkTS / JS 运行时错误或崩溃 |
| `CONSOLE` | `console` | 控制台来源错误 |
| `WEBVIEW` | `webview` | WebView 来源错误 |
| `AGENT` | `agent` | Agent 来源错误 |
| `CUSTOM` | `custom` | 业务手动上报 |

RUM 会自动监听 `errorManager.on('error')` 和 `errorManager.on('unhandledRejection')`。未处理的 Promise rejection 会作为普通非崩溃 error 上报，不会触发退出或恢复策略。

Error 事件包含：

| 字段 | 说明 |
|------|------|
| `error.message` | 错误消息 |
| `error.source` | 错误来源 |
| `error.stack` | 错误栈，存在时上报。只包含栈帧：errorManager 回调文本里的 `Error name:` / `Error message:` / `Stacktrace:` 标签行和 sourcemap 提示行会被剥离，它们属于回调格式而非栈内容 |
| `error.handling` | `handled` 或 `unhandled` |
| `error.is_crash` | 崩溃和卡死事件为 `true` |
| `error.type` | 错误类型。未捕获异常为异常名（如 `TypeError`）；Native 崩溃为信号（如 `SIGSEGV`）；卡死为故障名（如 `THREAD_BLOCK_6S`）；主线程卡顿为 `MAIN_THREAD_JANK`。`addError()` 上报的错误和网络错误不带类型，可在属性中传 `error.type` 指定 |
| `error.category` | 崩溃为 `Exception`，卡死为 `ANR`，主线程卡顿为 `Jank` |
| `view.in_foreground` | 崩溃和卡死时应用是否在前台。状态未知时（如启动早期系统尚未通知，或旧版本 SDK 记录的崩溃）不上报。需要 SDK 0.8.1 及以上 |
| `session.sampled` | 崩溃和卡死所在会话是否由采样率抽中：抽中或强制采集为 `true`，仅因报错被[异常补采](/zh/rum/sdk/harmony/advanced-config#远程配置)保留为 `false`。旧版本 SDK 记录的崩溃不上报。需要 SDK 0.8.1 及以上 |
| `error.source_type` | Crash 模块写入 `harmony`；未处理的 Promise rejection 写入 `promise` |
| `crash.recovered` | 通过 `REPORT_AND_RECOVER` 软着陆并在后续启动回放的崩溃中存在且为 `true` |
| `crash.crashed_at_ms` | 崩溃记入单独会话时写入，值为真实故障发生时间（毫秒） |
| `crash.fault_address` | Native 崩溃由内核故障触发时的出错地址（空指针为 `0x0`），写在 error 的 `context` 中。进程主动发出的信号（如 `abort()`）没有该字段 |
| `freeze.reason` | 卡死时系统给出的原始描述，写在 error 的 `context` 中 |
| `error.binary_images` | Native 崩溃关联的动态库符号信息 |
| `error.threads` | Native 崩溃和卡死时的全部线程，每个线程包含名称、状态和调用栈。故障线程（Native 崩溃的出错线程、卡死的主线程）标记 `crashed: true` 并排在第一位；线程总量有大小上限，超出时保留故障线程。ArkTS 崩溃没有线程快照，不上报该字段 |
| `crash.memory.rss_kb`、`crash.memory.sys_free_kb`、`crash.memory.sys_avail_kb`、`crash.memory.sys_total_kb` | 故障发生时的进程实际占用内存，以及设备的空闲、可用、总内存，单位 KB。来自系统故障事件，Native 崩溃和卡死在 API 22 及以上的设备上报，写在 error 的 `context` 中。ArkTS 崩溃由 SDK 在进程内采集，不带该字段 |
| `build_id` | 用于匹配 Native 符号的 build-id |

## 崩溃和卡死

Crash 模块通过实时和事后两条路径采集故障：

- 主线程上未捕获的 ArkTS 异常会进入实时 JS 崩溃策略路径。`REPORT_THEN_EXIT` 和 `REPORT_AND_RECOVER` 会在进程退出或重启前同步持久化 SDK 待处理崩溃记录；`REPORT_AND_CONTINUE` 会把崩溃实时上报到当前会话，进程继续运行，不写入待处理记录
- 下次启动时，Crash 模块会把 SDK 自身的待处理记录回放到 RUM，标记为已消费后删除持久化文件
- HarmonyOS `hiAppEvent` 会在后续启动时回放 `APP_CRASH` 和 `APP_FREEZE`，用于采集 ArkTS、Native C/C++ 崩溃和卡死

同一次 ArkTS 崩溃只会生成一个 crash error 事件，不会重复上报。

未处理的 Promise rejection 会单独采集为 `error.source_type: promise` 的普通非崩溃 RUM error。它不会使进程退出，也不会进入崩溃策略路径。

卡死（`error.category: ANR`）的 `is_crash` 为 `true`，计入 view 的 error 数，但不计入 crash 数：崩溃率不含卡死，卡死单独计入 ANR 率。需要 SDK 0.8.1 及以上。HarmonyOS 会冻结后台进程，系统不会为后台的应用产生卡死事件，因此后台没有卡死上报。

<span id="main-thread-jank"></span>
### 主线程卡顿

主线程单个任务耗时过长、但进程没有被终止时，Crash 模块把系统上报的主线程卡顿记为当前会话中的一条 error：`error.category: Jank`、`error.type: MAIN_THREAD_JANK`、`is_crash: false`，附带系统采样的调用栈，卡顿时长写在 `context.jank.duration_ms`（毫秒）。卡顿计入 view 的 error 数，不计入 crash 数。

需要 SDK 0.8.0 及以上，默认开启，可用 `setTrackMainThreadJank(false)` 关闭，见[高级配置](/zh/rum/sdk/harmony/advanced-config#crash-config)。API 15 及以上的设备每个进程最多上报 3 次卡顿。

### 崩溃归因

崩溃和卡死会归因到**故障真正发生的那个会话和视图**，而不是回放它的那次启动：

- SDK 能在进程内观察到的故障（主线程上未捕获的 ArkTS 异常）在退出前会把当时的 RUM 会话和视图一并写入待处理记录，下次启动按该记录回放
- SDK 无法在进程内观察到的故障（Native 信号崩溃、卡死）会直接杀死进程。SDK 在会话开始、结束和 view 更新时把当前会话和 view 记录到本地，下次启动时据此还原故障所属的会话和视图

回放时，SDK 在原会话中写入一条带真实故障时间的 `is_crash` error，并更新该视图的 crash 和 error 计数（卡死只更新 error 计数）。会话还没有 view 时（例如启动过程中，或会话刚续期），故障记入该会话的 `ApplicationLaunch` view；系统报告应用当时在后台时，记入 `Background` view。

未被采集的会话（未被采样率抽中，且未被异常补采保留）中发生的崩溃不会上报，与该会话的其他事件一致。

以下少见情况无法归因到原会话，崩溃会记入一个单独的会话，真实故障时间保留在 `crash.crashed_at_ms` 中。该会话使用上报这次崩溃的那次启动的应用版本和用户信息：

- 本地没有该会话的记录，例如崩溃发生在 RUM 启用或第一个会话建立之前，或记录属于另一个进程
- 故障发生时会话已经结束（调用了 `stopSession()`，或会话已过期，包括 view 超过 15 分钟没有更新）
- 视图已开始超过 4 小时（会话最长 4 小时）
- 故障发生距今已超过 23 小时（超过 24 小时的事件会被服务端丢弃）

极少数情况下，崩溃 error 写入成功而视图计数更新失败，此时该会话的崩溃数会比实际少 1。

崩溃事件会通过 RUM error 管道上报：

- ArkTS / JS 错误栈会按 V8 风格帧解析
- Native C/C++ 栈会按 `#NN pc <address> <lib.so>` 形式解析
- 如果上传了 `sourceMaps.map`、`nameCache.json` 和未 strip 的 `.so`，服务端会还原源文件、函数名、行列号和 Native 符号

## 上报行为

SDK 以 NDJSON 形式批量上报事件。

| 行为 | 当前实现 |
|------|----------|
| 上报地址 | `{site}/api/v2/rum`，默认 site 为 `https://browser.flashcat.cloud` |
| 请求方法 | `POST` |
| Content-Type | `text/plain;charset=UTF-8` |
| Content-Encoding | `deflate`（请求体默认压缩，压缩失败时回退为未压缩上传） |
| 鉴权 | 请求头 `DD-API-KEY: <clientToken>` |
| 查询参数 | `ddsource=harmony`，`ddtags` 包含 `sdk_version`，并在存在时追加 `env`、`service`、`version` |
| 默认上传间隔 | 2 秒（可用 `setUploadFrequency()` 调整） |
| 网络超时 | 连接超时和读取超时均为 30 秒 |
| 重试 | 网络错误、`401`、`403`、`408`、`429` 和 `5xx` 会保留批次并指数退避重试 |
| 丢弃 | 其他 `4xx` 视为永久错误并丢弃当前批次 |
| 强制刷新 | error 和 crash 事件会触发更快刷新 |
| 后台刷新 | 应用进入后台时会刷新当前 view 并触发上传 |

## 当前不采集的内容

当前 HarmonyOS SDK 不自动采集以下数据：

- Session Replay
- Web Vitals 或浏览器页面性能指标
- 长任务（long task）
- 自动 frustration 事件
