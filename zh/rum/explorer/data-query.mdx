RUM 查看器的查询由**词项**（terms）和**操作符**（operators）组成，可以组合出复杂的检索条件；不熟悉语法时也可以让 AI 代写，见下方。

## 用 AI 查询

入口是查询框左侧的 AI 按钮，也可以在普通查询模式下按 <kbd>⌘</kbd> + <kbd>Enter</kbd>（Windows 和 Linux 为 <kbd>Ctrl</kbd> + <kbd>Enter</kbd>）。它打开哪个面板取决于账户：账户已开启 AI SRE、且当前成员有 AI SRE 会话的访问权限时，按钮是 **打开 AI SRE**，打开的是查询框下方的一段 AI SRE 对话；未开启 AI SRE 或额度用尽时，按钮是 **AI 自然语言查询**，打开的是把一句话转成查询条件的基础面板。

### 用 AI SRE 查询和分析

一句话说清要看什么即可，AI SRE 自己把结果写到页面上：查询语句、事件类型和时间范围，需要图表时连统计方式、分组和图表类型一起设好；写完它会把页面查到的结果读回来答复您，所以可以接着追问同一个应用里的其他问题。

- **状态条**：运行中显示它这一步在做什么——**正在填入查询**、**正在核对**（对照应用里的真实字段取值）、**正在生成图表**、**正在查询**。本轮结束后状态条报告页面拿到了什么：**已查到 N 条**、**查询完成，暂无数据**、**需要补充**（它在等您回答）、**已回复**、**已停止**、**查询失败**、**页面已变化，尚未应用**。
- **撤销修改**：AI SRE 写过页面之后，状态条右侧出现 **撤销修改**，把查询条件、事件类型、时间范围和图表恢复成它动手之前的样子。您在查询框里自己改过内容后这个入口消失——此时页面上的内容归您，不再撤销；运行中它不可点。
- **停止与收起**：运行中点 **停止** 结束本轮，已经写上去的内容留在页面上。点状态条可以收起或展开对话；写过查询的一轮结束后对话自动收起，把结果留在视野里，只回答问题的那一轮会展开供您阅读。
- **追问与示例**：状态条会给出下一句最可能的追问，按 <kbd>Tab</kbd> 填入输入框，回车发送；AI SRE 反问时状态条显示 **需要补充**，输入框提示您回复它。还没有对话时，输入框下方给出几个示例问题，用 <kbd>↑</kbd> <kbd>↓</kbd> 选择、<kbd>Tab</kbd> 填入、回车直接发送。
- **运行中先写草稿**：本轮结束前按回车只会留下草稿，提示「当前仍在运行，草稿已保留，完成后再发送」，等本轮结束后再发。
- **换应用就是换对话**：切换右上角的应用或离开查看器都会结束本次对话，再次打开是一个新对话；再点一次这个按钮（此时提示 **结束本次 AI SRE 对话**）也会结束它。
- **额度与未开通**：额度用尽（本周期额度用完、钱包余额不足，或 On-Call 订阅缺失）时 AI SRE 起不了新一轮：对话里状态条显示 **额度不足** 并给出 **去充值**（On-Call 订阅缺失时为 **前往 On-Call 订阅**）；此后这个按钮改为打开基础的自然语言查询，面板顶部用一句话说明原因，右侧是同一个入口。未开启 AI SRE 的账户一直走基础查询。

### 基础自然语言查询

账户未开启 AI SRE 或额度用尽时，这个按钮打开的是下面这一套基础面板：用自然语言（中英文均可）描述要找的数据，AI 把它转成标准查询语句（DQL），字段与语法与手动查询完全一致。进入后输入框边框会高亮。

<Steps>
  <Step title="描述查询意图">
    用自然语言描述您想查找的数据，按 <kbd>Enter</kbd> 生成预览。例如：

    ```
    来自 Chrome 浏览器、耗时超过 2 秒的 5xx 资源请求
    ```

    AI 会将其转换为：

    ```
    browser_name:Chrome resource_status_code:>=500 resource_duration:>2s
    ```

    您无需记住字段名，AI 会按当前事件类型选择可查询的字段。
  </Step>
  <Step title="查看变更预览">
    预览给出 AI 返回的这条查询：查询框为空时整条显示；在原查询上补充条件时只显示新增的部分（前面带 `+`）；要替换原查询时把原查询划掉并标注 **替换当前查询**，整条新查询显示在下面。请求更适合其他事件类型或时间范围时（如提示「将切换事件类型为 错误」），另外给出对应的 旧 → 新 一行。预览里还会给出这条查询在当前时间范围内会查到多少条；生成过程中面板逐条显示服务端正在做的步骤。结果不理想时，修改描述后再次回车即可重新生成。
  </Step>
  <Step title="应用">
    点击 **应用**、**追加到查询**、**替换查询** 或 **切换并应用** 确认变更：查询写入查询框，事件类型和时间范围一并生效，面板随即关闭，页面上显示的就是新的结果。这套基础查询不提供撤销；需要回到 AI 动手之前的页面，请用 AI SRE 对话里的 **撤销修改**（见[用 AI SRE 查询和分析](#用-ai-sre-查询和分析)）。
  </Step>
</Steps>

#### 在现有查询上继续改

查询框里已有条件时，AI 会把当前查询一起带上去理解，返回的是一条**完整的新查询**，因此既能补充条件，也能删改：

- **补充条件**（如「再加上 401」「只看最近 1 天」）：返回的是「原查询 + 新条件」，预览只显示新增的部分（前面带 `+`），按钮是 **追加到查询**。
- **删改条件**（如「去掉耗时条件」「只看 `/incident`」「换成 Safari」）：返回的新查询不再包含原查询里的某些条件，预览把原查询划掉并标注 **替换当前查询**，按钮变成 **替换查询**。
- **换一个话题**（与当前条件无关的描述）：AI 忽略现有条件，按新描述生成一条新查询，同样以替换的方式应用。
- 查询框为空时按钮就是 **应用**；需要换事件类型时按钮是 **切换并应用**，应用后连同事件类型一起切过去。
- 返回的查询与当前查询完全一致、又没有别的变更时，面板提示「当前查询已经是这个条件」。

还没有生成结果时，面板底部会标出 **基于当前查询** 和查询框里的原条件，便于对照这次到底改了什么。

#### 应用前先看条数

生成完成后，服务端会先用这条查询在时间范围内真实跑一次计数，结果直接出现在预览里：

- 有数据时显示 **将查到 N 条**；一条都没有时显示 **当前时间范围内没有匹配的数据**（黄色提示），此时仍可应用。
- 命中为 0 时 AI 会先自行修正：对着该应用里这些字段的真实取值核对大小写与拼写（例如 `Mobile`、`Mac OS X`），必要时换到更合适的字段或事件类型，最多重写两次；仍然为 0 就照原样返回——您要的条件本身正确、只是没有这样的数据时，0 条就是答案。
- 生成过程中面板逐条显示服务端正在做的事：**理解问题** › **正在核对** › **生成查询** › **核对条数**；重写时显示 **重新生成查询** 和原因（**没查到数据，换个写法**、**改查「页面」**、**查询有误，修正中**、**再试一次**）。
- 计数拿不到时不影响结果：查询照常返回，只是不显示条数。

#### 分析类问题交给 AI SRE

「为什么这个页面变慢了」「上线后还有这个错误吗」「和上周比如何」「哪个页面最慢」这类要结论的请求，基础查询给不出答案：AI 判定这是在要结论、不是要筛条件，面板提示 **这是个分析问题，查询框给不出结论**，并给出通往 AI SRE 的入口——未开启 AI SRE 时后面跟一句 **AI SRE 可以帮你分析** 和 **开通 AI SRE**；额度不足或 On-Call 订阅缺失时是 **去充值** 或 **前往 On-Call 订阅**。

<Note>
- “最近 1 小时”“昨天”“过去 7 天”等时间表达会更新查看器的时间选择器，不会被写成 `client_time` 等 DQL 条件；性能时长条件仍属于 DQL，例如 `view_loading_time:>2s`。
- 时间范围最长 **14 天**。请求的范围更长时，预览会提示已截取最近 14 天：相对时间范围改为过去 14 天，绝对时间范围保留请求的结束时间并向前取 14 天。
</Note>

<Tip>
在 AI 输入框中用**自然语言**描述即可，直接输入查询语法（如 `browser_name:Chrome`）反而会降低转换准确率。需要精确控制条件时，请使用下方的查询语法。
</Tip>

## 查询基础

查询支持两种类型的词项：

| 类型 | 说明 | 示例 |
|------|------|------|
| **单词项** | 单个词汇 | `test`、`hello` |
| **短语** | 用双引号包围的词汇组 | `"hello flashduty"` |

查询条件整体只填一个 `*` 时，等同于不填条件：匹配时间范围内的全部事件。

### 布尔操作符

| 操作符 | 描述 | 示例 |
|--------|------|------|
| `AND` | 交集：两个词项都必须在选定的视图中（默认操作符） | `error AND timeout` |
| `OR` | 并集：任一词项包含在选定的视图中，需要使用 `()` 包裹起来 | `(error OR warning)` |
| `-` | 排除：后面的词项不在视图中 | `error -timeout` |

## 全文检索

<Warning>
全文检索仅部分字段支持，如未查询到结果，请转为字段查询。
</Warning>

| 查询语句 | 描述 |
|----------|------|
| `hello` | 精确匹配 `hello` 的字段 |
| `hello*` | 匹配以 `hello` 开头的字段 |
| `*hello` | 匹配以 `hello` 结尾的字段 |
| `*hello*` | 匹配含有 `hello` 的字段 |
| `"hello world"` | 精确匹配 `"hello world"` 的字段 |

## 转义特殊字符

检索包含特殊字符的字段值时，需要使用反斜杠 `\` 转义或者双引号。

<Note>
以下字符被视为特殊字符：`:`, `"`, `*`, `-`, `>`, `<`, `,`, `(`, `)`, `[`, `]`, `\` 和空格
</Note>

## 属性检索

使用 `attribute:term` 语法检索特定属性：

| 查询语句 | 描述 |
|----------|------|
| `browser_name:Chrome` | 检索值为 `Chrome` 的浏览器 |
| `view_name:*/detail` | 检索以 `/detail` 结尾的视图名称 |
| `browser_name:*` | 检索包含该字段的事件：`*` 单独作为整个值表示字段存在，不是通配符 |
| `-resource_status_code:0` | 检索状态码不为 `0` 的资源 |
| `os_name:"Mac OS X"` | 检索值为 `"Mac OS X"` 的系统名称 |

## 数值检索

对于数值类型的属性，可以使用比较操作符：

| 查询语句 | 描述 |
|----------|------|
| `session_error_count:>5` | 检索错误数大于 `5` 的会话 |
| `view_time_spent:>=1.00min` | 检索停留时间大于 `1min` 的视图 |
| `session_view_count:[2 TO 8]` | 检索视图访问量在 `2` 和 `8` 之间的会话 |

## 复杂检索示例

  <Tab title="错误分析">

    ```
    error_message:Warning\:* view_url_path:/wallet/*
    ```
  </Tab>
  <Tab title="性能分析">

  </Tab>

  </Tab>

    ```
    view_url_path:/incident (view_action_count:>=2 OR view_error_count:>=3)
    ```
  </Tab>
</Tabs>

## 路径字段与 URL 归一化

`view_url_path` 与 `view_url_path_group`（以及会话、错误、资源、操作、长任务事件上同名的路径字段）由页面 URL 归一化得到，两者都可以用于筛选和图表。按 `view_url_path` 分组属于高基数分组（统计方式仅限计数与求和，时间范围最长 7 天，见[分组字段的基数限制](/zh/rum/explorer/analytics#cardinality-limits)）；按页面汇总请用 `view_url_path_group`：

| 原始 URL | `view_url_path` | `view_url_path_group` |
|----------|-----------------|------------------------|
| `https://a.com/orders/123?tab=1` | `/orders/123` | `/orders/?` |
| `https://a.com/app/#/list?page=2` | `/app/#/list` | `/app#/list` |
| `https://a.com/docs/page#section-2` | `/docs/page` | `/docs/page` |

- 查询参数（`?tab=1`、`?page=2`）不进入这两个字段。
- **hash 路由保留在路径里**：以 `/` 开头的 fragment（hash 模式 SPA 路由的写法）会拼进路径与路径分组，因此这类应用的每个页面是不同的取值。按页筛选或分组时要把 `#/...` 段一起写上，例如 `view_url_path:/app/#/list`。
- 路由自带的查询会被丢弃（`#/list?page=2` 记成 `#/list`），空的 `#/` 与普通锚点（如 `#section-2`）被忽略。
- 数字、UUID、对象 ID、trace ID、长哈希、日期这类 ID 段在 `view_url_path_group` 中归一化为 `?`，所以「每个对象一个地址」的详情页会归到同一组；`view_url_path` 保留原值。
- 资源 URL 不走这套规则：`resource_url_path` 只取路径，资源地址上的 `#...` 一直被丢掉。

## 微信小程序专属属性

针对微信小程序平台采集的 View 事件，除通用的 `view_*` 字段外，还支持以下可查询属性，便于排查小程序页面冷启动、`setData` 调用和生命周期阶段耗时：

| 属性 | 说明 |
|------|------|
| `view_first_render` | 首屏渲染耗时 |
| `view_app_launch` | 小程序启动耗时 |
| `view_loading_time` | 页面加载耗时 |
| `view_setdata_count` | 页面 `setData` 调用次数 |
| `view_setdata_duration` | 页面 `setData` 累计耗时 |
| `view_onload_to_onshow` | `onLoad` 到 `onShow` 之间的耗时 |
| `view_onshow_to_onready` | `onShow` 到 `onReady` 之间的耗时 |

例如，检索首屏渲染超过 2 秒的小程序页面：

```
source:miniprogram view_first_render:>2s
```

## 会话属性检索

除上述示例中的字段外，会话（Session）还支持以下常用可查询属性，这些属性同样可用于列表列展示、CSV 导出和链接变量：

| 属性 | 说明 |
|------|------|
| `session_id` | 会话 ID |
| `session_view_count` | 会话内的视图访问量 |
| `session_has_replay` | 会话是否包含回放 |
| `session_sampled_for_error` | 会话是否为异常补采会话：为 `true` 时，该会话的事件在客户端被暂存、直到会话报错才上传，因此明细只从报错前的一小段开始 |
| `session_sampled_for_error_replay` | 会话回放是否因报错才保留：为 `true` 时，该回放是会话报错后才补充上传的 |
| `rc_version` | 远程配置版本，即会话上报时所使用的远程配置版本号 |

例如，检索由异常补采上传的会话：

```
session_sampled_for_error:true
```

异常补采的开关见应用管理中[远程配置](../quickstart/app-management#远程配置)的 **错误会话补充采集**（`sessionOnError`）与 **错误会话补充回放**（`sessionReplayOnError`）。

其中 `rc_version` 对应应用管理中[远程配置](../quickstart/app-management)的发布版本，可按配置版本筛选会话，评估远程配置发布（rollout）的生效情况。

## 最佳实践

- 多词短语用双引号包围，确保精确匹配。
- 谨慎使用通配符，避免条件过于宽泛。
- 用 `AND` / `OR` 组合多个条件，构建精确查询。
- 借助自动补全减少输入错误。
- 保存常用检索条件，方便重复查询。
