行为分析把 SDK 自动采集的点击与页面浏览整理成业务视角，用来回答三个问题：用户在哪一步流失、在页面上点了哪里、离开这一页之后去了哪里。

## 支持的应用类型

行为分析目前只对 **Web** 与 **Electron** 应用开放。切到其它类型的应用时，页面会提示该应用暂不支持，并引导您切换到 Web 或 Electron 应用。

点击数据依赖 SDK 自动采集的点击：Web 与 Electron 应用接入 SDK 后即可采集；元素名称取自被点击元素的文本。若页面上的点击没有被采集，请先检查 SDK 的用户交互采集配置，见 [Web SDK 数据采集](/zh/rum/sdk/web/data-collection)。

## 入口与页面结构

在 RUM 控制台左侧菜单选择 **行为分析**，默认进入 **漏斗分析**。顶部有三个标签页，右上角的 **事件管理** 是一个独立页面：

| 页面 | 用来做什么 | 详见 |
| --- | --- | --- |
| **漏斗分析** | 按顺序定义 2 到 10 个步骤，看每一步的到达、转化与流失 | [漏斗分析](/zh/rum/behavior-analysis/funnel) |
| **热力图** | 看单个页面上的点击分布、元素点击排行和滚动深度 | [热力图](/zh/rum/behavior-analysis/heatmap) |
| **路径分析** | 看用户到达某个页面前后分别去了哪些页面 | [路径分析](/zh/rum/behavior-analysis/paths) |
| **事件管理** | 把自动采集的点击定义为业务事件，供漏斗步骤引用 | [事件管理](/zh/rum/behavior-analysis/events) |

切换标签页时应用与时间范围保持不变。切换应用则是一次全新的查询，上一个应用的结果和未保存的草稿都不会带过来。

## 权限

行为分析由前端监控权限 **行为分析查看** 控制。没有该权限时菜单里不显示这个入口。权限点的完整列表见 [权限设计](/zh/platform/permission-design)。

## 数据从哪里来

- **页面浏览**：SDK 上报的页面访问，按页面路径归组。同一个路径带不同参数时归为同一个页面。
- **点击**：SDK 自动采集的点击，带页面、元素文本、选择器和点击坐标。
- **自定义事件**：代码中通过 `addAction` 上报的动作，按上报的 name 匹配。
- **点击图底图**：热力图的点击图以会话回放画面为背景，因此依赖回放数据。回放采样率在 **应用设置** 里调整，见 [会话重放 SDK 配置](/zh/rum/session-replay/sdk-config)。

事件规则在查询时匹配已采集的原始点击，不会改写已存储的数据，所以新建或修改事件后立即作用于历史数据，不需要重新上报。

## 数据量大时的抽样

查询范围很大时，控制台会按会话抽样并就地标注：路径分析与漏斗页面提示估算所基于的会话比例，热力图的点击量按抽样比例换算后显示。看到这类提示时，数量是估算值，比例关系仍然可信，单点数值不宜用来做精确对比。

## 已知限制

- 只有 Web 与 Electron 应用提供点击图与滚动深度。元素排行不依赖回放，可正常使用。
- 点击坐标自 SDK 上报该字段之日起才有，此前的点击只计入元素排行。
- 点击少于 100 次的元素不计算挫败点击率与点击后报错率，表格中标注 **样本少**。
- 时间范围过短或转化窗口长于时间范围时，漏斗转化率会偏低，控制台会提示 **转化窗口长于时间范围**。
