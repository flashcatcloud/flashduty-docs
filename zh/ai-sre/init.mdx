## 概述

在任意 AI SRE 会话的输入框中输入 `/init`，Agent 会切换成一名**运维 onboarding 访谈者**，带您从零搭建一份运维知识。它会扫描您的 Flashduty 故障与通知渠道、向您提问、把您口述的服务拓扑、排查手册、集群访问方式等沉淀成知识文件，并在需要时帮您接入外部工具（MCP）。

`/init` 是搭建知识的**起点**。AI SRE 的诊断质量直接取决于它能读到多少关于您系统的真实知识：[知识](/zh/ai-sre/knowledge)维护得越完整、越准确，Agent 定位根因就越快、越靠谱。`/init` 就是把这份知识从零建立起来的引导流程，建完之后每一次会话都会自动加载它。

<Note>
`/init` 写入或安装任何内容前都会先征得您的逐项确认，凭证也不会在对话里明文回显，详见[安全与同意](#安全与同意)。
</Note>

## 何时用 /init，何时直接说

`/init` 解决的是**结构化的从零搭建 / 系统性补全**；零散的小修小补不需要它。

| 场景 | 用法 |
|---|---|
| 第一次给某个账户 / 团队搭建知识 | **`/init`**——它会成体系地走完服务、可观测性、runbook、常见故障、集群访问等主题 |
| 系统性地补全或重整一份已有知识 | **`/init`**——可随时重跑，它会基于现有内容继续，而非推倒重来 |
| “补一篇 runbook”“更新 services.md”“记一下这个故障模式” | **直接用自然语言说**，无需 `/init`——Agent 会就当前会话作用域读取、编辑、保存 |

<Tip>
`/init` 与零散的自然语言编辑是互补的：用 `/init` 把底子打全，之后在日常排障中随时让 Agent“把这条经验记进知识”做增量维护。两者写入的是同一份知识。
</Tip>

## 如何运行

<Steps>
  <Step title="在会话中输入 /init">
    在任意一个 AI SRE 会话的输入框输入 `/init` 并发送。无需参数。
  </Step>
  <Step title="确认作用域">
    Agent 先和您确认本次写入的范围：会话绑定了团队就写入该**团队级**（仅该团队会话加载），否则写入**账户级**（账户内所有会话可见）。确认后整场会话固定使用这个范围。想换团队范围，请从目标团队重新打开 `/init`。
  </Step>
  <Step title="扫描并核对">
    Agent 读取您的渠道、近 30 天故障、团队与成员，归纳出您在用的集成类型和高频故障标签，用一段话回述：“我看到 N 个渠道、近 30 天 M 个故障……对吗？还缺什么？”等您确认或纠正，**此时不写入任何文件**。全新账户没有数据可扫描时，改为完全靠访谈采集。
  </Step>
  <Step title="从本地 AI 编程工具导入（可选）">
    需您主动同意，不会自动触发。如果您已经在 Claude Code、Codex、Cursor、Windsurf、Copilot、Gemini CLI 等本地工具里积累了知识与记忆，可以一次性导入。自托管 Runner 装在您本机时，Agent 直接读取这些工具的配置和记忆文件；否则 Agent 给您两段通用提示词，您在本地工具里运行后把结果粘贴或上传回来。运维和服务知识写入知识文件，个人偏好和可复用习惯写入 Agent 记忆，重复或无用的丢弃。导入内容在预览和写入前都会先做**密钥脱敏**。
  </Step>
  <Step title="按主题访谈并逐项确认">
    Agent 按下表的主题逐项提问，把您的回答整理成知识文件草稿。每项写入前，Agent 会列出将创建或更新的文件（各附 3–5 行摘要），您确认后才写入，并把新文件链接进 `DUTY.md` 目录。每项结束都会问您“继续下一项，还是先停在这里”。

    | 主题 | 产出 |
    |---|---|
    | 服务与拓扑 | `services.md`（可选 `topology.md`） |
    | 可观测性栈 | `observability.md`（数据源缺口的处理见下方说明；走 MCP 直连的登记到 `tools.md`） |
    | 运行手册 | `runbooks/<主题>.md`，一类故障一个文件 |
    | 常见故障 | `common-failures.md` |
    | 集群访问与运行时探查 | `clusters.md`（k8s）；MCP 方式追加到 `tools.md` |

    <Note>
      数据源缺口优先通过 Monitors 补齐：如果账户已在使用 Monitors（存在数据源或告警规则），Agent 会给出一个链接，直接打开 Monitors 中已预选对应类型的添加数据源表单（支持 Prometheus、Loki、VictoriaLogs、腾讯云 CLS、SLS、MySQL、PostgreSQL、Oracle、ClickHouse、Elasticsearch）。数据源启用后 AI SRE 即可查询，无须安装其他组件。完全没有使用 Monitors 时，才改为通过 MCP 直连您在用的工具（见 [MCP](/zh/ai-sre/mcp)）。`/init` 本身不会创建或修改 Monitors 数据源。
    </Note>

    <Note>
      集群访问**首选原生 kubectl**，k8s-MCP 为备用方式（同一集群二者不同时配置）。该路径仅适用于自托管 Runner：在 Runner 上为每个集群放置一份**只读** kubeconfig（`<工作区>/.kube/<名称>.config`），`clusters.md` 只记录其**路径**，绝不记录 token。
    </Note>
  </Step>
  <Step title="收尾，随时暂停或重跑">
    您表示完成时，Agent 给出小结：创建或更新了哪些文件、登记了哪些 MCP。您可以随时说“跳过这项”“回到上一项”“先到这里”。之后任何时候重新输入 `/init`，都会基于已有知识继续补全。
  </Step>
</Steps>

## 安全与同意

`/init` 会写知识、可能装 MCP、还会碰到凭证，因此同意与最小权限是它的硬性约束：

- **逐项显式同意**：任何写入或安装都必须经您明确同意。每项写入前都会列出将创建或更新的文件（各附 3–5 行摘要），您点头后才执行，不会凭一句含糊的“好”就写入。
- **凭证不明文回显**：您提供 token、密码、AK/SK 等敏感信息时，Agent 只记为 `<已记录（长度=N）>`，不在对话里重复明文。
- **最小权限凭证**：需要提供或生成凭证（kubeconfig、云 AK/SK、数据库账号、API token）时，Agent 会要求按**只读 / 最小权限**配置；能机器校验边界时，会先做一次只读边界检查再记录。
- **极简原则**：只写缺了就会让 AI 在故障中做出更差决定的内容，可有可无的细节不写，避免知识臃肿。

## 产出什么

`/init` 的成果是一份可被后续每次会话自动加载的[知识](/zh/ai-sre/knowledge)：

- **`DUTY.md`**——知识的目录入口，只放一句话导引和一份 `@文件名` 链接清单，指向各主题文件；
- **主题文件**——`services.md`、`topology.md`、`observability.md`、`runbooks/<主题>.md`、`common-failures.md`、`clusters.md` 等，实质内容都在这里；
- **MCP 登记**（可选）——若访谈中接入了外部工具，会在 `tools.md` 记录并完成 MCP 服务器注册。

<Note>
`/init` 的主要产出是**知识**，不是 Skill。它不会把内容存成 Skill，除非您明确要求。它也不会自动安装 Agent——这类资源目前需您在控制台手动添加。
</Note>

## /init 与 /insight：一对最佳实践

`/init` 和 [`/insight`](/zh/ai-sre/insight) 是运维知识“建立 → 打磨”闭环的两端：

<CardGroup cols={2}>
  <Card title="/init — 建底子" icon="seedling">
    从零把知识搭起来：服务、拓扑、runbook、集群访问一次成体系地沉淀，让 Agent 一上来就懂您的系统。
  </Card>
  <Card title="/insight — 持续打磨" icon="gauge-high">
    回看近 30 天会话，找出反复粘贴的上下文、缺失的 runbook、用错的数据源，告诉您**下一步该往知识里补什么**。
  </Card>
</CardGroup>

<Tip>
推荐的节奏：先用 `/init` 打好底子，跑几次真实排障后再用 `/insight` 复盘，把它指出的摩擦补回知识——必要时重跑 `/init` 做系统性整理。知识越完善，AI SRE 越精准好用。
</Tip>
