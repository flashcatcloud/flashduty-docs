## 概述

---

AI SRE 的能力可以通过扩展资源来增强。您在控制台中为 Agent 装配 Skill、接入外部工具（MCP）、沉淀团队知识、指定运行位置，Agent 在诊断故障时便会按需调用这些资源。

这些资源集中在三个入口，对应 AI SRE 左侧菜单：

<CardGroup cols={2}>
  <Card title="插件" icon="puzzle-piece">
    `Plugins` 菜单。下设三个标签页：**Skill**（Skill）、**Agents**（A2A 远端 Agent）、**MCP**（外部工具）。为 Agent 扩展可执行的能力与可委派的对象。
  </Card>
  <Card title="知识库" icon="book">
    `Knowledges` 菜单。以 Knowledge Pack 形式沉淀 DUTY.md、runbook 等运维知识，会话开始或按需挂载，供 Agent 检索。
  </Card>
  <Card title="环境" icon="server">
    `Environments` 菜单。管理您自托管的运行环境（BYOC Runner）。Agent 的工具调用、MCP 连接与 Skill 执行都在所选环境中完成。
  </Card>
</CardGroup>

<Note>
菜单中是否显示某一入口，取决于您在该账户下是否拥有对应的访问权限。无权限的入口不会出现在导航中。
</Note>

## 作用域：账户与团队

---

AI SRE 的**每一类**资源（Skill、知识库、MCP、A2A Agent、运行环境）都携带同一个两级作用域字段 `team_id`：

- `team_id = 0` —— **账户作用域**：在整个账户内可见。
- `team_id > 0` —— **团队作用域**：仅对该团队的成员可见。

控制台中这一选择呈现为「账户或团队…」的范围选择器；列表的「范围」列会显示该行属于「账户」还是某个具体团队。

| 资源类型 | 控制台入口 | 账户作用域（team_id=0） | 团队作用域（team_id>0） |
|---|---|---|---|
| Skill | 插件 → Skill | 账户内所有会话可见、可加载 | 仅该团队成员可见，仅在该团队会话中加载 |
| MCP | 插件 → MCP | 账户内所有 Agent 可调用 | 仅该团队成员可见、可编辑 |
| A2A Agent | 插件 → Agents | 账户内可见，可被 AI SRE 委派 | 仅该团队成员可见、可编辑 |
| 知识库 Knowledge Pack | 知识库 | 对账户内所有 Agent 可见 | 仅在该团队的会话中加载 |
| 运行环境 Environment | 环境 | 账户内所有会话可选用 | 仅该团队成员可见、可编辑 |

<Tip>
控制台对此的原话是：「账户范围在整个账户内可见；团队范围仅对该团队成员可见。」对于知识库，则是：「账户范围的知识对账户内所有 Agent 可见。团队范围的知识仅在该团队的会话中加载。每个目标最多可拥有一个 Pack。」
</Tip>

当某资源不属于您所在的团队时，列表会以「只读（其他团队）」标识——您可以查看，但无法编辑。

**编辑权限**：账户所有者或账户管理员可编辑账户内任意资源；团队成员可编辑本团队的团队作用域资源（无「创建者保留权限」例外）。各资源的具体权限说明见对应专页。

## 运行时如何加载

---

资源的可见性在「编辑界面」与「会话运行时」是两套规则——理解这一点，能帮您预期 Agent 在一次会话中究竟能用到哪些资源。

**会话开始时**，提示词中向 Agent 暴露的资源被限定为：

- 所有**账户作用域**的资源（team_id=0）；
- 加上**当前会话所绑定团队**的资源（例如由作战室故障带入、或在控制台中显式选定的团队）。

其它团队的 Skill / MCP 在会话伊始**不会**出现在 `<available_skills>` / `<available_mcp_servers>` 中。

**会话进行中按需挂载**：当 Agent 读取某个团队的知识入口（`.flashduty/knowledge/team_<id>/DUTY.md`）时，该团队的整套资源——Skill、MCP 与知识——会作为一条常驻的 `<system-reminder>` 挂载进**当前会话**，从该刻起对 Agent 可见可用。

<Note>
**账户是运行时唯一的安全边界**；团队只是所有权与编辑的标签。也就是说，同一账户内任何团队的资源，Agent 都可能在会话过程中通过读取对应团队的知识而合法地挂载；跨账户的资源则在任何情况下都不可见。
</Note>

下面这个流程直观地说明了「按需挂载」：

<Steps>
  <Step title="会话启动">
    Agent 看到账户级资源，以及会话绑定团队的资源。
  </Step>
  <Step title="诊断中引用某团队知识">
    故障定位过程中，Agent 读取 `.flashduty/knowledge/team_<id>/DUTY.md`——通常因为该故障归属或牵涉到这个团队。
  </Step>
  <Step title="该团队资源挂载进会话">
    这个团队的 Skill、MCP、知识随即挂载到当前会话，Agent 可立即调用。
  </Step>
  <Step title="资源在本次会话内持续可用">
    挂载以常驻 system-reminder 的形式保留，直到会话结束。
  </Step>
</Steps>
