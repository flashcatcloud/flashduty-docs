## 概述

AI SRE 每次新会话都从当前范围里已有的记忆文件读起。如果每次都要重新说明您的习惯、某类故障先看哪里、上次为什么放弃了某个做法，排障就得从头介绍背景。记忆把这些从对话里留下来，写成一份份 Markdown 文件，后面的会话继续用。

记忆和[知识](/zh/ai-sre/knowledge)是两回事。知识由人维护，写的是环境怎么运转。记忆由系统整理，写的是从对话里留下来的偏好、做法、事实和教训。两者同属控制台的 [上下文](/zh/ai-sre/context) 分组，但各有一页：**AI SRE → 自定义 → 上下文 → 记忆**。

## 记忆类型

每份记忆文件开头写明名称、一句话说明和类型。类型只有四种：

| 类型 | 适合记下的内容 |
| --- | --- |
| preference（偏好） | 回答习惯，比如先给结论、用哪个时区 |
| procedure（做法） | 某类情况先做哪几步 |
| fact（事实） | 会反复用到的环境事实，比如某个系统归谁 |
| lesson（教训） | 一种做法为什么走不通，下次不要再走 |

文件落在哪，看当时的会话。绑定了团队的会话写入这个团队；没有绑定团队的会话写入您个人。记忆留到您改掉或删掉为止。

## 记忆如何产生

记忆有两条来路：

- **您直接说**：在对话里要求记住、改掉或忘掉一件事，助手会写成或改掉对应的记忆文件。
- **会话结束后整理**：一轮会话结束，系统留下以后还会用到的内容。

两种来路写入的都是当前会话所属的范围。

## Agent 如何使用记忆

会话开始时，当前范围里的记忆文件会准备好。助手先看到每份文件的名称和说明，需要细节时再打开正文。绑定了团队的会话用的是这个团队的记忆；没有绑定团队的会话用的是你个人的记忆。

四类记忆的分量不同：procedure、fact、lesson 是过去的记录，用之前需要按当前情况核实；preference（偏好）是您明确提出的要求，在它说明的范围内照做，与 Skill 或工具的默认做法冲突时，以偏好为准。

## 作用域与隔离

记忆只有 personal（个人）与 team（团队）两种作用域，没有账户级记忆，跨账号读取会被直接拒绝。

| 维度 | personal（个人） | team（团队） |
| --- | --- | --- |
| 归属 | 记忆所属的那个人 | 记忆所属的那个团队 |
| 读取条件 | 记忆所属的本人 | 当前会话绑定该团队，或调用者本人是该团队的真实成员 |
| 豁免 | 不适用 | owner、admin 都没有豁免 |
| 跨团队读取 | 不适用 | 不存在这样的路径 |

这套隔离规则与 AI SRE 其它资源的权限模型一致：team 作用域不因为您是账户 owner 或 admin 而自动放开，必须是该团队的真实成员。

## 在控制台查看和修改

进入 **AI SRE → 自定义 → 上下文 → 记忆**。

- **选范围**：顶部在 **个人** 和 **团队** 之间切换；选团队时再从下拉里挑一个您所属的团队。没有共享（账户级）记忆。范围和团队记在页面地址里，刷新或分享链接会打开同一组记忆。
- **找记忆**：左侧列表按 偏好 / 做法 / 事实 / 教训 分组，组内按更新时间倒序；搜索框按名称、描述和文件名过滤。
- **新建或编辑**：点 **新建记忆**，或在右侧点 **编辑**，填写名称、类型、一句话描述（什么时候用得上）和内容后保存。
- **删除**：删除后，之后的对话不会再参考它。在对话里说忘掉一件事，效果相同。

如果这条记忆在您编辑期间被别人或 AI 改过，保存时会提示，再保存一次会用您的版本覆盖；取消可以查看最新内容。

### 让 AI 修改

有编辑权限时，正文下方有一个输入框（提示语为「想改什么？例如：把发布窗口改成工作日 10:00 到 16:00」）。发送后，控制台打开一个新对话，输入框里已带上这个范围的记忆引用和您的要求。个人记忆会开个人会话，团队记忆会开绑定该团队的会话，因为记忆只写入会话所属的范围。发出后，AI 先用文字说明要新增、合并或删除哪些记忆，您同意后才保存。
