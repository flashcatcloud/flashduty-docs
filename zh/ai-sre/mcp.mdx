> AI SRE 需在控制台开通，面向 On-call 专业版及以上订阅，按实际用量计费，详见[开通与计费](/zh/ai-sre/overview#开通与计费)。

## 概述

**MCP**（Model Context Protocol）让 AI SRE Agent 接入外部工具与数据源。每台 **MCP 服务器**是一个对外暴露一组工具（函数）的标准化端点，例如查询 GitHub Issue、向 Slack 发消息、读取 Kubernetes 资源、检索可观测平台指标等。

在控制台里配置好 MCP 服务器并启用后，Agent 会在排障故障时**自主判断**何时需要外部能力，并直接调用对应工具，无需您手工搬运数据。

<Warning>
本页讲的是 **AI SRE 控制台里的「MCP」**——也就是**Agent 去调用的第三方 MCP 服务器**（您把外部工具接进来给 Agent 用）。

这与开发者文档里的 [Flashduty MCP Server](/zh/developer/mcp-server) 是**两回事**：后者是 **Flashduty 自家对外暴露的 MCP 服务**，供您把 **Flashduty 的能力接入到第三方 AI 客户端**（如 Claude、Cursor）。一个是「Agent 调外部」，一个是「外部调 Flashduty」，方向相反，不要混淆。
</Warning>

## 什么是 MCP

**MCP**（Model Context Protocol，模型上下文协议）是一套开放协议，用统一的方式描述「一台服务器对外提供哪些工具、每个工具接收什么参数、返回什么结果」。它就像 AI Agent 世界的「USB 接口」——任何遵循 MCP 的服务器都能被 Agent 即插即用地发现和调用，无需为每个外部系统单独写适配代码。

在 AI SRE 中，MCP 的作用是把 Agent 的能力从「内置工具」扩展到「任意外部系统」：

- 您在控制台添加一台 MCP 服务器（声明它的端点、传输方式与认证）。
- 会话开始时，已启用且在当前作用域可见的服务器即对 Agent 可见、可调用。
- Agent 在需要时即可发现该服务器提供的工具并直接调用。

<Tip>
**MCP 与 Skill 的区别**：MCP 提供**外部工具的接入能力**，Skill 提供**如何编排这些工具完成一类任务的方法论**。Skill 可以在 `SKILL.md` 中以 `mcp:服务名/工具名` 的形式声明它需要哪台 MCP 服务器的哪个工具。详见 [Skill](/zh/ai-sre/skills)。
</Tip>

## 从市场安装 MCP 服务器

进入 **自定义 → 插件 → 概览** 页面，即可看到 Flashduty 精选的第三方 MCP 模板目录。目录按类别分页签展示（全部 / 可观测 / 云与基础设施 / 数据库与中间件 / 代码与协作 / Skill），右上角的搜索框按名称或描述过滤。

目录上方的 **推荐** 区会根据您账户已配置的告警集成（按近 30 天告警量排序）推荐最多 3 个模板，不包括已安装、需要 Runner 或您无权安装的模板。

<Steps>
  <Step title="找到要连接的模板">
    点击模板行或其右侧的 **+**，打开 **连接** 对话框。需要自托管 Runner 而账户没有可用 Runner 的模板会标注 **需要自托管 Runner**；您无权安装的模板不能点击。
  </Step>
  <Step title="核对模板信息并填写连接参数">
    对话框会显示模板的供应商、官方文档、简介和示例问题，然后填写连接参数。**共享**字段由全账号共用；成员授权（密钥）模式的模板还需要填写**您自己的 API Token**，其他成员首次使用时各自填写。
  </Step>
  <Step title="选择运行环境并提交">
    选择从哪个**运行环境**发起连接（默认为会话所在环境）。只能在内网访问的系统，请选择内网中的自托管 Runner。成员授权（OAuth）模式的模板，点击 **去〈名称〉授权** 后会在浏览器中完成授权，见下文[认证](#认证)。
  </Step>
  <Step title="确认连接结果">
    提交后系统会创建连接器并测试连接。成功后可以点击示例问题，新建一条预填该问题的对话。失败时会显示错误，可以 **重试**；需要 Runner 的模板还可以让 AI SRE 在 Runner 上安装缺失的命令行工具（如 `npx` 需要的 Node.js、`uvx` 需要的 uv）。
  </Step>
</Steps>

<Note>
连接参数以首次提交为准，之后如需修改，请到 **插件 → MCP** 编辑。如果账户中已有同名连接器，请直接使用它，或由账户所有者或管理员改名或删除后再连接。
</Note>

从市场安装的 MCP 服务器会记录来源模板，**固定为共享范围**（账户内所有成员可用）。同一模板在一个账户内只能安装一次。

<Warning>
需要 **BYOC Runner** 的模板只能在您自己部署的 Runner 上使用，云 Sandbox 不支持。当前市场的 50 个模板中，23 个是 **HTTP 流式**、不需要 Runner；27 个是 **stdio**、需要 Runner，包括阿里云 OpenAPI、阿里云可观测、夜莺 Nightingale、Gitee、GreptimeDB、Prometheus、Grafana (Self-Hosted)、Kafka (Confluent)、AWS、ClickHouse、MySQL、PostgreSQL、阿里云 RDS、Redis、MongoDB 等。这些模板通过 `uvx` / `npx` 在本地启动，安装前请确认账户已有可用的 BYOC Runner，详见 [运行环境（BYOC）](/zh/ai-sre/environments)。
</Warning>

### 只能由 Monitors 查询的系统

目录中还列出了**通过 Monitors 查询的系统**（当前是 Loki、VictoriaLogs、Oracle）。它们不能在市场中连接：在 Monitors 中添加这类数据源后，AI SRE 就能直接查询，不需要地址、令牌或 Runner。点击这类行可以看到账户中已有的该类数据源；已有数据源时可以点击 **在对话里试试**，还没有时可以点击 **去 Monitors 添加更多 →**（需要添加数据源的权限）。

部分模板（如 Prometheus、MySQL、PostgreSQL、ClickHouse、Elasticsearch、SLS）同时支持直连 MCP 和通过 Monitors 查询，标签为 `MCP · Monitors`，连接时可以选择接入方式。

<Note>
行名与模板名共用同一套命名空间：如果某个系统已经有同名模板，就只显示模板行（模板行才是带连接参数的那一行）。私有化部署如果**不含 Monitors 模块**，不会显示这些行和 Monitors 接入方式。
</Note>

## 添加 MCP 服务器

进入 **自定义 → 插件 → MCP** 页面，列表页右上角有两个入口：

- **添加 MCP**：点击后弹出表单，手工定义一台 MCP 服务器（字段见下文「基础字段」）。
- **在对话中添加**：新建一条预填提示的会话，由 Agent 询问您要接入自己的服务还是安装现成的，先查插件目录，没有再联网搜索候选供您选择。只有在能确定写入范围时（您有账户级权限，或当前只选中了一个您所属的团队）才显示此按钮。

### 基础字段

| 字段 | 类型 | 是否必填 | 说明 |
| --- | --- | --- | --- |
| 名称 | string | 是 | 服务器名，会作为 Agent 调用时的标识（如 `mcp:sqlite-explorer/query` 中的 `sqlite-explorer`）。须以字母开头，仅含字母、数字、`-`、`_`，长度 1–255。同一账户内**不区分大小写、不可重名**，也不能与内置服务器同名 |
| 传输方式 | 枚举 | 是 | Agent 与服务器通信的方式，见下文「传输方式」 |
| 范围 | 共享 / 团队 | 是 | 该 MCP 服务器的作用域：**共享**（账户内全局可见）或某个**团队**（仅该团队成员可见）。详见下文「作用域」 |
| 执行环境 | 云端环境 / BYOC Runner（可多选） | 否 | 该服务器在哪些执行环境中可用；不选则所有环境可用。调用总是在会话自身的环境中发起，因此只能内网访问的服务请只选能访问它的 Runner。会话环境不在列表中时，见下文[跨环境连接器](#跨环境连接器)。详见 [运行环境（BYOC）](/zh/ai-sre/environments) |
| 描述 | string | 是 | 描述此服务器的功能，便于在列表中识别 |

<Note>
Agent 首次列出某服务器的工具后，系统会自动生成一段 **AI 描述** 显示在列表中，并随工具变化自动更新。
</Note>

### 传输方式

| 传输方式 | 适用场景 | 需填字段 |
| --- | --- | --- |
| HTTP 流式（推荐） | 远程 MCP 服务器，通过 HTTP 端点连接 | URL（端点）、可选 Headers（JSON）；HTTPS 端点可按需开启「跳过 TLS 证书校验」 |
| SSE（独立、旧版） | 仅支持 Server-Sent Events 的旧版远程服务器 | URL（端点）、可选 Headers（JSON）；HTTPS 端点可按需开启「跳过 TLS 证书校验」 |
| stdio（本地命令） | 在 Runner 所在机器上以本地子进程方式启动的 MCP 服务器 | 命令、参数（每行一个）、环境变量（JSON） |

<Warning>
**stdio 仅适用于 BYOC 运行环境**（Runner 部署在您自己的机器上）。云 Sandbox 不能启动本地子进程；如果使用云端运行环境，请改用 **HTTP 流式**或 **SSE**，并确保该 MCP 服务器对 Sandbox 网络可达。运行环境的区别见 [运行环境（BYOC）](/zh/ai-sre/environments)。
</Warning>

<Note>
stdio 命令在 **Runner 所在机器**上运行，而不是您的电脑。不要使用个人路径（如 `/Users/<用户名>/...`），并确保 Runner 上已安装所需的运行时（如 `uv` / `uvx` / `node` / `npx`），否则连接会失败。
</Note>

连接与调用各有一个默认超时：连接超时默认 10 秒，工具调用超时默认 60 秒。

<Warning>
只有当 HTTPS 服务器使用自签证书、且网络环境受控时，才开启「跳过 TLS 证书校验」。不要对公网上不可信的端点开启。
</Warning>

### 认证

MCP 服务器支持三种**授权模式**，决定凭证如何提供给服务器：

<Tabs>
  <Tab title="服务授权（默认）">
    所有会话以同一个服务身份调用。凭证直接写在服务器配置里——HTTP/SSE 传输写进 **Headers**（JSON）（如 `{ "Authorization": "Bearer xxx" }`），stdio 传输写进**环境变量**（JSON）（如 `{ "API_KEY": "xxx" }`）。适合用账户级服务令牌访问的内部系统。

    以下键名（不区分大小写）的值会**加密存储**并以掩码显示，其余按原样保存，因此请把凭证放在这类键名下（如 `Authorization`、`X-API-Key`、`GITHUB_TOKEN`）：

    - 包含 `KEY`、`SECRET`、`TOKEN`、`PASSWORD`、`PASSWD`、`CREDENTIAL` 或 `AUTHORIZATION`；
    - 或按非字母数字字符拆分后，某一段正好是 `PWD` 或 `PASS`（如 `REDIS_PWD`、`db-pass`；`BYPASS`、`COMPASS` 不算）。

    账户内任何会话都能以这个身份调用该系统。涉及个人数据或高危写操作时，建议改用成员授权。
  </Tab>
  <Tab title="成员授权（密钥）">
    每位成员在**首次调用**时提供自己的密钥，密钥加密存储并按成员隔离。

    选择此模式需要填写**密钥 Schema**：

    | 字段 | 是否必填 | 说明 |
    | --- | --- | --- |
    | Header 名称 | 是 | 凭证注入到 MCP 请求的哪个 HTTP header（如 `X-Api-Key`） |
    | 帮助链接 | 否 | 指向「如何获取该密钥」的文档链接 |

    适合每个工程师使用各自 API Key 的第三方 SaaS（如个人 GitHub Token）。
  </Tab>
  <Tab title="成员授权（OAuth）">
    成员通过 **OAuth 2.1** 各自授权，首次调用时自动弹出授权窗口。支持动态客户端注册（DCR）；授权服务器不支持 DCR 但支持 Client ID Metadata Document 时也能自动完成，无需额外配置。令牌按成员存储，临近过期时自动刷新。适合支持 OAuth 的服务。
  </Tab>
</Tabs>

<Note>
成员授权模式下，缺少凭证时工具调用会暂停，提示当前成员填写或授权，完成后继续。
</Note>

### MCP 服务器授权（设置页）

成员授权（密钥 / OAuth）的凭证按成员隔离。除了在对话中按提示授权，您也可以在 MCP 列表中主动管理自己的授权，两种方式保存的是同一份凭证。

**授权状态**：MCP 列表的「**成员授权**」列显示您自己的授权状态：

- **成员授权（OAuth）**：**● 已连接**（已保存有效凭证）/ **○ 未连接**（尚未提供凭证）。
- **成员授权（密钥）**：**● 已保存** / **○ 未填写**。系统不会验证密钥是否有效。
- 两种模式通用：**⚠ 已过期**（凭证已过期，OAuth 令牌到期，需重新授权）。

服务授权模式显示为「—」。点击授权入口打开**凭证**对话框，它只管理您自己的凭证，不会改动服务器配置。

**凭证对话框中的操作**：

- **成员授权（OAuth）**：选择**执行环境**（云端 Sandbox 或在线的 BYOC Runner，不能选「自动」），然后点击 **去授权** 或 **重新授权**，在弹出的浏览器窗口中完成授权，无需复制令牌。只能从内网访问的 OAuth 服务，请选择能访问它的 Runner。系统会默认选中上次授权成功且在线的环境。
- **成员授权（密钥）**：点击 **填密钥** 或 **更新密钥**。
- **撤销**：删除您保存的凭证。

## 管理与检视

MCP 列表显示您添加的每台服务器的名称与描述、范围（共享或团队）、传输方式和启用状态。可以按「全部 / 共享 / 团队」筛选，并按名称、描述、传输方式或 URL 搜索。内置的 Flashduty MCP 服务器不在此列表中。

<AccordionGroup>
  <Accordion title="启用 / 禁用" icon="toggle-on">
    用列表里的开关切换。只有**已启用**的服务器才会对 Agent 可见；禁用后 Agent 看不到、也无法调用它。

    已停用的连接器不能在 **连接** 入口中使用，也不会出现在 **插件 → 概览** 的已启用区，需要账户所有者或管理员在 **插件 → MCP** 中重新启用。
  </Accordion>
  <Accordion title="编辑" icon="pen-to-square">
    点击编辑按钮（或直接点击行）打开表单，可修改名称、传输方式、描述、端点 / 命令、授权模式与作用域。无编辑权限时表单以**只读**模式打开，并提示原因。
  </Accordion>
  <Accordion title="删除" icon="trash">
    将 MCP 服务器从当前范围移除。**依赖它的 Agent 将无法再访问其工具**，正在使用它的活跃会话会随之失败。此操作有确认提示。
  </Accordion>
</AccordionGroup>

### 检视：查看某台服务器暴露的工具

控制台不展示 MCP 服务器的工具列表，因为同一台服务器在不同运行环境中的可达性和工具可能不同。

<Tip>
想确认某台 MCP 服务器在某个运行环境下实际暴露了哪些工具，最直接的方式是在**对话**里让 Agent 列出该服务器的工具，它会把工具清单与每个工具的用法列出来。详见 [对话](/zh/ai-sre/sessions)。
</Tip>

<Note>
Agent 读取 Flashduty 故障、告警等数据的能力是**内置**的（Flashduty MCP 服务器），默认可用，不需要也不能在此配置。
</Note>

### 跨环境连接器

MCP 服务器可能绑定在**当前会话之外的执行环境**中。由于不同环境的网络不互通，会话不能直接调用它，但 Agent 知道它的存在：

- Agent 能看到这类连接器的名称、用途和可用环境，按名字询问时也会得到说明，而不是「找不到」。
- Agent 会派一个子代理到目标环境中调用它（见 [Agent](/zh/ai-sre/agents)），再把结果带回当前对话。
- 只能派往**在线**的账户级 Runner、当前会话所绑定团队的 Runner，以及绑定的云端环境；其他环境 Agent 会说明暂时无法使用。
- 只有主会话能这样派发，子代理不能再派发。

在**当前**环境里直接可用，把它加进该服务器的「执行环境」列表即可（前提是它对这个会话可达）。运行环境本身的区别见 [运行环境（BYOC）](/zh/ai-sre/environments)。

## 作用域

MCP 与其他资源（Skill、知识、Agent、运行环境）共用同一套**两级作用域**模型，分为共享范围与团队范围：

| 作用域 | 可见性 |
| --- | --- |
| 共享 | 账户内所有成员可见 |
| 团队级 | 仅该团队成员可见 |

**编辑权限**：团队级 MCP 服务器只有该团队成员可以编辑（组织管理员也需先加入该团队）；共享范围的服务器只有账户所有者或管理员可以编辑。

**创建与改归属**：

- 创建团队级服务器需要是该团队成员；创建共享范围的服务器仅限账户所有者或管理员。
- 从市场安装的服务器固定为共享范围，任何成员都可以安装。例外：成员授权模式下还需要填写自定义地址的模板，只有账户所有者或管理员能安装，以免其他成员的凭证被发往安装者指定的地址。
- 账户所有者或管理员可以把服务器移到任意团队（用于接管空团队或离职成员的资源）；普通成员只能移到自己所属的团队。
- 市场安装的服务器不能改为团队范围；少数早期安装的团队级服务器可以由账户所有者或管理员改为共享范围。

**运行时可见性**：会话开始时，Agent 只能使用共享范围和会话所绑定团队的 MCP 服务器；读取其他团队的知识后，才会按需加载该团队的 MCP 服务器与 Skill。**账户是运行时唯一的安全边界，团队只用于归属与编辑权限。**
