## 概述

排障往往就发生在您的 IM 群里——告警推过来、大家在群里讨论、拉个作战室。AI SRE 把 Agent 直接放进这条协作链路：**您不必切换到控制台，就能在 IM 里召唤它排查**，团队成员也能全程看到它的分析过程。

AI SRE 的 IM 集成有四种触发方式：

<CardGroup cols={2}>
  <Card title="@ 提及召唤" icon="at">
    在群聊或私聊里 **@ AI SRE** 并描述问题，即可发起或续接一次排查。它在**线程内**回答，对话上下文与这条 IM 会话绑定。
  </Card>
  <Card title="作战室自动诊断" icon="people-group">
    为故障开启 IM 作战室时，若账户里有一条启用中的 **作战室创建触发** 自动化规则、且这条故障的协作空间与严重程度命中该规则，AI SRE 会执行一轮初步诊断，并把结论作为一条分析消息发回作战室——无需任何人手动召唤。
  </Card>
  <Card title="群内自动化回帖" icon="clock">
    在群里让 AI SRE 建一条普通自动化规则，它就把**当前这个群**作为运行位置：之后按周期、API 或 On-call 故障触发时，在原群里**新开一个会话**跑这一轮，结论直接回帖到群里。每次运行都是全新的会话，不带入群里的历史对话；集成开启话题回复时也新开一个话题，本次运行的第一条真实输出（进展或结论）就是话题的根消息，产出内容之前不会先发“已开始”之类的占位消息。绑定与范围在创建时固定、不能改到别的群：运行前会复核，群的团队范围或会话已变就整次**跳过**。
  </Card>
  <Card title="主动接话" icon="comment-dots">
    在集成里开启 **允许 AI 主动接话** 后，AI SRE 也会读到群里**没有被 @ 它**的消息，只在判断某条消息值得回复时才接话；@ 它的消息仍然必回。默认关闭，仅 Slack、飞书 / Lark 与 Microsoft Teams 支持，某个群还可以单独关掉。
  </Card>
</CardGroup>

前两种方式由人发起，第三种由您配好的自动化规则发起，第四种由 AI 自己判断这条消息要不要接。规则怎么建、执行位置与范围怎么固定，见[自动化](/zh/ai-sre/automations#执行位置规则跑在哪里)。

## 支持的 IM 平台

AI SRE 的 IM 交互覆盖四个主流平台，每个平台都支持入站的 @ 提及（webhook）、历史消息读取与出站回复：

| 平台 | 群聊 @ 提及 | 私聊（DM） | 处理中回执 | 主动接话 |
| --- | --- | --- | --- | --- |
| Slack | ✅ | ✅ | ✅ 表情（另有原生“正在处理”状态） | ✅ |
| 飞书 / Lark | ✅ | ✅ | ✅ 表情 | ✅ |
| 钉钉 / DingTalk | ✅ | ✅ | ✅ 内置表情 | ❌ 不支持 |
| 企业微信 / WeCom | ✅ | ✅ | ✅ 占位消息 | ❌ 不支持 |

“处理中回执”是机器人收到您的消息后给出的即时信号，各平台的具体形式见[处理中回执](#处理中回执)。Microsoft Teams 也支持 IM 交互与 **主动接话**（见 [Microsoft Teams](/zh/on-call/integration/instant-messaging/microsoft-teams)），不在上表之列；钉钉与企业微信不支持主动接话。

<Note>
IM 交互依赖您已在 Flashduty 中接入对应平台的机器人（用于告警通知与协作的同一套 IM 机器人）。请先在 Flashduty 的 IM 集成中完成机器人配置，AI SRE 才能在该平台收发消息。
</Note>

## IM 集成中的 AI SRE 设置

在 **On-call → 集成中心 → 集成列表 → 即时消息** 打开对应 IM 集成详情，在 **增强功能** 中配置该集成的 AI SRE 行为。以下三个开关中，前两个默认开启，最后一个默认关闭：

- **允许在 IM 中使用 AI SRE**：无需开启作战室即可配置，同时控制 **群聊 @ 提及** 与 **机器人私聊** 两个入口；Slack 在此之外还控制 `/fd` 命令。关闭后，群聊 @ 提及、机器人私聊（Slack 另含 `/fd` 命令）都不会触发 AI SRE 回复。企业微信的第三方应用模式只支持机器人私聊，群聊 @ 提及需使用企业自建应用模式。
- **普通群聊中 AI SRE 使用话题回复**：仅飞书/Lark 与 Slack 提供。开启后，普通群聊中的每个话题对应一个独立 Session；作战室仍直接在群内回复。
- **允许 AI 主动接话**：仅 Slack、飞书 / Lark 与 Microsoft Teams 提供，钉钉与企业微信没有这个开关。开启后，AI 会读取本集成接入的群聊里**未被 @ 的消息**，只在判断值得回复时才回复；@ 仍然必回。它读到但判断不值得回复的消息，既不会有回执，也不会有回复。每个群可以用 `/ambient off` 单独关掉（见 [/ambient 命令](#ambient-command)）。

<Note>
若账户尚未开通 AI SRE，这些开关不会实际生效；开通后会按各 IM 集成自己的设置生效。
</Note>

## @ 提及召唤

在已接入并开启了 **允许在 IM 中使用 AI SRE** 的 IM 群里 **@ 机器人** 并写下您的问题（例如“@AI SRE 看下 payment 服务为什么 5xx 飙升”），消息会通过平台 webhook 转给 AI SRE 处理：

<Steps>
  <Step title="识别提及">
    平台区分**群聊 @ 提及**与**私聊消息**两种入口。被提及后，AI SRE 会给这条消息添加一个“处理中”回执（见[处理中回执](#处理中回执)），并识别消息里是否带有斜杠命令。
  </Step>
  <Step title="绑定会话">
    同一个 IM 会话里的多次 @ 提及，会续接到**同一个 Agent 会话**，从而保留上下文。若是新会话，AI SRE 会带入该 IM 线程的起始消息，以及（若有）关联的故障作为初始上下文。在开启了话题回复的飞书 / Lark 群里，由**顶层 @** 新开的话题会话还会额外带入该群**最近 10 分钟**（截止到这条 @ 为止）的群消息，您在 @ 之前贴的报错文本或截图就是这样进入上下文的；话题内的回复只读它自己那个话题。
  </Step>
  <Step title="读取上下文作答">
    AI SRE 读取线程 / 会话的历史消息构建上下文，自主排查，并把结论**在线程内**回复。消息里一并 @ 到的其他人也会被保留为提及对象，在回复中带上，方便多方在群里协作。
  </Step>
</Steps>

<Tip>
**回复模式**可配置（off / first / all），决定 AI SRE 是否在回复时 @ 提问者、以及是在**线程内**还是主频道作答。在嘈杂的大群里，线程内回复能让排查讨论保持聚拢、不刷屏。
</Tip>

### 附件与图片

聊天里的图片、文档与语音，AI SRE 会自己下载并作为文件交给 Agent。不只是 **@ 它那条消息**上的附件，**同一线程 / 会话里更早的消息**上的附件也会一并带上：您先贴一张报错截图、再补一句“@bot 这个怎么回事”，模型拿到的是那张截图。

每轮的附件额度按类型计算，当前这条消息的附件先占额度，历史消息从剩下的额度里补，从最新的一条往前挑：

| 类型 | 每轮上限 |
| --- | --- |
| 图片 | 5 个 |
| 文档 | 3 个 |
| 语音 | 3 个 |

- **放不进额度的历史附件**：在提示里标注为“未附带”，不会承诺一个实际不存在的文件。
- **超限即拒**：单个附件超过 20 MiB，或直链不是 HTTPS，都会被拒绝。
- **历史附件有时间预算**：约 5 秒内没下载完的历史附件按“未附带”处理，排查不会为一张旧截图卡住。
- **当前消息的附件全部失败**：AI SRE 不调用 Agent，直接回复“无法处理本次附带的附件。请重试，或发送较小的文件。”；历史附件失败不会中止排查。

### 处理中回执

收到您的消息后，机器人会先给**您发出的那条消息**添加一个表情回执，作为“已收到、正在处理”的即时信号。表情从该平台的一小组表情里随机选取：

| 平台 | 表情 |
| --- | --- |
| Slack | eyes、hourglass_flowing_sand |
| 飞书 / Lark | Typing、OneSecond |
| 钉钉 / DingTalk | 平台内置表情：专注、忙疯了 |

Slack 除此之外还会显示一条原生的“正在处理”状态，与表情回执并存。

答案送达后，回执会被移除。

开启 **允许 AI 主动接话** 后，回执只加在 AI 决定接话的那条消息上：它读到但判断不值得回复的消息，既不会有回执，也不会有回复。

企业微信没有表情接口，它的“处理中”回执是一条占位消息（随机的一句“收到，处理中⋯⋯”），随后被任务清单卡片与最终回答就地替换。

### 答复如何抵达聊天

您把一次排查交给 AI SRE 之后，群里出现的每一条消息都属于两类之一：

- **结论**：回答您的具体问题，或给出一个可行动的阶段性结论。
- **进展**：工作仍在进行时的一两句话更新，说明确认的进展、当前在等什么、遇到的真实阻塞。进展消息**不是结论**，不结束这轮任务，结论会照常单独发出。

当 AI SRE 把工作交给后台子代理（Subagent 或 A2A 委派）、而这一轮还没有向聊天发过任何消息时，它会先发一条简短的**受理说明**——说明派了什么、结论会在子代理回报时补上——不会让群里一直静默到子代理跑完。这条同样属于进展消息，不结束本轮。

这套回复方式只作用于**由人发起的 IM 请求**：控制台会话仍按流式文本作答；作战室自动诊断是无人值守的后台回合，也保持流式输出。

<Note>
答复过长时，AI SRE 会精简内容，或把详细证据发布为产物，只在聊天里发结论和产物链接（见[产物](/zh/ai-sre/artifacts)）。如果您明确要求把完整报告贴在聊天里，则不受此限制。
</Note>

## 作战室自动诊断

作战室建好后 AI SRE 是否自动进场，由账户里的 **作战室创建触发** 自动化规则决定，而不是 IM 集成上的某个开关：**有命中的规则才跑，没有就不跑**。这条链路不需要任何人 @ 它，但前提是您已经配好这样一条规则：

<Steps>
  <Step title="创建作战室">
    在故障的协作流程中创建作战室（飞书 / 钉钉 / 企业微信 / Slack 群）。
  </Step>
  <Step title="匹配作战室创建触发的规则">
    平台会拿这次创建去匹配账户里已启用的 **作战室创建触发** 规则：故障所属**协作空间**要在规则选中的列表里，故障**严重程度**也要命中规则，两项都满足才会启动一轮运行。没有命中的规则时不产生任何分析。
  </Step>
  <Step title="发回结论">
    这次运行以该作战室的 IM 群为会话落点（不建控制台会话），AI SRE 带着这个故障的上下文排查，并把结论发回作战室。人还没开始排查，第一手分析就已经摆在群里了。
  </Step>
</Steps>

规则的触发卡片上要选什么、怎么建，见[自动化 · 作战室创建触发](/zh/ai-sre/automations#作战室创建触发war-room-created)。

<Note>
作战室自动诊断与故障上下文绑定：进入排查时，对应的 `incident_id` 会绑定到本次运行，AI SRE 可据此读取故障详情、时间线与近期变更。关于故障 / 作战室与 A2A 的联动细节，见 [Agent · 故障与作战室联动](/zh/ai-sre/agents#故障与作战室联动)。
</Note>

## 常驻任务与监控中卡片

Agent 的当前回合结束时，如果它留下的**常驻进程类任务**还在运行（例如 monitor 监视器、后台命令），AI SRE 会向聊天中投递一条监控中卡片：

```
🔭 监控中：<任务描述>（最多 N 分钟）
🔭 监控中：<任务描述>（无限期）
```

每个常驻任务占一行：任务自带截止时间的显示剩余分钟数（不足 1 分钟按 1 分钟计），没有截止时间的显示“无限期”。常驻任务列表发生变化时卡片会重新投递。

<Note>
常驻任务存活期间，本次 IM 会话的根消息保持打开（不关闭事故视图）：后续由任务通知触发的回合继续投递到**同一个聊天**，无需重新 @ 召唤。
</Note>

通知回合没有新内容时，AI SRE 不会向聊天发送任何消息；只有出现新结论时才会发言。

### 长排查中的进展消息

排查时间较长时，AI SRE 会在群里发一两条进展消息，说明还在查什么、卡在哪、下一步看什么。进展消息不是结论，不结束这轮任务，结论随后单独发出。如果没有新进展，或正在等您补充信息，AI SRE 可以不发。

## 连接与授权

控制台中缺少凭证时会显示授权卡片（见[控制台对话](/zh/ai-sre/sessions#需要授权时)），**IM 与 API 渠道没有卡片**，处理方式如下：

| 情况 | IM / API 渠道的行为 |
| --- | --- |
| 缺少您的 OAuth 授权 | Agent 发出授权链接，请在**电脑浏览器**中打开完成授权，然后回复 **“已授权”**（英文会话回复 `authorized`）继续。授权成功不会自动继续 |
| 缺少您的密钥 | Agent 会请您在**网页控制台打开同一会话**填写，不会让您在聊天里粘贴密钥 |
| 账户尚未连接所需的集成 | Agent 发出控制台中的连接链接，连接后回复 **“继续”**（英文会话回复 `continue`） |
| 共享服务器自身的凭证（环境变量 / Header） | 不走上面任何流程：在 **自定义 → 插件 → MCP**（该服务器）里填写，填完让 Agent 重试 |

自动化（`automation`）渠道没有人值守、也不会有回复：Agent 不会等待、不会把话写成问句，而是把缺失的连接或授权**记为阻塞项**写进最终报告，并交付已有证据能支持的部分。

## IM 会话内切换命令

IM 会话没有控制台那样的选择器 UI，但支持三条斜杠命令在**对话进行中**调整会话绑定与接话方式——控制台会话不支持这些操作：环境与团队绑定在创建时固定、不可变更，AI 主动接话也只在 IM 群聊里配置。

### /env — 切换运行环境

在群聊或私聊里向机器人发送 `/env <目标>`，可将当前 IM 会话重新绑定到另一个运行环境，对话历史与上下文完整保留。切换后，旧环境的工作目录不再可用：本次对话中在旧环境里创建或修改的文件已丢失，技能与知识文件会在新环境中按需重新挂载。

`<目标>` 有三种写法：

| 写法 | 切换到 |
| --- | --- |
| `/env <runner名称>` | 指定的在线 BYOC Runner |
| `/env sandbox` | 默认的云端沙箱 |
| `/env sandbox <模板名>` | 指定的云端沙箱模板（共享模板，或您所在团队的模板） |

直接发送不带参数的 `/env`，机器人会列出当前可切换的全部目标：共享环境、您所在团队的环境，以及云端沙箱（默认沙箱与各个命名模板）。找不到指定的沙箱模板时，机器人会回复“未找到名为“x”的云端沙箱模板。使用 /env sandbox 选择默认沙箱。”并附上可选模板列表。

<Note>
切换在当前轮次结束、下一条消息处理之前生效，不会打断正在进行的工具调用。若目标 Runner 离线或不存在，命令会立即报错且绑定不变。
</Note>

<Note>
**私有化部署没有云端沙箱**：私有化部署不运行云端沙箱设施，因此 `/env` 的沙箱选项、沙箱列表项与相关提示文案都不会出现，只能在 BYOC Runner 与“自动”之间切换。
</Note>

### /scope — 切换团队作用域

在群聊或私聊里向机器人发送 `/scope <团队名>`（或 `/scope personal` 切回个人作用域），可将当前 IM 会话重新绑定到指定团队，无需结束对话并新建会话。团队绑定是**使用权操作**，账户内任意成员均可将会话绑定到账户内的任意团队——这与作战室中响应人员通常不属于故障所属团队的场景一致。

切换后，AI SRE 会：

1. 将记忆快照刷新为新团队作用域下的记忆（旧团队的记忆不再适用于本次会话）。
2. 把新团队的知识排入挂载队列，在下一条消息处理时自动注入上下文。
3. 检查本次会话钉定的运行环境是否仍然可用：如果钉定的是**另一个团队独有**的 BYOC Runner 或云端沙箱模板，会把运行环境改回“自动选择”，并回复““x”不属于当前团队，运行环境已改回自动选择。”共享环境与账户级环境不受影响；无法确认归属时（例如模板列表拉取失败）保持原有钉定不变。

<Note>
已挂载到本次会话的知识不会被移除——挂载是对话级别的，切回之前挂载过的团队不会重复注入提醒。
</Note>

<span id="ambient-command"></span>
### /ambient — 控制本群是否主动接话

在**群聊**里向机器人发送 `/ambient <取值>`，只调整当前这个群接不接话，既不影响集成上的开关，也不影响其他群：

| 取值 | 作用 |
| --- | --- |
| `/ambient on` | 本群主动接话。集成没有开启 **允许 AI 主动接话** 时会被拒绝，并提示先在集成设置里开启 |
| `/ambient off` | 本群只响应 @ 提及，未被 @ 的消息不会得到回复 |
| `/ambient inherit` | 删除本群的取值，回到跟随集成开关 |
| `/ambient status` | 汇报本群当前生效的状态，以及本群的取值 |

直接发送不带参数的 `/ambient`，等同 `/ambient status`。

- 集成上的 **允许 AI 主动接话** 是总开关，群里的取值只能在它允许的范围内调整：集成关闭时 `/ambient on` 不生效，`/ambient off` 始终可用。
- 只能在群聊里配置，在私聊里发送会被拒绝；钉钉与企业微信不支持该命令。
- 本群的取值保留 30 天，过期后自动回到跟随集成开关。
- 不论本群取值如何，@ 机器人的消息仍然必回。
- Slack 上同一动作写成 `/fd ambient <取值>`。

## /feedback — 评价 AI SRE 的回复

AI SRE 的回复进入群聊后，群里任何人都可以评价它——不只是发起排查的人。向机器人发送 `/feedback`，即可对您正在看的那条回复给出评价或评论：

- **入口与定位**：`/feedback` 会对应到您正在看的那条回复，即使您没有参与过那次对话。
- **评价资格**：**不限会话成员**，账户内任何可使用 AI SRE 的成员都可以评价（只读群聊读者同样可以）。
- **评价方式**：可选 `like` / `dislike` / `none`；只写评论不选评价也可以提交（空评价不会清掉您之前给过的评价），显式的 `none` 才会清除已有评价。
- **多人评价**：同一条回复被群里多个人评价，各人的评价都会保留，互不覆盖。
- **控制台侧**：控制台会话头部也有对回复的点赞反馈（见 [会话反馈](/zh/ai-sre/sessions#会话反馈)），与 IM 的 `/feedback` 共用同一套评价体系。

## 与控制台会话的关系

无论从 IM 还是控制台发起，**都是同一个 AI SRE**：按顺序处理消息、流式输出、长对话自动压缩上下文、可绑定团队与运行环境。区别只在入口——

- **控制台**：在“对话”工作区里逐条提问、查看完整的工具调用与子会话面板；环境与团队绑定在创建时固定，后续不可变更。
- **IM**：在您日常协作的群里 @ 召唤，结论发回线程；支持 `/env` 和 `/scope` 命令在对话中途动态切换绑定，以及 `/ambient` 控制本群是否主动接话，适合在故障现场快速拿到分析，再到控制台深入。

会话的更多细节见 [对话](/zh/ai-sre/sessions)。
