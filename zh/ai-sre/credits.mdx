<Info>
  AI SRE 按 credits 计量模型用量、沙箱在线时长和联网检索。本页说明计费页面上每一栏的含义、按量付费怎么设、谁有权改，以及额度快用完时系统会怎么拦、怎么提醒。计费项与单价、资源包档位、抵扣顺序、有效期与退款规则以 [AI SRE credits 资源包购买协议](/zh/compliance/ai-sre-credit-package-purchase-agreement) 为准。
</Info>

## 计费入口与可见性

---

AI SRE 的额度与按量付费设置都在控制台的 **费用中心 → 订阅** 页面，切到 **AI SRE** 标签页即可查看（直达地址 `/wallet/plan?product=ai-sre`）。该标签页由三块内容组成：

| 区块 | 内容 |
| --- | --- |
| 开通状态 | 账户是**已开通**还是**未开通**，以及**当前账期**（本周期起止，按账户计费时区的当地零点显示）。未开通时这里给出开通按钮 |
| 额度概览 | 体验赠送剩余、资源包剩余（含最早到期日）、本周期按量已用 |
| 按量付费 | 月度上限的三种状态与保存按钮，**仅在账户已开通后显示** |

<Note>
控制台的额度卡片把 credits 显示为「积分」，「积分额度」即 credits 余额——两者是同一个单位，本页统一写作 credits。
</Note>

两点可见性限制：

- **按账户分批开放**：计费入口按账户逐步放开，判断结果就在额度概览响应的 `visible` 字段里。尚未放开的账户看不到 AI SRE 标签页，直接打开上面的地址会落回 On-call 标签页。
- **私有化部署不出现**：私有化部署不计量、不收费，因此既没有计费入口，也不会被额度拦截。

## 额度概览：每一栏是什么意思

---

| 控制台展示项 | 含义 |
| --- | --- |
| 积分额度（总计） | 体验赠送剩余 + 资源包剩余 |
| 体验赠送剩余 | Flashduty 发放的体验 credits 余额。每个计费周期最多发放一次，只发给没有其他资金来源的账户；随周期到期、不跨周期累积，账户终止 AI SRE 时清零 |
| 资源包剩余 | 未过期的已购资源包余额合计。有多张资源包时显示**最早到期日**（「最早 YYYY-MM-DD 到期」），抵扣顺序为体验赠送 → 最早到期的资源包 → 按量付费 |
| 当前账期 | 本周期的起止日期。按量已用额度与上限都按这个周期结算，周期切换后本周期按量已用清零 |
| 本周期按量已用 | 本周期已按量付费结算的金额（¥）。设置了月度上限时，这一栏以「已用 / 上限」的进度条形式展示 |

<Warning>
计费页面只展示 credits 与金额，不展示模型 token 明细。credits 的计量、结算与抵扣顺序见 [AI SRE credits 资源包购买协议](/zh/compliance/ai-sre-credit-package-purchase-agreement)。
</Warning>

## 按量付费的三种状态

---

「按量付费」指体验赠送与资源包都耗尽后，继续从账户通用钱包结算的方式。开通 AI SRE 即表示授权按量付费，它的上限是一个**金额**（¥），有三种状态，互不等价：

| 状态 | 控制台选项 | 含义 | 接口取值（`monthly_limit_amount`） |
| --- | --- | --- | --- |
| 不限额 | **不限额**（默认） | 资源包用完后持续按量付费，不设上限 | 字段省略或 JSON `null` |
| 月度上限 | **设置月度上限** + 填写金额 | 本周期按量付费最多消耗这么多金额 | 大于 0 的金额 |
| 禁止按量付费 | **禁止按量付费（资源包用完后停止运行）** | 完全不使用按量付费，资源包用完即停止运行 | `0` |

<Note>
`null` 与 `0` 是两种不同的状态，不要互相当作等价：`null` 是"没有上限"，`0` 是"不许按量付费"。控制台把金额四舍五入显示到小数点后 2 位，内部结算精度高于展示精度。
</Note>

达到上限（或选择禁止按量付费）后，**新的运行会被停止准入，正在进行的那一次运行可以跑完**。它跑完时产生的超出部分由 Flashduty 承担，不会向你收取，赠送与资源包余额也不会被扣成负数——按量付费的实际扣费金额不会超过你设置的上限。细节见 [购买协议](/zh/compliance/ai-sre-credit-package-purchase-agreement)。

设置月度上限：

<Steps>
  <Step title="进入计费页">
    打开 **费用中心 → 订阅 → AI SRE** 标签页（`/wallet/plan?product=ai-sre`）。按量付费卡片只在账户**已开通** AI SRE 后出现。
  </Step>
  <Step title="选择状态">
    在「月度上限」下选择 **不限额**、**设置月度上限**（填写一个大于 0 的金额）或 **禁止按量付费**。
  </Step>
  <Step title="保存">
    点击 **保存**。保存成功后页面用服务端返回的最新概览刷新，并提示「按量付费上限已保存」；保存后服务端会同步刷新准入判据，新的运行随即按新上限判断。
  </Step>
</Steps>

<Warning>
上限以金额（¥）表达，但它是本周期按量付费的额度上限，不是钱包余额提醒的阈值——两者是不同的功能，见 [与钱包余额不足提醒的区别](#与钱包余额不足提醒的区别)。
</Warning>

## 权限：谁能看、谁能改

---

| 操作 | 接口 | 权限要求 |
| --- | --- | --- |
| 查看额度概览 | `POST /safari/credits/overview` | **任何成员**。额度是账户级共享的，拦截时任何成员都会撞上，所以查看不设管理员门槛；对应权限点 `credits:read:overview`，归属费用中心的「查看」权限 |
| 修改按量付费上限 | `POST /safari/credits/limit` | **仅账户所有者 / 管理员**。非管理员调用会被服务端拒绝，提示 `Only account admins can change the pay-as-you-go credits cap.`；对应权限点 `credits:write:limit`，归属费用中心的「管理」权限 |

控制台里「开通 AI SRE」「购买资源包」「保存」这几个按钮还额外要求**钱包交易权限**（`wallet:buy`，页面上标注「需钱包交易权限」）。角色与权限点的对应关系见 [权限设计](/zh/platform/permission-design)。

若账户尚未开通 AI SRE，修改上限会返回 404 并提示 `AI SRE credits has not been enabled for this account yet.`——开通是一次独立的动作，改上限不会顺带把账户开通。

## 额度不足时的拦截

---

在准入时刻，服务端会判断"这个账户现在还能不能开始新的 AI SRE 工作"。三种情况都会拒绝新的运行，各带一句已经写清解法、并按调用方语言本地化的提示：

| `blocked_reason` | 情况 | 服务端提示（中文控制台） |
| --- | --- | --- |
| `not_enabled` | 账户尚未开通 AI SRE | 本账户尚未开通 AI SRE，开通后即可使用。 |
| `balance_exhausted` | 体验赠送、资源包与按量额度（或上限）都已用尽 | 本账户的 AI SRE credits 本周期额度已用完，可购买资源包或调高用量上限后继续使用。 |
| `wallet_insufficient` | 只能靠按量付费出资，但账户通用钱包余额不足 | 账户余额不足，请充值后继续以按量付费方式使用 AI SRE；刚完成的充值可能需要几分钟才生效。 |

这两个字段也直接出现在额度概览响应里（`blocked_reason` / `blocked_message`），控制台据此在发送框上方常驻一条**不可关闭**的警示横幅，并同步禁用发送按钮，横幅右侧的 **前往 AI SRE 计费** 按钮指向计费页。横幅的具体行为见 [控制台 → 账户级计费拦截](/zh/ai-sre/sessions)。

## 额度不足提醒（自动短信）

---

除了被拒绝时的那句提示，系统还会在额度**快用完但还没用完**时主动发一条短信——它是自动的，没有开关，也不需要配置阈值：

| 项目 | 规则 |
| --- | --- |
| 触发条件 | 剩余可用额度降到总额度的 **20%** |
| 总额度怎么算 | 体验赠送余额 + 未过期资源包余额 + 本周期按量剩余额度（上限减去已用），**合并计算**。只按量付费一种资金来源时，等价于"按量已用到上限的 80%" |
| 临近到期怎么算 | **7 天内到期**的资源包 credits 视为已经不可用：它仍计入总额度，但不计入剩余额度。资源包快到期时会因此提前提醒 |
| 谁会被提醒 | 只提醒已开通 AI SRE 的账户（体验模式账户、未开通账户、私有化部署都不在此列）。完全没有可用额度、已经被拦截的账户不会再收到"你快用完了" |
| 通道 | **短信**，发往账户资料里的手机号；没有手机号时不会发送 |
| 频率 | 每个计费周期**最多一条**。购买资源包后总额度上升，会重新具备提醒条件——同一周期内可能再收到一条 |
| 检查时机 | 随小时级的用量结算检查，因此从跌破阈值到收到短信可能有约一小时的延迟；发送失败会在下一个小时重试 |
| 内容口径 | **只说 credits，从不出现 ¥ 金额**，并指明两个解法：购买资源包，或调高用量上限——与上面那张拦截表给的动作一致 |

短信长这样（`XXX` 为账户名与剩余 credits，credits 保留两位小数）：

> 您的账户（XXX）AI SRE 本周期可用额度仅剩 416.19，不足两成，用完后将无法继续使用。请前往控制台购买资源包或调高用量上限。

### 与钱包余额不足提醒的区别

---

Flashduty 还有一条**钱包**层面的余额提醒，两者针对的对象、阈值和渠道都不同，不要混淆：

| | AI SRE 额度不足提醒 | 钱包余额不足提醒 |
| --- | --- | --- |
| 针对 | AI SRE 本周期的可用额度（体验赠送 + 资源包 + 按量剩余） | 账户通用钱包的可用余额 |
| 量纲 | credits，**从不出现金额** | 金额（¥），自行设置阈值（不小于 1 元） |
| 开启方式 | 自动，无开关 | 在 **可用余额 → 自动化 → 余额不足提醒** 中自行开启并设置阈值，需 **费用管理** 权限 |
| 渠道 | 短信 | 短信 + 邮件 |

钱包余额不足提醒的完整说明见 [定价 → 余额不足提醒](/zh/platform/pricing#余额不足提醒)。

## 接口与字段

---

控制台计费页调用的两个接口。它们都要求已登录成员身份，且**不对未开通的账户做任何写入**。

### `POST /safari/credits/overview`

请求体为空对象。返回账户当前的额度状态：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `enabled` | 布尔 | 账户是否已开通 AI SRE。从未开通过时它与下面的额度字段一起保持默认值：`false`、周期为空、余额为 0、`payg_cap_amount` 为 `null` |
| `free_mode` | 布尔 | 体验模式：用量照常计量但不计费 |
| `visible` | 布尔 | 计费入口（订阅页 AI SRE 标签页、购买页）是否对本账户开放 |
| `period_id` | 字符串 | 当前账期标识 |
| `period_start_sec` / `period_end_sec` | 整数（Unix 秒） | 当前账期起止。边界是 `timezone` 所在时区的当地零点，展示时必须按该时区格式化 |
| `timezone` | 字符串 | 计算账期的 IANA 时区 |
| `gift_remaining_nano` | 整数 | 体验赠送剩余额度，单位 nano-credits，`1 credit = 1,000,000,000` |
| `package_remaining_nano` | 整数 | 未过期资源包剩余额度合计，单位同上 |
| `package_earliest_expires_at_sec` | 整数（Unix 秒） | 上述资源包中最早的到期时间；没有可用资源包时为 0 |
| `payg_used_amount` | 金额（¥） | 本周期按量付费已用金额 |
| `payg_cap_amount` | 金额（¥）或 `null` | 本周期按量付费上限。`null` = 不限额，`0` = 禁止按量付费，正数 = 月度上限；字段本身不做省略，`null` 与 `0` 在线上是两种不同的值 |
| `blocked_reason` | 字符串 | 服务端的准入判决：`not_enabled` / `balance_exhausted` / `wallet_insufficient`；为空表示当前没有拦截 |
| `blocked_message` | 字符串 | 上一条判决对应的用户提示，与真正被拒绝的那次运行返回的句子完全相同 |

### `POST /safari/credits/limit`

请求体只有一个字段 `monthly_limit_amount`：填一个正数表示月度上限，填 `0` 表示禁止按量付费，省略该字段或填 `null` 表示不限额（负数会在参数校验阶段被拒绝）。语义与 `payg_cap_amount` 的三种状态一一对应。它**设置**上限而不是补丁式修改单个字段，因此"字段省略"与"显式 null"含义相同。成功时返回保存后的完整概览，结构同上。
