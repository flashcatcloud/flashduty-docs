配置故障 自定义操作，允许您在故障排查期间，快速调用外部接口，实现故障自愈、信息丰富等任何自定义操作。

## 创建操作

1. 登录 Flashduty 控制台，进入【集成中心-Webhook】
2. 点击添加 自定义操作 集成
3. 配置 操作名称，此名称将以按钮的形式体现在故障详情中
4. 配置 管理团队（可选），只有该团队成员可以编辑此集成配置
5. 配置 协作空间，可以配置多个，但每个协作空间至多添加五个 自定义操作
6. 配置 Endpoint、自定义 Headers
7. 保存，完成

## 推送描述

### 请求方式

<div className="md-block">

POST, Content-Type:"application/json"

</div>

### 请求 Payload

<div className="md-block">

| 字段 | 类型 | 必含 | 释义 |
| :--------: | :-------------------: | :--: | :--------- |
| event_time |         int64         |  是  | 事件发生 `毫秒时间戳` |
| event_type |        string         |  是  | 事件类型，固定值 `i_custom` |
|  event_id  |        string         |  是  | 事件 ID，`同一个事件可能因为超时等原因重试多次，接收方需要能够去重` |
| event_detail | object | 否 | 事件明细，固定结构见下方[事件明细](#EventDetail) |
|   person   |   [Person](/zh/on-call/integration/webhooks/incident-webhook#Person)   |  否  | 操作人，仅人为动作时存在 |
|  incident  | [Incident](/zh/on-call/integration/webhooks/incident-webhook#Incident) |  是  | 故障详情 |

`person`、`incident`（含 [Responder](/zh/on-call/integration/webhooks/incident-webhook#Responder)、[AssignedTo](/zh/on-call/integration/webhooks/incident-webhook#AssignedTo)、[Image](/zh/on-call/integration/webhooks/incident-webhook#Image)）的字段与[故障 Webhook](/zh/on-call/integration/webhooks/incident-webhook#请求-payload)中的相同，差异如下：

- `incident.alerts` 额外返回关联告警列表，字段见下方 [Alert](#Alert)；无关联告警时不返回该字段。
- `incident.links` 不返回，请使用故障 Webhook 获取。

<span id="Alert"></span>
**Alert**:

|       字段       |         类型          | 必含 | 释义|
| :--------------: | :-----------: | :--: | :----------------- |
|     alert_id     |        string         |  是  | 告警 ID|
|    account_id    |         int64         |  是  | 账户 ID|
|  integration_id  |         int64         |  是  | 集成 ID|
|    channel_id    |         int64         |  是  | 协作空间 ID|
|      title       |        string         |  是  | 告警标题|
|    title_rule    |        string         |  否  | 标题生成规则|
|   description    |        string         |  否  | 告警描述|
|    alert_key     |        string         |  是  | 告警关联依据|
|  alert_severity  |        string         |  是  | 严重程度，枚举值：Critical，Warning，Info|
|   alert_status   |        string         |  是  | 告警状态，枚举值：Critical，Warning，Info，Ok|
|     progress     |        string         |  是  | 处理进度，枚举值：Triggered，Closed|
|    created_at    |         int64         |  是  | 创建时间|
|    updated_at    |         int64         |  是  | 更新时间|
|    start_time    |         int64         |  是  | 首次触发时间（平台接收到的首个事件的时间），Unix 秒时间戳|
|    last_time     |         int64         |  是  | 最新事件时间（平台接收到的最新事件时间），Unix 秒时间戳|
|     end_time     |         int64         |  否  | 告警恢复时间（平台上一次接收到结束类型事件的时间），Unix 秒时间戳，默认为 0|
|    close_time    |         int64         |  否  | 关闭时间，不同于 end_time，这个是处理进度的关闭，不代表告警真的恢复。Unix 秒时间戳，默认为 0 |
|    ever_muted    |         bool          |  是  | 是否曾被静默策略静默|
|      labels      |   map[string]string   |  否  | 标签 KV，Key 和 Value 均为字符串|
|    event_cnt     |         int64         |  否  | 关联事件个数|
|      images      | [][Image](/zh/on-call/integration/webhooks/incident-webhook#Image) |  是  | 告警图片列表，无图片时为 null|

自定义操作中的告警对象有以下限制：

- 不返回 `incident`、`integration_ref_id`、`data_source_type`。
- `integration_name`、`integration_type`、`channel_name`、`channel_status`、`responder_name`、`responder_email`、`data_source_name`、`data_source_ref_id` 恒为空字符串。
- `data_source_id` 同 `integration_id`，请使用 `integration_id`。

<span id="EventDetail"></span>
**event_detail**（i_custom 固定结构）：

| 字段 | 类型 | 必含 | 释义 |
| :-------- | :------: | :--: | :--- |
| integration_id | int64 | 否 | 触发的自定义操作集成 ID |
| integration_name | string | 否 | 触发的自定义操作集成名称 |

</div>

HTTP status code 为 200，认为推送成功。

## 自定义请求体与值映射

自定义操作与故障 Webhook 一样支持 **自定义请求体** 和 **值映射**，变量路径引用上方[请求 Payload](#请求-payload)中的字段。语法和示例见[故障 Webhook](/zh/on-call/integration/webhooks/incident-webhook#自定义请求体)。

## 使用场景

### 重启主机

当主机内存或 CPU 打满，触发主机重启脚本，快速完成主机重启。

### 信息丰富

当故障发生时，回调您的服务，根据告警详情调取 Tracing、Logging、拓扑等信息，主动调用 Flashduty Open API 来更新故障信息，比如增加标签或设定自定义字段，辅助排障。

### 回滚变更

当发生故障时，如果确定故障由变更导致，可以直接触发回调到您的部署平台，开启回滚进程，加速故障恢复。

### 更新 status page

当确定故障影响到线上服务，可以触发外部 status page 更新，及时的通知到您的客户或上下游。

## 常见问题

1. **服务是否有响应超时时间？**

   - 服务需要在 2 秒内返回响应，超过 2 秒则认为响应失败

2. **推送失败后是否会持续推送？**

   仅以下网络错误会重试，最多 1 次：
   - 连接超时或读写超时（`i/o timeout`）
   - 连接被对端提前关闭（`EOF`）

   请求已发出、等待响应头超时的，不重试。
