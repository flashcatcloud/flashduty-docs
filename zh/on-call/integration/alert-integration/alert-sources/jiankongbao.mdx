通过 webhook 的方式同步监控宝告警事件到 Flashduty On-call。

<div className="hide">

## 在 Flashduty On-call
您可通过以下两种方式获取集成推送地址，任选其一即可。

### 使用专属集成

如果您只需将告警发往一个协作空间，选择此方式，配置更简单。

<AccordionGroup>
  <Accordion title="查看专属集成的配置步骤">
  
  1. 进入 Flashduty 控制台，选择 **协作空间**，打开一个协作空间
  2. 选择 **配置** → **集成数据** → **专属集成**，点击 **新增集成**
  3. 选择 **监控宝** 集成，点击 **保存**，生成卡片。
  4. 打开生成的集成卡片，复制 **推送地址**
  
    
</Accordion>
</AccordionGroup>

### 使用共享集成

如果您需要根据告警事件的 Payload 将告警路由到不同协作空间，选择此方式。

<AccordionGroup>
  <Accordion title="查看共享集成的配置步骤">
  
  1. 进入 Flashduty 控制台，选择 **集成中心 → 告警事件**
  2. 选择 **监控宝** 集成：
        - **集成名称**：为当前集成定义一个名称。
  3. 配置默认路由并选择协作空间；创建后可在 **路由** 中增加更多规则
  4. 点击 **保存**，复制生成的 **推送地址**
    
</Accordion>
</AccordionGroup>

</div>

## Alert Key

Flashduty 使用监控任务 ID `task_id` 作为 Alert Key。同一个监控任务产生的告警，无论来自哪个监控地址或检查项，都携带相同的 `task_id`，因此合并为同一条 Flashduty 告警。任务名称、状态、等级、时间或 `msg_id` 的变化不会改变 Alert Key。

需要在告警粒度上区分监控地址时，请拆分为多个监控任务，让每个任务有各自的 `task_id`。

## 状态和告警等级

<div className="md-block">

| 监控宝字段 | Flashduty |
| --- | --- |
| `message_status` = `2`（恢复） | 恢复 |
| `message_type` = `1` | Warning |
| `message_type` = `2` | Info |
| `message_type` 为空或其他值 | Info |

</div>

`message_status` 为 `2` 时，Flashduty 关闭 `task_id` 对应的告警。其他取值的通知按 `message_type` 生成或更新告警。恢复通知携带与触发通知相同的 `task_id`，因此能关闭触发时创建的告警。

## 告警内容

- **标题**：`<监控任务名称> / <指标摘要> - <监控类型>`，依次取自 `check`、`task_summary` 和 `task_type` 标签
- **描述**：`content` 字段

| 标签 | 来源 |
| :--- | :--- |
| `check` | 监控任务名称 `task_name` |
| `task_summary` | 指标摘要 `task_summary` |
| `task_type` | 监控类型 `task_type` |
| `task_groups` | 任务分组 `task_groups` |
| `server_id` | 服务器 ID `server_id` |
| `message_detail` 中的键 | 该字段为 JSON 对象时，其中每个键值对展开为一个标签，例如 `metric`、`value`、`location_type` |

## 排查问题

- **同一个任务的多条告警合并成一条**：Alert Key 取自 `task_id`，同一监控任务的告警会合并；需要分开时拆分为多个监控任务
- **告警没有恢复**：确认恢复通知的 `message_status` 为 `2`，并且由同一个监控任务发出（`task_id` 相同）；确认该监控任务仍勾选了 Webhook 通知
- **Flashduty 返回参数错误**：确认回调的数据格式为 JSON，请求体包含 `task_id`
