通过自定义 Webhook 的方式同步阿里云 DataWorks 智能监控（运维中心）告警事件到 Flashduty On-call。

<div className="hide">

## 在 Flashduty On-call
您可通过以下两种方式获取集成推送地址，任选其一即可。

### 使用专属集成

如果您只需将告警发往一个协作空间，选择此方式，配置更简单。

<AccordionGroup>
  <Accordion title="查看专属集成的配置步骤">
  
  1. 进入 Flashduty 控制台，选择 **协作空间**，打开一个协作空间
  2. 选择 **配置** → **集成数据** → **专属集成**，点击 **新增一个集成**
  3. 选择 **DataWorks 运维中心** 集成，点击 **保存**，生成卡片。
  4. 打开生成的集成卡片，复制 **推送地址**
  
    
</Accordion>
</AccordionGroup>

### 使用共享集成

如果您需要根据告警事件的 Payload 将告警路由到不同协作空间，选择此方式。

<AccordionGroup>
  <Accordion title="查看共享集成的配置步骤">
  
  1. 进入 Flashduty 控制台，选择 **集成中心 → 告警事件**
  2. 选择 **DataWorks 运维中心** 集成：
        - **集成名称**：为当前集成定义一个名称。
  3. 配置默认路由并选择协作空间；创建后可在 **路由** 中增加更多规则
  4. 点击 **保存**，复制生成的 **推送地址**
    
</Accordion>
</AccordionGroup>
</div>

## 在阿里云 DataWorks

<Steps>
<Step title="在 DataWorks 运维中心打开监控规则">

**操作路径**：DataWorks 控制台 › 数据开发与运维 › 运维中心 › 监控报警 › 规则管理

打开一个已有规则，或新建规则。自定义 Webhook 仅 DataWorks 企业版支持；自定义监控规则只对自动调度的周期实例生效。

</Step>
<Step title="在规则中启用 WebHook 并填写推送地址">

**操作路径**：规则管理 › 目标规则 › 报警行为

| 字段 | 值 | 必填 |
| --- | --- | --- |
| 报警方式 | 勾选 **WebHook** | 必填 |
| Webhook地址 | `{integration_url}` | 必填 |

保存规则。此后该规则触发的告警会实时推送到 Flashduty。

</Step>
<Step title="发送测试消息并确认">

**操作路径**：规则管理 › 目标规则 › 报警行为 › 发送测试消息

填写地址后点击 **发送测试消息** 验证连通性。测试消息仅用于验证推送地址，Flashduty 收到后返回成功但不产生告警事件。

要看到第一个事件，请真实触发该规则。回到 Flashduty，集成显示 **最新事件时间**，说明配置成功。
{/* console:
接入清单中的「收到第一个事件」同时变为已完成。
*/}

</Step>
</Steps>

## 状态和告警等级
<div className="md-block">

DataWorks 自定义告警 `remind_type` 到 Flashduty 告警等级映射关系：

| DataWorks remind_type | Flashduty |
| --------------------- | --------- |
| error | Critical |
| exhausted error | Critical |
| uncompleted | Warning |
| cycle uncompleted | Warning |
| run over time | Warning |
| resGroup use ratio | Warning |
| the number of waiting task in resGroup | Warning |
| completed | Info |
| 空值或未知值 | Warning |

基线告警 `status` 映射关系：

| DataWorks status | Flashduty |
| ---------------- | --------- |
| overSla | Critical |
| dangerous | Warning |
| 空值或未知值 | Warning |

事件告警 `event_type` 映射关系：

| DataWorks event_type | Flashduty |
| -------------------- | --------- |
| ERROR | Critical |
| SLOW | Warning |
| 空值或未知值 | Warning |

</div>

## Alert Key 与告警合并
<div className="md-block">

DataWorks 智能监控 Webhook 属于**一次性事件**：官方协议只定义告警通知，**不恢复**、无更新语义，也没有提供厂商级别的去重 ID 或指纹字段。因此本集成不会自动恢复（关闭）任何告警，所有事件均以触发状态投递。

每次 webhook 投递都会生成一个全新的随机 UUID 作为 Alert Key，即每条推送都会创建一条独立的告警事件，重复触发不会自动合并。如需降噪，请在 Flashduty 中配置告警聚合或收敛策略。

</div>

## 标签
<div className="md-block">

推送消息中的关键字段会作为标签保留在告警事件上，可用于路由、静默和通知模板渲染：

| 标签 | 来源字段 | 说明 |
| ---- | -------- | ---- |
| `alert_type` | `message.title` | 告警类型，取值为 `DataWorks_Remind`、`DataWorks_Baseline_Alert` 或 `DataWorks_Event_Remind` |
| `remind_name` | `remind_name` | 规则名称 |
| `remind_unit` | `remind_unit` | 监控粒度：Task、Baseline、Project、BizProcess、ScheduleResourceGroup、DiResourceGroup |
| `remind_type` | `remind_type` | 原始触发条件 |
| `occur_time` | `occur_time` | 原始发生时间字符串，格式 `2021-07-13 16:16:20`；三类告警都会生成 |
| `remind_founder` | `remind_founder` | 规则创建人 |
| `more_information` | `more_information` | 运维中心周期实例 URL |
| `task_size` / `number_of_alerts` | 同名字段 | 任务数量、第几次告警；任务数量大于 0、告警次数大于 0 时才生成 |
| `node_id_list` / `node_name_list` / `node_owner_list` | 同名字段 | 节点 ID、节点名、责任人列表，英文逗号分隔、最多 5 个；非资源组监控时生成 |
| `resource_group_name` / `threshold` / `duration` | 同名字段 | 资源组名、阈值、持续时间（分钟）；仅资源组监控时生成 |
| `baseline_name` / `baseline_owners` | 同名字段 | 基线名、基线责任人 |
| `cycle_number` / `key_instance` / `sla_time` / `buffer` / `status` | 同名字段 | 周期号（天基线为 1）、当前关键实例、承诺时间、基线余量（分钟）、基线状态（`dangerous` 为预警、`overSla` 为破线） |
| `task_name` / `task_owner_name` / `event_type` / `event_name` | 同名字段 | 异常任务名、任务责任人、事件类型（`ERROR` 出错、`SLOW` 变慢）、事件名称 |

空值字段不会生成标签。告警标题取自各告警族的名称字段：自定义告警取 `remind_name`，基线告警取 `baseline_name`，事件告警取 `task_name`。

</div>

## 常见问题
<div className="md-block">

**为什么告警不会自动恢复？**

DataWorks 智能监控 Webhook 协议没有定义恢复消息，属于一次性通知。如需关闭告警，请在 Flashduty 控制台手动处理，或为规则配置告警收敛策略。

**发送测试消息后为什么看不到告警？**

DataWorks 的连通性测试消息仅用于验证推送地址可达，Flashduty 收到后返回成功但不生成告警事件。请通过真实触发规则来验证端到端链路。

</div>
