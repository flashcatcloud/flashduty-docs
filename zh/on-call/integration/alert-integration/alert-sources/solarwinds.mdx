通过 webhook 的方式同步 SolarWinds 告警事件到 Flashduty On-call。

<div className="hide">

## 在 Flashduty On-call
您可通过以下两种方式获取集成推送地址，任选其一即可。

### 使用专属集成

如果您只需将告警发往一个协作空间，选择此方式，配置更简单。

<AccordionGroup>
  <Accordion title="查看专属集成的配置步骤">
  
  1. 进入 Flashduty 控制台，选择 **协作空间**，打开一个协作空间
  2. 选择 **配置** → **集成数据** → **专属集成**，点击 **新增集成**
  3. 选择 **SolarWinds** 集成，点击 **保存**，生成卡片。
  4. 打开生成的集成卡片，复制 **推送地址**
  
    
</Accordion>
</AccordionGroup>

### 使用共享集成

如果您需要根据告警事件的 Payload 将告警路由到不同协作空间，选择此方式。

<AccordionGroup>
  <Accordion title="查看共享集成的配置步骤">
  
  1. 进入 Flashduty 控制台，选择 **集成中心 → 告警事件**
  2. 选择 **SolarWinds** 集成：
        - **集成名称**：为当前集成定义一个名称。
  3. 配置默认路由并选择协作空间；创建后可在 **路由** 中增加更多规则
  4. 点击 **保存**，复制生成的 **推送地址**
    
</Accordion>
</AccordionGroup>

</div>

## 在 SolarWinds 中配置

SolarWinds 的告警类型有五种（Anomaly、Entity、Event、Log、Metric Group），每种类型对应不同的告警通道，所以需要创建五个 Webhook 通道，分别用于不同类型的告警。

<Steps>
<Step title="在 SolarWinds 中创建 Webhook 通知服务">

**操作路径**：SolarWinds › Settings › Notification Services › Webhook › CREATE CONFIGURATION

| 字段 | 填写 |
| --- | --- |
| Method（必填） | `POST` |
| Name（必填） | 建议使用 `类型_Flashduty` 的形式，例如 `Anomaly_Flashduty` |
| Destination URL（必填） | `{integration_url}`（在 Flashduty 填写集成名称并保存后生成） |
| Content Type（必填） | `application/json` |
| Select Custom Body Template Based On The Alert Types（必填） | 要创建的类型，例如 Anomaly Based Alert |
| HTTP POST Body | 系统会按所选类型自动生成，**请不要修改生成的模板内容** |

填写后点击 **CREATE**。

<img alt="SolarWinds Notification Services 列表中选择 Webhook" width="600" src="https://download.flashcat.cloud/flashduty/doc/sw-1.png" />

<img alt="Webhook 通道的 Create Configuration 表单与自动生成的 HTTP POST Body" width="600" src="https://download.flashcat.cloud/flashduty/doc/sw-2.png" />

如需创建其他类型的 Webhook 通道，重复以上操作。

</Step>
<Step title="在 SolarWinds 告警策略中使用该通道">

**操作路径**：SolarWinds › Alerts › Alert Settings › 创建或编辑告警策略 › Actions

告警规则按需配置，此处省略。在 **Actions** 部分：

| 字段 | 填写 |
| --- | --- |
| Services（必填） | `Webhook` |
| Configuration（必填） | 上一步创建的通道，例如 `Anomaly_Flashduty`（类型须与告警类型对应） |
| Send an additional notification when the Alert is cleared | 保持开启，Flashduty 才能收到恢复通知 |

其他配置完成后点击 **Save**。

<img alt="告警策略的 Actions 中选择 Webhook 通道并开启清除通知" width="600" src="https://download.flashcat.cloud/flashduty/doc/sw-4.png" />

</Step>
<Step title="触发告警并确认">

**操作路径**：SolarWinds › Alerts › Alert Settings

创建 Webhook 通道时 SolarWinds 提供的测试通知只能证明 Flashduty 地址可连通，不能代替真实告警验证。请让一条已关联该通道的告警规则真实触发，几秒后回到 Flashduty，集成显示 **最新事件时间**，说明配置成功；条件恢复后，原告警自动恢复。
{/* console:
接入清单中的「收到第一个事件」同时变为已完成。
*/}

</Step>
</Steps>

## 推送内容

SolarWinds 的五种告警通道推送的 JSON 结构不同，Flashduty 读取以下字段：

| 字段 | 含义 | 在 Flashduty 中 |
| :--- | :--- | :--- |
| `name` | 告警名称 | 告警标题，标签 `check` |
| `severity` | 告警等级 | 告警等级 |
| `description` | 告警描述 | 告警描述 |
| `detailUrl` | 告警详情链接 | Alert Key 的来源，标签 `detail_url` |
| `reason` | 清除原因 | 为 `DISABLED` 或 `AUTOMATIC` 时按恢复处理 |
| `entities[]` | 受影响对象 | 标签 `entities`（JSON）；第一个实体的 `reason` 也参与恢复判断 |
| `sWindsEvents` | 事件告警列表 | 标签 `event`（JSON） |
| `affectedEvaluations` | 受影响的评估 | 标签 `affected_evaluations`（JSON） |
| `tags` | 对象标签数组 | 标签 `tags`（JSON） |
| `runbook`、`condition`、`additionalInfo`、`recordCount`、`threshold`、`timespanStart`、`timespanEnd`、`query` | 告警上下文 | 标签 `runbook`、`condition`、`additional_info`、`record_count`、`threshold`、`timespan_start`、`timespan_end`、`query` |

`id` 和 `priority` 不读取，告警等级只取 `severity`。

## Alert Key

Flashduty 用 `detailUrl` 的 MD5 作为 Alert Key。同一条告警的触发通知和清除通知携带相同的详情链接，因此清除通知会关闭对应的告警。

推送中没有 `detailUrl` 时，每次推送都会生成一条新告警，清除通知也无法关闭原告警。修改告警名称、等级、原因或标签不会改变 Alert Key。

## 状态和告警等级

<div className="md-block">

| SolarWinds | Flashduty |
| --- | --- |
| Critical | Critical |
| Warning | Warning |
| Info | Info |

其他取值按 Info 处理；收到 `reason` 为 `DISABLED` 或 `AUTOMATIC` 的清除通知时告警恢复。

</div>

## 标签

| 标签 | 来源 |
| :--- | :--- |
| `check` | 告警名称 `name` |
| `runbook` | 处置手册 `runbook` |
| `detail_url` | 告警详情链接 `detailUrl` |
| `condition` | 触发条件 `condition` |
| `additional_info` | 附加信息 `additionalInfo` |
| `record_count` | 记录数 `recordCount` |
| `threshold` | 阈值 `threshold` |
| `timespan_start` / `timespan_end` | 统计时间范围 `timespanStart` / `timespanEnd` |
| `query` | 查询语句 `query` |
| `entities` | 受影响对象数组的 JSON |
| `event` | 事件列表 `sWindsEvents` 的 JSON |
| `affected_evaluations` | 受影响评估数组的 JSON |
| `tags` | 对象标签数组的 JSON，形如 `[{"key":"...","value":"..."}]` |

值为空的标签不会写入。

## 排查问题

- **告警没有恢复**：只有 `reason` 为 `DISABLED` 或 `AUTOMATIC` 的清除通知才按恢复处理；告警策略没有开启 **Send an additional notification when the Alert is cleared** 时，SolarWinds 不会发送清除通知
- **清除通知生成了新告警**：推送缺少 `detailUrl`，Flashduty 无法把它与触发通知关联；请保留系统自动生成的 HTTP POST Body，不要删改该字段
- **告警等级与预期不符**：`severity` 只识别大写的 `CRITICAL`、`WARNING` 和 `INFO`，其他取值（包括小写）按 Info 处理；`priority` 不参与
- **标签值是 JSON 字符串**：`entities`、`event`、`affected_evaluations` 和 `tags` 以 JSON 字符串写入，路由规则按字符串匹配
- **Flashduty 返回参数错误**：请求体必须是合法的 JSON 对象
