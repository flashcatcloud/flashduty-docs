通过 webhook 的方式同步 Uptime Kuma 告警事件到 Flashduty On-call。

<div className="hide">

## 在 Flashduty On-call
您可通过以下两种方式获取集成推送地址，任选其一即可。

### 使用专属集成

如果您只需将告警发往一个协作空间，选择此方式，配置更简单。

<AccordionGroup>
  <Accordion title="查看专属集成的配置步骤">
  
  1. 进入 Flashduty 控制台，选择 **协作空间**，打开一个协作空间
  2. 选择 **配置** → **集成数据** → **专属集成**，点击 **新增集成**
  3. 选择 **Uptime Kuma** 集成，点击 **保存**，生成卡片。
  4. 打开生成的集成卡片，复制 **推送地址**
  
    
</Accordion>
</AccordionGroup>

### 使用共享集成

如果您需要根据告警事件的 Payload 将告警路由到不同协作空间，选择此方式。

<AccordionGroup>
  <Accordion title="查看共享集成的配置步骤">
  
  1. 进入 Flashduty 控制台，选择 **集成中心 → 告警事件**
  2. 选择 **Uptime Kuma** 集成：
        - **集成名称**：为当前集成定义一个名称。
  3. 配置默认路由并选择协作空间；创建后可在 **路由** 中增加更多规则
  4. 点击 **保存**，复制生成的 **推送地址**
    
</Accordion>
</AccordionGroup>

</div>

## 推送内容

Uptime Kuma 的 **FlashDuty** 通知类型把事件推送到标准告警接口，Flashduty 读取以下字段：

| 字段 | 含义 | 在 Flashduty 中 |
| :--- | :--- | :--- |
| `title` | 通知标题，监控异常时为 `Uptime Kuma Monitor 🔴 Down`，恢复时为 `Uptime Kuma Monitor ✅ Up` | 告警标题 |
| `description` | 由通知标题、监控名称和心跳消息依次拼成 | 告警描述 |
| `event_status` | 监控异常时取通知渠道的 **Severity**，恢复时为 `Ok` | 告警状态和等级 |
| `alert_key` | 监控 ID | Alert Key |
| `labels.resource` | 监控地址：优先主机名，`port` 类型为 `主机名:端口`，没有主机名时为监控 URL | 标签 `resource` |
| `labels.check` | 监控名称 | 标签 `check` |
| `labels.<Tag 名称>` | 监控的每个 Tag | 同名标签 |

通知标题由 Uptime Kuma 固定生成，监控名称在描述和 `check` 标签中。没有选择 **Severity** 时，监控异常的告警按 `Info` 推送。

## Alert Key

Uptime Kuma 直接把监控 ID 作为 `alert_key` 发送。同一监控的异常通知和恢复通知携带相同的值，因此恢复通知会关闭对应的告警；监控连续失败期间发送的重复通知会合并到同一条告警。

不同监控的 ID 不同，各自生成一条告警；修改监控名称、地址或 Tag 不会改变 Alert Key。

## 状态和告警等级
<div className="md-block">
  
监控变为 Down 时，告警等级取自通知渠道中的 **Severity**（下表）；变为 Up 时发送恢复事件，关闭同一监控的告警。

Uptime Kuma 到 Flashduty 告警等级映射关系：

| Uptime Kuma | Flashduty |
| ------------ | -------- |
| Critical | Critical |
| Warning | Warning |
| Info | Info |

</div>

## 标签

| 标签 | 来源 |
| :--- | :--- |
| `resource` | 监控地址，优先取主机名 |
| `check` | 监控名称 |
| Tag 名称 | 监控的每个 Tag，值为空时不会写入 |

## 排查问题

- **测试通知生成了一条告警**：通知渠道的 **Test** 按钮发送的是测试消息，Flashduty 按 Info 生成标题为 `Uptime Kuma Alert` 的告警；这条消息使用随机的 `alert_key`，不会自动恢复，验证后可在 Flashduty 中手动关闭
- **告警标题都是 Uptime Kuma Monitor 🔴 Down**：标题由 Uptime Kuma 固定生成，监控名称在描述和 `check` 标签中；需要按监控区分时用标签匹配，或用[告警处理 Pipeline](/zh/on-call/integration/alert-integration/alert-pipelines) 重写标题
- **告警没有恢复**：只有 Uptime Kuma 判定监控恢复并发送 Up 通知时才会恢复；确认监控已恢复，且该通知仍绑定在监控上
- **标签中没有监控 Tag**：Tag 只填了名称、没有值时不会写入，补全值后会出现在标签中
- **Uptime Kuma 提示 FlashDuty notification failed**：确认 Integration Key 填的是集成密钥或完整推送地址，且对应的集成没有被删除
