通过 Webhook 将 EMQX 的告警事件推送到 Flashduty。

<div className="hide">

## 在 Flashduty On-call

您可通过以下两种方式获取集成推送地址，任选其一即可。

### 使用专属集成

如果您只需将告警发往一个协作空间，选择此方式，配置更简单。

<AccordionGroup>
  <Accordion title="查看专属集成的配置步骤">

  1. 进入 Flashduty 控制台，选择 **协作空间**，打开一个协作空间
  2. 选择 **配置** → **集成数据** → **专属集成**，点击 **新增集成**
  3. 选择 **EMQX** 集成，点击 **保存**，生成卡片。
  4. 打开生成的集成卡片，复制 **推送地址**

  </Accordion>
</AccordionGroup>

### 使用共享集成

如果您需要根据告警事件的 Payload 将告警路由到不同协作空间，选择此方式。

<AccordionGroup>
  <Accordion title="查看共享集成的配置步骤">

  1. 进入 Flashduty 控制台，选择 **集成中心 → 告警事件**
  2. 选择 **EMQX** 集成：
        - **集成名称**：为当前集成定义一个名称。
  3. 配置默认路由并选择协作空间；创建后可在 **路由** 中增加更多规则
  4. 点击 **保存**，复制生成的 **推送地址**

  </Accordion>
</AccordionGroup>
</div>

## 在 EMQX 中配置

EMQX Cloud（托管服务）内置 Flashduty 告警集成类型，自建 EMQX 需通过规则引擎转发系统告警事件，请按部署形态选择。

<Steps>
<Step title="在 EMQX 中配置告警推送">

<Tabs>
<Tab title="EMQX Cloud（托管服务）">

**操作路径**：EMQX Cloud 控制台 › 您的部署 › Alerts › Alert Integrations › Webhook 集成区域 › + New

| 字段 | 填写 |
| --- | --- |
| 类型（必填） | `FlashDuty` |
| URL（必填） | `{integration_url}` |

填写后点击 **确认** 保存。告警产生时，EMQX Cloud 以 POST 请求推送告警到推送地址，推送内容携带 `deployment_id`、`level`、`message`、`region` 四个标签。EMQX Cloud 没有单独的恢复配置，跳过下一步。

</Tab>
<Tab title="自建 EMQX">

**操作路径**：EMQX Dashboard › Integration › Rules › 新建规则（Create）

<Note>
规则引擎自 EMQX 5.8.5 起支持 `$events/sys/alarm_activated`（告警激活）和 `$events/sys/alarm_deactivated`（告警解除）两个系统告警事件，请确保您的 EMQX 版本不低于 5.8.5。
</Note>

<Warning>
EMQX Dashboard「监控 → 告警」页面提供的 Webhook 快捷配置推送的是 EMQX 原生告警格式，与 Flashduty 要求的事件格式不一致，请按以下步骤通过规则引擎自定义请求体。
</Warning>

| 字段 | 填写 |
| --- | --- |
| SQL（必填） | 见下方，匹配告警激活事件 |
| 动作（必填） | 添加 **HTTP 服务器** 动作 |
| 连接器 URL（必填） | `{integration_url}` |
| 请求方法（必填） | `POST` |
| 请求体（必填） | 见下方模板 |

SQL：

```sql
SELECT
  name,
  message,
  node
FROM
  "$events/sys/alarm_activated"
```

请求体模板，将告警字段转换为 Flashduty 标准告警事件格式：

```json
{
  "event_status": "Critical",
  "alert_key": "emqx::${node}::${name}",
  "title_rule": "EMQX 告警：${message}",
  "description": "${message}",
  "labels": {
    "alarm_name": "${name}",
    "node": "${node}"
  }
}
```

模板中的 `${name}`、`${message}`、`${node}` 会被规则 SQL 输出的字段值替换。填写后保存规则。

</Tab>
</Tabs>

</Step>
<Step title="在 EMQX 中创建告警恢复规则（仅自建 EMQX）">

**操作路径**：EMQX Dashboard › Integration › Rules › 新建规则（Create）

按上一步再创建一条规则，动作配置相同，字段差异如下：

| 字段 | 填写 |
| --- | --- |
| SQL（必填） | 把事件改为 `"$events/sys/alarm_deactivated"`，`SELECT` 字段同上 |
| 请求体（必填） | 与上一步模板相同，但 `event_status` 固定为 `Ok` |

```sql
SELECT
  name,
  message,
  node
FROM
  "$events/sys/alarm_deactivated"
```

`alert_key` 与激活规则一致，告警解除时 Flashduty 中对应的告警会自动恢复。

</Step>
<Step title="触发告警并确认 Flashduty 收到事件">

**操作路径**：EMQX Cloud 控制台 › Alerts › Alert Integrations（EMQX Cloud）；EMQX Dashboard › Monitoring › Alarms（自建 EMQX）

- EMQX Cloud：在已保存的集成上点击 **测试**，EMQX 发送一条示例告警，用来确认推送地址可达；再以真实告警确认字段和等级。
- 自建 EMQX：规则只在系统告警激活或解除时触发，没有测试按钮；在 **Monitoring › Alarms** 的 Active 页签可查看当前激活的告警，等待真实告警即可。

几秒后回到 Flashduty，集成显示 **最新事件时间**，说明配置成功。
{/* console:
接入清单中的「收到第一个事件」同时变为已完成。
*/}

</Step>
</Steps>

## 状态和告警等级

<div className="md-block">

**EMQX Cloud（托管服务）**：EMQX Cloud 自动按以下关系映射告警等级：

| EMQX Cloud 告警等级 | Flashduty |
| --- | --- |
| Critical | Critical |
| Error / Warning | Warning |
| Info | Info |

**自建 EMQX**：告警等级由规则请求体模板中的 `event_status` 字段决定。上述示例中告警激活推送 `Critical`、告警解除推送 `Ok`，您可以在模板中将激活等级改为 `Warning` 或 `Info`。`event_status` 的合法取值为 `Critical`、`Warning`、`Info`、`Ok`。

</div>

## 常见问题

<AccordionGroup>
<Accordion title="为什么在 Flashduty 没有收到告警？">

**在 Flashduty On-call**

1. 查看集成是否展示了 **最新事件时间**？如果没有，代表 Flashduty 没有收到推送，请优先排查 EMQX 侧配置。
2. 如果您使用 **共享集成**，请先确认已配置 **路由规则**。没有路由规则时，系统会拒绝新的推送，因为没有协作空间承接告警。请将路由规则指向目标协作空间。

**在 EMQX**

1. 自建 EMQX：确认规则的请求体模板与上文示例一致，`event_status` 必须是 `Critical`、`Warning`、`Info`、`Ok` 之一，否则 Flashduty 会拒绝该请求。
2. 在 EMQX Dashboard 的规则详情页查看规则的运行统计，确认动作执行成功、无失败计数。
3. 确认 EMQX 节点可以访问外网 `api.flashcat.cloud` 域名。

如果以上步骤执行之后，仍然没有查询到问题根因，请 **携带请求响应中的 request_id** 联系我们。

</Accordion>
</AccordionGroup>
