通过 webhook 的方式同步腾讯云事件总线 EB 事件到 Flashduty On-call。

<div className="hide">

## 在 Flashduty On-call
您可通过以下两种方式获取集成推送地址，任选其一即可。

### 使用专属集成

如果您只需将告警发往一个协作空间，选择此方式，配置更简单。

<AccordionGroup>
  <Accordion title="查看专属集成的配置步骤">
  
  1. 进入 Flashduty 控制台，选择 **协作空间**，打开一个协作空间
  2. 选择 **配置** → **集成数据** → **专属集成**，点击 **新增集成**
  3. 选择 **腾讯云 EventBridge** 集成，点击 **保存**，生成卡片。
  4. 打开生成的集成卡片，复制 **推送地址**
  
    
</Accordion>
</AccordionGroup>

### 使用共享集成

如果您需要根据告警事件的 Payload 将告警路由到不同协作空间，选择此方式。

<AccordionGroup>
  <Accordion title="查看共享集成的配置步骤">
  
  1. 进入 Flashduty 控制台，选择 **集成中心 → 告警事件**
  2. 选择 **腾讯云 EventBridge** 集成：
        - **集成名称**：为当前集成定义一个名称。
  3. 配置默认路由并选择协作空间；创建后可在 **路由** 中增加更多规则
  4. 点击 **保存**，复制生成的 **推送地址**
    
</Accordion>
</AccordionGroup>

</div>

## 推送内容

事件规则按 CloudEvents 格式推送 JSON 对象，Flashduty 读取以下字段：

| 字段 | 含义 | 在 Flashduty 中 |
| :--- | :--- | :--- |
| `id` | 事件 ID | 未知事件类型的 Alert Key |
| `subject` | 事件对象，例如实例 ID | 标签 `subject` 和 `resource`；已知事件类型的 Alert Key |
| `type` | 事件类型 | 告警标题，标签 `type` 和 `check`；已知事件类型的 Alert Key |
| `source` | 事件来源 | 标签 `source`；已知事件类型的 Alert Key |
| `region` | 地域 | 标签 `region`；已知事件类型的 Alert Key |
| `status` | 事件状态 | 为 `0` 时按恢复处理 |
| `data` | 事件内容 | 标签 `data`（JSON） |
| `tags` | 自定义标签 | 每个键值对写成同名标签 |
| `specversion` | CloudEvents 版本 | 标签 `specversion` |

`time` 和 `datacontenttype` 不读取，告警时间以 Flashduty 收到推送的时间为准；`tagList` 数组也不会写入标签。

## Alert Key

Alert Key 按事件类型分两种：

- 腾讯云预置的事件类型（`type` 形如 `cvm:ErrorEvent:DiskReadonly`）：由 `subject`、`type`、`source` 和 `region` 计算，同一实例的同一事件反复推送会合并到一条告警
- 其他事件：直接使用事件 `id`，每次推送各自生成一条告警

`status` 为 `0` 的推送按恢复处理，会关闭同一 Alert Key 的告警。`data` 和 `tags` 的变化不会改变已知事件类型的 Alert Key。

## 状态和告警等级
<div className="md-block">
  
腾讯云事件总线所有事件均对应到 Flashduty On-call “警告（warning）”级别告警。

</div>

## 标签

| 标签 | 来源 |
| :--- | :--- |
| `id` | 事件 ID `id` |
| `source` | 事件来源 `source`，不是固定的 `tencent` |
| `type` / `check` | 事件类型 `type` |
| `subject` / `resource` | 事件对象 `subject` |
| `region` | 地域 `region` |
| `specversion` | CloudEvents 版本 |
| `data` | 事件内容 `data` 的 JSON |
| `tags` 中的键 | 自定义标签，每个键值对写成同名标签 |

## 排查问题

- **告警没有恢复**：只有 `status` 为 `0` 的推送才按恢复处理，其他取值都按触发处理
- **每次事件都生成一条新告警**：`type` 不在腾讯云预置的事件类型中时，Alert Key 使用事件 `id`，每次推送都是新告警
- **没有自定义标签**：只有 `tags` 对象中的键值对会写入标签，`tagList` 数组不读取
- **Flashduty 返回参数错误**：未知事件类型缺少 `id` 时无法生成 Alert Key
- **告警标题是事件类型**：标题固定为 `type`，事件对象在 `subject` 标签中；需要更直观的标题时用[告警处理 Pipeline](/zh/on-call/integration/alert-integration/alert-pipelines) 重写
