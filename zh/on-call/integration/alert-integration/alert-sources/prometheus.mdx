通过 webhook 的方式将 Prometheus 告警事件通过 AlertManager 推送到 Flashduty On-call。

<div className="hide">

## 使用限制

### 在 AlertManager

- 您必须拥有修改 AlertManager 配置文件的权限。
- 您的 AlertManager server 必须能够访问域名 api.flashcat.cloud，将告警推送到外网。

## 支持版本

本文适配 **Alertmanager 0.16.0 及以上** 版本。

## 操作步骤

### 在 Flashduty On-call

您可通过以下两种方式获取集成推送地址，任选其一即可。

#### 使用专属集成

如果您只需将告警发往一个协作空间，选择此方式，配置更简单。

<AccordionGroup>
  <Accordion title="查看专属集成的配置步骤">
  
  1. 进入 Flashduty 控制台，选择 **协作空间**，打开一个协作空间
  2. 选择 **配置** → **集成数据** → **专属集成**，点击 **新增一个集成**
  3. 选择 **Prometheus Alertmanager** 集成，点击 **保存**，生成卡片。
  4. 打开生成的集成卡片，复制 **推送地址**
    
</Accordion>
</AccordionGroup>

#### 使用共享集成

如果您需要根据告警事件的 Payload 将告警路由到不同协作空间，选择此方式。

<AccordionGroup>
  <Accordion title="查看共享集成的配置步骤">
  
  1. 进入 Flashduty 控制台，选择 **集成中心 → 告警事件**
  2. 选择 **Prometheus Alertmanager** 集成：
        - **集成名称**：为当前集成定义一个名称。
  3. 配置默认路由并选择协作空间；创建后可在 **路由** 中增加更多规则
  4. 点击 **保存**，复制生成的 **推送地址**
    
</Accordion>
</AccordionGroup>
</div>

## 在 Alertmanager 中配置

<Steps>
<Step title="在 alertmanager.yml 中添加 Flashduty receiver">

**操作路径**：alertmanager.yml › receivers（配置文件一般位于 Alertmanager 部署根目录）

| 配置项 | 填写 |
| --- | --- |
| `name`（必填） | receiver 名称，例如 `flashcat`，下一步的路由引用此名称 |
| `webhook_configs.url`（必填） | `{integration_url}`，推送地址的 query string 中须携带 `integration_key` |
| `webhook_configs.send_resolved`（可选） | `true`，告警恢复时同时推送恢复事件（Alertmanager 默认值即为 `true`） |
| `webhook_configs.http_config.proxy_url`（可选） | 需要通过代理访问 Flashduty 时填写代理地址 |

```yaml alertmanager.yml
receivers:
- name: 'flashcat'
  webhook_configs:
  - url: '{integration_url}'
    send_resolved: true
```

需要通过代理访问 Flashduty 时：

```yaml alertmanager.yml
receivers:
- name: 'flashcat'
  webhook_configs:
  - url: '{integration_url}'
    send_resolved: true
    http_config:
      proxy_url: 'http://proxyserver:port'
```

</Step>
<Step title="在 alertmanager.yml 中把告警路由到 Flashduty">

**操作路径**：alertmanager.yml › route

所有告警只发往 Flashduty 时，将默认路由的 receiver 改为上一步的 receiver：

```yaml alertmanager.yml
route:
  receiver: 'flashcat'
```

需要保留原有推送渠道时，把 Flashduty 加为第一条子路由并设置 `continue: true`。子路由默认在第一条匹配后停止，且有子路由匹配时默认路由的 receiver 不再收到告警，所以原渠道也要作为子路由列出：

```yaml alertmanager.yml
route:
  receiver: 'feishu'
  routes:
  - receiver: 'flashcat'
    continue: true
  - receiver: 'feishu'
```

</Step>
<Step title="在 Alertmanager 主机上重新加载配置">

**操作路径**：Alertmanager 所在主机的终端

保存配置文件，检查语法后重新加载，以下两种方式任选其一：

```bash
amtool check-config alertmanager.yml

# 方式一：调用 reload 接口
curl -X POST http://localhost:9093/-/reload

# 方式二：向进程发送 SIGHUP 信号
kill -HUP $(pidof alertmanager)
```

</Step>
<Step title="在 Alertmanager 中发送测试告警并确认">

**操作路径**：Alertmanager 所在主机的终端

```bash
amtool alert add alertname=FlashdutyTest severity=warning \
  --annotation=summary="Flashduty integration test" \
  --alertmanager.url=http://localhost:9093
```

Alertmanager 按 `group_wait`（默认 30 秒）等待后推送。随后回到 Flashduty，集成显示 **最新事件时间**，说明配置成功。
{/* console:
接入清单中的「收到第一个事件」同时变为已完成。
*/}

</Step>
</Steps>

## 自定义事件时间

默认情况下，系统使用当前时间作为事件触发时间。如果您希望使用告警实际发生的时间，在 Prometheus 告警规则文件中为每条规则的 `annotations` 添加 `timestamp` 字段：

```yaml
annotations:
  timestamp: '{{ with query "time()" }}{{ . | first | value }}{{ end }}'
  ...
```

保存后重新加载 Prometheus 配置（向进程发送 SIGHUP 信号，或 POST 请求 `/-/reload` 接口）使更改生效。

## 火山引擎托管 Prometheus（VMP）

VMP 的通用 Webhook 按 Alertmanager 格式推送告警，直接使用本集成的推送地址即可。

1. 登录火山引擎托管 Prometheus 控制台，进入 **告警中心** → **告警通知策略**，选择 **通知对象** 页签
2. 点击 **创建通知对象**，对象类型选择 **联系人**，Webhook 勾选 **通用 Webhook**（不要选飞书、钉钉或企业微信机器人，格式不兼容），地址填写集成推送地址，**Token 保持不勾选**
3. 将该联系人加入一个联系人组（VMP 只能按联系人组配置通知策略）
4. 在 **告警通知策略** 中创建或编辑策略，通知对象选择该联系人组
5. 在告警规则的告警通知配置中选择该通知策略，保存，完成

<Note>
火山引擎正在将 VMP 的告警通知功能迁移至云监控告警中心。根据火山引擎公告，2026 年 10 月 12 日后，系统将对未完成迁移的告警配置执行自动迁移，原 VMP 告警通知相关接口将逐步下线。迁移后，VMP 告警可通过已有的 [火山引擎云监控告警事件](/zh/on-call/integration/alert-integration/alert-sources/volcengine-cm-metrics) 集成接入 Flashduty；也可以在告警中心的 **通知回调** 模板中输出 Alertmanager 格式的 Webhook 报文，再推送到本集成。
</Note>

<Tip>
VMP 的 `alertname` 标签是告警规则的 UUID，默认生成的告警标题会是一串 UUID。规则名称在 `alerting_rule_name` 标签中，请在本集成的 **标题规则** 中使用 `$alerting_rule_name`。
</Tip>

## 状态和告警等级

系统依次提取告警事件标签中的 `severity`、`priority`和 `level`，对应值将作为 Prometheus 自身的告警等级。如果都没有提取到，再读取 VMP 的 `internal_label_alert_level` 标签：`P0` 对应 Critical，`P1` 对应 Warning，`P2` 对应 Info。仍未提取到时，系统自动设置 Prometheus 告警等级为 `Warning`。

Prometheus 到 Flashduty On-call 告警等级映射关系：

| Prometheus | Flashduty |
| ------------ | -------- |
| critical | Critical |
| warning | Warning |
| warn | Warning |
| info | Info |
| acknowledged | Info |
| unknown | Info |
| unk | Info |
| ok | Ok |

## 常见问题

<AccordionGroup>
  <Accordion title="为什么在 Flashduty 没有收到告警？">

  **在 Flashduty On-call**
  
  1. 查看集成是否展示 **最新事件时间**。如果没有，说明 Flashduty 未收到推送，请先排查 AlertManager。
  2. 如果您使用 **共享集成**，请先确认已配置 **路由规则**。没有路由规则时，系统会拒绝新的推送，因为没有协作空间承接告警。请将路由规则指向目标协作空间。

  **在 AlertManager**

  1. 确认 AlertManager 是否产生了新告警。如果没有，请等待新告警触发后再验证。
  2. 打开 AlertManager 配置文件，如果您设置了子路由，请确保您的路由设置正确（子路由默认在第一条匹配后停止，排在 Flashduty 前面且未设置 `continue: true` 的子路由会让告警到不了 Flashduty。建议仅设置一个指向 Flashduty On-call 的默认路由）。同时验证，目标回调地址是否和集成推送地址完全匹配。如果不匹配，请修改配置后重新验证。
  3. 如果匹配，请确认 AlertManager 实例可以访问 api.flashcat.cloud。如果无法访问，请为实例开通外网，或单独放行 Flashduty On-call 的域名。
  4. 如果网络正常，请继续查看 AlertManager 的错误日志。


  如果完成以上步骤后仍未找到原因，请联系我们。
    
</Accordion>
</AccordionGroup>
