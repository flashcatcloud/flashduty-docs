通过 Keep 的 Provider 将告警事件推送到 Flashduty On-call。

<div className="hide">

## 在 Flashduty On-call

您可通过以下 2 种方式，获取集成密钥，任选其一即可。

### 使用专属集成

如果您只需将告警发往一个协作空间，选择此方式，配置更简单。

<AccordionGroup>
  <Accordion title="查看专属集成的配置步骤">
  
  1. 进入 Flashduty 控制台，选择 **协作空间**，打开一个协作空间
  2. 选择 **配置** → **集成数据** → **专属集成**，点击 **新增集成**
  3. 选择 **Keep** 集成，点击 **保存**，生成卡片。
  4. 打开生成的集成卡片，复制 **推送地址**，其中 `integration_key=` 之后的部分即为集成密钥
    
</Accordion>
</AccordionGroup>

### 使用共享集成

如果您需要根据告警事件的 Payload 将告警路由到不同协作空间，选择此方式。

<AccordionGroup>
  <Accordion title="查看共享集成的配置步骤">
  
  1. 进入 Flashduty 控制台，选择 **集成中心 → 告警事件**
  2. 选择 **Keep** 集成：
        - **集成名称**：为当前集成定义一个名称。
  3. 配置默认路由并选择协作空间；创建后可在 **路由** 中增加更多规则
  4. 点击 **保存**，复制生成的 **推送地址**，其中 `integration_key=` 之后的部分即为集成密钥
    
</Accordion>
</AccordionGroup>
</div>


## 在 Keep 中配置

<Steps>
<Step title="在 Keep 中配置 Flashduty Provider">

**操作路径**：Keep › Providers › Flashduty

| 字段 | 填写 |
| --- | --- |
| Flashduty Integration Key（必填） | `{integration_key}` |

填写后点击 `Save` 保存配置。

<img alt="drawing" width="600" src="https://download.flashcat.cloud/flashduty/doc/en/fd/keep-1.png" />

</Step>
<Step title="在 Keep 的 Workflow 中使用 flashduty-action">

**操作路径**：Keep › WorkFlows › 创建或编辑 Workflow › Steps

| 字段 | 填写 |
| --- | --- |
| Trigger（必填） | 按需配置 |
| Steps（必填） | 选择 `flashduty-action`，并选择上一步配置的 `Flashduty Provider` |
| flashduty-action 的 Configure（必填） | 配置告警标题、告警状态、告警描述、告警标签等（字段含义见[字段释义](#字段释义)） |

填写后点击 `Save` 保存配置。要让告警自动恢复，需要用同一个 `alert_key` 再发送 `event_status` 为 `Ok` 的事件，例如再配置一个在 Keep 告警恢复时触发的 Workflow。

<img alt="drawing" width="600" src="https://download.flashcat.cloud/flashduty/doc/en/fd/keep-2.png" />

</Step>
<Step title="触发 Workflow 并确认 Flashduty 收到事件">

**操作路径**：Keep › WorkFlows

让 Workflow 的 Trigger 被真实告警触发。几秒后回到 Flashduty，集成显示 **最新事件时间**，说明配置成功。
{/* console:
接入清单中的「收到第一个事件」同时变为已完成。
*/}

</Step>
</Steps>

## 字段释义

字段|必含|类型|释义
:-:|:-:|:-:|:---
| title       | 是   | string | 告警标题，不超过`512`个字符，超出后将自动截断。
| event_status | 是   | string | 告警状态。<br /><br />枚举值（`首字母大写`）：*Critical*：严重，*Warning*：警告，*Info*：提醒，*Ok*：恢复。<br /><br />当指定为 Ok 时，意味着对告警进行自动恢复。
| alert_key    | 否   | string | 告警标识，用于对已经存在的告警进行更新或自动恢复。<br /><br />您可以自定义此值，但不可超过`255`个字符。您也可以依赖系统自动生成，该值会在响应中返回。<br /><br />如果您上报的是恢复事件，则此值必须存在。                     
| description  | 否   | string | 告警描述，不超过`2048`个字符，超出后将自动截断。
| labels       | 否   | map    | 告警标签集合，key 为标签名称，value 为标签值：<br /><br />1. 标签的 key 和 value 均为 string 类型，区分大小写。<br />2. 标签的 key 不要超过`128`个字符，遵循 Prometheus 标签命名规范。value 不超过`8192`字节（即 8 KB），超出后将自动截断，截断会回退到 UTF-8 字符边界，不会截出半个汉字。<br />3. 至多传入`50`个标签。请参考[标准告警最佳实践](/zh/on-call/integration/alert-integration/alert-sources/standard-alert#最佳实践)。<br /><br />示例："resource": "171.26.23.22", "check": "api latency > 500ms"
