通过 webhook 的方式同步 Dynatrace 告警事件到 Flashduty On-call。

<div className="hide">

## 在 Flashduty On-call
您可通过以下两种方式获取集成推送地址，任选其一即可。

### 使用专属集成

如果您只需将告警发往一个协作空间，选择此方式，配置更简单。

<AccordionGroup>
  <Accordion title="查看专属集成的配置步骤">
  
  1. 进入 Flashduty 控制台，选择 **协作空间**，打开一个协作空间
  2. 选择 **配置** → **集成数据** → **专属集成**，点击 **新增集成**
  3. 选择 **Dynatrace** 集成，点击 **保存**，生成卡片。
  4. 打开生成的集成卡片，复制 **推送地址**
  
    
</Accordion>
</AccordionGroup>

### 使用共享集成

如果您需要根据告警事件的 Payload 将告警路由到不同协作空间，选择此方式。

<AccordionGroup>
  <Accordion title="查看共享集成的配置步骤">
  
  1. 进入 Flashduty 控制台，选择 **集成中心 → 告警事件**
  2. 选择 **Dynatrace** 集成：
        - **集成名称**：为当前集成定义一个名称。
  3. 配置默认路由并选择协作空间；创建后可在 **路由** 中增加更多规则
  4. 点击 **保存**，复制生成的 **推送地址**
    
</Accordion>
</AccordionGroup>

</div>

## 在 Dynatrace 中配置

<Steps>
<Step title="在 Dynatrace 中添加 Custom integration 通知">

**操作路径**：Dynatrace › Settings › Integration › Problem notifications › Add notification

新版 Dynatrace 的入口为左侧导航栏 **Apps** › **Manage** 区域的 **Settings**；Dynatrace Classic 为 **Settings Classic**。

<div style={{textAlign: "center"}}>
<img alt="Add notification 按钮" width="600" src="https://download.flashcat.cloud/flashduty/doc/dyn-3.png" />

| 字段 | 填写 |
| --- | --- |
| Notification type（必填） | `Custom Integration` |
| Display name（必填） | `Flashduty` |
| Webhook URL（必填） | `{integration_url}` |
| Call webhook if problem is closed | 保持开启。关闭后 Flashduty 收不到问题关闭通知，告警不会自动恢复 |
| Alerting profile | 选择决定哪些问题触发该通知的 Alerting profile |

<div style={{textAlign: "center"}}>
<img alt="Custom Integration 基本配置" width="600" src="https://download.flashcat.cloud/flashduty/doc/dyn-4.png" />
</div>

</Step>
<Step title="在 Dynatrace 中填写 Custom payload">

**操作路径**：Dynatrace › Settings › Integration › Problem notifications › Add notification › Custom payload

在 **Custom payload** 中填写以下内容：

```
{
    "State":"{State}",
    "PID":"{PID}",
    "ProblemTitle":"{ProblemTitle}",
    "ProblemImpact":"{ProblemImpact}",
    "ProblemDetails":"{ProblemDetailsText}",
    "ProblemURL":"{ProblemURL}",
    "ProblemSeverity":"{ProblemSeverity}",
    "ImpactedEntityNames":"{ImpactedEntityNames}",
    "Tags":"{Tags}"
}
```

<div style={{textAlign: "center"}}>
<img alt="Custom payload 配置" width="600" src="https://download.flashcat.cloud/flashduty/doc/dyn-5.png" />
</div>

点击 **Save changes** 保存。

</Step>
<Step title="发送测试并用真实问题验证">

**操作路径**：Dynatrace › Settings › Integration › Problem notifications

打开刚创建的通知，点击 **Send test notification**

**Send test notification** 只能证明 Dynatrace 能连通 `{integration_url}`；测试内容是否带有 `PID`、`ProblemSeverity` 等字段以 Dynatrace 实际发送为准，不要把它当作 payload 验证。请在 Dynatrace 中产生一个真实问题（或等待已有问题触发），几秒后回到 Flashduty，集成显示 **最新事件时间**，说明配置成功。
{/* console:
接入清单中的「收到第一个事件」同时变为已完成。
*/}

问题关闭时 Dynatrace 会再推送一次 `State` 为 `RESOLVED` 的通知，对应的 Flashduty 告警恢复。

</Step>
</Steps>

## 状态和告警等级

<div className="md-block">

| Dynatrace | Flashduty |
| --- | --- |
| AVAILABILITY | Critical |
| ERROR | Warning |
| PERFORMANCE | Info |
| RESOURCE_CONTENTION | Info |
| CUSTOM_ALERT | Info |
| 其他或空 | Info |

</div>

## Alert Key 与恢复

Flashduty 用 payload 中的 `PID`（Dynatrace 问题 ID）作为 Alert Key，同一问题的多次推送合并为同一条告警。`State` 为 `RESOLVED` 时告警恢复，其他取值按上表等级触发。告警标题为「受影响实体名称::问题标题」。
