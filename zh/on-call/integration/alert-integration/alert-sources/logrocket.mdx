通过 LogRocket 时间序列图表（Timeseries）告警的 Webhook 类型，将指标告警同步到 Flashduty On-call。每条 LogRocket 告警对应一条 Flashduty 告警：指标越过阈值时触发，回到阈值内时自动恢复。

<div className="hide">

## 在 Flashduty On-call

您可通过以下两种方式获取集成推送地址，任选其一即可。

### 使用专属集成

1. 进入 Flashduty 控制台，选择 **协作空间**，打开一个协作空间
2. 选择 **配置** → **集成数据** → **专属集成**，点击 **新增一个集成**
3. 选择 **LogRocket**，点击 **保存**
4. 打开生成的集成卡片，复制 **推送地址**

### 使用共享集成

1. 进入 Flashduty 控制台，选择 **集成中心 → 告警事件**
2. 选择 **LogRocket**，填写集成名称
3. 配置默认路由并选择协作空间；创建后可在 **路由** 中增加更多规则
4. 点击 **保存**，复制生成的 **推送地址**

</div>

## 在 LogRocket 中配置

<Steps>
<Step title="为时间序列图表添加 Webhook 告警">

1. 在 LogRocket 中打开 **Analytics → Timeseries**，构建需要告警的图表并点击 **Save**（告警只支持已保存的 Timeseries 图表）
2. 点击图表右上角的 **Alerts → Create Alert**，填写 **Alert name**
3. 在 **Trigger alert when** 中设置比较方向（**greater than** 或 **less than**）、阈值和时间窗口，例如 “Session count is less than 1 sessions within 5 minutes”
4. 在 **Send alert via** 中勾选 **Webhook**，将 Flashduty 集成的完整推送地址（需包含 `integration_key`）粘贴到 **Webhook** 输入框，点击 **Save Alert**

一个账号最多可创建 100 条告警，所有告警可在 **Settings → Alerts** 页面统一管理。

</Step>

<Step title="验证">

让指标越过阈值，确认 Flashduty 收到活动告警；指标回到阈值内后，确认该告警自动恢复。

</Step>
</Steps>

Issues Alerts（新增严重问题）的 Webhook 使用另一种消息格式，且不带告警 ID，无法关联恢复，Flashduty 收到后直接返回成功，不创建告警。

## Alert Key

Alert Key 使用 LogRocket 推送的 `alert_id`。LogRocket 说明该 ID 在同一条告警多次触发和恢复之间保持不变，因此触发和恢复事件使用同一个 Alert Key。修改告警的阈值、时间间隔或图表位置不会改变 Alert Key。缺少 `alert_id` 的请求会被拒绝。

## 状态和告警等级

| LogRocket `status` | Flashduty 状态 | Flashduty 等级 |
| :--- | :--- | :--- |
| `triggered` | 触发 | Warning |
| `resolved` | 恢复 | - |

LogRocket 的 Webhook 不携带等级，指标越过阈值不等同于服务中断，因此统一按 Warning 处理。其他 `status` 值会被拒绝。

## 标签

| 标签 | 来源 |
| :--- | :--- |
| `alert_id` | LogRocket 告警 ID |
| `status` | `triggered` 或 `resolved` |
| `check` | 告警标题，取自 `reason` |
| `project_url` | LogRocket 项目链接 |
| `dashboard_url` | 图表所在仪表盘链接 |
| `metric_url` | 图表链接 |
| `operator` | 比较方向，`GT` 或 `LT` |
| `threshold` / `threshold_unit` | 阈值及其单位 |
| `interval` / `interval_unit` | 评估的时间间隔及单位，单位为 `MINUTES` 或 `HOURS` |

告警标题和描述取自 `reason`（LogRocket 会填入您设置的告警名称）；缺少 `reason` 时标题为 `LogRocket alert <alert_id>`。

## 排查问题

- **Flashduty 返回参数错误**：确认 URL 完整且包含 `integration_key`；确认推送来自 Timeseries 图表告警而非 Issues Alerts
- **告警没有恢复**：确认恢复通知也推送到了同一个 URL，且 Flashduty 收到的 `alert_id` 与触发时一致
- **告警长期不恢复**：可在协作空间中开启 **超时自动关闭**，作为恢复通知丢失时的兜底，详见 [创建协作空间](/zh/on-call/channel/create-edit)

更多字段含义请参阅 [LogRocket 指标告警](https://docs.logrocket.com/docs/metrics-alerting)。
