Raritan PX 系列 PDU 通过事件规则中的 **Send email** 动作发送邮件，可以自定义邮件主题和内容。Flashduty 的 [邮件集成](/zh/on-call/integration/alert-integration/alert-sources/email) 可以接收这些邮件，并按规则从邮件标题判断是触发还是恢复，因此不需要单独的 Raritan 集成：在 Flashduty 创建邮件集成，把它的邮件地址填进 PDU 的 Send email 动作，把邮件主题设成下文的固定格式，再配置推送规则。

## 在 Flashduty On-call
---

您可通过以下两种方式获取集成邮件地址，任选其一即可。**集成类型都选择邮件 Email**，不是 Raritan。

### 使用专属集成

1. 进入 Flashduty 控制台，选择 **协作空间**，打开一个协作空间
2. 选择 **配置** → **集成数据** → **专属集成**，点击 **新增一个集成**
3. 选择 **邮件 Email**，点击 **保存**
4. 打开生成的集成卡片，复制 **邮件地址**，再按下文配置推送规则

### 使用共享集成

1. 进入 Flashduty 控制台，选择 **集成中心 → 告警事件**
2. 选择 **邮件 Email**，填写集成名称，复制 **邮箱地址**
3. 按下文配置推送规则
4. 配置默认路由并选择协作空间，点击 **保存**

## 在 Flashduty 中配置推送规则
---

下面的主题格式把设备名、事件规则名和断言标志放进标题。断言标志 `1` 表示事件条件成立，`0` 表示事件条件解除。规则从标题提取设备名和事件规则名作为 Alert Key，触发和恢复邮件的这两部分相同，恢复邮件因此能关闭对应的告警。

1. **推送模式** 选择 **根据规则触发或关闭告警**
2. 按顺序添加下面 2 条规则。每条规则的条件都是 **邮件标题** **匹配** 给出的正则，Alert Key **提取自** **邮件标题**
3. **默认规则** 选择：如果以上规则均不满足，则 **丢弃该邮件**

规则 1：关闭告警

```
条件：邮件标题 匹配 /^Raritan PX \| .* \| 0$/
正则表达式：/^Raritan PX \| (.+) \| (.+) \| 0$/
```

规则 2：触发告警

```
条件：邮件标题 匹配 /^Raritan PX \| .* \| 1$/
正则表达式：/^Raritan PX \| (.+) \| (.+) \| 1$/
```

关闭规则排在触发规则前面。默认规则选丢弃，是为了让不符合主题格式的邮件（例如其他事件规则发出的默认邮件）不生成无法自动关闭的告警。

## 在 Raritan PX 中配置
---

以下路径来自 Raritan PX-Series PDU 用户指南（固件 4.3.11），在 PDU 的 Web 界面中操作。

1. **SMTP**：在 **SMTP Server** 页面配置发信服务器，Send email 动作默认使用该服务器
2. **创建动作**：进入 **Device Settings** → **Event Rules**，新建动作，**Action** 选择 **Send email**，在 **Recipient email addresses** 填 Flashduty 邮件集成的地址
3. **邮件主题**：勾选 **Custom subject**，填入：

```
Raritan PX | [DEVICENAME] | [EVENTRULENAME] | [ISASSERTED]
```

`[DEVICENAME]`（事件发生的设备名）、`[EVENTRULENAME]`（匹配的事件规则名）、`[ISASSERTED]`（事件条件变为成立时为 1，解除时为 0）是用户指南列出的占位符，发送时会替换成实际值。渲染后的主题形如：

```
Raritan PX | PX3-rack12 | Rack12 temperature high | 1
```

4. **创建事件规则**：进入 **Device Settings** → **Event Rules**，新建规则，选择要监控的事件（例如温度传感器的 **Above upper critical threshold**），**Trigger condition** 选择 **Both**，使事件发生和解除时都触发动作；在 **Available actions** 里选中第 2 步创建的 Send email 动作
5. **邮件正文**：规则只读取邮件标题，正文用默认内容或自定义内容都可以

## 限制
---

- **事件规则名要唯一**：Alert Key 由设备名和事件规则名组成，多个事件共用同一个规则名时会合并到同一条告警。每个要监控的事件建一条独立的事件规则，并起不同的规则名。
- **触发条件**：**Trigger condition** 选择 **Asserted** 时只有触发邮件，没有恢复邮件，告警不会自动关闭。
- **类型与严重程度**：告警在 Flashduty 中显示的集成类型是邮件 Email；严重程度统一为 Warning，可以通过 [告警处理 Pipeline](/zh/on-call/integration/alert-integration/alert-pipelines) 按标题内容调整。
