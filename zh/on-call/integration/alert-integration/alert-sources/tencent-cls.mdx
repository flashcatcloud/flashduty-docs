通过 webhook 的方式同步腾讯云日志服务 CLS 监控告警事件到 Flashduty On-call。

<div className="hide">

## 在 Flashduty On-call
您可通过以下两种方式获取集成推送地址，任选其一即可。

### 使用专属集成

如果您只需将告警发往一个协作空间，选择此方式，配置更简单。

<AccordionGroup>
  <Accordion title="查看专属集成的配置步骤">
  
  1. 进入 Flashduty 控制台，选择 **协作空间**，打开一个协作空间
  2. 选择 **配置** → **集成数据** → **专属集成**，点击 **新增集成**
  3. 选择 **腾讯云 CLS** 集成，点击 **保存**，生成卡片。
  4. 打开生成的集成卡片，复制 **推送地址**
  
    
</Accordion>
</AccordionGroup>

### 使用共享集成

如果您需要根据告警事件的 Payload 将告警路由到不同协作空间，选择此方式。

<AccordionGroup>
  <Accordion title="查看共享集成的配置步骤">
  
  1. 进入 Flashduty 控制台，选择 **集成中心 → 告警事件**
  2. 选择 **腾讯云 CLS** 集成：
        - **集成名称**：为当前集成定义一个名称。
  3. 配置默认路由并选择协作空间；创建后可在 **路由** 中增加更多规则
  4. 点击 **保存**，复制生成的 **推送地址**
    
</Accordion>
</AccordionGroup>
</div>

## 推送内容

CLS 按您在通知渠道组中填写的请求内容推送 JSON 对象，Flashduty 读取以下字段：

| 字段 | 含义 | 在 Flashduty 中 |
| :--- | :--- | :--- |
| `alarm` | 告警策略名称 | 告警标题 |
| `alarm_id` | 告警策略 ID | Alert Key |
| `level` | 告警级别 | 告警等级，标签 `level` |
| `notify_type` | 通知类型 | 为 `2` 时按恢复处理，标签 `notify_type` |
| `message` | 告警消息 | 告警描述 |
| `query_result` | 查询结果 | 第一行结果追加到描述 |
| `condition` | 触发条件 | 追加到描述 |
| `query_log` | 查询日志 | 第一条日志写入标签 `first_query_log` |
| `analysis_result` | 多维分析结果 | 标签 `analysis_result`（JSON） |
| `label` | 告警策略标签 | 每个键值对写成同名标签 |
| `topic`、`topic_id`、`region`、`uin`、`nickname` | 日志主题与账号信息 | 同名标签 |
| `start_time`、`notify_time`、`consecutive_alert_nums`、`duration`、`trigger_params`、`happen_threshold`、`alert_threshold` | 告警上下文 | 同名标签 |
| `detail_url`、`query_url` | 详情与查询链接 | 同名标签 |

告警描述依次拼接 `message`、`query_result` 的第一行和 `condition`。`alarm`、`alarm_id` 和 `level` 为必填字段，缺少任一项时返回参数错误。

## Alert Key

Flashduty 使用 `alarm_id` 作为 Alert Key。同一条告警策略的多次触发和恢复通知携带相同的 `alarm_id`，会落在同一条告警上；不同告警策略各自生成一条告警。

修改告警策略名称、级别、标签或查询语句都不会改变 Alert Key。

## 标签

| 标签 | 来源 |
| :--- | :--- |
| `alarm` | 告警策略名称 `alarm` |
| `level` | 告警级别 `level` |
| `notify_type` | 通知类型 `notify_type` |
| `topic` / `topic_id` | 日志主题名称和 ID |
| `region` / `uin` / `nickname` | 地域和账号信息 |
| `happen_threshold` / `alert_threshold` | 触发阈值和告警阈值 |
| `consecutive_alert_nums` / `duration` / `trigger_params` | 连续触发次数、持续时间和触发参数 |
| `start_time` / `notify_time` | 告警开始时间和通知时间 |
| `detail_url` / `query_url` | 详情链接和查询链接 |
| `first_query_log` | `query_log` 第一条日志的 JSON |
| `analysis_result` | 多维分析结果的 JSON |
| `label` 中的键 | 告警策略标签，原样写成同名标签 |

值为空字符串或字符串 `null` 的标签会被丢弃。

## 排查问题

- **告警没有恢复**：只有 `notify_type` 为 `2` 的推送才按恢复处理；自定义回调内容中缺少 `notify_type` 时，恢复通知也会被当作触发
- **推送被拒绝**：`alarm`、`alarm_id` 和 `level` 为必填；`label` 必须是 JSON 对象，使用 `{{.Label}}` 而不是加 `escape` 的字符串，否则请求体解析失败
- **告警等级与预期不符**：`level` 只识别 `Info`、`Warn` 和 `Critical`（区分大小写），其他取值按 Info 处理
- **标签没有出现**：回调内容中的变量在推送时没有取值，会渲染为空字符串并被丢弃；`label` 中值为字符串 `null` 的键同样会被丢弃
- **同一策略的告警合并成一条**：Alert Key 取自 `alarm_id`，这是预期行为
