通过 webhook 的方式同步 Influxdata 告警事件到 Flashduty On-call。

<div className="hide">

## 在 Flashduty On-call
您可通过以下两种方式获取集成推送地址，任选其一即可。

### 使用专属集成

如果您只需将告警发往一个协作空间，选择此方式，配置更简单。

<AccordionGroup>
  <Accordion title="查看专属集成的配置步骤">
  
  1. 进入 Flashduty 控制台，选择 **协作空间**，打开一个协作空间
  2. 选择 **配置** → **集成数据** → **专属集成**，点击 **新增集成**
  3. 选择 **Influxdata** 集成，点击 **保存**，生成卡片。
  4. 打开生成的集成卡片，复制 **推送地址**
  
    
</Accordion>
</AccordionGroup>

### 使用共享集成

如果您需要根据告警事件的 Payload 将告警路由到不同协作空间，选择此方式。

<AccordionGroup>
  <Accordion title="查看共享集成的配置步骤">
  
  1. 进入 Flashduty 控制台，选择 **集成中心 → 告警事件**
  2. 选择 **Influxdata** 集成：
        - **集成名称**：为当前集成定义一个名称。
  3. 配置默认路由并选择协作空间；创建后可在 **路由** 中增加更多规则
  4. 点击 **保存**，复制生成的 **推送地址**
    
</Accordion>
</AccordionGroup>
</div>

## 在 Influxdata 中配置

支持 Influxdata 1.x ~ 2.x 版本，不同版本配置有差异，在各步骤的页签中分别说明。

<Steps>
<Step title="在 Influxdata 中创建推送通道">

<Tabs>
<Tab title="2.x 版本">

**操作路径**：InfluxDB 控制台 › Alerts › Alerts › Notification Endpoints › Create

| 字段 | 填写 |
| --- | --- |
| Destination（必填） | `HTTP` |
| Name（必填） | `Flashduty` |
| HTTP Method（必填） | `POST` |
| URL（必填） | `{integration_url}` |
| Auth method（可选） | `None` |

填写后点击 **Create Notification Endpoint**。

<img alt="drawing" width="600" src="https://download.flashcat.cloud/flashduty/doc/influxdb-1.png" />

</Tab>
<Tab title="1.x 版本">

**操作路径**：Chronograf › Alerting › Alert Rules › 点击需要同步事件的告警规则 › Alert Rule Builder › Alert Handlers

| 字段 | 填写 |
| --- | --- |
| Alert Handlers（必填） | 选择 `Add Another Handler`，类型选择 `post` |
| HTTP endpoint（必填） | `{integration_url}` |

<img alt="drawing" width="600" src="https://download.flashcat.cloud/influxdb-alert-rule.png" />

</Tab>
</Tabs>

</Step>
<Step title="在 Influxdata 中使用该通道">

<Tabs>
<Tab title="2.x 版本">

**操作路径**：InfluxDB 控制台 › Alerts › Alerts › Notification Rules › Create

| 字段 | 填写 |
| --- | --- |
| About（必填） | 按需配置名称与执行周期 |
| Conditions（必填） | 按需配置，**When status is equal to** 选择要推送的状态 |
| Message（必填） | 选择上一步创建的 `Flashduty` |

填写后点击 **Create Notification Rule**。Notification Rule 只在状态等于所选状态时推送；要在恢复时自动恢复 Flashduty 中的告警，再创建一条状态为 `OK` 的规则，通道同样选择 `Flashduty`。

<img alt="drawing" width="600" src="https://download.flashcat.cloud/flashduty/doc/influxdb-2.png" />

</Tab>
<Tab title="1.x 版本">

**操作路径**：Chronograf › Alerting › Alert Rules › Alert Rule Builder

点击 **Save Rule** 保存规则。告警恢复时 Kapacitor 会推送 level 为 `OK` 的事件，Flashduty 中对应的告警自动恢复。

</Tab>
</Tabs>

</Step>
<Step title="触发告警并确认 Flashduty 收到事件">

**操作路径**：InfluxDB 控制台 › Alerts › Alerts › Notification Rules（2.x）；Chronograf › Alerting › Alert Rules（1.x）

两个版本都没有可以直接发送测试事件的入口，等待告警规则被真实数据触发。几秒后回到 Flashduty，集成显示 **最新事件时间**，说明配置成功且收到事件。
{/* console:
接入清单中的「收到第一个事件」同时变为已完成。
*/}

</Step>
</Steps>

## 直接使用 Kapacitor（不经过 Chronograf）

Chronograf 的 `post` 处理器就是 Kapacitor 的 `post` 事件处理器，直接使用 Kapacitor 时，可以在 TICKscript 的 `alert()` 节点上添加 `.post('<推送地址>')`，或用 topic 处理器（`kind: post`，`options.url` 填推送地址）。完整步骤见 [Kapacitor 告警集成](/zh/on-call/integration/alert-integration/alert-sources/kapacitor)。

## 状态和告警等级

<div className="md-block">
  
Influxdata 告警事件到 Flashduty 告警等级映射关系：

| Influxdata 1.x（`level`） | Flashduty |
| ---------- | -------- |
| CRITICAL | Critical |
| WARNING / WARN | Warning |
| INFO | Info |
| OK | Ok（恢复，等级取事件的 `previousLevel`） |

1.x 的 `level` 取其他值时，请求会被拒绝。

| Influxdata 2.x（`_level`） | Flashduty |
| ---------- | -------- |
| crit | Critical |
| warn | Warning |
| info | Info |
| ok | Ok（恢复） |
| 其他值（如 unknown） | Info |

</div>
