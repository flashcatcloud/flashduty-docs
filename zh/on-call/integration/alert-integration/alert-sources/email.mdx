在 Flashduty On-call 生成唯一的邮件地址，通过邮件的方式将告警的发生与恢复同步到 Flashduty On-call。

<div className="hide">

## 创建邮件集成

您可通过以下 2 种方式，获取一个邮件地址，任选其一即可。

### 使用专属集成

如果您只需将告警发往一个协作空间，选择此方式，配置更简单。

<AccordionGroup>
  <Accordion title="查看专属集成的配置步骤">
  
  1. 进入 Flashduty 控制台，选择 **协作空间**，打开一个协作空间
  2. 选择 **配置** → **集成数据** → **专属集成**，点击 **新增一个集成**
  3. 选择 **邮件 Email** 集成，点击 **保存**，生成卡片。
  4. 点击生成的卡片，可以查看到 **邮件地址**，复制备用，完成。
    
</Accordion>
</AccordionGroup>

### 使用共享集成

如果您需要根据告警事件的 Payload 将告警路由到不同协作空间，选择此方式。

<AccordionGroup>
  <Accordion title="查看共享集成的配置步骤">
  
  1. 进入 Flashduty 控制台，选择 **集成中心 → 告警事件**
  2. 选择 **邮件 Email** 集成：
        - **集成名称**：为当前集成定义一个名称。
        - **邮件地址**：为邮件设定一个方便记忆的前缀，需要保证在账户下唯一。
  3. 配置默认路由并选择协作空间；创建后可在 **路由** 中增加更多规则
  4. 保存后复制 **邮件地址** 备用。
    
</Accordion>
</AccordionGroup>
</div>

## 配置邮件集成

<Steps>
<Step title="在 Flashduty 中保存集成并复制邮件地址">

**操作路径**：Flashduty › 集成中心 › 该邮件集成 › 配置 › 邮箱地址

系统默认生成一个唯一的邮件前缀，您可以修改：

| 规则 | 说明 |
| --- | --- |
| 字符 | 只能使用字母和数字，建议只用小写 |
| 长度 | 不超过 50 个字符 |
| 唯一性 | 在账户下唯一 |

地址在 **保存** 后才生效，保存前发到该地址的邮件会被拒收。保存后复制完整的邮件地址。

</Step>
<Step title="在发件系统中把该地址加为告警收件人">

**操作路径**：发件系统 › 告警通知设置 › 收件人

在监控系统、云服务或脚本的告警通知中，把上一步的邮件地址加为收件人。如果该系统在 Flashduty 有专用集成（例如 Prometheus、Zabbix、Grafana），优先使用专用集成：专用集成可以识别告警等级和恢复状态，邮件集成的告警等级固定为 Warning。

</Step>
<Step title="从发件系统发送一封测试邮件">

**操作路径**：发件系统 › 告警通知设置 › 发送测试（没有测试入口时，等待一封真实告警邮件）

尽量发送一封与真实告警格式相同的邮件，下一步要在它的标题上划选。邮件到达后，它会出现在集成的示例邮件中，集成显示 **最新事件时间**。
{/* console:
接入清单中的「收到第一个事件」同时变为已完成。
*/}

</Step>
<Step title="在 Flashduty 中按真实邮件回答两个问题">

**操作路径**：Flashduty › 集成中心 › 该邮件集成 › 配置

**问题 1：同一个故障的多封邮件，怎么归到一起？**

| 选项 | 适用场景 | 行为 |
| --- | --- | --- |
| 每封都是新告警 | 通知类、不会重复发的邮件 | 每封邮件生成一条新告警，不会合并，也不会关闭 |
| 标题完全相同就合并（新建集成的默认值） | 定时重发、标题不变的提醒 | 标题完全相同的邮件合并到同一条未关闭的告警 |
| 按标题里的一段识别（推荐） | 触发和恢复邮件标题不同，例如 `PROBLEM: …` 和 `RESOLVED: …` | 在示例邮件标题中划出「是哪个故障」的那一段，系统据此生成 Alert Key 规则 |

选择 **按标题里的一段识别** 后：

1. 在 **示例邮件** 中选择上一步收到的邮件，也可以粘贴一封邮件的主题和正文
2. 在邮件标题中划选能代表故障的那一段，例如主机名加检查项 `web-01 disk`。不要包含 `PROBLEM`、`RESOLVED` 这类状态词和每次都会变化的数值
3. 系统生成一个只含一个捕获组的正则，例如 `^(?:PROBLEM|RESOLVED): (\S+ \S+) usage`，触发邮件和恢复邮件都能匹配。需要时点击 **改正则** 手动调整

**问题 2：怎么认出恢复邮件？**

| 选项 | 行为 |
| --- | --- |
| 标题包含关键词 | 填写恢复邮件标题中的关键词，例如 `RESOLVED`、`OK`。标题包含任一关键词的邮件会关闭 Alert Key 相同的告警 |
| 不发恢复邮件 | 告警需要手动关闭，或开启下文的静默检测 |

**其他邮件**：选择不匹配任何规则的邮件 **生成告警**（级别 Warning）还是 **丢弃**。丢弃的邮件仍会出现在示例邮件和接入清单中，并标记「已丢弃」。

点击 **保存**。

</Step>
<Step title="在 Flashduty 中核对触发和恢复是否关联">

**操作路径**：Flashduty › 集成中心 › 该邮件集成 › 配置 › 对一对：触发和恢复是否会关联

分别选择或粘贴一封触发邮件和一封恢复邮件：

- 两封得到同一个 Alert Key：恢复邮件会关闭这条告警，配置完成。
- Key 不同：页面同时显示两封邮件提取出的内容，回到问题 1 调整划选范围或正则。

**这封邮件会变成** 中显示示例邮件的处理结果：生成告警、关闭告警或丢弃，以及告警等级、标题、Alert Key 和标签。规则匹配但正则没有捕获到内容时，页面会提示 Alert Key 改用邮件标题生成。

</Step>
</Steps>

## 规则如何生效

问题 1 和问题 2 的回答会保存为一条 **触发** 规则和一条 **关闭** 规则。展开 **高级** 可以直接编辑底层规则（规则类型、过滤条件、Alert Key 提取字段和正则）。已有集成的规则原样显示在 **高级** 中；规则不符合问题 1、问题 2 的形式时，**高级** 保持展开，规则不会被改写。

- 每封邮件先按配置顺序匹配关闭规则，再按配置顺序匹配触发规则，命中第一条即停止。
- Alert Key 正则须为合法的 RE2 正则，可写成 `/…/` 的形式，保存时校验，非法的表达式会被拦截并提示「请输入合法的正则表达式」。至少需要一条触发规则。
- Alert Key 由正则捕获组的内容生成，多个捕获组用 `,` 连接。**正则没有捕获到内容时，系统使用邮件标题生成 Alert Key**，告警不会因为配置错误而丢失。
- Alert Key 可以从邮件标题或邮件正文中提取。
- 没有规则匹配时，按 **其他邮件** 的选择生成告警（Alert Key 由邮件标题生成）或丢弃。

### 为什么不能用 /(.*)/ 提取 Alert Key

`/(.*)/` 捕获整个标题。触发邮件 `PROBLEM: web-01 disk usage 93%` 和恢复邮件 `RESOLVED: web-01 disk usage 71%` 得到的 Alert Key 不同，恢复邮件找不到对应的告警，告警永远不会被关闭。

正则只应捕获代表故障本身的部分。例如对上面两封邮件使用：

```
^(?:PROBLEM|RESOLVED): (\S+ \S+) usage
```

两封邮件都捕获到 `web-01 disk`，Alert Key 相同。再设置关闭规则「标题包含 `RESOLVED`」，恢复邮件就会关闭触发邮件生成的告警。

## 静默检测

在集成卡片（编辑与预览）中，**静默检测**（Heartbeat）配置位于推送设置下方：在指定时间内未收到有效事件时，系统会生成一条 Warning 告警。

| 配置项 | 说明 |
| :--- | :--- |
| **启用静默检测** | 开关，默认关闭。开启后，仅成功通过集成校验的上游事件会刷新检测时间 |
| **检测时间（分钟）** | 在指定时间内未收到有效事件，即生成一条 Warning 告警。取值须为整数，范围为 10 分钟到 48 小时（默认 10 分钟） |
| **收到新事件后自动恢复** | 开关，默认开启。收到下一条有效事件时，自动恢复静默检测产生的告警 |

## 注意事项

1. 如果邮件消息体大于 5MB，系统会直接拒绝接收。
2. 如果邮件文字内容长度超过 128KB，系统会进行截断，并在故障详情中增加标签提示：

   ```
   body_cut = true
   ```

3. 如果邮件中包含附件，系统会直接丢弃附件，并在故障详情中增加标签提示：

   ```
   attachment_stripped = true
   ```

4. 邮件触发的新告警中，**标题即邮件标题，描述即邮件内容**，发件人在 `from` 标签中。

5. 如果您修改了账户域名，此邮件地址也会变更，务必记得更新推送地址。

## 状态和告警等级

当前邮件集成推送到 Flashduty On-call 的告警等级均为 Warning，但您可以通过[告警处理 Pipeline](/zh/on-call/integration/alert-integration/alert-pipelines) 来自定义严重程度。
