通过 webhook 的方式将夜莺（Nightingale / n9e）或 Flashcat 告警事件推送到 Flashduty。当告警触发时，向 Flashduty 发送触发事件；当告警恢复时，向 Flashduty 发送恢复事件。

在夜莺/Flashcat v8.0.0-beta.7 版本之后（含 beta.7），可以直接在告警通知规则中配置协作空间，不再需要使用路由规则；更早的版本通过 Webhook 回调地址推送，需要在 Flashduty 中设置路由规则。

<div className="hide">

## 前置条件

<Tabs>
  <Tab title="在夜莺/Flashcat">
    - 您必须拥有修改 **系统配置 → 全局通知** 或 **告警管理 → 告警规则** 的权限
    - 您的夜莺 Server 必须能够访问域名 `api.flashcat.cloud`
  </Tab>
  <Tab title="在 Flashduty">
    - 您必须拥有 Flashduty 账户并具备创建集成的权限
    - 您需要提前创建好协作空间并配置分派策略
  </Tab>
</Tabs>

## 在 Flashduty 获取推送地址

您可以通过以下两种方式获取推送地址，请根据您的需求选择。

### 使用专属集成（推荐）

如果您只需将告警发往一个协作空间，选择此方式，配置更简单。

<AccordionGroup>
  <Accordion title="查看专属集成的配置步骤">

  1. 登录 [Flashduty 控制台](https://console.flashcat.cloud)，选择 **协作空间**，进入目标空间的详情页面
  2. 选择 **配置** → **集成数据** → **专属集成**，点击 **新增一个集成**，选择 **夜莺/Flashcat** 集成类型，点击 **保存**
  3. 点击生成的集成卡片，复制 **推送地址** 备用
  4. （可选）点击 **编辑** 按钮，在 **控制台地址** 中输入夜莺控制台域名，Flashduty 将为新告警自动生成夜莺详情跳转链接

</Accordion>
</AccordionGroup>

### 使用共享集成

当您需要根据告警事件的 Payload 信息将告警路由到不同的协作空间时，选择此方式。

<AccordionGroup>
  <Accordion title="查看共享集成的配置步骤">

  1. 登录 [Flashduty 控制台](https://console.flashcat.cloud)，选择 **集成中心 → 告警事件**
  2. 选择 **夜莺/Flashcat** 集成，填写以下信息：
        - **集成名称**：为当前集成定义一个名称
        - **控制台地址**：（可选）输入夜莺控制台域名
  3. 配置默认路由并选择对应的协作空间。您可以稍后在 **路由** 页面配置更多路由规则
  4. 点击 **保存** 后，复制生成的 **推送地址** 备用

</Accordion>
</AccordionGroup>

</div>

## 在夜莺/Flashcat 中配置

<Steps>
<Step title="在夜莺中添加 Flashduty 推送地址">

<Tabs>
<Tab title="v8.0.0-beta.7 及以上">

**操作路径**：夜莺 › 通知 › 通知媒介 › FlashDuty

部分 v8 版本的 **通知媒介** 位于 **告警管理** 菜单下。

| 字段 | 填写 |
| --- | --- |
| 名称（必填） | 自定义名称，例如 `Flashduty` |
| URL（必填） | `{integration_url}` |
| 代理（可选） | 夜莺 Server 需要通过代理访问 Flashduty 时填写 |
| 超时时间（毫秒）、重试次数 | 保持默认（5000 毫秒、3 次） |

点击 **保存**。

![添加通知媒介](https://download.flashcat.cloud/flashduty/doc/zh/fd/n9e-1.png)

</Tab>
<Tab title="v6–v8.0.0-beta.6">

**操作路径**：夜莺 › 系统配置 › 通知设置 › 回调地址

启用一个新的 Webhook，在 `URL` 中填写 `{integration_url}`，保存。全局回调地址推送所有告警事件；如只需推送部分告警规则，跳过此步，在步骤 3 中按告警规则配置。

![全局 Webhook 配置](https://download.flashcat.cloud/flashduty/integration/n9e/n9e_v6_webhook.png)

</Tab>
<Tab title="v5.4–v5.15">

**操作路径**：夜莺 Server 实例 › etc/server.conf › [Alerting.Webhook]

在 `Alerting` 配置部分添加以下内容，保存后重启 n9e Server 使配置生效。全局 Webhook 推送所有告警事件；如只需推送部分告警规则，跳过此步，在步骤 3 中按告警规则配置。

```toml server.conf
[Alerting.Webhook]
Enable = true
Url = "{integration_url}"
BasicAuthUser = ""
BasicAuthPass = ""
Timeout = "5s"
Headers = ["Content-Type", "application/json", "X-From", "N9E"]
```

</Tab>
</Tabs>

</Step>
<Step title="在夜莺中创建发往 Flashduty 的通知规则">

**操作路径**：夜莺 › 通知 › 通知规则 › 新增

仅 v8.0.0-beta.7 及以上版本需要此步，更早的版本跳过。

| 字段（位于通知配置） | 填写 |
| --- | --- |
| 通知媒介（必填） | 上一步创建的 Flashduty 通知媒介 |
| Channels（可选） | 告警发往的协作空间，可多选；留空时发往集成的默认协作空间 |
| 适用级别、适用时段、适用标签（可选） | 按需过滤 |

协作空间需提前在 [Flashduty](https://console.flashcat.cloud/channel) 中创建，并配置分派策略。点击 **保存**。

![配置通知规则](https://download.flashcat.cloud/flashduty/doc/zh/fd/n9e-2.png)

</Step>
<Step title="在夜莺中为告警规则关联 Flashduty">

<Tabs>
<Tab title="v8.0.0-beta.7 及以上">

**操作路径**：夜莺 › 告警管理 › 告警规则 › 新增或编辑 › 通知配置

选择上一步创建的通知规则，点击 **保存**。

![关联告警规则](https://download.flashcat.cloud/flashduty/doc/zh/fd/n9e-3.png)

</Tab>
<Tab title="v5–v8.0.0-beta.6">

**操作路径**：夜莺 › 告警管理 › 告警规则 › 批量更新告警规则 › 回调地址

步骤 1 已配置全局回调地址时跳过此步。否则批量选中需要推送的告警规则，点击右上角 **批量更新告警规则**，在弹窗中选择 **回调地址** 字段，填写 `{integration_url}`。

![批量配置回调地址](https://download.flashcat.cloud/saas-n9e-rule.png)

</Tab>
</Tabs>

</Step>
<Step title="在夜莺中发送测试通知并确认">

**操作路径**：夜莺 › 通知 › 通知规则 › 目标规则 › 通知测试

v8.0.0-beta.7 及以上版本：点击 **通知测试**，选择一条历史告警事件发送。更早的版本没有该入口，请等待新告警触发。

几秒后回到 Flashduty，集成显示 **最新事件时间**，说明配置成功。

</Step>

## 静默检测

在集成卡片（编辑与预览）中，告警推送设置下方提供 **静默检测**（Heartbeat）配置：在指定时间内未收到有效事件时，系统会生成一条 Warning 告警。

| 配置项 | 说明 |
| :--- | :--- |
| **启用静默检测** | 开关，默认关闭。开启后，仅成功通过集成校验的上游事件会刷新检测时间 |
| **检测时间（分钟）** | 在指定时间内未收到有效事件，即生成一条 Warning 告警。取值须为整数，范围为 10 分钟到 48 小时（默认 10 分钟） |
| **收到新事件后自动恢复** | 开关，默认开启。收到下一条有效事件时，自动恢复静默检测产生的告警 |

## 状态和告警等级

夜莺/Flashcat 与 Flashduty 的告警等级映射关系如下：

| 夜莺等级 | Flashduty 等级 | 说明 |
| :---: | :---: | :--- |
| 1 | Critical | 严重 |
| 2 | Warning | 警告 |
| 3 | Info | 提醒 |

## 常见问题

<AccordionGroup>
  <Accordion title="为什么 Flashduty 没有收到告警？">
    **在 Flashduty 排查**
    
    1. **检查最新事件时间**：查看集成是否显示了 **最新事件时间**。如果没有，说明 Flashduty 未收到推送，请优先排查夜莺配置。
    
    2. **检查路由规则**：如果您使用的是 **共享集成**，请确认是否配置了 **路由规则**。未配置路由规则时，系统会拒绝新的推送。

    **在夜莺/Flashcat 排查**
    
    1. **确认告警已生成**：前往 **告警管理 → 历史告警**，确认配置 Webhook 后是否产生了新告警（状态必须为 **Triggered**）。
    
    2. **验证回调地址**：进入告警详情，检查 **回调地址** 是否与 Flashduty 推送地址完全匹配。
    
    3. **检查网络连通性**：登录夜莺 Server，确认可以访问 `api.flashcat.cloud` 域名。
    
    ```bash
    curl -I https://api.flashcat.cloud
    ```
    
    4. **查看错误日志**：如果网络正常，请检查 Server 日志中是否存在相关错误信息。

    <Tip>
    如果以上步骤仍无法解决问题，请联系 Flashduty 技术支持。
    </Tip>
  </Accordion>
  
  <Accordion title="告警恢复后 Flashduty 中的故障没有自动关闭？">
    请确认以下几点：
    
    1. 夜莺告警规则配置了恢复通知
    2. 恢复事件的 Webhook 回调地址与触发事件一致
    3. 告警的唯一标识（fingerprint）在触发和恢复时保持一致
  </Accordion>
  
  <Accordion title="如何测试集成是否配置成功？">
    您可以通过以下方式测试：
    
    1. 在夜莺中手动触发一条测试告警
    2. 等待几秒后，检查 Flashduty 集成列表中的 **最新事件时间** 是否更新
    3. 进入协作空间，确认是否生成了对应的故障
</Accordion>
</AccordionGroup>
