本集成接收 Amazon EventBridge 事件，可以通过 API destination 直接推送，也可以经 SNS 主题转发。CloudWatch 告警、GuardDuty、Security Hub、AWS Health、Amazon Inspector、AWS Config 和 DevOps Guru 事件会按各自的告警或发现合并，并在来源状态恢复时自动恢复；其他事件每条生成一条告警。

<div className="hide">

## 在 Flashduty On-call
您可通过以下两种方式获取集成推送地址，任选其一即可。

### 使用专属集成

如果您只需将告警发往一个协作空间，选择此方式，配置更简单。

<AccordionGroup>
  <Accordion title="查看专属集成的配置步骤">
  
  1. 进入 Flashduty 控制台，选择 **协作空间**，打开一个协作空间
  2. 选择 **配置** → **集成数据** → **专属集成**，点击 **新增一个集成**
  3. 选择 **AWS EventBridge** 集成，点击 **保存**，生成卡片。
  4. 打开生成的集成卡片，复制 **推送地址**
  
    
</Accordion>
</AccordionGroup>

### 使用共享集成

如果您需要根据告警事件的 Payload 将告警路由到不同协作空间，选择此方式。

<AccordionGroup>
  <Accordion title="查看共享集成的配置步骤">
  
  1. 进入 Flashduty 控制台，选择 **集成中心 → 告警事件**
  2. 选择 **AWS EventBridge** 集成：
        - **集成名称**：为当前集成定义一个名称。
  3. 配置默认路由并选择协作空间；创建后可在 **路由** 中增加更多规则
  4. 点击 **保存**，复制生成的 **推送地址**
    
</Accordion>
</AccordionGroup>

## 在 AWS EventBridge 中配置

<Steps>
<Step title="在 Amazon EventBridge 中创建指向 Flashduty 的 API destination">

<Tabs>
<Tab title="API destination（推荐）">

**操作路径**：Amazon EventBridge › Integration › API destinations › Connections › Create connection

| 字段 | 填写 |
| --- | --- |
| Connection name（必填） | `Flashduty` |
| Destination type（必填，位于 Authorization） | `Other` |
| Authorization type（必填） | `API Key` |
| API key name（必填） | `Flashduty` |
| Value（必填） | `{integration_key}`，即推送地址中的 `integration_key` |

点击 **Create** 保存。

<img alt="Connection 配置" width="600" src="https://download.flashcat.cloud/flashduty/doc/aws-eb-4.png" />

**操作路径**：Amazon EventBridge › Integration › API destinations › Create API destination

| 字段 | 填写 |
| --- | --- |
| Name（必填） | `Flashduty` |
| API destination endpoint（必填） | `{integration_url}` |
| HTTP method（必填） | `POST` |
| Connection type（必填） | `Use an existing connection`，选择上面创建的 `Flashduty` |

点击 **Create** 保存。

<img alt="API destination 配置" width="600" src="https://download.flashcat.cloud/flashduty/doc/aws-eb-6.png" />

</Tab>
<Tab title="SNS 主题">

**操作路径**：Amazon SNS › Subscriptions › Create subscription（主题不存在时先到 Topics › Create topic，`Type` 选择 `Standard`）

| 字段 | 填写 |
| --- | --- |
| Topic ARN（必填） | 用于转发 EventBridge 事件的 SNS 主题 |
| Protocol（必填） | `HTTPS` |
| Endpoint（必填） | `{integration_url}`，须是**本集成**的推送地址 |

点击 **Create subscription**，等待订阅状态变为 `Confirmed`。Flashduty 只访问 `sns.<region>.amazonaws.com`、`sns.<region>.amazonaws.com.cn` 和 `sns.<region>.amazonaws.eu` 上的订阅确认地址。SNS 主题和订阅的完整步骤见 [AWS CloudWatch 集成](/zh/on-call/integration/alert-integration/alert-sources/aws-cloudwatch)。

</Tab>
</Tabs>

</Step>
<Step title="在 Amazon EventBridge 中创建事件规则">

**操作路径**：Amazon EventBridge › Buses › Rules › Create rule

| 字段 | 填写 |
| --- | --- |
| Builder（控制台提供选择时） | `Advanced Builder` |
| Name（必填） | 自定义名称，例如 `Flashduty-Events` |
| Event bus | `AWS default event bus` |
| Rule type（必填） | `Rule with an event pattern`，点击 **Next** |
| Event source（必填） | `AWS events or EventBridge partner events` |
| Creation method / Method（必填） | `Custom pattern (JSON editor)` |
| Event pattern（必填） | 粘贴下方事件模式，点击 **Next** |
| Target types（必填） | `EventBridge API destination`，选择 `Use an existing API destination` 和上一步创建的 `Flashduty`（SNS 方式选择 `AWS service` › `SNS topic` 和该主题） |
| Execution role（必填） | `Create a new role for this specific resource` |
| Input transformer | 不要配置，保持发送完整事件 |


在规则中填写事件模式，例如：

```json
{
  "source": ["aws.guardduty", "aws.securityhub", "aws.health", "aws.inspector2", "aws.config", "aws.devops-guru", "aws.cloudwatch"],
  "detail-type": [
    "GuardDuty Finding",
    "Security Hub Findings - Imported",
    "Security Hub Findings - Custom Action",
    "AWS Health Event",
    "Inspector2 Finding",
    "Config Rules Compliance Change",
    "DevOps Guru New Insight Open",
    "DevOps Guru Insight Severity Upgraded",
    "DevOps Guru New Anomaly Association",
    "DevOps Guru Insight Closed",
    "CloudWatch Alarm State Change"
  ]
}
```

<Warning>
不要在规则中过滤掉恢复状态，否则告警无法自动恢复。例如只匹配 `"state": {"value": ["ALARM"]}`、`"newEvaluationResult": {"complianceType": ["NON_COMPLIANT"]}`、Security Hub 的 `"findings": {"Workflow": {"Status": ["NEW"]}}` 或 Inspector 的 `"status": ["ACTIVE"]`，都会丢掉恢复事件。
</Warning>

AWS Health 事件发往事件发生的区域，全局服务的事件在 `us-east-1`。需要在每个关心的区域创建规则。

<img alt="在 EventBridge 规则中选择 API destination 作为目标" width="600" src="https://download.flashcat.cloud/flashduty/doc/aws-eb-7.png" />

</Step>
<Step title="构造一条 CloudWatch 告警测试事件并确认">

**操作路径**：能访问 Flashduty 推送地址的终端

规则只会转发 AWS 真实产生的事件。要立即验证，可以向推送地址 POST 一条按事件格式构造的测试事件：

```bash
curl -X POST '{integration_url}' \
  -H 'Content-Type: application/json' \
  -d '{"version":"0","id":"flashduty-test-1","detail-type":"CloudWatch Alarm State Change","source":"aws.cloudwatch","account":"123456789012","region":"us-east-1","resources":["arn:aws:cloudwatch:us-east-1:123456789012:alarm:flashduty-test"],"detail":{"alarmName":"flashduty-test","state":{"value":"ALARM","reason":"Flashduty integration test"}}}'
```

把 `state.value` 改为 `OK` 再发送一次，可确认告警自动恢复。几秒后回到 Flashduty，集成显示 **最新事件时间**，说明配置成功。

## Alert Key 和恢复

| 来源 | `detail-type` | Alert Key | 恢复条件 |
| :--- | :--- | :--- | :--- |
| CloudWatch | `CloudWatch Alarm State Change` | 告警 ARN（`resources[0]`） | `state.value` 为 `OK` |
| GuardDuty | `GuardDuty Finding` | 账号 + 区域 + `detail.id` | 不自动恢复 |
| Security Hub | `Security Hub Findings - Imported`、`Security Hub Findings - Custom Action` | 每个发现的 `ProductArn` + `Id` | `Workflow.Status` 为 `RESOLVED` 或 `SUPPRESSED`，或 `RecordState` 为 `ARCHIVED` |
| AWS Health | `AWS Health Event` | `eventArn` + 受影响账号 | `statusCode` 为 `closed` |
| Amazon Inspector | `Inspector2 Finding` | `findingArn` | `status` 为 `CLOSED` 或 `SUPPRESSED` |
| AWS Config | `Config Rules Compliance Change` | 账号 + 区域 + 规则名 + 资源类型 + 资源 ID | `complianceType` 为 `COMPLIANT` 或 `NOT_APPLICABLE` |
| DevOps Guru | 所有 `DevOps Guru ...` 事件 | 账号 + 区域 + `insightId` | `DevOps Guru Insight Closed` |
| 其他事件 | 任意 | 事件 `id` | 不自动恢复 |

- 同一来源的后续事件（GuardDuty 的重复发现、Security Hub 的更新、Health 事件的进展）会合并到原告警
- 一个 Security Hub 事件包含多个发现时，每个发现生成一条告警
- 缺少上表 Alert Key 字段的事件会被拒绝（HTTP 400）
- GuardDuty 归档发现时不发送事件，告警需要手动关闭

## 状态和告警等级

EventBridge 事件没有统一的等级字段，所有事件都以 Warning 触发，与接入以来的行为一致。来源自带的等级保留在标签中，可以在 [告警处理](/zh/on-call/integration/alert-integration/alert-pipelines) 中按标签改写等级：

| 来源 | 等级标签 |
| :--- | :--- |
| GuardDuty | `guardduty_severity`（数值） |
| Security Hub | `severity_label` |
| Amazon Inspector | `inspector_severity` |
| AWS Health | `event_type_category` |
| AWS Config | `compliance_type` |
| DevOps Guru | `insight_severity` |

CloudWatch 告警可以在 **Alarm description** 中写 `flashduty_severity: critical`（可选 `critical`、`warning`、`info`）指定等级，写法与 [AWS CloudWatch 集成](/zh/on-call/integration/alert-integration/alert-sources/aws-cloudwatch) 相同。

## 标题和标签

- 告警标题为 `来源::detail-type`，例如 `aws.guardduty::GuardDuty Finding`
- 所有事件都带 `source`、`region`、`account`、`check`（`detail-type`）、`detail`（事件 `detail` 的 JSON）和 `resources` 标签
- `summary` 标签是可读摘要：有专门处理的来源取发现或告警的标题；其他事件依次取 CloudTrail 的 `eventSource eventName`、RDS 的 `SourceIdentifier Message`、ECS 的 `group stoppedReason`、EC2 的 `instance-id state`
- 有专门处理的来源还会附加 `finding_id`、`finding_arn`、`event_arn`、`config_rule_name`、`insight_id` 等来源字段，`resource` 取受影响资源（DevOps Guru 洞察没有该标签）

## 排查问题

- **API destination 调用失败**：确认 endpoint 是完整推送地址且包含 `integration_key`，`HTTP method` 为 `POST`
- **SNS 订阅停留在 `Pending confirmation`**：确认订阅的是本集成的推送地址，然后在 SNS 控制台执行 **Request confirmation**
- **告警没有恢复**：检查规则的事件模式是否过滤掉了恢复状态，以及目标是否配置了 Input transformer
- **同一发现产生多条告警**：确认事件来自上表中的来源且 `detail-type` 未被改写
