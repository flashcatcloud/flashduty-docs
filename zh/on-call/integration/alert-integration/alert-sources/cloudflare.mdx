通过 webhook 的方式同步 Cloudflare 告警事件到 Flashduty On-call。

<div className="hide">

## 在 Flashduty On-call
您可通过以下两种方式获取集成推送地址，任选其一即可。

### 使用专属集成

如果您只需将告警发往一个协作空间，选择此方式，配置更简单。

<AccordionGroup>
  <Accordion title="查看专属集成的配置步骤">
  
  1. 进入 Flashduty 控制台，选择 **协作空间**，打开一个协作空间
  2. 选择 **配置** → **集成数据** → **专属集成**，点击 **新增集成**
  3. 选择 **Cloudflare** 集成，点击 **保存**，生成卡片。
  4. 打开生成的集成卡片，复制 **推送地址**

    
</Accordion>
</AccordionGroup>

### 使用共享集成

如果您需要根据告警事件的 Payload 将告警路由到不同协作空间，选择此方式。

<AccordionGroup>
  <Accordion title="查看共享集成的配置步骤">
  
  1. 进入 Flashduty 控制台，选择 **集成中心 → 告警事件**
  2. 选择 **Cloudflare** 集成： 
        - **集成名称**：为当前集成定义一个名称。
  3. 配置默认路由并选择协作空间；创建后可在 **路由** 中增加更多规则
  4. 点击 **保存**，复制生成的 **推送地址**
    
</Accordion>
</AccordionGroup>
</div>

## 在 Cloudflare 中配置

<Steps>
<Step title="在 Cloudflare 中创建 Webhook 通知目的地">

**操作路径**：Cloudflare 控制台 › Alerts › Destinations › Webhooks › Create

旧版界面中 **Alerts** 称为 **Notifications**。

| 字段 | 填写 |
| --- | --- |
| Name（必填） | `Flashduty` |
| URL（必填） | `{integration_url}` |
| Secret（可选） | Flashduty 通过推送地址中的 `integration_key` 认证，无需填写 |

点击 **Save and Test** 保存。

</Step>

<Step title="在 Cloudflare 中让通知使用该 Webhook">

**操作路径**：Cloudflare 控制台 › Alerts

创建或编辑需要接入的通知，在发送目的地中选择上一步创建的 Webhook。配置 Webhook 通道后，即可在通知策略中使用。

</Step>

<Step title="验证">

**操作路径**：Cloudflare 控制台 › Alerts › 通知的 ⋯ 菜单 › Test

**Save and Test** 和 Test 只验证 Cloudflare 能否连通该地址；测试成功不代表 Flashduty 已收到可用的告警事件，请不要仅凭测试成功判断接入完成。等待一条真实通知触发，回到 Flashduty，集成显示 **最新事件时间** 即说明配置成功。
{/* console:
接入清单中的「收到第一个事件」同时变为已完成。
*/}

</Step>
</Steps>

## 状态和告警等级

<div className="md-block">

当前 Cloudflare 集成推送到 Flashduty 的告警等级均为 Warning，但您可以通过[告警处理 Pipeline](/zh/on-call/integration/alert-integration/alert-pipelines) 来自定义严重程度。

Cloudflare 通知没有恢复事件，告警不会自动恢复，请手动关闭，或在协作空间中开启[超时自动关闭](/zh/on-call/channel/create-edit)。Alert Key 取通知体中的 `policy_id`（通知策略 ID），同一策略的多次通知合并到同一条告警；没有 `policy_id` 时随机生成，每次通知都是一条新告警。

</div>
