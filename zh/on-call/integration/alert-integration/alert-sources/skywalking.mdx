通过 webhook 的方式同步 Skywalking 告警事件到 Flashduty On-call。

<div className="hide">

## 在 Flashduty On-call
您可通过以下两种方式获取集成推送地址，任选其一即可。

### 使用专属集成

如果您只需将告警发往一个协作空间，选择此方式，配置更简单。

<AccordionGroup>
  <Accordion title="查看专属集成的配置步骤">
  
  1. 进入 Flashduty 控制台，选择 **协作空间**，打开一个协作空间
  2. 选择 **配置** → **集成数据** → **专属集成**，点击 **新增集成**
  3. 选择 **Skywalking** 集成，点击 **保存**，生成卡片。
  4. 打开生成的集成卡片，复制 **推送地址**
  
    
</Accordion>
</AccordionGroup>

### 使用共享集成

如果您需要根据告警事件的 Payload 将告警路由到不同协作空间，选择此方式。

<AccordionGroup>
  <Accordion title="查看共享集成的配置步骤">
  
  1. 进入 Flashduty 控制台，选择 **集成中心 → 告警事件**
  2. 选择 **Skywalking** 集成：
        - **集成名称**：为当前集成定义一个名称。
  3. 配置默认路由并选择协作空间；创建后可在 **路由** 中增加更多规则
  4. 点击 **保存**，复制生成的 **推送地址**
    
</Accordion>
</AccordionGroup>
</div>

## 在 Skywalking 中配置

<Steps>
<Step title="在告警规则中添加 level 标签">

**操作路径**：Skywalking OAP 服务器 › `./config/alarm-settings.yml` › `rules`

登录 Skywalking 服务器，打开配置文件 `./config/alarm-settings.yml`，在每条告警规则中添加 `tags.level`，Flashduty 据此确定告警等级。

| 键 | 填写 |
| --- | --- |
| `tags.level`（可选，v8.6.0 及以上版本才支持 `tags`，其他版本可以不添加） | `Critical`、`Warning` 或 `Info`，注意大小写；不填或其他取值按 Info 处理 |

```yaml
rules:
    endpoint_relation_resp_time_rule:
        expression: sum(endpoint_relation_resp_time > 1000) >= 2
        period: 10
        message: Response time of endpoint relation {name} is more than 1000ms in 2 minutes of last 10 minutes
        tags:
            level: Warning
```

</Step>
<Step title="添加 Flashduty 的 webhook 地址并重启">

**操作路径**：Skywalking OAP 服务器 › `./config/alarm-settings.yml` › 文件底部

按 Skywalking 版本选择写法，地址为 `{integration_url}`：

<Tabs>
<Tab title="v8.8.0 ~ v9.5.0">

```yaml
webhooks:
    - url: {integration_url}
```

</Tab>
<Tab title="v10.0.0">

```yaml
hooks:
  webhook:
    default:
      is-default: true
      urls:
        - {integration_url}
```

</Tab>
</Tabs>

保存配置文件，并重启 Skywalking 服务使其生效。

</Step>
<Step title="触发告警并确认">

**操作路径**：Skywalking OAP 服务器 › `./config/alarm-settings.yml`

Skywalking 没有 webhook 测试入口，等待某条已配置规则的 `expression` 命中，即可产生真实告警。

几秒后回到 Flashduty，集成显示 **最新事件时间**，说明配置成功。
{/* console:
接入清单中的「收到第一个事件」同时变为已完成。
*/}

</Step>
</Steps>

## 推送内容

Skywalking 的 Webhook 一次 POST 一个 JSON 数组，数组中每条告警生成一条 Flashduty 告警。Flashduty 读取以下字段：

| Skywalking 字段 | 用途 |
| :--- | :--- |
| `alarmMessage` | 告警标题 |
| `ruleName` | 告警规则名称，写入标签 `check`，并参与 Alert Key |
| `id0` | 告警实体 ID，参与 Alert Key |
| `name` | 实体名称，写入标签 `name` |
| `scope` | 实体类型，写入标签 `scope` |
| `tags[]` | 每个键值对写入同名标签；`level` 同时决定告警等级 |

## Alert Key

Flashduty 用 `id0` 和 `ruleName` 计算 Alert Key。同一个实体上的同一条告警规则产生的多次告警携带相同的 `id0` 和 `ruleName`，会合并为一条 Flashduty 告警。

告警消息 `alarmMessage`、实体名称 `name`、`scope` 和 `tags` 的变化不会改变 Alert Key；不同实体或不同告警规则各自产生一条告警。一次推送中的多条告警逐条按各自的 Alert Key 归并。

## 状态和告警等级

<div className="md-block">
  
| Skywalking | Flashduty |
| --- | --- |
| Critical | Critical |
| Warning | Warning |
| Info | Info |
| 其他或为空 | Info |

告警等级取自标签 `tags.level`，取值区分大小写；没有该标签或取其他值时按 Info 处理。

Skywalking 不发送恢复通知，Flashduty 不会因此自动恢复告警。在接收该集成的协作空间开启超时自动关闭（**Flashduty 控制台 › 协作空间 › 配置 › 设置 › 高级配置**），建议 24 小时，见[超时自动关闭](/zh/on-call/channel/create-edit)。

</div>

## 标签

| 标签 | 来源 |
| :--- | :--- |
| `check` | 告警规则名称 `ruleName` |
| `name` | 实体名称 `name` |
| `scope` | 实体类型 `scope` |
| `level` | `tags.level` 的取值，同时决定告警等级 |
| `tags` 中的其他键 | 每个键值对展开为一个标签 |

## 排查问题

- **告警等级不是预期**：检查规则的 `tags.level`，只识别 `Critical`、`Warning` 和 `Info`，其他取值按 Info 处理；`tags` 需要 Skywalking v8.6.0 及以上版本
- **同一规则的告警合并成一条**：Alert Key 取自实体 ID 和规则名称，同一实体上同一规则的告警会合并，这是预期行为
- **告警没有恢复**：Skywalking 不发送恢复通知，请在该协作空间开启超时自动关闭
- **Flashduty 返回参数错误**：请求体必须是 Skywalking 告警消息的 JSON 数组，单个对象或非 JSON 内容会被拒绝
