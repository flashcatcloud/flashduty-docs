通过 webhook 的方式同步 AppDynamics 告警事件到 Flashduty On-call。

<div className="hide">

## 在 Flashduty On-call
您可通过以下两种方式获取集成推送地址，任选其一即可。

### 使用专属集成

如果您只需将告警发往一个协作空间，选择此方式，配置更简单。

<AccordionGroup>
  <Accordion title="查看专属集成的配置步骤">
  
  1. 进入 Flashduty 控制台，选择 **协作空间**，打开一个协作空间
  2. 选择 **配置** → **集成数据** → **专属集成**，点击 **新增集成**
  3. 选择 **AppDynamics** 集成，点击 **保存**，生成卡片。
  4. 打开生成的集成卡片，复制 **推送地址**
  
    
</Accordion>
</AccordionGroup>

### 使用共享集成

如果您需要根据告警事件的 Payload 将告警路由到不同协作空间，选择此方式。

<AccordionGroup>
  <Accordion title="查看共享集成的配置步骤">
  
  1. 进入 Flashduty 控制台，选择 **集成中心 → 告警事件**
  2. 选择 **AppDynamics** 集成：
        - **集成名称**：为当前集成定义一个名称。
  3. 配置默认路由并选择协作空间；创建后可在 **路由** 中增加更多规则
  4. 点击 **保存**，复制生成的 **推送地址**
    
</Accordion>
</AccordionGroup>

</div>

## 在 AppDynamics 中配置

<Steps>
<Step title="在 AppDynamics 中创建 HTTP Request Template">

**操作路径**：AppDynamics › Alert & Respond › HTTP Request Templates › New

<img alt="HTTP Request Templates 列表" width="600" src="https://download.flashcat.cloud/flashduty/doc/appdyn-1.png" />

| 字段 | 填写 |
| --- | --- |
| Name（必填） | `Flashduty` |
| Request URL › Method（必填） | `POST` |
| Request URL › Raw URL（必填） | `{integration_url}` |
| Payload › MIME Type | `application/json` |
| Payload › Payload Encoding | `UTF-8` |
| Payload（必填） | 粘贴下方 JSON |
| Response Handling Criteria › Failure Criteria | 状态码 `400` |
| Response Handling Criteria › Success Criteria | 状态码 `201` |

<img alt="Request URL 配置" width="600" src="https://download.flashcat.cloud/flashduty/doc/appdyn-2.png" />

Payload：

```
{
	"policy_name":"${policy.name}",
	"message": "${latestEvent.eventMessage}",
	"application_name": "${latestEvent.application.name}",
	"link": "${latestEvent.deepLink}",
	"incident_id": "${latestEvent.incident.id}",
	"details": {
		"event_id": "${latestEvent.id}",
		"event_name": "${latestEvent.displayName}",
		"event_time": "${latestEvent.eventTime}",
		"event_type": "${latestEvent.eventType}",
		"health_rule_name":"${latestEvent.healthRule.name}",
		"node_name": "${latestEvent.node.name}",
		"severity": "${latestEvent.severity}"
	}
}
```

<img alt="Payload 配置" width="600" src="https://download.flashcat.cloud/flashduty/doc/appdyn-3.png" />

<img alt="Response Handling Criteria 配置" width="600" src="https://download.flashcat.cloud/flashduty/doc/appdyn-4.png" />

点击 **Save** 保存。

**特别说明（可选配置）**

配置：`Custom Templating Variables`

<img alt="Custom Templating Variables 配置" width="600" src="https://download.flashcat.cloud/flashduty/doc/appdyn-5.png" />

如果需要配置 `Custom Templating Variables`，可以参考以下 JSON 模版，其中 custom_variables 是固定写法，custom_variables 中的变量是自定义的 `Variables`，页面中定义的名称需要与 JSON 模版中引用的变量名保持一致。这些变量会成为 Flashduty 告警的同名标签。

```
{
	"policy_name":"${policy.name}",
	"message": "${latestEvent.eventMessage}",
	"application_name": "${latestEvent.application.name}",
	"link": "${latestEvent.deepLink}",
	"incident_id": "${latestEvent.incident.id}",
	"details": {
		"event_id": "${latestEvent.id}",
		"event_name": "${latestEvent.displayName}",
		"event_time": "${latestEvent.eventTime}",
		"event_type": "${latestEvent.eventType}",
		"health_rule_name":"${latestEvent.healthRule.name}",
		"event_type_key": "${latestEvent.eventTypeKey}",
		"node_name": "${latestEvent.node.name}",
		"severity": "${latestEvent.severity}"
	},
	"custom_variables":{
		"host":"${host}"
	}
}
```

</Step>
<Step title="在 AppDynamics 中创建 HTTP Action">

**操作路径**：AppDynamics › Alert & Respond › Actions › Create Action

1. 在左侧导航栏中选择 `Actions`，选择要为哪个应用类型创建，并点击 `Create`。
2. 在弹出的 `Create Action` 框中，选择 `Make an HTTP Request` 并点击 `OK`。

   <img alt="Create Action 对话框" width="600" src="https://download.flashcat.cloud/flashduty/doc/appdyn-6.png" />

3. 在 `Create HTTP Action` 框中输入 `Name`，`HTTP Request Template` 选择上一步创建的 **Flashduty**，点击 `SAVE`。

   <img alt="Create HTTP Action 对话框" width="600" src="https://download.flashcat.cloud/flashduty/doc/appdyn-7.png" />

</Step>
<Step title="在告警策略中使用该 Action">

**操作路径**：AppDynamics › Alert & Respond › Policies

1. 创建或编辑已有的策略（告警规则按需配置即可，此处省略告警规则的配置）。
2. 在策略配置页面的 `Actions` 处，点击添加并选择上一步创建的 Action。

   <img alt="策略中添加 Action" width="600" src="https://download.flashcat.cloud/flashduty/doc/appdyn-8.png" />

3. 在策略的触发条件（Health Rule Violation Events）中，除了健康规则违规开始的事件外，也勾选违规结束（Ended）和取消（Canceled）的事件。Flashduty 依据推送中的 `event_type` 判断恢复：包含 `CLOSE` 或 `CANCELED` 的类型会使对应告警恢复；没有勾选这类事件，AppDynamics 不会推送恢复，告警不会自动恢复。
4. 其他配置完成后，点击 `Save` 保存即可。

</Step>
<Step title="触发健康规则并验证">

让该策略覆盖的健康规则产生一次违规（或等待真实违规）。几秒后回到 Flashduty，集成显示 **最新事件时间**，说明配置成功；违规结束后确认对应告警恢复。
{/* console:
接入清单中的「收到第一个事件」同时变为已完成。
*/}

</Step>
</Steps>

## 状态和告警等级

<div className="md-block">

| AppDynamics | Flashduty |
| --- | --- |
| ERROR | Critical |
| WARN | Warning |
| INFO 及其他取值 | Info |

</div>

## Alert Key 与恢复

Flashduty 用 payload 中的 `incident_id` 作为 Alert Key；如果 `incident_id` 仍是未替换的 `${latestEvent.incident.id}`，则改用 `details.event_id`。`details.event_type` 包含 `CLOSE` 或 `CANCELED` 时告警恢复。告警标题为「应用名称::事件名称」。
