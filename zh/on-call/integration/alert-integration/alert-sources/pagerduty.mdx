Flashduty 实现了 PagerDuty Events API，输入和响应完全兼容。因此您可以通过 PagerDuty 协议推送告警事件到 Flashduty On-call。

同样的，对于已经支持推送事件到 PagerDuty 的告警系统（如 ElastAlert），您仅需要修改目的推送地址，即可利用 PagerDuty 协议推送事件到 Flashduty 。

<div className="hide">

## 在 Flashduty On-call
您可通过以下两种方式获取集成推送地址，任选其一即可。

### 使用专属集成

如果您只需将告警发往一个协作空间，选择此方式，配置更简单。

<AccordionGroup>
  <Accordion title="查看专属集成的配置步骤">
  
  1. 进入 Flashduty 控制台，选择 **协作空间**，打开一个协作空间
  2. 选择 **配置** → **集成数据** → **专属集成**，点击 **新增集成**
  3. 选择 **PagerDuty 兼容** 集成，点击 **保存**，生成卡片。
  4. 打开生成的集成卡片，复制 **推送地址**
  
    
</Accordion>
</AccordionGroup>

### 使用共享集成

如果您需要根据告警事件的 Payload 将告警路由到不同协作空间，选择此方式。

<AccordionGroup>
  <Accordion title="查看共享集成的配置步骤">
  
  1. 进入 Flashduty 控制台，选择 **集成中心 → 告警事件**
  2. 选择 **PagerDuty 兼容** 集成：
        - **集成名称**：为当前集成定义一个名称。
  3. 配置默认路由并选择协作空间；创建后可在 **路由** 中增加更多规则
  4. 点击 **保存**，复制生成的 **推送地址**
    
</Accordion>
</AccordionGroup>

</div>

## 在告警系统中配置
### 请求地址

```
{api_host}/event/push/alert/pagerduty
```

该地址同时支持 PagerDuty V1 和 V2 Events API。**您必须修改 PagerDuty 地址为该地址。**

### Pagerduty V2 Events

<div className="md-block">

#### 参考文档

[PagerDuty V2 Events](https://developer.pagerduty.com/api-reference/368ae3d938c9e-send-an-event-to-pager-duty)

#### 鉴权方式

两种方式任选其一：

- 方式 1：在 QueryString 中包含参数 integration_key
- 方式 2：将 integration_key 作为 routing_key 参数传入 Payload

</div>

### Pagerduty V1 Events

<div className="md-block">

#### 参考文档

[PagerDuty V1 Events](https://developer.pagerduty.com/api-reference/f0037990796c8-send-an-event-to-pager-duty)

#### 鉴权方式

两种方式任选其一：

- 方式 1：在 QueryString 中包含参数 integration_key
- 方式 2：将 integration_key 作为 service_key 参数传入 Payload

</div>

### 状态和告警等级

| 事件 | Flashduty |
| :--- | :--- |
| V2 `payload.severity` 为 `critical` 或 `error` | Critical |
| V2 `payload.severity` 为 `warning` | Warning |
| V2 `payload.severity` 为 `info` | Info |
| V1 `trigger` 事件 | Warning（V1 没有等级字段） |
| V1 或 V2 的 `resolve` 事件（V2 为 `event_action`，V1 为 `event_type`） | 恢复，关闭 `dedup_key`（V1 为 `incident_key`）对应的告警 |

V2 的 `severity` 取其他值时请求会被拒绝。非 `trigger` 事件必须带 `dedup_key`（V1 为 `incident_key`），否则请求会被拒绝。

### 配置示例

以 [ElastAlert2](https://github.com/jertel/elastalert2) 为例：

<Steps>
<Step title="在 ElastAlert2 中修改推送地址">

**操作路径**：ElastAlert2 源码 › `elastalert/alerters/pagerduty.py`

在当前页面填写集成名称并保存，重新打开集成详情，复制推送地址。修改已经部署好的 ElastAlert 实例对应源码，把该文件中 V2 和 V1 两处 PagerDuty 地址（`https://events.pagerduty.com/v2/enqueue`、`https://events.pagerduty.com/generic/2010-04-15/create_event.json`）都替换为：

```
{integration_url}
```

[查看 diff](https://github.com/jertel/elastalert2/commit/e815a62a6b1eecef6e1fef13afd99d905b67fc34)：

<img alt="drawing" width="600" src="https://download.flashcat.cloud/pagerduty-replace-endpoint.png" />

</Step>

<Step title="在 ElastAlert2 规则文件中配置告警">

**操作路径**：ElastAlert2 规则文件 › `alert`

遵循 [ElastAlert PagerDuty 推送配置文档](https://elastalert2.readthedocs.io/en/latest/alerts.html#pagerduty) 步骤，配置告警。Flashduty 相关的配置项如下：

| 配置项 | 填写 |
| --- | --- |
| `alert`（必填） | `pagerduty` |
| `pagerduty_service_key`（必填） | `{integration_key}` |
| `pagerduty_client_name`（必填） | 监控客户端名称，例如 `elastalert2` |
| `pagerduty_api_version`（可选） | `v2`；默认为 `v1` |
| `pagerduty_v2_payload_*`（可选） | `class`、`component`、`group`、`severity`、`source` 等，仅 `v2` 生效；`severity` 默认 `critical`，可选 `error`、`warning`、`info` |

完整规则示例：

```
name: "app error rule"
type: "frequency"
index: "app-logs-*"
is_enabled: true
num_events: 1
realert:
  minutes: 1
terms_size: 50
scan_entire_timeframe: true
timeframe:
  minutes: 60
timestamp_field: "created_at"
timestamp_type: "unix_ms"
use_strftime_index: false
alert_subject: "{0} error on {1}"
alert_subject_args:
  - "service"
  - "host"
alert_text: "{0}"
alert_text_args:
  - "message"
filter:
  - query:
   query_string:
     query: "created_at:*"

# ------- Flashduty ----------------
alert: pagerduty
pagerduty_service_key: {integration_key}
pagerduty_client_name: elastalert2
pagerduty_api_version: v2
pagerduty_v2_payload_class: ping failure
pagerduty_v2_payload_component: mysql
pagerduty_v2_payload_group: app-stack
pagerduty_v2_payload_severity: error
pagerduty_v2_payload_source: mysql.host.name
# ------- Flashduty ----------------
```

</Step>

<Step title="重启 ElastAlert 并验证">

**操作路径**：ElastAlert2 所在主机的终端

重启 ElastAlert，等待规则触发（`pagerduty_event_type` 默认为 `trigger`）。ElastAlert 没有 Flashduty 的测试按钮，需要一次真实触发的告警来验证。

</Step>
</Steps>
