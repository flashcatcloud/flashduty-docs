通过 webhook 的方式同步 Sentry 告警事件到 Flashduty On-call。

<div className="hide">

## 在 Flashduty On-call
您可通过以下两种方式获取集成推送地址，任选其一即可。

### 使用专属集成

如果您只需将告警发往一个协作空间，选择此方式，配置更简单。

<AccordionGroup>
  <Accordion title="查看专属集成的配置步骤">
  
  1. 进入 Flashduty 控制台，选择 **协作空间**，打开一个协作空间
  2. 选择 **配置** → **集成数据** → **专属集成**，点击 **新增集成**
  3. 选择 **Sentry** 集成，点击 **保存**，生成卡片。
  4. 打开生成的集成卡片，复制 **推送地址**
  
    
</Accordion>
</AccordionGroup>

### 使用共享集成

如果您需要根据告警事件的 Payload 将告警路由到不同协作空间，选择此方式。

<AccordionGroup>
  <Accordion title="查看共享集成的配置步骤">
  
  1. 进入 Flashduty 控制台，选择 **集成中心 → 告警事件**
  2. 选择 **Sentry** 集成：
        - **集成名称**：为当前集成定义一个名称。
  3. 配置默认路由并选择协作空间；创建后可在 **路由** 中增加更多规则
  4. 点击 **保存**，复制生成的 **推送地址**
    
</Accordion>
</AccordionGroup>
  
</div>

## 在 Sentry 中配置

Sentry 提供了两类告警机制：Issue Alerts 和 Metric Alerts。Issue Alerts 支持通过 Integrations 中的 WebHooks 实现通知功能，而 Metric Alerts 则限定于使用 Internal Integration 进行告警通知。值得注意的是 Internal Integration 不仅适用于 Metric Alerts，也兼容 Issue Alerts。鉴于 Internal Integration 的广泛适用性，我们决定统一采用这一方式，不再单独依赖 WebHooks，以此来简化告警通知的配置。

<Steps>
<Step title="在 Sentry 中创建 Internal Integration">

**操作路径**：Sentry › Settings › Developer Settings › Custom Integrations › Create New Integration › Internal Integration

旧版 Sentry 的入口为 **Settings → Custom Integrations**。

| 字段 | 填写 |
| --- | --- |
| Name（必填） | `Flashduty` |
| Webhook URL（必填） | `{integration_url}` |
| Alert Rule Action（必填） | 开启，配置参考下图 |
| PERMISSIONS › Issue & Event（必填） | `Read` |
| WEBHOOKS › issue（必填） | 勾选。**不要勾选 error 和 comment** |

<img alt="Internal Integration 的 Alert Rule Action 配置" width="600" src="https://fcpub-1301667576.cos.ap-nanjing.myqcloud.com/flashduty/doc/sentry-1.png" />

配置完成后，点击 **Save Changes** 完成创建。

<img alt="Internal Integration 的 Webhooks 配置" width="600" src="https://fcpub-1301667576.cos.ap-nanjing.myqcloud.com/flashduty/doc/sentry-2.png" />

**关于 WEBHOOKS 配置的特殊说明：**

1. 勾选 **issue** 后 Flashduty On-call 可以接收 issue 的 resolved 事件，即在 issue 列表中对某个问题进行手动触发 resolved 时，我们会自动恢复 Flashduty On-call 中关联的故障。
2. 不支持 issue 的其他事件，如 create、assigned、archived 和 unresolved。
3. 如果同时勾选了 error 和 comment，Flashduty 并不会接收和处理这类事件。

</Step>
<Step title="在 Sentry 告警规则中使用 Flashduty">

**操作路径**：Sentry › Alerts › Create Alert

1. 选择要创建的 Alert 类型，如 Issue。

   <img alt="选择 Alert 类型" width="600" src="https://fcpub-1301667576.cos.ap-nanjing.myqcloud.com/flashduty/doc/sentry-3.png" />

2. 触发条件请按需配置。
3. 在 **THEN perform these actions** 处 **Add action**，选择 **Send a notification via**。

   <img alt="添加 Send a notification via 动作" width="600" src="https://fcpub-1301667576.cos.ap-nanjing.myqcloud.com/flashduty/doc/sentry-4.png" />

4. 通知渠道选择上面添加的 **Flashduty**。

   <img alt="选择 Flashduty 通知渠道" width="600" src="https://fcpub-1301667576.cos.ap-nanjing.myqcloud.com/flashduty/doc/sentry-5.png" />

5. 配置好其他选项后，点击 **Save Rule** 保存即可。

</Step>
<Step title="触发真实告警并验证">

让规则命中一次真实的 issue 或指标告警，几秒后回到 Flashduty，集成显示 **最新事件时间**，说明配置成功。再到 Sentry 的 issue 列表中把该 issue 标记为 resolved，确认 Flashduty 中对应的告警恢复。
{/* console:
接入清单中的「收到第一个事件」同时变为已完成。
*/}

</Step>
</Steps>

## 状态和告警等级

<div className="md-block">
  
| Sentry | Flashduty |
| --- | --- |
| critical | Critical |
| warning | Warning |
| triggered | Warning |
| resolved | Ok |

</div>

## Alert Key 与恢复

Flashduty 按 Sentry 推送的对象计算 Alert Key：指标告警（Metric Alert）用 `metric_alert.id`，Issue 告警用 `event.issue_id`，issue 已解决事件用 `issue.id`。`action` 为 `resolved` 的推送使对应告警恢复；`action` 不在上表中的推送（如 created、assigned）会被拒绝。
