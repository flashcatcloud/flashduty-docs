<div className="hide">

## 在 Flashduty On-call
您可通过以下两种方式获取集成推送地址，任选其一即可。

### 使用专属集成

如果您只需将告警发往一个协作空间，选择此方式，配置更简单。

<AccordionGroup>
  <Accordion title="查看专属集成的配置步骤">
  
  1. 进入 Flashduty 控制台，选择 **协作空间**，打开一个协作空间
  2. 选择 **配置** → **集成数据** → **专属集成**，点击 **新增集成**
  3. 选择 **Sentry** 集成，点击 **保存**，生成卡片。
  4. 打开生成的集成卡片，复制 **推送地址**
  
    
</Accordion>
</AccordionGroup>

### 使用共享集成

如果您需要根据告警事件的 Payload 将告警路由到不同协作空间，选择此方式。

<AccordionGroup>
  <Accordion title="查看共享集成的配置步骤">
  
  1. 进入 Flashduty 控制台，选择 **集成中心 → 告警事件**
  2. 选择 **Sentry** 集成：
        - **集成名称**：为当前集成定义一个名称。
  3. 配置默认路由并选择协作空间；创建后可在 **路由** 中增加更多规则
  4. 点击 **保存**，复制生成的 **推送地址**
    
</Accordion>
</AccordionGroup>
  
</div>

## 在 Sentry 中配置

Sentry 提供了两类告警机制：Issue Alerts 和 Metric Alerts。Issue Alerts 支持通过 Integrations 中的 WebHooks 实现通知功能，而 Metric Alerts 则限定于使用 Internal Integration 进行告警通知。值得注意的是 Internal Integration 不仅适用于 Metric Alerts，也兼容 Issue Alerts。鉴于 Internal Integration 的广泛适用性，我们决定统一采用这一方式，不再单独依赖 WebHooks，以此来简化告警通知的配置。

<Steps>
<Step title="在 Sentry 中创建 Internal Integration">

**操作路径**：Sentry › Settings › Developer Settings › Custom Integrations › Create New Integration › Internal Integration

旧版 Sentry 的入口为 **Settings → Custom Integrations**。

| 字段 | 填写 |
| --- | --- |
| Name（必填） | `Flashduty` |
| Webhook URL（必填） | `{integration_url}` |
| Alert Rule Action（必填） | 开启，配置参考下图 |
| PERMISSIONS › Issue & Event（必填） | `Read` |
| WEBHOOKS › issue（必填） | 勾选。**不要勾选 error 和 comment** |

<img alt="Internal Integration 的 Alert Rule Action 配置" width="600" src="https://fcpub-1301667576.cos.ap-nanjing.myqcloud.com/flashduty/doc/sentry-1.png" />

配置完成后，点击 **Save Changes** 完成创建。

<img alt="Internal Integration 的 Webhooks 配置" width="600" src="https://fcpub-1301667576.cos.ap-nanjing.myqcloud.com/flashduty/doc/sentry-2.png" />

**关于 WEBHOOKS 配置的特殊说明：**

1. 勾选 **issue** 后 Flashduty On-call 可以接收 issue 的 resolved 事件，即在 issue 列表中对某个问题进行手动触发 resolved 时，我们会自动恢复 Flashduty On-call 中关联的故障。
2. 不支持 issue 的其他事件，如 create、assigned、archived 和 unresolved。
3. 如果同时勾选了 error 和 comment，Flashduty 并不会接收和处理这类事件。

</Step>
<Step title="在 Sentry 告警规则中使用 Flashduty">

**操作路径**：Sentry › Alerts › Create Alert

1. 选择要创建的 Alert 类型，如 Issue。

   <img alt="选择 Alert 类型" width="600" src="https://fcpub-1301667576.cos.ap-nanjing.myqcloud.com/flashduty/doc/sentry-3.png" />

2. 触发条件请按需配置。
3. 在 **THEN perform these actions** 处 **Add action**，选择 **Send a notification via**。

   <img alt="添加 Send a notification via 动作" width="600" src="https://fcpub-1301667576.cos.ap-nanjing.myqcloud.com/flashduty/doc/sentry-4.png" />

4. 通知渠道选择上面添加的 **Flashduty**。

   <img alt="选择 Flashduty 通知渠道" width="600" src="https://fcpub-1301667576.cos.ap-nanjing.myqcloud.com/flashduty/doc/sentry-5.png" />

5. 配置好其他选项后，点击 **Save Rule** 保存即可。

</Step>

让规则命中一次真实的 issue 或指标告警，几秒后回到 Flashduty，集成显示 **最新事件时间**，说明配置成功。再到 Sentry 的 issue 列表中把该 issue 标记为 resolved，确认 Flashduty 中对应的告警恢复。

## 推送内容

Sentry 的 Internal Integration 推送 JSON 对象，Flashduty 按 `data` 中出现的对象解析，可能是以下三种之一：

**指标告警（`data.metric_alert`）**

| 字段 | 含义 | 在 Flashduty 中 |
| :--- | :--- | :--- |
| `action` | 推送动作 | 告警状态和等级 |
| `data.metric_alert.id` | 指标告警规则 ID | Alert Key |
| `data.description_text` | 告警描述文本 | 告警标题 |
| `data.web_url` | 告警链接 | 标签 `web_url` |
| `data.metric_alert.projects` | 涉及的项目 | 标签 `projectName`，多个项目用逗号分隔 |

**Issue 告警（`data.event`）**

| 字段 | 含义 | 在 Flashduty 中 |
| :--- | :--- | :--- |
| `action` | 推送动作 | 告警等级 |
| `data.event.issue_id` | Issue ID | Alert Key |
| `data.event.title` | Issue 标题 | 告警标题 |
| `data.triggered_rule` | 触发规则名称 | 标签 `check` |
| `data.event.culprit` | 出错位置 | 标签 `culprit` |
| `data.event.environment` | 环境 | 标签 `environment` |
| `data.event.location` | 位置 | 标签 `location` |
| `data.event.message` | 错误消息 | 标签 `message` |
| `data.event.url` | Issue 详情链接 | 标签 `detail_url` |
| `data.event.web_url` | 项目内链接 | 标签 `web_url` |
| `data.event.tags` | 事件标签数组 | 每个二元组写成同名标签 |

**Issue 已解决（`data.issue`）**

| 字段 | 含义 | 在 Flashduty 中 |
| :--- | :--- | :--- |
| `action` | 推送动作，只接受 `resolved` | 告警恢复 |
| `data.issue.id` | Issue ID | Alert Key |
| `data.issue.title` | Issue 标题 | 告警标题 |
| `data.issue.project.name` | 项目名称 | 标签 `projectName` |
| `actor.name` | 操作人 | 标签 `operator` |

指标告警不读取 `data.description_title`，Issue 告警不读取 `data.event.level`。`data` 中三种对象都没有时，Flashduty 返回参数错误。

## Alert Key

Flashduty 按推送的对象取 Alert Key：指标告警用 `data.metric_alert.id`，Issue 告警用 `data.event.issue_id`，Issue 已解决事件用 `data.issue.id`。

同一个 Issue 的 Issue 告警和已解决事件使用同一个 Issue ID，因此已解决事件会关闭对应的告警；同一条指标告警规则的多次触发落在同一条告警上。修改标题、等级或事件标签不会改变 Alert Key。

| Sentry | Flashduty |
| --- | --- |
| critical | Critical |
| warning | Warning |
| triggered | Warning |
| resolved | Ok |

## 标签

| 标签 | 来源 |
| :--- | :--- |
| `check` | 触发规则名称 `data.triggered_rule`，仅 Issue 告警 |
| `culprit` | `data.event.culprit` |
| `environment` | `data.event.environment` |
| `location` | `data.event.location` |
| `message` | `data.event.message` |
| `detail_url` | `data.event.url` |
| `web_url` | 指标告警的 `data.web_url`，或 Issue 告警的 `data.event.web_url` |
| `projectName` | 指标告警的项目列表（逗号分隔），或已解决事件的 `data.issue.project.name` |
| `operator` | 已解决事件的 `actor.name` |
| 事件标签中的键 | Issue 告警的 `data.event.tags`：每个二元组的第一个值是标签名，第二个值是取值 |

指标告警只写 `web_url` 和 `projectName`。`data.event.tags` 与内置标签同名时（例如 `environment`），事件标签的取值会覆盖内置值。

## 排查问题

- **告警没有恢复**：Issue 已解决事件只接受 `action` 为 `resolved` 的推送；在 Sentry 的 issue 列表手动标记 resolved 后仍不恢复时，确认 Internal Integration 勾选了 `issue`
- **Flashduty 返回参数错误**：`action` 取值不受支持。Issue 告警只接受 `critical`、`warning` 和 `triggered`；对 `data.event` 推送 `resolved` 会被拒绝，恢复要走 `data.issue`
- **告警等级都是 Warning**：Issue 告警的等级取自 `action`，`data.event.level` 不参与；Sentry 的 Issue 告警动作通常是 `triggered`，因此映射为 Warning
- **内置标签被覆盖**：`data.event.tags` 中与内置标签同名的键会覆盖内置值，路由规则请按实际取值配置
- **没有产生告警**：确认告警规则的动作为 **Send a notification via** 并选择了 `Flashduty`；`data` 中既没有 `metric_alert`、`event` 也没有 `issue` 的推送会被拒绝
