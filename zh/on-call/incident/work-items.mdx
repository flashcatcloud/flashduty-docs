## 概述

行动项（Action）用于跟踪故障处理过程中需要完成的具体工作，例如"扩容数据库连接池"或"回滚最近一次发布"。故障概览页右侧的 **行动项** 卡片集中管理当前故障的全部行动项，每一项都支持设置标题、描述和多名负责人。

行动项可以转换为 **跟进项**（Follow-up），进入复盘流程。跟进项与行动项共享同一套工作项模型（相同的字段与状态），区别在于所代表的阶段：行动项属于处置过程，跟进项属于故障结束后的改进工作。跟进项可以直接创建在已关闭的故障下，不要求先有复盘报告，也可在复盘报告的 **待办事项** 区块中维护。详见[转为跟进项与关联复盘](#转为跟进项与关联复盘)。

## 概览面板

故障概览页右侧同时展示 **行动项** 与 **跟进项** 两张卡片，二者的可编辑阶段互补：

| 卡片 | 可编辑阶段 |
| :--- | :--- |
| **行动项** | 故障进行中 |
| **跟进项** | 故障已关闭 |

不可编辑阶段的卡片只读，只展示已有条目。可编辑的那张卡片排在前面。

两张卡片使用同一套行内操作（编辑、删除、完成、标记为不处理），下文以行动项为例说明；同一套操作对跟进项同样适用。

## 创建与编辑行动项

### 创建

在故障概览页右侧的 **行动项** 卡片中，点击 **添加一个行动项**（卡片中已有行动项时为 **添加**），在弹窗中填写以下字段：

| 字段 | 必填 | 说明 |
| :--- | :---: | :--- |
| **行动项标题** | 是 | 简要描述要完成的工作，最长 **512** 字符 |
| **描述** | 否 | 补充需要执行的具体内容，最长 **65535** 字符 |
| **负责人** | 否 | 支持搜索并从账户成员中多选，不限制人数；也可以选择固定在列表顶部的 **AI SRE**（副文案 **分配给 AI 执行**），把这条工作项交给账号的 AI SRE 执行 |

创建成功后，行动项会展示在卡片中，并在故障时间线上记录一条"创建了行动项"事件。被指定为负责人的成员会收到一条个人通知，提醒其跟进处理（默认通过**邮件和应用内推送**发送，可在[个人设置](/zh/on-call/configuration/personal-settings)中调整通知渠道）。

### 指派给 AI SRE

负责人选择器把 **AI SRE** 固定在成员列表上方，与成员之间用一条分隔线隔开；它不参与搜索过滤，输入任何关键词都会留在结果里。选中后，这条工作项交给账号的 AI SRE 执行，同时仍可以保留成员负责人。行动项与跟进项共用同一个创建/编辑弹窗，负责人字段行为一致。

- 卡片上以 **AI SRE** 头像展示该指派，与成员头像并列（最多显示 2 个头像，其余折叠为 `+N`）
- 鼠标悬停 AI SRE 头像会弹出悬浮卡，写明 AI SRE 以哪位成员的身份和权限执行，并提供 **接续对话** 入口，点击会在 AI SRE 面板中打开这次执行关联的会话
- 执行来自 IM 会话时，悬浮卡只给出 **IM 会话暂不支持在 Web 查看** 的说明，不提供进入入口
- 打开会话要求账号已启用 AI SRE，且您拥有使用 AI SRE 对话的权限；个人会话（仅创建者可见）或已失效的会话无法接续
- 故障时间线上，这条工作项记录会以联合署名列出指派对象（例如「张三 和 AI SRE」）

需要列出所有交给 AI SRE 的工作项时，使用 [CLI](/zh/developer/cli) 的 `flashduty incident work-item-list --assignee-type ai_sre`。

### 编辑与删除

- 拥有故障更新权限的成员，点击行动项标题，或通过 **更多** 菜单中的 **编辑** 打开弹窗，修改标题、描述或负责人
- 新增负责人时，新加入的负责人同样会收到个人通知；移除负责人不会触发通知
- **更多** 菜单中的 **删除** 需要二次确认，删除操作不可撤销

## 状态流转

每条行动项通过复选框和 **更多** 菜单管理状态：

| 操作 | 效果 |
| :--- | :--- |
| 勾选复选框 | 将行动项标记为 **已完成**，条目以弱化样式展示 |
| 取消勾选复选框 | **取消完成**，行动项回到未完成状态 |
| **更多** → **标记为不处理** | 将行动项标记为 **不处理**，标题显示删除线 |
| 不处理状态下点击 X 图标 | 重新打开行动项 |

**更多** 菜单中还提供 **标记为已完成** 与 **取消完成行动项** 快捷操作。状态变更同样会记录到故障时间线。

## 转为跟进项与关联复盘

跟进项属于已结束的故障。系统在故障关闭时自动转换，您也可以在关闭后继续补充：

- **关闭时自动转换**：关闭故障时，系统会把该故障下所有未完成的行动项批量转为跟进项（工作项类型从 Action 变为 Follow-up），并在时间线上写入一条 **将 N 个未完成行动项转为跟进项：标题、标题…** 的记录。已完成或已标记为不处理的行动项保持原状，仍以行动项展示（只读）
- **自动关联复盘**：转换或创建跟进项时，若故障已有复盘报告，系统会自动把跟进项关联到该复盘；若尚无复盘，跟进项先保持未关联，待该故障的复盘报告创建后，系统会自动把故障下所有未关联的跟进项绑定到该复盘
- **在复盘报告中维护**：关联成功后，跟进项同样可以在复盘报告的 **待办事项** 区块中编辑、完成或删除，相关操作也会记录到故障时间线

复盘的编写与发布详见[创建与编辑复盘](/zh/on-call/post-mortem/create-edit-post-mortem)。

## 权限模型

行动项与跟进项的访问遵循以下规则：

| 角色/场景 | 能力 |
| :--- | :--- |
| 拥有故障更新权限的成员 | 故障进行中：创建、编辑、删除行动项及任意状态流转；故障关闭后：创建、编辑、删除跟进项及任意状态流转 |
| 行动项/跟进项负责人 | 即使没有故障更新权限，也可以将自己负责的条目标记为 **已完成**（不能编辑内容、不能删除） |
| 已关联复盘报告的跟进项 | 编辑与删除需要对应复盘报告的编辑权限；**完成**只看是否为负责人（负责人可标记为已完成，与是否关联复盘无关） |
| 未关联复盘报告的跟进项 | 按故障更新权限校验；适用于直接在已关闭故障下创建、复盘报告尚未生成的跟进项 |

此外，行动项的读写还受故障所属**协作空间**约束：只有账号所有者、账号管理员，以及能访问这个故障所属协作空间的成员才能操作；如果故障是手动创建、未挂载协作空间，则保持账户内可见，账户成员均可访问。这与故障本身的访问规则一致。

上表中的「负责人」指账户成员。指派给 **AI SRE** 的工作项由 AI SRE 执行：AI SRE 不是账户成员，上表针对成员的完成权限与个人通知都不适用于它（同一条工作项上还选了成员负责人时，成员负责人照常收到通知）。

## 已关闭故障

故障关闭后，行动项卡片进入只读状态，跟进项卡片同时解锁为可编辑：

- **行动项**：不能创建、编辑、删除，也不能变更状态；通过 API 也无法为已关闭故障创建行动项。卡片中通常只剩下已完成或标记为不处理的行动项
- **跟进项**：可直接新增、编辑、完成或删除
- 若希望某项工作保留为行动项，请在关闭故障前将其标记为 **已完成** 或 **不处理**，否则它会在关闭时被转为跟进项
