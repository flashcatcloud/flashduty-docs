## 概述

行动项（Action）用于跟踪故障处理过程中需要完成的具体工作，例如"扩容数据库连接池"或"回滚最近一次发布"。故障概览页右侧的工作项面板由 **行动项** 与 **跟进项** 两张卡片组成：前者管故障处理中要完成的工作，后者管故障结束后要完成的改进工作。每张卡片都支持设置标题、描述和多名负责人，卡片标题后显示当前条目数，没有条目时展示一条空态提示（行动项为"使用行动项跟踪故障处理中需要完成的工作"，跟进项为"记录故障结束后需要完成的改进工作"）。

两张卡片的可编辑状态随故障阶段切换：故障处理中 **行动项** 卡片可编辑、**跟进项** 卡片只读；故障关闭后两者互换，**跟进项** 卡片可编辑、**行动项** 卡片降级为只读。面板始终把可编辑的那张卡片排在前面。

行动项可以转换为 **跟进项**（Follow-up），进入复盘流程。跟进项与行动项共享同一套工作项模型（相同的字段与状态），区别在于跟进项归属故障复盘：转换或创建跟进项时，若故障已存在复盘报告，系统会自动将其关联到复盘，随后在复盘报告的 **待办事项** 区块中维护。

若需要集中查看还有工作项未完成的故障，可在故障列表按 **未完成的行动项/跟进项** 筛选，详见[检索与查看故障](/zh/on-call/incident/search-view-incident)。

## 创建与编辑行动项

### 创建

在故障概览页右侧的 **行动项** 卡片中，点击 **添加一个行动项**（卡片中已有行动项时为 **添加**），在弹窗中填写以下字段：

| 字段 | 必填 | 说明 |
| :--- | :---: | :--- |
| **行动项标题** | 是 | 简要描述要完成的工作，最长 **512** 字符 |
| **描述** | 否 | 补充需要执行的具体内容，最长 **65535** 字符 |
| **负责人** | 否 | 支持搜索并从账户成员中多选，不限制人数 |

创建成功后，行动项会展示在卡片中，并在故障时间线上记录一条"创建了行动项"事件。被指定为负责人的成员会收到一条个人通知，提醒其跟进处理（默认通过**邮件和应用内推送**发送，可在[个人设置](/zh/on-call/configuration/personal-settings)中调整通知渠道）。

### 编辑与删除

- 拥有故障更新权限的成员，点击行动项标题，或通过 **更多** 菜单中的 **编辑** 打开弹窗，修改标题、描述或负责人
- 新增负责人时，新加入的负责人同样会收到个人通知；移除负责人不会触发通知
- **更多** 菜单中的 **删除** 需要二次确认，删除操作不可撤销

## 状态流转

每条行动项通过复选框和 **更多** 菜单管理状态：

| 操作 | 效果 |
| :--- | :--- |
| 勾选复选框 | 将行动项标记为 **已完成**，条目以弱化样式展示 |
| 取消勾选复选框 | **取消完成**，行动项回到未完成状态 |
| **更多** → **标记为不处理** | 将行动项标记为 **不处理**，标题显示删除线 |
| 不处理状态下点击 X 图标 | 重新打开行动项 |

**更多** 菜单中还提供 **标记为已完成** 与 **取消完成行动项** 快捷操作。状态变更同样会记录到故障时间线。

## 转为跟进项与关联复盘

处置过程中确认某条行动项需要持续跟进时，可以将其转换为复盘跟进项：

- 转换后，行动项原位变为跟进项（工作项类型从 Action 变为 Follow-up），进入复盘流程
- 若故障此时已创建复盘报告，转换后的跟进项会**自动关联**到该复盘
- 若尚未创建复盘，跟进项保持未关联状态；待复盘创建后，可将故障下所有未关联的跟进项批量关联（绑定）到该复盘

关联成功后，跟进项可在复盘报告的 **待办事项** 区块中编辑、完成或删除，相关操作同样会记录到故障时间线（如"将跟进项关联到故障复盘"）。复盘的编写与发布详见[创建与编辑复盘](/zh/on-call/post-mortem/create-edit-post-mortem)。

### 在故障下直接创建跟进项

故障关闭后，也可以在 **跟进项** 卡片中直接新建跟进项，不必先有行动项：

- 点击 **添加一个跟进项**（卡片中已有跟进项时为 **添加跟进项**），弹窗标题为 **创建跟进项**，字段与行动项一致：**跟进项标题**（必填，最长 **512** 字符）、**描述**（最长 **65535** 字符）、**负责人**（支持多选）
- 新建的跟进项同样会记录到故障时间线（"创建了跟进项"），负责人会收到个人通知
- 服务端要求故障已关闭；若该故障已有复盘报告，服务端会自动把新建的跟进项关联到该复盘
- 点击跟进项标题，或使用 **更多** 菜单中的 **编辑**，弹窗标题为 **编辑跟进项**；**更多** 菜单中的 **删除** 需要二次确认，提示为"确定要删除这条跟进项吗？此操作不可撤销。"
- 跟进项的状态流转（勾选复选框标记 **已完成**、**标记为不处理** 等）与行动项一致

## 权限模型

行动项与跟进项的访问遵循以下规则：

| 角色/场景 | 能力 |
| :--- | :--- |
| 拥有故障更新权限（`incident:update`）的成员 | 创建、编辑、删除行动项，以及任意状态流转 |
| 行动项负责人 | 即使没有故障更新权限，也可以将自己负责的行动项标记为 **已完成**（不能编辑内容、不能删除） |
| 故障下的跟进项（未关联复盘） | 新增、编辑、删除与状态流转需要故障更新权限（`incident:update`），且故障必须已关闭 |
| 复盘跟进项 | 需要对应复盘报告的编辑权限 |

此外，行动项的读写还受故障所属**协作空间**约束：只有账号所有者、账号管理员以及能访问该故障协作空间的成员才能操作；如果故障是手动创建、未挂载协作空间，则保持账户内可见，账户成员均可访问。这与故障本身的访问规则一致。

## 已关闭故障

关闭故障不会丢下未完成的工作：关闭动作会自动把该故障下所有未完成的行动项转为跟进项，不需要事先手工转换。

- 转换在关闭请求内同步完成，界面在关闭后重新拉取工作项，因此你看到的已经是转换后的终态
- 故障时间线会记录一条批量事件"将 N 个未完成行动项转为跟进项"，后接被转换条目的标题列表；启用作战室时，作战室会收到同一条消息"故障已关闭，N 个未完成行动项已转为跟进项，可在故障详情继续跟踪。"
- 只有未完成的行动项会被转换：标记为 **已完成** 或 **不处理** 的行动项保持行动项身份不变
- 若该故障已存在复盘报告，转换出的跟进项会一并关联到该复盘；尚未创建复盘的保持未关联状态，待复盘创建后批量关联（绑定）

关闭后两张卡片的行为随之切换：

- **跟进项** 卡片可编辑：可以新增、编辑、删除跟进项，也可以变更其状态，具体操作见上一节"在故障下直接创建跟进项"
- **行动项** 卡片只读：仍可查看保留下来的行动项（已完成或不处理），便于回顾处置过程，但不能编辑、删除或变更状态；面板不再显示添加按钮与操作入口，后端也会拒绝为已关闭故障创建行动项。该卡片没有条目时不显示
