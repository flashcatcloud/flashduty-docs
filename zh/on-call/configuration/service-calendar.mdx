## 应用场景

| 场景 | 说明 |
| --- | --- |
| **分派策略** | 按工作日/休息日分派给不同的值班人员 |
| **静默规则** | 仅在休息日静默低优先级告警 |

## 创建日历

进入 **配置中心 → 服务日历**，点击 **创建**，在右侧面板 **创建服务日历** 中填写信息。

| 配置项 | 说明 |
| --- | --- |
| **日历名称** | 必填，长度为 1~40 个字符，建议按业务维度命名，如「结算业务系统」 |
| **管理团队** | 必填。日历归属于该团队，团队成员将获得编辑该日历的权限 |
| **日历描述** | 概述业务特性，便于团队成员快速了解 |

<Note>
每个账户默认最多可创建 5 个服务日历。如需创建更多，请联系 Flashduty 技术支持。
</Note>

<Tip>
新建日历默认全部为工作日。创建成功后进入日历详情页关联国家节假日，系统会自动将法定假日标记为休息日，您也可以手动调整。
</Tip>

## 编辑日历

| 操作 | 说明 |
| --- | --- |
| **修改基础信息** | 日历名称、描述、管理团队 |
| **关联节假日** | 在日历详情页关联国家节假日日历，系统自动将法定假日标记为休息日、调休补班日标记为工作日，可随时调整或取消关联。下拉中只列出当前界面语言对应的节假日日历（已关联的其他日历会保留在列表中，便于取消关联），可同时关联多个；勾选或取消即保存生效，无需另行保存 |
| **批量标记休息日** | 按星期几快速标记，如每周六、日为休息日。一周至少保留一个工作日，只剩最后一个工作日时它的按钮不可再切换为休息日；未设置任何休息日时七天全部按工作日计 |
| **调整日期** | 点击一个日期，或先后点击两个日期选中一段日期，在下方操作栏点击 **设为工作日**、**设为休息日** 或 **恢复默认**，备注选填 |

![编辑日历](https://fcpub-1301667576.cos.ap-nanjing.myqcloud.com/flashduty/doc/rili-1.png)

<Warning>
删除日历不可恢复，请确认没有分派策略或静默规则引用后再删除。
</Warning>

## 同一天有多个设置时，以哪个为准？

按以下顺序，由排在最前、且对这一天有设置的一项决定：

1. **手动设置**：在日历上设为工作日或休息日的日期
2. **关联的节假日日历**：调休补班日优先于节假日休息日
3. **每周休息日**：按星期几批量标记的休息日

同一个日历内，同一天只保留最后一条手动设置。在已有设置覆盖到的日期上再次点击 **设为工作日** 或 **设为休息日**，旧设置会被覆盖：完全落在本次选中范围内的旧设置被删除，部分重叠的被截短，跨越整个范围的被拆成两段。

以上都没有设置的日期为工作日。对日期点击 **恢复默认** 会清除手动设置，该日期回到节假日日历和每周休息日的判定。

日历上黄色表示休息日，绿色表示手动设置或节假日补班的工作日，没有颜色的日期按每周设置为工作日。由本日历手动设置的日子还会额外描一圈边框，与节假日日历或每周规则决定的日子区分开；将鼠标悬停在某一天上，可以看到是哪一层决定了这一天，以及被它覆盖掉的设置（以删除线列出）。

## 常见问题

<AccordionGroup>
  <Accordion title="服务日历与值班表有什么区别？">
    两者定位不同：
    
    - **值班表**：定义「谁来处理」，是故障的接收对象
    - **服务日历**：定义「什么时候处理」，是分派策略的时间条件
    
    服务日历位于值班表的上层，先判断是否在工作日，再决定是否分派给值班人员。
  </Accordion>
</AccordionGroup>
