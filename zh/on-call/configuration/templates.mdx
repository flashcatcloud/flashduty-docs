## 使用场景

手动创建故障、自动生成故障、重新分派、升级分派和重开分派时，系统都会使用模板渲染通知。

<Note>
系统使用 [Golang 模板语法](https://pkg.go.dev/html/template@go1.18.1) 解析数据，支持逻辑判断、循环、pipeline 及常用函数。更多函数请参考 [sprig 函数库](https://github.com/flashcatcloud/sprig/tree/flashcat)。
</Note>

<Warning>
出于安全考虑，以下 sprig 函数已被禁用，在模板中使用会触发 `function "xxx" not defined` 解析错误：

| 分类   | 已禁用函数                                                                                                                                                            |
| :--- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 环境读取 | `env`、`expandenv`                                                                                                                                                |
| 网络解析 | `getHostByName`                                                                                                                                                  |
| 密码学  | `bcrypt`、`htpasswd`、`derivePassword`、`encryptAES`、`decryptAES`                                                                                                    |
| 证书生成 | `genPrivateKey`、`buildCustomCert`、`genCA`、`genCAWithKey`、`genSelfSignedCert`、`genSelfSignedCertWithKey`、`genSignedCert`、`genSignedCertWithKey`                    |
| 随机数  | `randBytes`、`uuidv4`、`randAlphaNum`、`randAlpha`、`randAscii`、`randNumeric`、`randInt`、`shuffle`                                                                     |
| 错误抛出 | `fail`                                                                                                                                                           |

如需在模板中使用唯一标识，可改用故障变量（如 `{{.ID}}`、`{{.Num}}`）；如需引用环境信息，请通过告警标签或字段映射传入，不要在模板中读取宿主机环境变量。
</Warning>

## 配置模板

<Steps>
<Step title="创建自定义模板">
进入 **模板管理** 页面，点击 **创建自定义模板** 或 **复制默认模板**
</Step>
<Step title="编辑模板内容">
按通知渠道编辑对应内容，可引用下方变量列表中的字段
</Step>
<Step title="保存模板">
点击 **保存** 完成创建
</Step>
</Steps>

<Tip>
**系统预置模板与只读**：系统预置模板和当前成员没有模板管理权限的模板，详情页一律是只读状态，标题旁标有 **系统预置 · 只读**（权限不足的模板不显示这个标识，但同样不能改）。要改成自己的内容，点右上角 **复制为新模板** 复制一份副本再改，副本名称预填「复制 原模板名」；复制需要「通知模板管理」权限和 On-call 专业版。

可编辑的模板，右上角是 **模板设置**（齿轮图标），用来改模板名称、管理团队和模板描述，不涉及正文；删除收在 **更多操作** ⋯ 菜单里，系统预置模板没有这个菜单，也不能删除。
</Tip>

### 应用模板

<Steps>
<Step title="进入分派策略">
前往 **协作空间** → **分派策略**，点击 **编辑**
</Step>
<Step title="选择模板">
在策略配置中选择 **按照哪个模板** 进行通知
</Step>
<Step title="保存配置">
点击 **保存** 完成配置。详见 [配置分派策略](/zh/on-call/channel/escalation-rule)
</Step>
</Steps>

```go

// 引用 resource 标签值
{{.Labels.resource}}

// 引用带 "." 的标签（如 "A.B"）
{{index .Labels "A.B"}}

## 预览与发送测试

模板详情页右侧是预览区：按所选故障渲染当前渠道的内容，下方带一行诊断信息和预览给出的警告。预览区标题栏还有 **发送测试**，可以把编辑器里的当前内容真实发到渠道里看效果。

<span id="preview-notices"></span>

### 预览会提示什么

预览按 **用这个故障的数据渲染** 里选中的故障渲染当前渠道的内容；没选故障时用系统默认数据。编辑器内容为空时，预览按该渠道的系统默认模板渲染，并提示「未设置模板内容，将使用系统默认模板」。

预览下方一行元信息说明这条内容是怎么渲染出来的：

| 栏位 | 说明 |
| :--- | :--- |
| 渠道格式 | 飞书应用显示 **飞书卡片 2.0**；企业微信机器人显示 **Markdown** 或 **Markdown v2**；其他渠道不显示 |
| 原生表格 N / Markdown 表格 N | 这次渲染里有几张表画成原生表格、几张画成 Markdown 表格；为 0 时不显示 |
| 已用 / 上限 | 内容字节数和该渠道的大小上限，如 `12.3 KB / 30.0 KB`；渠道没有已知上限时只显示已用字节数 |

元信息上方的黄色提示说明这条模板在真实发送时会变形或超限，出现任意一条，保存前按提示精简：

| 提示 | 含义 |
| :--- | :--- |
| 该渠道不渲染 Markdown 表格，接收方会看到原文。可以改写成列表。 | 钉钉、Slack、Telegram 机器人，企业微信机器人（Markdown v1），以及钉钉、Slack、企业微信、Teams 应用不渲染表格，接收方看到的是未渲染的表格原文，建议改写成列表 |
| 部分表格不能用原生表格发送，会改用 Markdown 表格。 | 飞书应用开了 **表格转原生表格**，但这次有表格达不到原生表格的条件，具体提示见[表格转原生表格](#native-tables) |
| 单个飞书 Markdown 组件最多支持 4 张表格，超出的表格可能无法显示。 | 飞书卡片 2.0 的一个 Markdown 组件里放了 4 张以上按 Markdown 文本发送的表格（没转成原生表格的那些），超出的表格可能不展示。建议拆成多个 Markdown 组件，或开启 **表格转原生表格** |
| 内容超过渠道大小上限 | 提示分 3 种，见下表 |

内容超过渠道大小上限时，提示分 3 种：

| 提示 | 含义 |
| :--- | :--- |
| 内容超过渠道大小上限，发送会失败，真实告警也一样。请精简模板。 | 渠道直接拒收，这条通知发不出去，必须精简模板，例如飞书卡片超过 30 KB |
| 内容超过渠道大小上限，超出部分会被截断。 | 超出上限的部分被截断，通知仍会发出，各渠道的具体上限见下文 |
| 内容超过 4096 字节，发送时会改为精简摘要。 | 企业微信机器人 Markdown v2 超过 4096 字节时改发精简摘要，不丢通知 |

### 发送测试

**发送测试** 在预览区标题栏。它把编辑器当前内容（**含未保存的修改**）按预览里选中的故障渲染后，真实发到渠道里，用来确认接收方看到的样子。需要「通知模板管理」权限；系统预置模板也可以发送测试。模板校验没通过时按钮不可点。

支持的渠道：5 个 IM 应用（飞书、钉钉、企业微信、Slack、Teams）、6 个群聊机器人（飞书、钉钉、企业微信、Slack、Telegram、Zoom）和邮件。短信和语音不提供发送测试——它们按条计费，而预览内容就等于实际发出的内容。

发送内容与预览是同一份：编辑器当前内容 + 选中的故障数据（未选故障时用系统默认数据），渠道渲染开关（卡片字段显隐、飞书卡片 2.0 的表格与空白行开关、企业微信机器人的 Markdown v2）也一致。编辑器内容为空时，发的是该渠道的系统默认模板。

各渠道的发送目标：

| 渠道 | 发送目标 | 说明 |
| :--- | :--- | :--- |
| IM 应用 | 我自己 / 群聊 | 企业微信应用只有 **我自己**：企业微信没有「列出机器人所在的群」的接口，群消息走企业微信机器人模板 |
| 群聊机器人 | 临时填机器人地址 | 与通知规则里填的地址相同，裸 token 或完整地址都行；Telegram 另填 Chat ID，Zoom 另填 Verify Token。这些值只用于这一次发送，不会保存 |
| 邮件 | 自己的账号邮箱 | 账号没有邮箱时不能发送 |

- **我自己**：要求当前账号已关联该 IM 集成，未关联时发送按钮不可点，有权限的成员可以点 **去关联** 到接入向导完成关联。Slack 应用例外，不需要逐人关联（按工作区成员直接私信），但发送时仍要把你解析成该工作区的成员，解析不到会提示「你的账号还没有关联这个 IM，无法私信」。
- **群聊**：只列出该机器人在这个集成里**已加入**的群（Slack 按频道，Teams 按团队下的频道或群聊）。群里所有成员都会收到这条测试消息。
- 同一渠道配了多个集成时，先在 **集成** 里选一个；只列已启用的集成。

测试消息的标记：

- 故障标题前加 `[测试] `（英文账户为 `[Test] `）。
- 正文末尾加脚注「测试消息 · 模板「模板名」· 由 发送人 发送」。
- 卡片上的按钮点击后只回一句「这是测试消息，按钮不会改动故障。」，不会认领或关闭任何故障；**创建作战室** 按钮在测试消息里不出现。

发送结果有两种：

| 渠道 | 提示 |
| :--- | :--- |
| IM 应用 | 「已发送到你的飞书私聊」/「已发送到「群名」」 |
| 群聊机器人与邮件 | 「已提交发送，通常几秒内送达；没收到请检查地址」 |

IM 应用提示「已发送」才表示消息已送达；机器人和邮件的「已提交发送」只表示已提交，地址填错时不会有即时报错。

限制与常见失败原因：

- 每个成员每分钟最多发 5 条测试消息，超过会提示「发送太频繁，请稍后再试」。
- 失败时控制台给出下面的提示：

| 提示 | 含义 |
| :--- | :--- |
| 模板渲染失败，请先修正模板 | 模板语法或执行出错 |
| 这个渠道不支持发送测试 | 该渠道不提供发送测试 |
| 发送目标填写不完整或格式不对 | 机器人没填地址、Telegram 缺 Chat ID、Zoom 缺 Verify Token，或群聊不属于该集成 |
| 找不到这个集成，可能已被删除或停用 | 集成已被删除或停用，或不是该渠道的集成 |
| 你的账号还没有关联这个 IM，无法私信 | 你的账号没有关联这个 IM，无法私信自己 |
| 发送太频繁，请稍后再试 | 超过每分钟 5 条的限制 |
| 地址不允许：只支持公网 http/https | 机器人地址只支持公网 `http`/`https`，填完整地址时内网地址会被拒绝；裸 token 由平台拼成厂商地址，不做这项检查。仅 SaaS 版本有此限制，私有化部署不受限 |
| 内容超过渠道大小上限 | 内容超过渠道大小上限，例如飞书卡片 30 KB |
| 渠道返回失败：渠道的原始报错 | 渠道返回失败，提示里带渠道的原始报错 |

<Note>
测试发送与真实通知的差别：模板语法有错时，真实通知会静默回退成系统默认模板继续发，而发送测试直接提示「模板渲染失败，请先修正模板」，把模板问题暴露出来。反过来，测试发送不会在故障上留下通知记录，所以它不会认领、关闭故障或创建作战室。
</Note>

## 渠道模板

不同通知渠道支持的模板格式和限制不同。

### 卡片字段与底部操作按钮

**正文内容** 旁的 **附加信息** 页签用于控制卡片底部展示哪些系统内容。各渠道支持的开关如下：

| 开关 | 飞书应用 | 钉钉应用 | Slack 应用 | Microsoft Teams | 企业微信应用 |
| --- | --- | --- | --- | --- | --- |
| 协作空间、暂缓截止时间、严重程度、聚合告警数、处理人员、详情按钮 | ✓ | ✓ | ✓ | ✓ | ✓ |
| AI 分析 | ✓ | ✓ | ✓ | — | — |
| 创建作战室 | ✓ | ✓ | ✓ | — | — |
| 故障关闭后保留自定义操作 | ✓ | ✓ | ✓ | ✓ | — |

- **创建作战室**（默认关闭）：开启后，故障未关闭、尚无作战室且有处理人员时，卡片底部显示 **👥 创建作战室** 按钮，点击即可建群。
- **故障关闭后保留自定义操作**（默认关闭）：开启后，故障关闭后 3 天内仍可在消息卡片上执行已配置的自定义操作；关闭时或超过 3 天，请到故障详情页执行。

修改开关后需保存模板才会生效。

<Tabs>
<Tab title="飞书应用">
需预先配置 [飞书集成](/zh/on-call/integration/instant-messaging/lark)。支持消息卡片格式，系统会自动删除因标签不存在导致的渲染空行。

{{if .Labels.resource}}**resource** : {{(joinAlertLabels . "resource" ", ")}}{{end}}
{{range $k, $v := .Labels}}
{{if not (in $k "resource" "body_text" "body_text_with_table")}}**{{$k}}** : {{$v}}{{end}}{{end}}
{{ $root := . }}
{{ range $i, $v := .Images }}
  {{ $transferURL := transferImage $root $v.Src }}
  {{ if $transferURL }}![]({{$transferURL}}){{ end }}
{{ end }}
```

### 表格转原生表格

**飞书卡片 2.0** 下另有一个开关 **表格转原生表格**（默认关闭，随模板保存）。开启后，模板里的 GFM Markdown 表格会被识别出来，渲染成飞书卡片的原生表格组件，接收方看到的是可翻页的表格，而不是一行行带 `|` 的文本。

原生表格有以下限额。单张卡片的原生表格超过 5 个，或卡片超过 30 KB 时，**这张卡片上的所有表格**都按 Markdown 文本发送；其余限额只影响超限的那一张表，它按 Markdown 文本发送，其他表格不受影响：

| 限制 | 上限 |
| :--- | :--- |
| 原生表格数量 | 单张卡片最多 5 个 |
| 每表列数 | 最多 8 列 |
| 每表行数 | 最多 100 行 |
| 单元格内容 | 每格最多 2000 字节 |
| 每页行数 | 每页显示 10 行，超出部分在卡片里翻页 |

触发退回时，预览会给出对应提示（见[预览会提示什么](#preview-notices)）：

| 提示 | 触发条件 |
| :--- | :--- |
| 表格数量超过原生表格上限，发送时会全部改用 Markdown 表格。 | 这张卡片上的原生表格超过 5 个 |
| 表格列数超过原生表格上限，发送时会改用 Markdown 表格。 | 某张表超过 8 列 |
| 表格行数超过原生表格上限，发送时会改用 Markdown 表格。 | 某张表超过 100 行 |
| 有单元格内容过长，发送时会改用 Markdown 表格。 | 某个单元格超过 2000 字节 |
| 有单元格包含原生表格不支持的内容，发送时会改用 Markdown 表格。 | 单元格里除纯文本和 `<br>` 换行外还有其它 Markdown 标记，表头有空单元格，或某行的列数与表头不一致 |
| 用原生表格后卡片会超过大小上限，发送时会改用 Markdown 表格。 | 用原生表格后卡片会超过飞书的大小上限，这张卡片上的所有表格都改用 Markdown 表格 |

飞书卡片整体上限是 **30 KB**。超过时飞书直接拒收这条消息，预览会提示「内容超过渠道大小上限，发送会失败，真实告警也一样。请精简模板。」，需要精简模板后再发。

按 Markdown 文本发送的表格另有一条限制：**单个飞书 Markdown 组件最多 4 张表格**，超出的表格可能不显示。表格较多时开启 **表格转原生表格**，或把内容拆到多个 Markdown 组件里。
</Tab>

### 开启 Markdown v2

<Steps>
<Step title="进入模板管理">
打开 **模板管理**，创建自定义模板或复制已有模板。
</Step>
<Step title="选择企业微信机器人">
在模板内容中选择 **企业微信机器人**，开启 **使用 Markdown v2 格式**。

<Step title="编辑并保存模板">

</Step>

<Note>

## 常见问题

<AccordionGroup>
<Accordion title="如何知道 Labels 有哪些标签？">
- 手动创建的故障没有标签
- 自动创建的故障存在标签，与合入的第一条告警的标签相同

前往 **故障列表** → 查看故障详情，可以看到全部标签信息。
</Accordion>

<Accordion title="配置了自定义模板，实际却使用了默认模板？">
创建自定义模板时，保存模板时的语法检查通过，不代表所有故障都能渲染成功。实际发送时渲染失败，系统将改用默认模板。

<Tip>
建议在引用变量前先判断是否存在：

```go
// ❌ 错误：直接读取标签
{{.Labels.resource}}

// ✅ 推荐：先判断再读取
{{if .Labels.resource}}{{.Labels.resource}}{{end}}
```
</Tip>
</Accordion>

<Accordion title="故障标题含有字符转义（如 &gt;）？">
使用 `toHtml` 函数处理：

```go
// 转义 HTML 字符
{{toHtml .Title}}

// 使用第一个不为空的值渲染
{{toHtml .Description .Title}}
```
</Accordion>

<Accordion title="如何转换时间格式？">
```go
// date 函数：将时间戳转换为可读格式
{{date "2006-01-02 15:04:05" .StartTime}}

// ago 函数：将时间差转换为可读格式（如 "5 分钟前"）
{{ago .StartTime}}
```
</Accordion>

<Accordion title="如何在 for 循环内部引用外部变量？">
在外部变量前增加 `$`：

```go
{{range .Responders}}
  {{if eq $.Progress "Triggered"}}
    【待处理】{{.Email}}
  {{end}}
{{end}}
```
</Accordion>

<Accordion title="如何提取带 . 的字段值（如 obj.instance）？">
使用 `index` 函数：

```go
{{index .Labels "obj.instance"}}
```
</Accordion>

<Accordion title="如何提取关联告警中的 label 并去重？">
```go
// alertLabels：得到去重后的数组
{{alertLabels . "resource"}}

// joinAlertLabels：去重后按分隔符拼接为字符串
{{joinAlertLabels . "resource" ", "}}
```
</Accordion>

<Accordion title="如何遍历并打印 Labels？">
```go
// 完整遍历
{{range $k, $v := .Labels}}
  {{$k}} : {{toHtml $v}}
{{end}}

// 排除单个 label
{{range $k, $v := .Labels}}
  {{if ne $k "resource"}}
    {{$k}} : {{toHtml $v}}
  {{end}}
{{end}}

// 排除多个 labels
{{range $k, $v := .Labels}}
  {{if not (in $k "resource" "body_text")}}
    {{$k}} : {{toHtml $v}}
  {{end}}
{{end}}
```
</Accordion>

<Accordion title="如何从 JSON 字段中提取信息？">
使用 `jsonGet` 函数从合法 JSON 中按 path 提取值。语法参考 [gjson.dev](https://gjson.dev/)。

```go
// 提取 rule_note 标签中的 detail_url 字段
{{jsonGet .Labels.rule_note "detail_url"}}

// 提取 JSON 数组中第一个元素的 name 字段
{{jsonGet .Labels.slice "0.name"}}

// 遍历数组，匹配 userId==7777 的 instanceId 字段
{{jsonGet .Labels.rule_note "#(userId==7777)#.instanceId"}}
```

<Accordion title="如何在发送应用消息时携带图片？">
**通过 imageSrcToURL 获取图片 URL**

**imageSrcToURL** 函数用于将图片的 `Src` 属性转换为可访问的 URL。

**参数说明：**
- `$root`：根上下文对象
- `Src`：图片源，可以是 `image_key` 或 http/https URL

**处理逻辑：**
- 如果 `Src` 是从图片上传界面获取的 `image_key`，会转换为可访问的 URL（短期有效）
- 如果 `Src` 是 http/https 地址，直接返回该地址

**适用平台：** 钉钉应用、Slack 应用

**使用示例：**

```go
{{ $root := . }}
{{ range $i, $v := .Images }}
  {{ $imageURL := imageSrcToURL $root $v.Src }}
  {{ if $imageURL }}![]({{$imageURL}}){{ end }}
{{ end }}
```

**通过 transferImage 上传图片到第三方平台**

**transferImage** 函数用于将图片转换并上传到第三方通知平台。

**参数说明：**
- `$root`：根上下文对象
- `Src`：图片源，可以是 `image_key` 或 http/https URL

**限制条件：**
- 最大图片大小：10 MB
- 支持格式：JPG、JPEG、PNG、WEBP、GIF、BMP、ICO、TIFF、HEIC

**权限要求：** 需要应用具备"获取与上传图片或文件资源"的权限

**适用平台：** 飞书应用（Lark App）

**使用示例：**

```go
{{ $root := . }}
{{ range $i, $v := .Images }}
  {{ $transferURL := transferImage $root $v.Src }}
  {{ if $transferURL }}![]({{$transferURL}}){{ end }}
{{ end }}
```
</Accordion>

<Accordion title="如何让查询语句里的 ~ 原样显示？">
**codeBlock** 函数用于把值包进代码块，让聊天端原样显示。Slack 的 mrkdwn 把单个 `~` 当作删除线标记，`module=~"api|worker"` 这类匹配条件不包进代码块就会渲染成删除线。

```go
{{range $k, $v := .Labels}}
  {{if in $k "prom_ql" "host_ql"}}
    *{{$k}}* : {{codeBlock $v}}
  {{end}}
{{end}}
```

空值和已经含有三个反引号围栏的值会原样返回，值本身不做转义。
</Accordion>
